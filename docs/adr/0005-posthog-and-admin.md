# 0005 分析を PostHog へ移し、管理画面を 3 画面に縮小する

- 状態: 承認済み（2026-11-14）。詳細はフェーズ 2 とフェーズ 5 の冒頭で決めます。

## 状況

分析は自前です。ブラウザから `/api/analytics` へ送り、D1 の `analytics_*` テーブルに貯め、5 分ごとの集計と数十個のトリガーで日次の値を作り、管理画面で見ています。分析のコードは `gameRoom.ts` やマッチングにも埋まっています。

管理画面は約 6,400 行の別アプリで、分析の閲覧のほかに、公開チャットのモデレーション、フィードバック管理、お知らせの編集、大会の作成と公開、計測リンクの発行を持っています。

現行のプライバシーポリシーと README は、外部の解析サービスへ提供しないこと、処理は Cloudflare だけで行うことを利用者に約束しています。

## 決定

- 分析は PostHog Cloud に任せます。無料枠で始め、リージョンは EU にします。
- 使うのは、製品分析、Web 分析、エラー追跡、セッションリプレイです。対局の開始と終了、マッチングはサーバー側から送ります。
- 送信するのは本番だけです。開発環境は既定で送信しません。
- セッションリプレイでは、チャット欄、ユーザー名、プロフィール文を記録から除外します。ログイン、アカウント設定、退会のページは録画しません。
- PostHog を有効にする前に、プライバシーポリシーと利用規約を改定して告知します。告知から 7 日後を適用日とし、既存の同意記録の仕組みで再同意を取ります。
- 自前の分析（テーブル、トリガー、集計、取得の API、管理画面の分析画面）は撤去します。長期の日次集計だけ、一度 CSV に書き出して保管します。
- 管理画面に残すのは、大会の作成と公開、公開チャットのモデレーション、フィードバック管理の 3 画面です。Cloudflare Access で保護し、アカウント ID の一覧による自前の認可はやめます。
- お知らせはリポジトリ内の Markdown にし、デプロイで公開します。ユーザー一覧と計測リンクは PostHog に任せて廃止します。

## 却下した案

- **GA4 を足し、自前の分析も続ける。** 以前の検討案です。自前の集計の保守が残ります。
- **PostHog をセルフホストする。** 既存サービスに任せるという目的に反します。
- **フィードバックを Notion へ送る。** 開発者の判断で、管理画面に残します。

## 影響と未決

- 無料枠は、製品分析が月 100 万イベント、セッションリプレイが月 5,000 件、エラー追跡が月 10 万件、プロジェクトは 1 つ、データ保持は 1 年です（2026-11-14 に公式の料金ページで確認）。
- セッションリプレイは、入力欄を既定でマスクしますが、通常のテキストは既定でマスクしません（同日、公式文書で確認）。除外する要素はこちらで指定します。
- **未確認**: Cookie を使わない計測方式の内容と、それがセッションリプレイと両立するか。開発者は Cookie 同意バナーを作らない方向を望んでいます。両立しない場合は、どちらを優先するかを開発者に確認します。
- **未確認**: EU リージョンへの送信が、個人情報の保護に関する日本の法律でどう扱われるか。ポリシー改定の時点で確かめます。
