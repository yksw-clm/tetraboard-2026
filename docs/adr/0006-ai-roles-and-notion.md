# 0006 Claude Code が設計とレビュー、Codex が実装を担い、タスクは Notion で管理する

- 状態: 承認済み（2026-11-14）

## 状況

開発者は 1 人で、実装を AI エージェントに任せ、自分はレビューと承認を受け持ちます。全体の進む速さは、開発者がレビューに使える時間で決まります。

これまでは GitHub Issues でタスクを管理し、`codex-ready`、`stage:*`、`qa-ready` のラベルで状態を表していました。作業規約は QA 担当への引き継ぎを前提にしていましたが、実際には開発者が QA と運営も兼ねています。

## 決定

- Claude Code が設計とレビューを受け持ちます。Notion のタスクに設計と受け入れ条件を書き、Codex CLI を直接呼んで実装させ、差分をレビューし、コミットと PR を作ります。文書とハーネスは Claude Code が書きます。
- Codex は、タスクごとの git worktree の中だけを変更します。commit、push、PR 作成はしません。
- 影響の大きい PR は、Codex の追加レビューも取ります。
- フェーズの冒頭で開発者が設計を承認したら、そのフェーズ内のタスクは 1 件ごとの着手確認なしで進めます。マージと本番デプロイは、毎回開発者の明示的な承認を待ちます。
- 1 タスク 1 PR にします。並走は、触るファイルが重ならないタスク 2 本までです。
- タスクは Notion の「TetraBoardタスク管理」に一本化します。`TB-123` の形の ID を、ブランチ名と PR タイトルに入れます。GitHub Issues と上記のラベルは使いません。
- スキルの実体は `.agents/skills/` に置き、`.claude/skills/` からは symlink で参照します。

## 却下した案

- **GitHub Issues を続ける。** 開発者の判断で Notion に寄せます。
- **開発者が Codex を手で起動する。** 受け渡しのたびに開発者の手が要り、レビューの時間を削ります。
- **実装も Claude Code が行う。** 書いた本人がレビューすることになります。
