# 0001 同じリポジトリの中で段階的に作り替える

- 状態: 承認済み（2026-11-14）

## 状況

web は React の SPA で約 3.3 万行、worker は約 2.8 万行あり、本番で利用者が対局しています。文書は README だけで 338KB あり、CI は PR 1 回に約 13 分かかります。開発者は 1 人で、実装は AI エージェントに任せ、開発者はレビューと承認を受け持ちます。

この状態から、web の SvelteKit 化、バックエンドの再設計、分析の外部サービス化、CI と文書の整理を行います。

## 決定

- 本番を動かしたまま、このリポジトリの中で段階的に置き換えます。各フェーズの終わりに本番へ出せる状態を保ちます。
- フェーズは、土台（ハーネスと文書）、CI、分析、バックエンド、web、管理画面、掃除の順です。バックエンドと web は並走します。
- 各フェーズの冒頭で設計を深掘りし、開発者が承認してから実装に入ります。
- アカウント、レート、戦績、棋譜は完全に保持します。自前の分析データは保持しません。
- 改善が終わるまで機能開発を凍結し、不具合修正と法務対応だけ続けます。

## 却下した案

- **新しいリポジトリで作り直し、一度に切り替える。** 完成するまで本番で確かめられず、切り替えの日にデータ移行と全機能の検証が重なります。1 人でレビューする体制では、切り替え後の不具合の原因を絞りにくいと判断しました。
- **機能開発と並行して進める。** 同じ機能を旧構成と新構成で二度作ることになります。

## 影響と未決

- 移行中は、React と Svelte、生 SQL と drizzle のように、新旧の作りが同じリポジトリに並びます。どこまで移したかは Notion のタスクで追います。
- 本番デプロイは月〜木に行い、大会のある土日と前日の金曜は避けます。
