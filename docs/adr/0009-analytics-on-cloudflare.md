# 0009 分析は Cloudflare の中で作り直す

- 状態: 承認済み（2026-11-14）。[0005](0005-posthog-and-admin.md) のうち、分析を PostHog へ移す部分を置き換えます。管理画面を縮小する部分は 0005 のままですが、残す画面に KPI の画面を 1 つ足します。

## 状況

0005 で分析を PostHog Cloud へ移すと決めた後、フェーズ 2 の深掘りで次のことが分かりました。

- PostHog の契約相手は米国法人で、EU リージョンを選んでも、個人情報保護法の外国にある第三者への提供として、同意か体制整備の根拠が必要になりそうです。プロフィールを送るなら、なおさらです。
- 外部送信規律の公表、DPA の締結、退会時の削除連携、ポリシーの改定と再同意が必要で、どれも開発者が判断しなければなりません。
- Cookie を使わない方式では、PostHog のセッションリプレイは使えません。

一方、今の自前の分析は、D1 の約 30 テーブル、業務テーブルに付いた分析用のトリガー約 20 個、5 分ごとの集計で成り立っていて、`gameRoom.ts` やマッチングの処理に埋め込まれています。フェーズ 3 のバックエンド再設計の重荷になり、CI の不安定なテストの原因にもなっていました。

今のプライバシーポリシーは「処理と保存は運営者と委託先 Cloudflare で行う」と約束しています。

## 決定

- 分析は Cloudflare の中で完結させます。外部の解析サービスは使いません。
- 訪問数、ページビュー、参照元、端末、表示速度は、Cloudflare Web Analytics（Cookie なし）で計測します。
- イベントは Workers Analytics Engine に書きます。最初のアクセス時の参照元と UTM、対局の開始・終了・打ち切り、マッチングの各段階、登録の各段階、ブラウザの未処理のエラーです。最初のアクセスは、HTML を返す Worker が書きます。
- 完了した対局、アカウント数、登録数などの確定値は、今の業務のテーブルから出します。
- ブラウザの識別には、今の計測用 Cookie（自サイトだけで使う 1 年の乱数 ID）を残します。
- Analytics Engine の保持は 3 か月なので、毎月 1 回 KPI の月次の値を D1 の小さなテーブルに保存します。トリガーは付けません。
- 管理画面に KPI の画面を 1 つ置き、Cloudflare の SQL API（Worker の binding）で問い合わせます。
- 次のものは消します。D1 の分析テーブルと業務テーブルに付いた分析用のトリガー、5 分ごとの集計、管理画面の分析の画面、ユーザー一覧と最終ログイン日時のテーブル、短縮 UTM の計測リンク。
- イベントの書き込みは、業務のコードから直接 Analytics Engine を呼ばず、小さなインターフェース越しに行います。テストでは偽物を差し込みます。
- 何をどう数えるかの正本は [docs/specs/analytics.md](../specs/analytics.md) です。

## 却下した案

- **PostHog Cloud（0005 の案）。** 法務の判断と手続きが開発者の負担になります。
- **今の自前の分析をそのまま残す。** テーブル、トリガー、集計の重さがフェーズ 3 まで残ります。
- **Cookie を使わない計測だけにする。** 「訪問ブラウザ数」と「開始率」がこれまでの定義で出せなくなります。

## 影響と未決

- 失うもの: セッションリプレイ、画面で組めるファネルやリテンションの分析、利用者ごとの最終利用日、短縮 UTM。
- Analytics Engine は件数が多いと間引きが起きることがあり、正確さは保証されていません。1 日数千件程度なら起きない見込みですが、集計では `_sample_interval` を使い、間引きが起きていないかを KPI の画面に表示します。
- Analytics Engine には JOIN がなく、新しい SQL API は入れ子の集計もできません。訪問者ごとや対局ごとにまとめた行を取り出し、割合の計算は Worker のコードで行います。
- 新しい SQL API は 2026-10 公開のベータ版です。使うのは管理画面だけです。
- **未確認**: Analytics Engine の binding をテスト環境（Vitest と workerd）で使えるか。Worker が返す HTML に Web Analytics のスクリプトが自動で入るか（入らなければ手で入れます）。
- Analytics Engine は現時点では課金されていませんが、数か月以内に課金が始まる予定です（2026-11-14 に公式の料金ページで確認）。今の規模では無料の範囲に収まる見込みです。
