# 0007 CI は通常の PR で 4 分以内を目標にし、テストを層で分ける

- 状態: 承認済み（2026-11-14）。手順はフェーズ 1 の冒頭で決めます。

## 状況

Full CI は PR 1 回に約 13 分かかります（2026-11-13 時点、直近 9 件の中央値 約 790 秒）。2026-10-30 の記録では 212〜229 秒でした。悪化の原因は、2026-11-08 から 11-11 に足した Rust の AI まわりです。

- `packages/ai` のテストが 135〜210 秒かかり、実行キューの最後に回るため、全体の最長経路になっています。
- 本番 AI の dry-run が Docker イメージを 4 個ビルドし、126〜177 秒かかります。
- イメージを検証するジョブ（約 200 秒）が、チェックの後に直列で走ります。Docker のビルドは、Full CI 1 回で最大 3 回走ります。

Worker の統合テストは 2 群の並列で 106〜129 秒かかります。これは 2026-10-30 から変わっていません。約 1 分で終わる Fast CI は、worker、protocol、ゲームに触れると使えないため、ほぼ使われていません。コミット時のフックは、毎回 `bun run check` の全体を実行します。

## 決定

- 目標は、通常の PR で 4 分以内、ローカルの `bun run check` で 90 秒以内です。
- AI の Docker ビルドと `packages/ai` のテストは、`packages/ai` に差分がある PR とリリース時だけ走らせます。
- ワークスペース別のジョブに分けて並列で走らせます。自作の Fast／Full の判定は、変更パスによる単純な判定に置き換えます。
- コミット時のフックは、format と lint だけにします。
- PR の前にローカルで必須にするのは `bun run check` だけです。build と deploy の dry-run は CI が実行します。
- Worker の統合テスト（Vitest と workerd）は、Durable Object と D1 の結合の確認に絞ります。ロジックは純粋な TypeScript に移し、Bun test で確かめます（0003）。
- テストを消すときは、同じ振る舞いを別の層のテストで確かめ直します。これまでの「テストケースを削除しない」というルールを、この形に改めます。

## 却下した案

- **テストを Bun test に寄せることだけで短縮する。** 悪化分のほとんどは Docker のビルドと `packages/ai` のテストで、テストランナーの違いではありません。
- **テストを減らして短縮する。** 確かめている振る舞いが減ります。

## 影響と未決

- `packages/ai` に差分がない PR では、AI のイメージを検証しません。イメージに影響する変更（ベースイメージや共有の設定）を見落とさない判定条件を、フェーズ 1 の冒頭で決めます。
- 統合テストが不安定で、再実行が起きています（管理分析のテストが直近で 3 回失敗）。このテストは 0005 の撤去で消えます。
