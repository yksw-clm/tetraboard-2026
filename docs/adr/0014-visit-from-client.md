# 0014 訪問の開始は画面の起動後に画面から送る

- 状態: 承認済み（2026-11-25）。[0009](0009-analytics-on-cloudflare.md) の「最初のアクセスは、HTML を返す Worker が書きます」を置き換えます。

## 状況

0009 では、訪問の開始（`visit_started`）を、画面の HTML を返す Worker が書くと決めました。ブラウザ以外のアクセスは User-Agent で除いています。

2026-11-14〜11-25 の本番のイベントでは、訪問ブラウザ 1,002 件のうち 505 件が「PC、直接流入、1 ページだけ、対局なし」でした。深夜も 1 日 40〜55 件が一定に来ています。Cookie を保たないボットが、ブラウザを名乗る User-Agent で判定をすり抜けていると見ています。そのため「訪問ブラウザ数」と「対局開始率」が実態とずれています。

## 決定

- Worker は、画面の HTML を返すときに訪問の開始を書かず、計測用 Cookie の発行だけを続けます。
- 画面の JavaScript が起動したら、1 回だけ Worker に訪問を送ります。Worker はそれを受けて訪問の開始を書きます。記録する項目は変えません。
- 計測の対象かどうかは、HTML を返す Worker が決め、HTML に目印として埋め込みます。画面は目印のある文書からだけ送ります。HTTP のステータスを知っているのは Worker だけで、404 でも同じ HTML を返すページがあるためです。
- 送られた訪問に計測用 Cookie がなければ記録しません。Cookie を発行した後の通常のブラウザなら、送るときには Cookie があります。Cookie のない訪問は対局への参加と結び付かず、対局開始率を下げるだけだからです。
- 参照元は、画面が送る `document.referrer` のホストだけを使います。

## 却下した案

- **User-Agent やヘッダーの判定を強める。** 画面の変更は要りませんが、ブラウザを名乗るボットは除けません。
- **Cookie のない訪問も新しい ID で記録する。** Cookie を拒否する人も数えられますが、Cookie を保たないボットが残ります。
- **指紋採取や外部のボット判定サービス。** [計測の仕様](../specs/analytics.md) の「守ること」に反します。

## 影響と未決

- JavaScript を動かさない訪問と、Cookie を拒否するブラウザの訪問は数えなくなります。訪問ブラウザ数は、切り替えの前後で比べられません。
- 画面の起動前に離れた訪問も数えなくなります。
- JavaScript を動かし、Cookie も保つボットは、これまでどおり数えます。
- 切り替えの前の訪問は書き換えません。
