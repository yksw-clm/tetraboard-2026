# ランダムマッチング

2026-11-08の実装承認に基づくフェーズ4の仕様です。初回は四人リバーシのシングルス、レートなし、1人3分切れ負け（秒読みなし）を対象とします。人間は名前設定済みゲストアカウントと登録アカウントです。盤面・脱落・順位は[ルール正本](rules/four-reversi.md)を維持します。

実力に応じた組合せとCPU入り対局の集計は、後述の[フェーズ4.5仕様（承認済み・未実装）](#フェーズ45仕様承認済み未実装)です。その節以外のフェーズ4の動作説明・測定条件を、新仕様の実装完了として読み替えません。

## 成立と開始

- 待機順で人間を優先します。4人なら即時、4人未満なら最古の有効な待機開始から30秒後に不足席をCPUで補充します。更新・再読み込み・参加者の追加で待機開始時刻を戻しません。
- 初回の補充はRustの`lv3-v1`（ヨミ）に固定します。CPUの実際のprofile・設定hash・名前・レベル・判断方法を席と棋譜へ保存します。既存のCPU level 1/2のフィールドは旧CPUへの互換用として維持し、Rustのレベルは別のprofileメタデータで表示します。新しいprofileを旧CPUのLv2として表示しません。
- CPUはコロ（Lv1・一様ランダム）、カド（Lv2・1手評価）、ヨミ（Lv3・MaxN）、モンテ（Lv4・MCTS）、ノヴァ（Lv5・探索量を増やしたMCTS）です。同じprofileが複数席に入る場合はヨミ1・ヨミ2のように区別します。アイコンは既存のロボット、CPU表記を併用します。現状のLv4/5は探索量の差で、未検証の棋風を新設しません。
- 成立後に専用ルームへ入り、人間全員の認証済み接続から5秒カウントダウンして自動開始します。カウントダウン中は持ち時間を進めません。30秒は組合せを決める待機時間で、入室時間とは別です。
- ルーム準備から30秒の間に入室とカウントダウンを完了します。本人の最後の接続が切れた場合はカウントダウンを中止し、全員復帰後に再度5秒を数えます。期限は延長しません。開始できなかった場合は未接続者・取消者を外し、有効な参加者を元の待機優先度で戻します。
- 対局開始後に人間をCPUへ置き換えません。投了・退室・切断・時間切れは現行の脱落規則です。Rustエンジンも脱落色を手番・全滅保護から外し、脱落石を盤上へ残し、脱落順の順位を保持します。

## 待機・資格・表示

- 操作元のタブから10秒ごとに継続し、30秒で待機を失効します。明示的な取消・ログアウト・退会で待機を終えます。ページ破棄や再読み込みだけでは取消を送りません。失効後の復帰で自動再参加させません。
- 1アカウントにつき全ゲームの通常席・大会待機・ランダムマッチを合わせて1つだけに制限します。同じ操作の再送は同じ待機を返し、取消済みの操作を再送しても再参加しません。
- 別タブ・別端末では枠を増やさず「このタブで続ける」で操作元を明示的に切り替えます。リロードは同じタブの保存情報と生存確認を使って復元します。引き継ぎは世代と参加資格を更新し、旧操作元の更新・取消・参加資格を無効にします。
- 専用ルームは公開観戦できますが、通常参加・ホストによる設定変更・CPU変更・手動開始・直接再戦を受け付けません。一般のルーム・大会の仕様は維持します。
- 終局後は「もう一度マッチング」「ロビーへ」「棋譜を見る」を案内します。次のマッチングは明示操作とし、旧席の退室を確定してから新しい待機へ入れます。
- CPU入りは履歴・棋譜のみ、人間4人の保存済み対局は現行の対人戦績・ランキング・バッジの集計条件に従います。レーティング・CPUの対人レート較正・人間だけで待つ選択・他ゲーム・ダブルスは初回に追加しません。

## 責務と公開

待機と割当は既存Workers / Durable Objects、全体の相互排他はD1席予約で扱います。待機列のキーはゲーム・ルール版・時計・対戦種別から定め、初回は1列だけです。AI Serviceへ本人・待機列・席予約を渡しません。複数の保存先を同時に確定したものと扱わず、操作ID付きの永続予約と再実行可能な回復で整合させます。

Service未設定・公開フラグ無効では新規参加を受け付けません。2026-11-08の開発環境への反映指示により、開発用Workerと開発専用Serviceを接続する構成を追加しました。削除済みの検証用Cloudflare環境は再作成しません。本番の有効化は別途承認後です。

## フェーズ4.5仕様（承認済み・未実装）

2026-11-08に開発者がフェーズ4.5-Aの計画を承認しました。Aはこの節と[CPU評価・実力推定の較正仕様](../packages/ai/docs/calibration.md)の文書化までです。**以下の組合せ・CPU選択・集計変更は、まだ実装していません。** 現在の4人での即時成立、ヨミ固定、CPU入り対局の集計除外は、後続のコード変更まで維持します。

### 対象と利用者への説明

四人リバーシ・シングルス、名前設定済みゲスト・登録アカウント、1人3分切れ負け、同じ待機列と入口を使います。公開ランク・レートマッチや公開レート数値は追加せず、「実力の近い相手を優先」と案内します。CPUの固有名・ロボットアイコン・CPU表記を維持します。Game Roomが盤面・合法手・手番・順位を確定し、AI Serviceは着手を計算します。

### 人間の組合せ

1. 有効な待機のうち最古の1人を中心に、待機順の先頭16人を候補とします。待機開始時刻が同じ場合は操作IDの昇順で固定します。更新・追加参加で最古の待機開始をリセットしません。
2. 有効対局数10局以上かつσがβ以下の人間を、組合せに使える推定を持つ参加者とします。βは25/6です。候補に暫定参加者がいる場合は、推定で弱い側へ寄せず待機順を使います。4人いれば成立し、不足時は最古の待機から30秒でCPU補充へ進みます。
3. 候補全員に使える推定がある場合は、最古の参加者を含む4人組についてμの最大差を比較します。下表の範囲を満たす組のうち差が最小の組を選び、同点は参加者の待機順を順に比較して決めます。条件内の4人組がなければ範囲拡大または30秒を待ちます。
4. 最古の待機から30秒経過後は実力差の制限を解除します。候補から人間を最大4人まで優先し、4人組が複数なら最古の参加者を含み差が最小の組を使います。候補が4人未満なら有効な人間全員を含め、不足席をCPUで補充します。

| 最古の待機からの経過 | 安定した推定値を持つ4人組のμの最大差 |
| -------------------- | ------------------------------------ |
| 0秒以上・10秒未満    | β以下                                |
| 10秒以上・20秒未満   | 2β以下                               |
| 20秒以上・30秒未満   | 3β以下                               |
| 30秒以上             | 制限なし。成立を優先                 |

30秒は組合せ条件を切り替える基準であり、通信・入室・開始カウントダウンまでが30秒以内に必ず終わるという意味ではありません。待機lease・本人資格・全ゲームの同時参加制限、入室期限、接続確認と5秒カウントダウン、再マッチング時の旧席解放はフェーズ4を維持します。

### 補充CPUの選択

選ばれた人間全員が使える推定を持つ場合は、そのμの中央値に最も近い、採用済みの較正結果を持つprofileを選びます。偶数人の中央値は中央2値の平均とします。同距離なら代表μの小さい側、それも同じならprofile ID昇順で固定します。補充席は同じprofileにそろえ、名前の番号で席を区別します。

暫定参加者がいる場合、使用可能な参照値がない場合、profileの版・hash・予算と較正結果が一致しない場合は、既定のヨミ`lv3-v1`へ固定します。未較正のprofileや、設定を変えたCPUを候補へ足しません。CPU参照値を人間との1局ごとに自動変更しません。対局開始後に人間をCPUへ置き換えることもしません。

CPU間の較正と対人尺度の較正は区別し、初回本番では人間の尺度を暫定として扱います。開発環境で予備検証後、本番で対人データを蓄積します。内部のμ・σ・有効対局数は公開APIへ載せず、推定不足を理由に弱い参加者と断定しません。

### 戦績・ランキング・バッジ

集計対象は**従来の対人戦に、新仕様の由来情報を持つランダムマッチを加えたもの**です。CPU入りでも人間本人の対局数・優勝数・優勝率・順位別戦績へ同じ1局として加算します。CPU自身はアカウントのランキングに載せません。同率1位も現行どおり優勝として数えます。

対局数・優勝数バッジも同じ条件へ合わせ、達成イベントは保存・集計の確定後に一度だけ反映します。マイページ、ロビー、プレイヤー情報カード、バッジで異なる集計条件を使わず、「対人戦のみ集計」などの説明を新条件へ更新します。実力推定値で既存の優勝数・対局数ランキングを並べ替えることはしません。

通常ルームのCPU戦は追加対象外です。旧CPU戦をprofile名や部屋番号からランダムマッチと推測して加算せず、既存の対人戦績は維持します。未終局・保存待ちは加算せず、結果の再送でも二重加算しません。代替手が使われても、Game Roomが合法な終局として保存した局は集計しますが、CPU較正と内部実力更新からは外します。

### 保存と本番公開

後続実装では対局由来、集計規則版、較正版、推定方式版、CPU識別情報と代替手使用を保存します。現在の保存棋譜にはランダムマッチ由来の明示項目がないため、部屋索引だけに依存しない保存を追加してから集計を拡張します。

本番ではランダムマッチを外部AI接続の対象とし、通常ルームのCPUを意図せず切り替えない制御を追加します。現在はService URLの設定が通常ルームにも影響するため、URLを設定しただけでこの制御が完成したとは扱いません。

運用性能・費用の目標は[評価・較正仕様](../packages/ai/docs/calibration.md#運用性能と費用の判断基準)に従います。初期の追加費用は月5 USD・税抜を目安とし、本番用Service・Secret・公開差分・確認結果・停止手順をそろえて承認を得ます。新規受付の停止時も、進行中対局と終局保存を維持し、実力を考慮した組合せだけを待機順へ戻せることを検証します。Aではこれらのコード・設定・クラウド資源を変更しません。
