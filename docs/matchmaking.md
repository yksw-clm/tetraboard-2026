# 四人リバーシのマッチング

2026-11-08の実装承認に基づくフェーズ4の仕様です。初回は四人リバーシのシングルス、レートなし、1人3分切れ負け（秒読みなし）を対象とします。人間は名前設定済みゲストアカウントと登録アカウントです。盤面・脱落・順位は[ルール正本](rules/four-reversi.md)を維持します。

現行の新規受付は[四人リバーシのレート戦](#四人リバーシのレート戦)を参照してください。以下のフェーズ4の動作説明と測定条件は、旧ランダムマッチの記録です。

## 成立と開始

- 待機順で人間を優先します。4人なら即時、4人未満なら最古の有効な待機開始から30秒後に不足席をCPUで補充します。更新・再読み込み・参加者の追加で待機開始時刻を戻しません。
- 初回の補充はRustの`lv3-v1`（ヨミ）に固定します。CPUの実際のprofile・設定hash・名前・レベル・判断方法を席と棋譜へ保存します。既存のCPU level 1/2のフィールドは旧CPUへの互換用として維持し、Rustのレベルは別のprofileメタデータで表示します。新しいprofileを旧CPUのLv2として表示しません。
- CPUはコロ（Lv1・一様ランダム）、カド（Lv2・1手評価）、ヨミ（Lv3・MaxN）、モンテ（Lv4・MCTS）、ノヴァ（Lv5・探索量を増やしたMCTS）です。同じprofileが複数席に入る場合はヨミ1・ヨミ2のように区別します。アイコンは既存のロボット、CPU表記を併用します。現状のLv4/5は探索量の差で、未検証の棋風を新設しません。
- 成立後に専用ルームへ入り、人間全員の認証済み接続から5秒カウントダウンして自動開始します。カウントダウン中は持ち時間を進めません。30秒は組合せを決める待機時間で、入室時間とは別です。
- ルーム準備から30秒の間に入室とカウントダウンを完了します。本人の最後の接続が切れた場合はカウントダウンを中止し、全員復帰後に再度5秒を数えます。期限は延長しません。開始できなかった場合は未接続者・取消者を外し、有効な参加者を元の待機優先度で戻します。
- 対局開始後に人間をCPUへ置き換えません。投了・退室・切断・時間切れは現行の脱落規則です。Rustエンジンも脱落色を手番・全滅保護から外し、脱落石を盤上へ残し、脱落順の順位を保持します。

## 待機・資格・表示

- 操作元のタブから10秒ごとに継続し、30秒で待機を失効します。明示的な取消・ログアウト・退会で待機を終えます。ページ破棄や再読み込みだけでは取消を送りません。失効後の復帰で自動再参加させません。
- 1アカウントにつき全ゲームの通常席・大会待機・ランダムマッチを合わせて1つだけに制限します。同じ操作の再送は同じ待機を返し、取消済みの操作を再送しても再参加しません。
- 別タブ・別端末では枠を増やさず「このタブで続ける」で操作元を明示的に切り替えます。リロードは同じタブの保存情報と生存確認を使って復元します。引き継ぎは世代と参加資格を更新し、旧操作元の更新・取消・参加資格を無効にします。
- 専用ルームは公開観戦できますが、通常参加・ホストによる設定変更・CPU変更・手動開始・直接再戦を受け付けません。一般のルーム・大会の仕様は維持します。
- 終局後は「もう一度マッチング」「ロビーへ」「棋譜を見る」を案内します。次のマッチングは明示操作とし、旧席の退室を確定してから新しい待機へ入れます。
- CPU入りは履歴・棋譜のみ、人間4人の保存済み対局は現行の対人戦績・ランキング・バッジの集計条件に従います。レーティング・CPUの対人レート較正・人間だけで待つ選択・他ゲーム・ダブルスは初回に追加しません。

## 責務と公開

待機と割当は既存Workers / Durable Objects、全体の相互排他はD1席予約で扱います。待機列のキーはゲーム・ルール版・時計・対戦種別から定め、初回は1列だけです。AI Serviceへ本人・待機列・席予約を渡しません。複数の保存先を同時に確定したものと扱わず、操作ID付きの永続予約と再実行可能な回復で整合させます。

Service未設定・公開フラグ無効では新規参加を受け付けません。2026-11-08の開発環境への反映指示により、開発用Workerと開発専用Serviceを接続する構成を追加しました。削除済みの検証用Cloudflare環境は再作成しません。本番の有効化は別途承認後です。

## 四人リバーシのレート戦

2026-11-09に承認された切り替え仕様です。フェーズ4.5で計画した[CPU評価と実力推定の較正](../packages/ai/docs/calibration.md)を引き継ぎます。CPU補充は待機20秒で試み、公開レートを使います。

### 対象と利用者への説明

四人リバーシ・シングルス、1人3分切れ負け（秒読みなし）に固定します。参加には登録アカウントが必要です。「ランダムマッチ」の入口と新規受付を「レート戦」に切り替え、受付中の待機列は1本とします。

ロビーのレート戦ダイアログで公開レートとランク、認定前は本人の進捗を確認して検索します。検索中に閉じる場合は取消を確認し、その間に成立した場合も自動入室します。人間全員の接続後、ルーム内で5秒数えて開始します。CPUは固有名・ロボットアイコン・CPU表記で区別します。GameRoomが盤面・合法手・手番・順位を確定し、AI Serviceが着手を計算します。

### 人間の組合せ

1. 有効な待機のうち最古の1人を中心に、待機順の先頭16人を候補とします。待機開始時刻が同じ場合は操作IDの昇順で固定します。更新・追加参加で最古の待機開始をリセットしません。
2. 有効対局数10局以上かつσがβ以下の人間を、対人の組合せに使える推定を持つ参加者とします。βは25/6です。候補に暫定参加者がいる場合は待機順を使い、4人そろえば成立させます。この内部条件と公開レートの認定5局は別です。
3. 候補全員に使える推定がある場合は、最古の参加者を含む4人組についてμの最大差を比較します。下表の範囲を満たす組のうち差が最小の組を選び、同点は待機順で決めます。
4. 最古の待機から20秒に達した時点で実力差の制限を解除し、人間を最大4人まで優先します。候補が4人未満なら有効な人間全員を含め、不足席をCPUで補充することを試みます。

| 最古の待機からの経過 | 安定した推定値を持つ4人組のμの最大差 |
| -------------------- | ------------------------------------ |
| 0秒以上・10秒未満    | β以下                                |
| 10秒以上・20秒未満   | 2β以下                               |
| 20秒到達             | 制限なし。人間を優先し、不足席を補充 |

20秒でCPU補充を試み、枠が埋まっている場合は元の待機順で再試行します。待機中は対人戦の成立と取消を受け付けます。レート戦ダイアログの「○人が待機中」には、そのゲームで待つ人間と、補充時刻を過ぎて枠の空きを待つ組合せの不足CPU席を含めます。成立した組合せは人数から外します。

通信、入室、開始カウントダウンは成立後に行います。待機lease、全ゲームの同時参加制限、入室期限、再マッチング時の旧席解放はフェーズ4の仕組みを使います。

### 補充CPUの選択

認定済みの人間が1人なら本人のμ、複数ならそのμの中央値に最も近い、採用済みの較正結果を持つprofileを選びます。全員が認定中なら中間の強さに相当する採用済みprofileを使います。偶数人の中央値は中央2値の平均とします。同距離なら代表μの小さい側、それも同じならprofile ID昇順で決めます。補充席は同じprofileにそろえ、名前の番号で席を区別します。

CPUの参照値はprofileの版・hash・予算にひも付け、採用した版の値を対局開始時に記録します。開発環境の試験候補は較正版 `four-reversi-lv1-lv5-v1` のLv1・2・3・5です。Lv4はLv3との差が判定保留のため候補から外します。設定hash・Engine・ルール・局面版が一致する候補がない場合、新規受付を停止します。開始後の投了・退室・切断・時間切れはゲームの脱落規則に従います。

### 認定・レート・ランク

- 最後の人間が脱落後に退室しても、CPUだけで終局まで進めます。確定した脱落順位は維持し、終局保存後に再参加できます。旧版で未終局のまま中断されたと確認できるCPU混在局は、再参加時に残っていた保存待ち予約を解除します。

- 最初の有効な5局を認定戦とします。補充CPU入りの局も数え、5局目の保存後にレートとランクを公開します。認定後も、人間4人の局とCPU入りの局で一つのレートを更新します。他の人間と有効な対局を終えるまでは「対人戦未経験」と表示します。
- レートはGameRoomが確定した1〜4位から計算します。同順位を維持し、石数差による加点は行いません。OpenSkill 5.0.1のPlackett–Luceを使い、CPUの固定参照値を入力して、人間側だけを更新します。
- 開始前の取消・入室失敗、未保存の局、AIの代替手を使った局は認定・レート更新の対象外です。対局結果の保存が確定してから反映し、保存を再試行しても同じ対局の更新は一度とします。
- ランク名は将棋と共通で、ブロンズ、シルバー、ゴールド、プラチナ、ダイヤモンドの各帯を3、2、1の順とします。レート・境界はゲーム別です。内部のμ・σは非公開です。
- 認定後の有効局は、丸めた公開レートの前後差をCPU入りで最大±24、人間4人で最大±32に制限し、上限を適用した実力推定を保存します。参加者ごとに認定状態を判定し、最初の5局は通常の更新式を使います。
- 終局画面では順位と、名前の右にその対局の更新後レートと増減を表示します。認定中は本人に進捗、相手に「認定中」、CPUには固定の基準レートを表示します。本人の認定5局目には初回レートと「認定完了」を表示します。終局後の再マッチングは結果の保存確定を待ちます。

### 公開レートとランク

公開レートは `Math.round(1500 + 50 × (μ − 25))` で計算します。プレイヤーの初期推定値とCPU Lv3の較正値は、どちらも1500に換算します。対戦相手の選定と終局時の推定更新には、丸め前の内部値を使います。

ランクは丸めた公開レートから求めます。以下は開発環境で確認するための暫定境界です。

| ランク | 3 | 2 | 1 |
| --- | ---: | ---: | ---: |
| ブロンズ | 1199以下 | 1200〜1299 | 1300〜1399 |
| シルバー | 1400〜1499 | 1500〜1599 | 1600〜1699 |
| ゴールド | 1700〜1799 | 1800〜1899 | 1900〜1999 |
| プラチナ | 2000〜2099 | 2100〜2199 | 2200〜2299 |
| ダイヤモンド | 2300〜2399 | 2400〜2499 | 2500以上 |

5局目の保存前は本人に認定進捗を返し、5局目の保存後は整数のレートとランクを返します。例として1500はシルバー2、1499はシルバー3です。開発環境では人間4人の局とCPU混在局を分け、認定終了時の到達帯、認定後の1局あたりの増減、境界付近での昇降頻度を確認します。

### 戦績・ランキング・バッジ

通常戦績・ランキング・バッジの対象は[共通の集計仕様](../README.md#戦績の表示)に従います。

旧ランダムマッチの棋譜と戦績を引き継ぎます。認定と公開レートの対象は、切り替え後にレート戦として成立した対局です。従来の優勝数・対局数ランキングと、レート戦のランクは別に扱います。

戦績は従来の対人戦に、レート戦として記録した局を加えます。CPU入りでも人間本人の対局数・優勝数・優勝率・順位別戦績へ同じ1局として加算します。CPU自身はアカウントのランキングに載せません。同率1位も現行どおり優勝として数えます。

対局数・優勝数バッジも同じ条件へ合わせ、達成イベントは保存・集計の確定後に一度だけ反映します。マイページ、ロビー、プレイヤー情報カード、バッジで異なる集計条件を使わず、「対人戦のみ集計」などの説明を新条件へ更新します。実力推定値で既存の優勝数・対局数ランキングを並べ替えることはしません。

通常ルームのCPU戦は追加対象外です。旧CPU戦の集計は成立時の扱いを維持します。保存確定時に一度だけ加算します。AIの代替手を使っても合法な終局として保存した局は戦績集計に含め、認定・レート更新とCPU較正の対象から外します。

### 保存と本番公開

レート戦では較正版、推定方式版、CPU識別情報と代替手使用を保存します。旧ランダムマッチの新規受付を止め、成立済みの対局は成立時のルールで終局・保存します。割当前の旧待機は終了します。旧URL `/games/four-reversi/matchmaking` は `/games/four-reversi?matchmaking=1` へ転送します。旧クライアントとの互換用に、状態参照と操作APIは `?rated=1` で新しい待機列を選びます。旧列の成立済みの割当と入室資格は旧APIで復旧できます。

本番ではレート戦のCPUを外部AI接続の対象とし、通常ルームのCPUとは設定を分けます。

運用性能・費用の目標は[評価・較正仕様](../packages/ai/docs/calibration.md#運用性能と費用の判断基準)に従います。初期の追加費用は月5 USD・税抜を目安とし、本番用Service・Secret・公開差分・確認結果・停止手順をそろえて承認を得ます。新規受付の停止時も、進行中対局と終局保存を継続できることを確認します。
