# 通常リバーシのレート戦

前局が進行中・レート保存待ちの間は、別ゲームも含めた[再検索制限と観戦案内](../README.md#前局が進行中保存待ちのときのレート戦)に従います。

未ログイン・ゲスト向けの連携案内と認証後の復帰は、[レート戦の共通仕様](../README.md#未ログイン時のレート戦の連携案内)に従います。

名前・アイコンから開くプレイヤー情報には、レート戦の成立時に固定した対局前レートを表示し、棋譜でも同じ値を使います。CPUはその局の基準レート、認定前の登録者は「認定中」とします。通常ルーム・大会では表示しません。過去の記録と現在プロフィールの区別は[プレイヤー情報の共通仕様](../README.md#プレイヤー情報カード)に従います。終局結果の更新後レートと増減は従来どおりです。

登録アカウントが通常リバーシのロビーから参加できます。持ち時間は1人5分の切れ負け（秒読みなし）です。着手・自動パス・引き分け・時間切れは[通常リバーシのルール](rules/reversi.md)に従います。

## 対戦相手と開始

検索中の残り時間の目安・見積もれない場合の経過時間は、[マッチング時間の共通仕様](../README.md#レート戦のマッチング時間の目安)に従います。

ダイアログの待機人数は、有効な人間の待機者と利用可能なCPU枠を加算する[共通仕様](../README.md#レート戦の待機人数)に従います。CPU枠が未使用で人間の待機もなければ4人です。

対人戦を優先し、最も長く待っている人を起点にレート差100以内で探します。5秒から200以内、10秒から300以内へ広げます。15秒で条件内の相手がいなければ、本人に最も近い基準レートのCPUで補充します。同じ距離なら基準レートの低いCPUを選びます。CPU枠は通常リバーシのレート戦で最大4局・4席です。枠が埋まっている間も対人戦を探します。専用ルームに人間全員が接続してから5秒後に自動で開始します。

CPUは[較正結果](https://github.com/yksw-clm/tetraboard-2026/pull/316)に基づく次の暫定値を使います。割当時に設定の版と基準レートを固定し、新規ルームにはCPU名を保存します。ルームのカードには名前と「CPU」を表示し、入室メッセージ、プレイヤー情報、終局結果、棋譜にも同じ名前を使います。

| CPU名 | CPU設定 | 基準レート |
| --- | --- | ---: |
| パチ | レベル1の探索手を25%使用 | 1,297 |
| クルリ | レベル1の探索手を50%使用 | 1,490 |
| カエシ | レベル1の探索手を75%使用 | 1,748 |
| セキ | 標準レベル1 | 2,109 |
| フチ | 標準レベル2 | 2,385 |
| シメ | 標準レベル4 | 2,650 |
| クロシロ | 標準レベル8 | 3,003 |

弱体化設定では、探索手を使わない手番に合法手を一様に選びます。この着手は設定どおりの通常の着手です。AI障害で従来Lv2に切り替えた局は棋譜を保存し、認定局数とレート更新の対象から外します。

## 認定とレート更新

初期値は1,500です。有効な対人戦と補充CPU戦を合わせた最初の5局が認定戦です。レートは[将棋のレート戦](shogi-rated-match.md#レート更新)と同じElo式で更新します。勝ちは1、引き分けは0.5、負けは0です。

| 本人の状態 | 対人戦のK | CPU戦のK |
| --- | ---: | ---: |
| 認定中 | 64 | 48 |
| 認定後 | 32 | 16 |

認定5局目には認定中のKを使います。対人戦では両者、CPU戦では人間側を更新します。棋譜・レート更新・保存待ちの解除を同じD1バッチで行い、保存の再試行でも1局を一度だけ反映します。公開プロフィールでは認定後のレートを表示し、対人戦の経験有無を示す補足ラベルは表示しません。

## 開発環境と公開β

`/games/reversi?matchmaking=1` から検索し、入室・結果・再参加を共通の画面で扱います。本人のレートまたは認定進捗はマイページにも表示します。新規参加は開発環境の `REVERSI_MATCHMAKING_ENABLED=true` と外部AIの接続設定で有効になります。AI Gatewayは探索レベル1・2・4・8を受け付ける版を使用します。

基準レートは従来の内蔵Lv2を1,500と置いたCPU同士の相対値です。公開βではCPU設定ごとの期待得点と実際の成績を比較し、特に最弱の25%設定と初期レートに近い50%設定を見直します。公開環境での有効化は開発環境での確認とリリース承認の後に行います。
