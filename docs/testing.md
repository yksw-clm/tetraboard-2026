# テスト方針

`bun run check` にformat確認・lint・型チェック・全テストを含め、目標を180秒以内とします。GitHub Actionsはcheck全体の秒数をsummaryとログに記録します。180秒を超えた場合は、重複する検証と型チェックの処理を見直します。ビルドとWorker dry-runは別の必須検証です。

## 実行環境

| 対象 | 実行環境 | 境界の扱い |
| --- | --- | --- |
| エンジン・純粋関数・状態モデル | Bun（DOMなし） | 固定fixtureと明示的な入力で確認 |
| Web・AdminのReact部品・hook | Bun＋happy-dom（別プロセス） | 時刻・タイマー・fetch・WebSocket・保存領域・画像loaderを制御 |
| API・ルーム・認証・永続化 | Vitest＋Cloudflare Worker | 実HTTP・WebSocket・Durable Object・D1・R2の既存統合テスト |
| 型のゲーム境界 | TypeScriptの既存の否定ケース | 型の取り違え・局面情報の欠落を拒否 |
| 出力資産 | Viteビルド時検査 | ゲーム別の遅延読み込みとWASMの同一origin URL・出力バイナリ |

```sh
bun run check
bun run build
bun run --cwd apps/worker deploy:dry-run
```

部分実行では `bun test --cwd apps/web ./test/matchReplayLoader.test.ts`、`bun test --cwd apps/web --preload ../../test-support/dom.ts ./test-dom/roomSession.test.tsx`、`bun run --cwd apps/admin test:dom` を使います。`test` は単体とDOMの両プロセスを実行します。共有DOMは `test-support/dom.ts`、React操作と偽時計・保留可能なfetchは `apps/web/test-dom/support.tsx` に置きます。タイマーは直接進め、実時間のsleepと外部通信を使いません。WebSocketも状態と送受信内容だけを確認します。画像は入出力・処理中・失敗・古い完了の破棄を確認し、実デコードや画素の描画を行いません。効果音も音声API・取得・時刻の境界を制御し、実音声デコード・ネイティブ入力・他アプリとの同時再生は実機で確認します。

純粋なfixtureは `apps/web/test/fixtures/` に置き、通信モックから分離します。`test-fixtures/matches/` の固定棋譜・固定期待値は維持し、実行時に期待値を再生成しません。

Workerの公開ルーム索引のページングfixtureは、テスト専用の実D1 `ROOM_INDEX_TEST_DB` に保存し、一覧HTTPリクエストの `APP_DB` だけをそのDBに差し替えます。通常の `APP_DB` には以前のルームのrevisionとGameRoomの非同期更新が残るため、固定の部屋番号と衝突するとfixtureの古いrevisionが無視されます。部屋のライフサイクル・索引反映の検証は通常の `APP_DB` を使い続けます。

## 廃止した自動検証

Web・AdminのブラウザテストとWorker E2E、全Playwright設定、専用SQL、ブラウザ型チェック、専用workflow・コマンドは廃止します。既存のPlaywright依存は維持します。HTML・スクリーンショット・traceのレポートを生成・保存せず、デプロイ用の `web-<SHA>` artifactだけを維持します。

対応表の旧「右列」はすべて自動検証対象から外します。画面幅・ブラウザ別のケース、寸法・収まり・色・アニメーション・実フォーカス移動・ネイティブ入力・実画像デコード・低速回線計測は再作成しません。偽イベントによる状態遷移や焦点指定は論理検証として扱います。ゲームと画面の仕様は維持します。リバーシ・将棋の少数E2Eの再構築は次の作業で行い、今回はE2Eを追加しません。
