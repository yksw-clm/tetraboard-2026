# ルーム共有の仕様

ルーム共有（共有ダイアログ、X での募集、ルーム向けの OGP）の仕様の正本です。全 6 ゲームで共通です。

- 「利用者に見える仕様」は、README の「ルーム共有の確定仕様」から移しました（2026-11-20、TB-183）。
- 「維持する契約」は、`docs/development.md` の「ルーム共有の実装計画」の制約から、サーバーと画面の側で守る約束を移しました。計画の目的、参照の順序、完了条件、実装の順序は消しました。過去の内容は Git 履歴にあります。
- 受け入れの確認は[テスト方針](../testing.md#ルーム共有の確認)、実装の入口は[ルーム共有の実装](../development.md#ルーム共有の実装)にあります。

## 維持する契約

- 全6ゲームの共通ロビー・ルームへ接続します。自動表示は通常の作成成功直後の作成者に1回だけとし、「CPUと遊ぶ」・参加・観戦・再読み込み・再接続・戻りでは開きません。URLに自動表示用の共有フラグを含めず、参加先に自動表示の意図を引き継ぎません。
- 既存ボタンの文言と動作を置き換え、幅・高さ・余白・配置・周囲のレイアウトを変えません。既存のHeroUI・AppDialog・ボタン・toast・ゲームテーマ・フォーカス制御を使います。
- 共有URLは既存の部屋番号と `instanceId` を使い、コピーとXで一致させます。参加資格トークンを含めず、招待先の参加案内、登録からの復帰、参加資格の保存と世代照合を変更しません。
- 満室・対局中のX募集抑止は最新のルーム状態へ追従します。Xは別タブの投稿画面を開く方式とし、自動投稿、投稿完了の推測、XのAPI認証・連携、外部SDKを追加しません。
- ゲームごとの静的画像6枚と共通画像1枚を配信します。動的な人数・名前・募集状態を画像へ埋め込まず、実行時の画像生成サービス、新しい依存技術、ルームごとの画像生成を採用しません。
- Workerは直接アクセスの初期HTMLへゲームに対応するメタ情報を設定します。部屋世代が異なる・存在しない・期限切れのURLは共通カードにし、古いリンクに再利用後の別ルームのゲーム情報を載せません。取得失敗によって既存の画面配信や参加を妨げない構成にします。
- ルームのHTML・HTTPのnoindex、開発環境のOriginと検索除外、総合ロビー・6ゲームロビー・四人将棋のルール・大会一覧・公開済み大会詳細のサイトマップ、API・WebSocket・認証Cookie・HTTP配信の契約を維持します。メタ情報とキャッシュをルーム間・環境間で混在させません。ゲーム進行、時計、参加資格、棋譜・戦績の保存形式を変更しません。

## 利用者に見える仕様

2026-10-11に開発者が承認した仕様です。共有ダイアログ、Xでの募集、ルーム向けOGPを提供します。全6ゲーム（四人リバーシ・四人将棋・リバーシ・将棋・五目並べ・四人五目並べ）を共通の仕様で扱います。

### 表示のタイミングと既存ボタン

- 「みんなで遊ぶ」から「ルームを作る」で作成に成功し、作成者としてルーム画面を表示した直後に、共有ダイアログを1回だけ自動表示します。[CPU戦の後の「友達と遊ぶ」](#cpu戦の後に友達を誘う)で作成に成功した場合も同じです。作成失敗、「CPUと遊ぶ」、参加・観戦からの入室では自動表示しません。
- 閉じた後の再読み込み・再接続・ルームへの戻りでは再表示しません。作成者以外の画面には連動して開きません。
- ルーム情報の「招待リンクをコピー」を「ルームを共有」に変更し、押すと同じダイアログを開きます。既存ボタンの幅・高さ・余白・配置と周囲のレイアウトはすべて維持します。手動表示は対局者・観戦者が利用できます。
- ダイアログは既存の共通UIとゲームのテーマを使い、右上の閉じるボタン・Escape・背景操作による閉鎖、背景のぼかし・スクロール・フォーカス制御も共通の動作に従います。

### CPU戦の後に友達を誘う

2026-11-25に開発者が承認した仕様です（TB-201）。全6ゲームで共通です。

- 「CPUと遊ぶ」や「みんなで遊ぶ」のルームで、終局した対局の人間の参加者が本人1人だけ（ほかの席がすべてCPU）のとき、本人の「対局結果」ダイアログに「友達と遊ぶ」を出します。
- 置き場所は結果の表示とXへの結果共有の下で、ダイアログの幅いっぱいの主ボタンにします。登録の案内とゲストの結果連携は、その下に続けます。
- ランダムマッチ（レート戦を含む）と大会のルーム、人間が2人以上いた対局、観戦者には出しません。
- 押すと、今のルームから「ロビーへ」と同じ手順で退室し、同じゲームの「みんなで遊ぶ」のルームを作成者として作ります。作成に成功したら新しいルームを表示し、上の自動表示の規則どおりに共有ダイアログを1回だけ開きます。
- 新しいルームは、直前のルームの持ち時間、シングルス・ダブルス、四人将棋の三人攻撃禁止、五目並べの禁じ手を引き継ぎます。CPUとそのレベルは引き継がず、席はすべて空けます。作った後は、ルーム設定で通常どおり変えられます。
- 退室に失敗したときは、ダイアログを開いたまま「退室できませんでした。再度お試しください。」を表示し、もう一度押せるようにします。退室後に作成に失敗したときは、そのゲームのロビーに「ルームを作る」の失敗と同じ案内を表示します。
- 退室と作成の処理中は、ボタンを処理中の表示にして重ねて押せないようにします。再読み込みや戻る操作で、ルームの作成をやり直しません。

### ダイアログの内容とコピー

| 項目       | 確定内容                                                    |
| ---------- | ----------------------------------------------------------- |
| タイトル   | ルームを共有                                                |
| 説明       | リンクを送って友達を招待したり、Xで対戦相手を募集できます。 |
| URL欄      | 選択して手動コピーできる、読み取り専用のルームURL           |
| コピー操作 | ルームURLをコピー                                           |
| X操作      | Xのロゴと「Xで対戦相手を募集」                              |

共有URLは現在の環境のOriginに、既存の `/rooms/:id?invite=:instanceId` を付けたURLです。コピーとX投稿で同じURLを使い、参加資格トークンは含めません。リンクを開いた未参加者への参加案内、部屋世代の照合、参加・観戦の条件は既存仕様を維持します。

コピー成功は「ルームURLをコピーしました」のtoastを3秒表示し、ダイアログは開いたままにします。失敗時はURL欄の近くに「コピーできませんでした。URLを選択してコピーしてください。」と表示し、手動コピーと再試行ができます。コピー処理中はコピー操作の重複を防ぎます。

### Xの募集

「Xで対戦相手を募集」は投稿文を入力したXの投稿画面を別タブで開きます。利用者はX上で文章を編集して投稿を確定します。TetraBoardから自動投稿や投稿完了の判定はしません。Web Intentsを使い、XのAPI認証・アカウント連携は追加しません。

投稿文は次の4行です。`[ゲーム名]` はゲームカタログの表示名、`[ルームURL]` は上記の共有URLに置き換えます。ハッシュタグも表示名と一致させます。

```text
[ゲーム名]の対戦相手を募集中！
ブラウザですぐ遊べます。気軽に参加してください！
[ルームURL]
#[ゲーム名] #TetraBoard
```

満室・対局中は募集ボタンを無効にします。対局中は「対局中のため、現在は観戦のみできます」、待機中の満室は「満室のため、現在は参加できません」とダイアログ内に表示します。ダイアログ表示中もルームの最新状態に合わせて更新し、URLのコピーは引き続き利用できます。

### 共有カードとOGP

- ゲームごとに1200×630pxを基本とする専用画像を1枚、存在しない・期限切れのルーム向けに共通のTetraBoard画像を1枚用意します。ゲーム画像はテーマ色の背景、盤面、大きなゲーム名、TetraBoardのロゴと「ブラウザですぐ遊べる」で構成します。
- [公開ページ](../../README.md#ゲームロビーの検索向け紹介と配信)でも同じ画像と代替説明を使います。ゲーム画像は「{ゲーム名}の盤面とTetraBoardのロゴ」、共通画像は「TetraBoardのロゴとボードゲームの盤面」です。
- 画像にはルーム番号・プレイヤー名・空席数・「募集中」を入れません。対局中や満室でも同じゲーム画像を使います。
- 有効な共有URLのタイトルは「[ゲーム名]のルーム | TetraBoard」、説明は「ブラウザで遊べる[ゲーム名]。リンクからルームに参加・観戦できます。」、URLは `invite` を含む共有URLにします。
- 初期HTMLに `og:title`・`og:description`・`og:type=website`・`og:url`・`og:image`・画像の寸法と代替説明・`og:site_name` を設定します。X向けにもタイトル・説明・画像・画像の代替説明と `twitter:card=summary_large_image` を設定します。画像URLはその環境の絶対URLです。
- Workerが直接アクセスの初期HTMLへメタ情報を含めます。JavaScript実行やX専用のUser-Agent判定を前提とせず、ルーム番号と `instanceId` を照合したゲームの情報を使います。存在しない・期限切れ・部屋世代が異なるURLは共通カードへ戻し、別の部屋の情報を出しません。
- ルームのHTMLとHTTPヘッダーの `noindex` を維持します。開発環境のURL・画像を本番へ転送せず、サイトマップの対象は総合ロビー、6ゲームロビー、四人将棋のルール、大会一覧、公開済みの大会詳細です。画面内遷移でも前の画面のメタ情報が残らないようにします。

カードの実際の表示と反映時期はXなど共有先の取得・キャッシュ・表示方式に依存します。
