# 利用状況の計測

運営者が、サービスがどれだけ遊ばれているかを把握するための計測の仕様です。何を集め、どう数え、どれだけ残すかを書きます。仕組みの判断は [ADR 0009](../adr/0009-analytics-on-cloudflare.md) にあります。

## 守ること

- 計測は Cloudflare の中で完結させ、外部の解析サービスへ送りません。
- 広告に使わず、販売せず、他のサービスをまたいで追跡しません。
- 保存しないもの: URL 全文（パスの種類と UTM の 3 項目は除く）、参照元のパスとクエリ、IP アドレス、UA 全文、メールアドレス、名前、チャット、ルームの参加資格、OAuth のトークン。
- 端末は UA から「スマートフォン」「タブレット」「PC」の 3 つに分けるだけにします。
- ブラウザの識別に使うのは、計測用 Cookie の乱数 ID だけです。指紋採取はしません。
- 運営者自身と動作確認用のアカウントは「テスト」として記録し、KPI から除きます。

## 計測の分担

| 何を | どこで | 保持 |
| --- | --- | --- |
| 訪問数、ページビュー、参照元のホスト、端末、国、表示速度 | Cloudflare Web Analytics | 6 か月 |
| 下の「イベント」 | Workers Analytics Engine | 3 か月 |
| 完了した対局、アカウント、登録 | 業務のテーブル（D1） | 業務のデータとして |
| KPI の月次の値 | D1 の月次テーブル | 無期限 |

## 計測用 Cookie

- 名前: `tetraboard-2026.analytics`。値は乱数の UUID、有効期間は 1 年、自サイトだけで使います。
- 画面の HTML を返すときに、Cookie がなければ Worker が発行します。`/privacy`、`/terms`、`/admin` では発行しません。

## イベント

すべてのイベントに、発生時刻と「テストかどうか」を付けます。アカウントの ID は内部の乱数 ID です。

訪問の開始には、アカウント ID と「テストかどうか」を付けません（HTML を返すたびにセッションを読まないため）。テストの訪問は、KPI の集計で、テストとして記録された対局や登録に出てきたブラウザ ID を除いて扱います。

| イベント | いつ | 主な項目 |
| --- | --- | --- |
| 訪問の開始 | 画面の HTML を返すとき（画面内の遷移、クローラー、`/privacy`・`/terms`・`/admin` では記録しない） | ブラウザ ID、画面の種類、ゲーム（パスから分かるときだけ）、参照元の分類とホスト、`utm_source`・`utm_medium`・`utm_campaign`、端末の分類 |
| 対局の開始 | 対局が始まったとき | 対局 ID、ゲーム、シングルスかダブルスか、対局の種類（通常、レート戦、大会）、人間の数、CPU の数 |
| 対局への参加 | 対局の開始時に、人間の席ごと | 対局 ID、ゲーム、ブラウザ ID、アカウント ID、ゲストか登録者か |
| 対局の終了 | 対局が決着したとき、または決着せずに閉じたとき | 対局 ID、ゲーム、結果（完了か打ち切りか）、終了の理由、対局の長さ |
| マッチング | 受付、成立、開始、取消、失敗、再試行のとき | 操作 ID、アカウント ID、ゲーム、段階、理由、待ち時間、人間の数、レート戦かどうか |
| 登録 | 入口、OAuth 開始、OAuth 成功、新規登録、既存ログイン、プロフィール完了のとき | 手続き ID、ブラウザ ID、入口、ゲーム、段階 |
| ブラウザのエラー | 未処理の例外と Promise の拒否 | エラーの種類、メッセージの先頭 200 文字、画面の種類 |

ブラウザのエラーは、1 つのブラウザから 1 分に 10 件までにします。メッセージに URL が含まれる場合は、クエリを取り除いてから記録します。

## KPI の定義

期間は日本時間で区切ります。割合だけでなく実数も表示します。

| KPI | 定義 | 出どころ |
| --- | --- | --- |
| 訪問ブラウザ数 | 期間内に訪問を開始したブラウザ ID の数 | イベント |
| 訪問数・ページビュー | Web Analytics の Visits と Page views | Web Analytics |
| 対局開始率 | 訪問したブラウザのうち、同じ期間に対局へ参加したブラウザの割合 | イベント |
| 対局完了率 | 期間内に開始した対局のうち、完了した対局の割合 | イベント |
| 完了対局数 | 期間内に完了した対局の数 | 業務のテーブル |
| 対局者数 | 期間内に完了した対局に参加したアカウントの数（CPU を除く） | 業務のテーブル |
| 対人戦の割合 | 期間内に開始した対局のうち、CPU のいない対局の割合 | イベント |
| 7 日以内の再対局率 | 期間内に初めて対局を完了したアカウントのうち、翌日以降 7 日以内に別の対局を完了したアカウントの割合。7 日の観測が終わっていないアカウントは分母から除く | 業務のテーブル |
| 新規登録数 | 期間内に Google または Discord で新規登録したアカウントの数 | 業務のテーブル |
| 流入元ごとの訪問と対局開始 | 参照元の分類、UTM、端末ごとの訪問ブラウザ数と、そのうち対局へ参加したブラウザ数 | イベント |
| 登録の段階ごとの数 | 入口ごとに、各段階へ進んだ手続きの数 | イベント |
| マッチング | 段階ごとの数、待ち時間の中央値と 90 パーセンタイル | イベント |

KPI の画面には、Analytics Engine で間引きが起きていないか（`_sample_interval` が 1 を超える行があるか）も表示します。

## 月次の値

毎月 1 日に、前月の KPI を計算して D1 の月次テーブルに保存します。保存するのは上の表の値だけで、ブラウザ ID やアカウント ID は保存しません。

## 退会

退会したアカウントの ID は、Analytics Engine のイベントからは個別に消せません。イベントは 3 か月で自動的に消えます。
