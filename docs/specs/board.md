# 掲示板

2026-11-26 に開発者が承認した仕様です（TB-10）。

ゲームごとの掲示板の仕様の正本です。登録者がゲームごとのタイムラインに投稿し、投稿ごとの詳細ページで全文、添付した棋譜の局面、返信を読めます。目的は、第一に滞在と再訪を伸ばすこと、第二に大会を盛り上げること、副次に詳細ページを検索に載せて流入を増やすことです。詳細ページを検索に載せる方式の判断は [ADR 0015](../adr/0015-board-post-pages.md) にあります。

「掲示板」「投稿」「返信」の定義は[用語集](../../GLOSSARY.md#掲示板とチャット)にあります。

## 初回の公開案内

全6ゲームのロビーで、投稿受付を確認した後に「掲示板を公開しました！」と案内します。連携済みの利用者は「さっそく投稿してみる」から、そのゲームの掲示板へ進みます。未ログインの利用者とゲストには「ユーザー登録をして投稿してみる」の直下に Google と Discord のボタンを表示します。同意文は両ボタンの直後に置き、各ボタンの読み上げ用の説明にも使います。連携と必要な初回設定が終わったら、そのゲームの掲示板へ戻ります。

- 同じブラウザーで一度だけ表示し、開いた時点で既読を保存します。ロビー間を移動したり、別のアカウントで開いたりしても既読を引き継ぎます。従来のレート戦開幕ダイアログの既読とは別に扱います。
- 入室・レート戦・登録からの復帰、別のダイアログ、すでに始めた操作を優先します。画面が非表示の間は表示を保留し、操作が始まっていなければフォーカス復帰後に判定します。投稿受付を確認できなかった場合や、他の操作を優先した場合は、次に対象ロビーを訪れたときに改めて判定します。

## 投稿と返信

- 投稿と返信ができるのは、ログインとプロフィール設定を完了した登録者だけです。ゲストは投稿、返信、いいねができません。閲覧は、未ログインを含めて誰でもできます。
- 投稿には、どのゲームの投稿かを必ず付けます。対象は全 6 ゲームです。返信のゲームは、返信先の投稿と同じです。
- 本文は 1〜1,000 字です。見た目の文字単位で数えます。改行を含められます。
- 本文に書ける URL は、TetraBoard の中の公開棋譜、大会、ルームの URL だけです。ルームの URL には、共有ダイアログと X 共有が作る招待の形（`/rooms/:id?invite=:instanceId`）と、総合ロビーが作る観戦の形（招待の形に `&watch=1` を付けたもの）も含みます。ほかの URL を含む本文は受け付けません。画像は付けられません。
- 投稿と返信を合わせて、アカウントごとに 30 秒に 1 件まで受け付けます。ゲーム、複数のタブ、複数の端末を通じて共通に数えます。
- 応答が届かずに同じ内容を送り直しても、同じ投稿や返信を重ねて保存、表示しません。
- 返信は 1 段だけです。返信への返信も、同じ投稿への返信として並べます。
- 投稿と返信は編集できません。本人は自分の投稿と返信を削除できます。
- 投稿と返信では、投稿者の公開参照があれば名前とアイコンを 1 つのリンクにし、その人の公開プレイヤーページを開きます。投稿のゲームを最初に表示し、モードを選べるゲームではシングルスを開きます。公開参照がないときは名前とアイコンを表示します。

## 削除された投稿の表示

本人の削除、運営の削除、退会のどれで消えた場合も同じ扱いです。削除と退会を受け付けた後の、次の取得から反映します。

この仕様で「返信の数」は、削除されていない返信の数です。表示する数、枠を残すかの判定、[検索の条件](#検索への公開)のどれも、この数を使います。

- 返信の数が 0 の投稿は、タイムラインから消え、詳細ページは見つからない案内（HTTP 404）になります。
- 返信の数が 1 以上の投稿は、「削除された投稿」の枠と投稿日時、返信の数だけを残します。本文、投稿者（名前、アイコン、公開プレイヤーページへの導線）、添付した棋譜の局面、いいねの数は出しません。画面、検索向けの HTML とメタ情報、構造化データのどれにも出しません。返信はそのまま読めます。
- 枠には新しい返信もいいねも付けられません。
- 削除された返信は詳細ページから消え、返信の数からも引きます。枠だけの投稿の最後の返信が削除や退会で消えたときは、その時点で枠もタイムラインから消え、詳細ページは HTTP 404 になります。
- 削除された投稿は検索対象にせず、投稿のサイトマップから外します。その投稿への返信の通知は、ベルの一覧から外します。

## タイムライン

- URL は `/games/:gameId/posts` です。767px 以下ではゲームロビーと共通のゲーム名・遊び方・タブ行を表示し、「投稿」を選択します。直接開いたときや再読み込みでも同じ表示です。
- 新しい投稿を上にして、投稿した順に並べます。返信が付いても順番は変わりません。
- 20 件ずつ表示し、「もっと見る」で続きを読み込みます。自動では更新しません。スマートフォンで一覧から投稿詳細を開いて戻ると、読み込み済みの一覧とスクロール位置を復元します。
- 本文が 5 行を超える投稿は省略し、「続きを読む」から詳細ページへ移ります。
- 返信は本文を出さず、返信の数だけを表示します。
- 検索対象外（`noindex, follow`）です。
- 768px 以上では見出し「{ゲーム名}の掲示板」とゲームロビーへのリンクを置きます。投稿が 0 件のときは「まだ投稿はありません。」と表示します。
- 投稿のカード（削除された投稿の枠を含む）は、全体を押すと詳細ページへ移ります。カードの中の投稿者の名前とアイコン、本文中のリンクとカード、「続きを読む」、添付の局面の表記、いいね、削除、通報は、それぞれの動きのままです。キーボードと読み上げでは、投稿日時のリンク（読み上げは「投稿の詳細」を含む）から詳細ページへ移ります。
- タイムラインとロビーの投稿プレビューは、カードにポインターを置いたときも同じ背景色で表示します。リンクとボタンの操作状態は各部品で示します。

## 投稿の詳細

- URL は `/posts/1234567` のように、投稿ごとに割り当てた正の整数を使います。既存の投稿も番号で開けます。以前の UUID 形式の URL は HTTP 404 になります。
- 投稿の全文、添付した棋譜の局面、いいねの数、返信を表示します。
- 返信は古い順に並べます。最初に 50 件まで表示し、続きは「もっと見る」で 50 件ずつ読み込みます。
- 一時的な障害で投稿を読み取れないときは、HTTP 503 を返し、画面で再試行を案内します。
- 投稿日時は正確な日時（秒まで）で表示します。返信と、タイムラインの投稿の日時は、最近の対局と同じ相対日時で表示します。
- 見出し「投稿の詳細」の左に、そのゲームの掲示板を開く左向きアイコンを置きます。読み上げのリンク名は「{ゲーム名}の掲示板へ」とし、押せる範囲は 44px 四方以上です。そのゲームのロビーへのリンクも置きます。
- 返信があるときは、投稿の下に「返信 {数} 件」の小見出しを置き、返信を字下げして左の縦線で投稿につなげて表示します。
- 投稿と返信のカード内では、投稿者や局面など個別のリンクから移動します。
- 見つからないときは「投稿が見つかりません。削除されたか、URL が間違っている可能性があります。」と総合ロビーへのリンクを表示します。読み取りに失敗したときは「投稿を取得できませんでした。」と「再試行」を表示します。

## 投稿欄と操作の表示

タイムラインの上に投稿欄、詳細ページの返信の下に返信欄を置きます。受付中かつ投稿停止中でなければ、プロフィール設定を完了した登録者、ゲスト、未ログインの利用者に同じ入力欄を表示します。制限がある場合は、入力欄の代わりに次の表示を出します。上の行ほど優先します。

| 状態 | 表示 |
| --- | --- |
| 受付停止中 | 現在、掲示板への投稿を受け付けていません。投稿は閲覧できます。 |
| 投稿停止中 | このアカウントは掲示板への投稿を停止されています。 |
| プロフィール未設定 | プロフィールの初回設定を完了すると投稿できます。と「プロフィールを設定する」 |
| 削除された投稿の詳細 | 削除された投稿には返信できません。（返信欄の代わり） |

- 入力欄の案内文は、投稿欄が「{ゲーム名}について投稿する」、返信欄が「返信を書く」です。文字数を「{数}/1000」で表示します。
- アカウントがある利用者の入力欄の左に、本人のアイコンを表示します。画像がないときは既定のアイコンを使います。
- ゲストと未ログインの利用者が「投稿する」「返信する」を押した場合は連携ダイアログを開きます。連携のために移動するときは、下書きを同じタブに一時保存します。連携と必要なプロフィール設定を終えると、元の入力欄に本文が戻ります。棋譜添付がある投稿は、添付付きの入力欄に戻ります。内容を確かめてから送信できます。
- スマートフォンで別のロビータブへ切り替えたときは、同じゲームと閲覧者に対して書きかけの本文と棋譜の添付を保持します。投稿に成功した下書きは消去します。
- Enter は改行です。Ctrl+Enter または ⌘+Enter で送信します。日本語の変換中は送信しません。送信中は重ねて送信できません。
- 送信に失敗したときは入力を残し、理由を入力欄の下に表示します。
- いいねはハートのアイコンと数で表示し、押した後は塗りつぶしのハートにします。押すと結果を待たずに表示を変え、失敗したら元に戻して理由を出します。ゲストと未ログインで押したときは、投稿・返信と同じ連携ダイアログを開きます。プロフィール未設定の人には「プロフィールの初回設定を完了するといいねできます。」と表示します。
- いいねのボタンは枠を出さず、ハートと数だけを表示します。押せる範囲は、指で押せる大きさ（44px 四方以上）にします。押した後は、塗りつぶしのハートと色で分かるようにします。
- 投稿の返信の数は、吹き出しのアイコンと数で表示し、読み上げでは「返信 {数} 件」とします。返信といいねのアイコンはどちらも 20px で、返信の数、いいねの順に左から並べます。
- タイムラインとロビーで返信のアイコンを押すと投稿の詳細を開きます。返信のリンクといいねのボタンは、ポインターを置くとアイコンが少し拡大し、押している間は縮みます。動きを減らす設定では静止表示にします。
- 公開中の投稿の右下に三点ボタンを置きます。メニューの「リンクをコピー」で投稿の数字URLをクリップボードへコピーし、結果を知らせます。本人のメニューには「削除」も表示します。本人の返信の「削除」は返信の操作欄に置きます。「投稿を削除しますか？」または「返信を削除しますか？」と、「削除すると元に戻せません。」を表示し、確認後に削除します。返信の数が 0 の投稿を詳細ページで削除したときは、そのゲームの掲示板へ移ります。

## いいね

掲示板の連携ダイアログには「アカウントを連携して、掲示板を楽しもう！」と表示し、投稿・返信・いいねが利用できることを案内します。上部では吹き出しとハートの短い動きを一度表示します。動きを減らす設定では静止表示にします。Google または Discord で続けられます。

- 投稿と返信に、登録者がいいねできます。自分の投稿と返信にもいいねできます。押したいいねは取り消せます。
- いいねの数は公開し、誰が押したかは表示しません。
- いいねの通知は行いません。

## 棋譜の局面の添付

- 投稿と返信に、任意で棋譜の局面を 1 件だけ添付できます。添付できるのは、投稿と同じゲームの、公開棋譜のある対局です。局面を 1 つ指定します。
- 添付した局面は盤面で表示します。768px 以上ではカードの内幅を上限に添付枠を 384px で表示し、767px 以下ではカードの内幅いっぱいに表示します。盤面の画像は生成しません。
- 盤面の下に、棋譜の画面の局面の一覧と同じ表記で局面を表示します（例「36: 青H5」「黒 パス」「開始局面」）。対局者の名前は出しません。棋譜を読めないときは「棋譜を表示できません。」と表示します。
- 局面の表記を押すと、公開棋譜のその局面を開きます。盤面を押すと、タイムラインでは投稿の詳細ページへ移り（カードを押したのと同じ）、詳細ページでは何も起きません。
- 投稿欄の下の「棋譜を添付」から、そのゲームの最近の本人対局を選ぶか、TetraBoard の公開棋譜の URL を貼り付けます。未ログインでも URL を使えます。
- 盤面をプレビューし、棋譜の画面と同じ局面一覧から選びます。URL に有効な局面指定がある場合はその局面、対局一覧から選んだ場合や局面指定がない場合は最終局面を最初に表示します。「この局面を添付」で確定します。
- 確定した盤面と局面名を本文の下に表示します。添付は変更・取り外しできます。選択をキャンセルしたときや新しい棋譜を読み込めなかったときは、本文と確定済みの添付を保持します。
- 公開棋譜と、マイページの本人用の棋譜の画面に「この局面で投稿する」を置き、表示中の局面を添付した投稿を始められます。押すとそのゲームのタイムラインの投稿欄が添付つきで開き、投稿欄で添付を外せます。
- 返信欄から添付する入口はまだありません。
- 公開棋譜 `/matches/:matchId` と本人用の棋譜 `/account/matches/:matchId` は、`?position=N` で局面を指定して開けます。開始局面が `0` です。再読み込みでも指定の局面を表示します。範囲外の値と、数字として読めない値では、指定のないときと同じく最終局面を表示します。
- `N` は、棋譜の画面で局面を選ぶ一覧（開始局面、着手、自動パス、各脱落）の並びでの位置です。開始局面が `0` で、一覧の 1 項目ごとに 1 増えます。手数とは別の番号です。添付を保存するときも、同じ番号で範囲を確かめます。

## TetraBoard の中のリンク

本文に書いた公開棋譜、大会、ルームの URL は、リンクとカードで表示します。外部へのリンクはないので、リンクに `rel` を付けません。

- カードには、公開棋譜はゲーム名と対局日時、大会は大会名、ルームは「ルーム {番号}」を表示します。
- 公開棋譜と大会の情報を取得できないときは、カードを出さずにリンクだけを表示します。
- タイムラインで本文を省略した投稿のカードは、全文を表示する詳細ページで読み込みます。

## ロビーのプレビュー

- 768px 以上のゲームロビーでは、公開ルームとランキング・最近の対局の 2 列の下に「みんなの投稿」を全幅で置き、そのゲームの新しい投稿を 3 件表示します。767px 以下のロビーでは「投稿」タブからタイムラインを開きます。
- ロビーの初期 HTML には含めず、画面を表示してから取得します。自動では更新しません。
- 見出しは「みんなの投稿」、説明は「{ゲーム名}の掲示板の新しい投稿です。」です。「投稿する」は見出し行に塗りつぶしのボタンで表示し、押すとタイムラインへ移ります。受付中であることを取得できたときだけ表示します。
- 区画の最後に、枠付きの全幅のボタン「掲示板をすべて見る」を置き、タイムラインへ移ります。読み込み中、投稿がないとき、取得の失敗でも出します。
- タイムラインの先頭から、削除されていない投稿を 3 件まで表示します。削除された投稿の枠は出しません。
- 各投稿は、投稿者の名前とアイコン、相対日時、本文、返信の数、いいねのボタンを表示します。棋譜の局面が添付されている投稿には、本文の下に「棋譜付き」と表示します。添付の盤面は投稿の詳細で見られます。本文は 3 行を超えると省略し、本文中の URL はリンクにしません。投稿者の名前とアイコンは、[掲示板と同じ条件](#投稿と返信)で公開プレイヤーページへのリンクになります。本文、「棋譜付き」、カードの余白を押すと、投稿の詳細ページへ移ります。
- 返信の数、いいね、右下の三点メニューは、掲示板と同じです（[投稿欄と操作の表示](#投稿欄と操作の表示)）。押せない理由や失敗の理由はその投稿の中に表示します。本人がロビーで削除した投稿はロビーの一覧から消えます。
- 投稿がないときは「まだ投稿はありません。」と表示し、受付中なら「対局の感想や気になる局面を、最初に投稿してみませんか。」を続けます。
- 読み込み中は 3 件分の高さを確保します。取得に失敗したときは、区画の中に「投稿を取得できませんでした。」と「再試行」を表示します。区画の部品を読み込めなかったときは、区画の中に「画面を読み込めませんでした。アプリが更新された可能性があります。再読み込みしてください。」と「再読み込み」を表示し、押すとページを読み直します。自動では読み直しません。どちらの場合も、ロビーのほかの部分はそのまま使えます。

## 返信の通知

- 自分の投稿に返信が付いたら、ベルのお知らせで本人へ知らせます。1 件の返信につき 1 件の通知で、まとめません。自分の投稿への自分の返信では知らせません。
- 一覧のラベルは「返信」です。既存の「運営からのお知らせ」「大会結果」「バッジ」と同じ一覧に並べます。既読と保存の扱いは[ベルのお知らせ](../../README.md#ベルのお知らせ一覧と既読)に従います。
- 一覧のタイトルは「{返信者の名前}さんから返信: {返信の本文の先頭}」です。本文の先頭は、改行と続く空白を 1 つの空白にして 30 字までとし、超えたら「…」を付けます。
- 詳細には、一覧と同じ見出し、「{ゲーム名}の掲示板」、返信の本文の全文（改行を保つ）を表示し、「投稿を見る」から返信先の投稿の詳細ページへ移ります。
- 返信者の名前と本文は、通知を作った時点ではなく、一覧を取得した時点のものを表示します。
- 返信または返信先の投稿が削除されたとき、どちらかの投稿者の退会を受け付けたときは、その通知を一覧、詳細、未読の判定から外します。本文も表示しません。
- 投稿の受付を始めるときには含めず、その後に加えます。

## 通報と運営

- 投稿と返信を通報できます。通報できるのは、名前設定済みのゲストと、ログインとプロフィール設定を完了した登録者です。直近 1 時間で 1 アカウント 5 件まで受け付け、同じ投稿や返信への再通報は重ねて数えません。証拠は通報から 7 日を上限に管理者だけが閲覧できます。
- 通報では理由を 1 つ選びます。選択肢は「晒し・嫌がらせ」「暴言」「スパム・宣伝」「個人情報」「その他」です。
- 管理画面の「掲示板」で、通報の一覧、投稿と返信の削除、アカウントごとの投稿停止と解除、掲示板全体の投稿受付の停止と再開ができます。
- 掲示板と大会チャットの投稿停止は、それぞれの管理画面から設定します。
- 投稿停止中と受付停止中も閲覧はできます。止まっていることを投稿欄に表示し、サーバーでも投稿と返信を拒否します。
- 本人以外の公開中の投稿と返信に「通報」を置きます。削除された投稿の枠には置きません。未ログインの人が押すと「通報するにはログインしてください。」を表示します。
- 通報のダイアログは、見出し「投稿を通報」（返信は「返信を通報」）、「この投稿を運営に通報しますか？理由を1つ選んでください。」（返信は「この返信を…」）、理由の選択（初期は未選択）、「通報する」「キャンセル」です。理由を選ぶまで「通報する」は押せません。受け付けたら「通報を受け付けました。」、同じ投稿や返信を通報済みなら「通報を受け付けています。」を、その投稿や返信の下に表示します。対象が見つからないときと上限を超えたときは「投稿が見つからないか、通報回数の上限に達しています。」をダイアログに表示します。
- 管理画面の「掲示板」は、全体の投稿受付の状態と停止・再開、通報の一覧（通報から 7 日以内、新しい順。通報日時、理由、同じ投稿や返信への通報の数、対応の状態、ゲーム、投稿か返信か、投稿者の名前、本文、投稿日時、削除済みか、運営が削除した日時、公開ページへのリンク。行ごとに投稿の削除、投稿者の投稿停止または解除、対応済みにする操作）、投稿の ID か URL を指定した削除と投稿者の投稿停止、投稿停止中のアカウントの一覧と解除を置きます。どの操作も確認してから実行します。
- 運営が削除した投稿と返信は、本人の削除と同じく[削除された投稿の表示](#削除された投稿の表示)に従います。通報の証拠は、対象が削除された後も通報から 7 日まで残します。運営が削除したときは、その時点で期限内の通報に削除した日時を記録し、投稿者がその後に退会しても通報の側で確かめられるようにします。ゲストが登録へ統合されたときも、各通報の理由、対応の状態、通報日時はそのまま残します。投稿者が退会したときは、証拠の投稿者の名前を「退会したプレイヤー」にし、投稿停止の操作を出しません。

## 退会と保存期間

- 投稿と返信は期限を設けずに残します。
- 退会したアカウントの投稿と返信は本文を消し、[削除された投稿の表示](#削除された投稿の表示)に従います。退会したアカウントが押したいいねは消し、数から引きます。
- 既存の登録者には、規約とポリシーの版を上げて、次の登録・初回設定・参加の操作で現在版への同意を求めます。専用の案内画面は設けません。

## 投稿の受付を開く条件

- 掲示板全体の投稿受付は、最初は停止しています。停止中も閲覧はできますが、投稿は 0 件です。
- 次のものが本番に出た後に、開発者の承認を得て、管理画面から受付を開きます。
  - 掲示板の公開範囲と保存期間を書いた[プライバシーポリシーと利用規約](privacy.md)。
  - 通報と、管理画面での削除・投稿停止・受付停止（[通報と運営](#通報と運営)）。

## 検索への公開

- 本番では、次の条件をすべて満たす投稿の詳細ページを検索対象にし、投稿のサイトマップに載せます。
  - 削除されていない。
  - 投稿から 24 時間が過ぎている。
  - 返信の数（削除されていない返信の数）が 1 以上ある、または本文が 50 字以上ある。
- いいねの数は条件に使いません。
- 条件を満たさない詳細ページと削除された投稿の枠は、HTML と HTTP ヘッダーで `noindex, follow` にします。開発環境とローカルの詳細ページは、ほかの画面と同じく検索対象にしません。
- 詳細ページの初期 HTML には、title、description、canonical、OGP、本文と最初の 50 件の返信を入れます。画面内遷移でも title、description、canonical、robots、OGP を入れ替えます。
  - title は `{本文の先頭 30 字}｜{ゲーム名}の掲示板 | TetraBoard`、description は本文の先頭 120 字です。改行は空白にし、字数を超えたら末尾に「…」を付けます。字数は見た目の文字単位です。
  - 削除された投稿の枠は、title が `削除された投稿｜{ゲーム名}の掲示板 | TetraBoard`、description が `{ゲーム名}の掲示板の削除された投稿です。返信 {数} 件を読めます。` です。
  - canonical は `https://tetraboard.net/posts/{投稿番号}`（開発環境とローカルはその環境の origin）です。
- 詳細ページの初期 HTML には `DiscussionForumPosting` の構造化データを付け、投稿の全文、投稿者の名前、投稿日時、いいねの数、最初の 50 件の返信を入れます。削除された投稿の枠には付けません。削除された投稿と返信の本文は、ページにも構造化データにも入れません。
- 詳細ページを直接開いた場合は、詳細 API の応答に合わせてメタ情報と構造化データを更新します。構造化データには詳細 API の最初の 50 件までの返信を使います。詳細 API が 404 の場合は `noindex, follow` にし、構造化データを取り除きます。
- 投稿のサイトマップは `/sitemap-posts.xml` で、ロビーと大会を載せている `/sitemap.xml` とは別のファイルです。robots.txt から参照します。本番だけで、開発環境とローカルでは 404 です。検索対象の投稿を新しい順に最大 50,000 件載せます。各投稿の `lastmod` は、投稿、返信、返信の削除（退会を含む）のうち最も新しい日時の日付です。いいねでは変えません。
- OGP の画像は、投稿のゲームの既存の画像を使います。

## 計測

掲示板の効果は、次の 2 つで見ます。表示率（プレビューの表示を訪問などで割った値）は使いません。

- 投稿の数。保存した投稿から数えます。
- ロビーのプレビューが画面に入ったブラウザの数。日別、ゲーム別に数えます。元になるのは「掲示板のプレビューの表示」のイベントです（[計測の仕様](analytics.md#イベント)）。

## 大会との連携

投稿に任意で大会を付け、大会の詳細ページにその大会の投稿を出します。投稿の受付を始めるときには含めず、利用状況を見てから加えます。

## 最初に含めないもの

- 投稿と返信の編集、画像、外部の URL、ゲストの投稿、いいねの通知、スレッドのタイトル。
- 総合ロビー `/` への掲出。
