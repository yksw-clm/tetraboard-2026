# 四人将棋ルール

> ステータス: ルール確定・ゲームエンジンとCPU Lv1／Lv2実装済み（独立パッケージ）・オンライン対局と終局保存・戦績・棋譜・ランキング・16戦型の成立通知対応。大会対局の固定ルール・専用開始・集計対応 / 最終更新日: 2026-10-16

## この文書の目的と承認範囲

TetraBoard の四人将棋について、合法手、手番、詰み、脱落、順位をゲームエンジンで再現するためのルールを定める。外部資料には複数の方式があるため、参照先の説明をそのまま一つの標準ルールとして扱わない。

2026-10-03 に開発者が FS-001〜FS-009 を承認した。FS-004 は当初提案から変更し、指定された日本四人将棋連盟の説明会資料を基準に三人攻撃禁止を採用する。追加指示により、三人攻撃禁止を使う・使わない設定を切り替えられるようにする。それ以外は提示した推奨案を採用する。

同日に三人攻撃の境界処理と初期値（FS-010〜FS-014）も、提示した補完案どおりに承認された。追加の明示指示で合意による引き分け（FS-015）を採用した。**「確定ルール仕様」を TetraBoard の四人将棋の正本とする。** 決定事項と調査資料は採用理由を残すための参考情報であり、競合時は確定ルール仕様を優先する。

ルーム、参加、投了、通信切れ、持ち時間、チャットは [README のゲーム共通仕様](../../README.md#ゲーム共通仕様) を正本とする。ルール判定とCPU Lv1／Lv2は独立した `@tetraboard/four-shogi` パッケージに実装し、オンラインルームへ接続している。`/games/four-shogi` から作成・参加・観戦・公開一覧を利用でき、共通URL `/rooms/:id` で対局する。表示・操作仕様は [README の四人将棋ルーム画面](../../README.md#四人将棋のルーム画面) を参照する。直前1局の棋譜は部屋内で閲覧できる。終局データとイベント棋譜を恒久保存し、本人のマイページ戦績・棋譜と将棋ロビーのランキングへ反映する。この文書の確定ルールは変更しない。

### 大会対局の例外

2026-10-16に開発者が承認済みモックを合格とし、[大会の確定仕様](../../README.md#四人将棋大会の確定仕様)と実装計画の確定を指示しました。以下は実装済みの大会ルール版1の追加契約です。 通常ルームの確定ルールを変更するものではありません。

- 大会対局はシングルス・登録済みの人間4人、持ち時間なし・秒読み30秒・三人攻撃禁止ONで固定し、CPU補充と合意による引き分けを認めません。通常対局の合意引分は維持します。
- 大会は4人の認証済み接続後に、サーバー管理の5秒カウントダウンを経て開始します。開始までは対局時計を動かさず、最後の本人接続が切れたらカウントダウンを解除します。再び全員がそろった時点から数え直し、実開始時に大会の終了時刻と資格を再検査します。通常ルームのホスト開始は維持します。
- リロードでは同じ大会対局・同じ本人の席へ復帰し、開始済みの対局時計を巻き戻しません。同じ本人の複数接続は1人として扱い、最後の接続がなくなった場合だけ開始前のカウントダウンを解除します。明示退室した本人は不成立後の自動再待機から除外します。待機の引き継ぎ・30秒の入室猶予・大会締切は[大会の復帰仕様](../../README.md#リロード別タブ接続失敗からの復帰)に従います。
- 合法手・王手・詰み・同時脱落・千日手・局内順位・撃破の定義は本書の確定ルールに従います。大会専用の勝ち点は局内順位から別に計算し、棋譜の順位や通常戦績を書き換えません。
- 大会の1位4点・2位2点・3位1点・4位0点、同順位の占める配点の均等分配、累計・撃破・平均順位による大会順位はREADMEを正本にします。管理画面では大会ごとの説明文を編集でき、これらの機械条件は編集できません。

## 確定ルール仕様

### 盤、座標、陣営

- 正方形の9×9盤、計81マスを使う。盤外のマスはない。
- 陣営を南・西・北・東の4方向で識別する。色や画面上の表示位置をルール判定の識別子にしない。
- 基準座標は、南を手前に見た左上を `A1 = (x: 0, y: 0)` とし、左から右を `A`〜`I`、上から下を `1`〜`9` とする。通常の将棋の筋・段とは別の表記である。
- 自分の前方向・右方向と成れる区域は次のとおり。成れる区域は盤幅全体の3列または3行であり、初期駒のある範囲だけに限定しない。

| 陣営 | 前 `(dx, dy)` | 自分から見た右 `(dx, dy)` | 成れる区域（対面側3段） | 二歩を調べる筋 |
| ---- | ------------- | ------------------------- | ----------------------- | -------------- |
| 南   | `(0, -1)`     | `(1, 0)`                  | `y = 0, 1, 2`           | 同じ `x`       |
| 西   | `(1, 0)`      | `(0, 1)`                  | `x = 6, 7, 8`           | 同じ `y`       |
| 北   | `(0, 1)`      | `(-1, 0)`                 | `y = 6, 7, 8`           | 同じ `x`       |
| 東   | `(-1, 0)`     | `(0, -1)`                 | `x = 0, 1, 2`           | 同じ `y`       |

- 対局開始ごとに4人を4方向へ重複なくランダムに割り当てる。初手は南、通常の手番順は南→西→北→東→南とする。再戦でも割り当て直す（FS-008）。
- エンジンには決定済みの割り当てを入力する。表示を回転しても基準座標、駒の所属、前方向は変えない。画面の色・レイアウト・回転操作は別途画面設計で定める。

### 棋譜表記

2026-10-10に承認した表示仕様です。内部のA1〜I9座標・保存形式・ルール版・着手判定は維持します。終局後のルーム内棋譜・本人用保存棋譜・公開棋譜は「1: 南5六歩」「2: 西6五歩」の形式を共用し、着手者の南・西・北・東と手数を残します。

表示座標は南を下に固定し、筋は右から半角数字1〜9（`9 - x`）、段は上から漢数字一〜九（`y + 1`）です。参加・観戦・本人／公開棋譜・盤面回転で変えません。方向語だけは着手者の向きから判定します。駒名は王・飛・金・銀・歩、成駒は龍・成銀・とです。

成・不成・打、同、曖昧な着手の合法手候補と方向語は[通常将棋の棋譜表記](shogi.md#棋譜表記)を共用します。三人攻撃による禁止手・成りも候補から除きます。龍を3枚以上持てるため、通常の補助語で識別できない龍の縦移動だけは「直」を使います。同じ地点へ上下から縦移動できる龍もある場合は「直上」「直引」で区別します。通常将棋と、従来の補助語で識別できる四人将棋の龍にはこの例外を使いません。括弧の移動元座標は表示しません。「同」は本人の前の手ではなく、全陣営を通じた直前の着手を参照し、引分提案・取消・外部脱落を挟んでも保持します。

外部脱落は「南 投了」「西 退室」「北 時間切れ」「東 通信切れ」、提案・取消は「南 引分提案」「西 引分取消」の形式で、着手番号を増やしません。自動詰み・同時脱落・千日手の項目や付加説明は追加せず、群・順位・理由は局面・カード・結果へ保持します。両モードで同じ表記を使います。

### 初期配置

各陣営は王1枚、飛車1枚、金2枚、銀2枚、歩3枚の計9枚を持つ。合計36枚とし、角・桂・香は使わない。全駒は不成、持ち駒は全員0枚で始める。

| 陣営 | 王   | 飛車 | 金      | 銀      | 歩         |
| ---- | ---- | ---- | ------- | ------- | ---------- |
| 南   | `E9` | `E8` | `D9 F9` | `C9 G9` | `D8 F8 E7` |
| 西   | `A5` | `B5` | `A4 A6` | `A3 A7` | `B4 B6 C5` |
| 北   | `E1` | `E2` | `D1 F1` | `C1 G1` | `D2 F2 E3` |
| 東   | `I5` | `H5` | `I4 I6` | `I3 I7` | `H4 H6 G5` |

SDIN の初期盤面と将棋ったーの初期配置を基準とする。南から西への回転は `(x, y) → (8 - y, x)`、北へは `(8 - x, 8 - y)`、東へは `(y, 8 - x)` となる。

### 駒の動きと成り

以下の「前・後・左右」は所属陣営の向きを基準とする。

| 駒   | 動き                                           | 成った後                                |
| ---- | ---------------------------------------------- | --------------------------------------- |
| 王   | 縦・横・斜めの隣接8マスのいずれかへ1マス       | 成らない                                |
| 飛車 | 縦横のいずれかへ、障害物のない範囲で任意の距離 | 龍。飛車の動きに斜めへの1マス移動を追加 |
| 金   | 前・後・左右・斜め前の6方向へ1マス             | 成らない                                |
| 銀   | 前・斜め前・斜め後の5方向へ1マス               | 成銀。金と同じ動き                      |
| 歩   | 前へ1マス                                      | と金。金と同じ動き                      |

- 1回の着手で自分の駒1枚を移動するか、持ち駒1枚を打つ。パスや一度に複数枚を動かす操作はできない。
- すべての盤上駒と裏王は移動を遮る。飛車・龍も飛び越せない。
- 移動先が自分の駒なら移動できない。シングルスでは他陣営の王以外の駒を捕獲できる。
- 移動元または移動先が成れる区域にあれば、飛車・銀・歩はその移動時に成るか不成かを選べる。区域内の移動や区域から出る移動でも選べる。成った駒は盤上で元に戻せない。
- 不成の歩が自分の前方向の最終段へ進む場合は、必ず成る。南は1行目、西はI列、北は9行目、東はA列が最終段である。
- 王を実際に捕獲する着手は存在しない。王手と詰みで脱落を判定する。裏王も捕獲できない。

駒の基本的な動き・成りの詳細は本将棋の規則を補助資料とし、陣営の向きと対面側の成れる区域へ適用する。四人用の勝敗・手番は本将棋から自動的に補完しない。

### 捕獲、持ち駒、打ち駒

- 捕獲した駒は捕獲者の持ち駒になる。所属と向きは捕獲者のものへ変わり、成駒は不成の飛車・銀・歩へ戻す。
- 持ち駒は駒種ごとの枚数で管理する。捕獲元の陣営による使用制限はない。
- 持ち駒は空きマスにだけ、不成の状態で打てる。打った手で成ることはできない。
- 二歩を禁止する。自陣営の不成の歩が同じ筋にあるマスへ、不成の歩を打てない。他陣営や脱落陣営の歩、と金は二歩の判定に含めない。
- 自分の最終段へ歩を打てない。裏王の存在だけを理由に、盤上の歩を「行き所なし」とは判定しない。
- 歩を打った結果、その歩が直接王手をかける生存中の敵王に応手がなければ、打ち歩詰めとして禁止する。複数の敵への王手が生じても、直接の歩の王手先に対して判定する。盤上の歩を進める突き歩詰めは許可する。
- 歩を打ったマスの一つ前が裏王になる手を禁止する。裏王の所有者にかかわらず適用する。既存の歩をその位置へ進めることは許可するが、裏王そのものを取ることはできない。

### 利き、王手、合法手

- 「利き」は駒の移動形、遮る駒、所属、脱落状態から求める。捕獲できない自駒等に遮られた飛車の利きは、その先に及ばない。
- 自駒のあるマスへ移動はできないが、そのマスへの幾何的な利きは守りとして数える。飛車は最初に遮る駒のマスまで届き、その先を数えない。
- 生存中の敵駒の利きが自王のマスへ届くと王手になる。脱落者の駒と裏王には利きがない。
- 利きの判定で攻撃側の自王の安全性を再帰的に検査しない。動かすと攻撃者の王が危険になる駒も、その移動形の利きを持つ。この細部は将棋ったーの挙動を参考にした採用仕様である。
- 着手後に着手者自身の王が王手される手は、王手放置・自王への王手として禁止する。他の王が王手中であることだけを理由に、着手者の手を禁止しない。
- 王同士を敵王の利きへ移動させることはできない。ダブルスで味方の王・駒の利きはこの安全判定から除外する。
- 着手者以外の飛車の前から駒を動かして生じる空き王手も、通常の王手として検出する。利きの持ち主と直前の着手者が一致するとは限らない。
- シングルスで三人攻撃禁止がONの場合、下記の規則を合法手判定に加える。OFFの場合はこの追加制限と攻撃履歴を使わず、ほかの禁止手・手番・勝敗規則を共通で適用する（FS-004）。
- 手番違い、禁止手、持ち駒不足、成れない駒の成り、不可能な移動、終局後の着手等は状態を変更せず拒否する。拒否した操作で反則負けにはせず、手番と計時を継続する。確定した着手の取り消しは設けない。

### 三人攻撃禁止

基準は開発者が指定した [説明会](https://www.youtube.com/live/TziuZwzGk9g) の概要欄から公開されている [2022-10-24 のPDF](https://drive.google.com/file/d/1xqKGwY2e36IxNsVa6G_GYa9QrLYs49gC/view) とする。以下は資料の規則に、開発者が承認した機械判定に必要な補完（FS-010〜FS-014）を加えた採用仕様である。

#### 適用と攻撃状態

- 三人攻撃禁止のON／OFFを対局設定として保持する。新規ルームと「すぐ遊ぶ」の初期値はONとし、作成時に選び、待機中はホストが変更できる。変更時の準備状態解除は README の共通仕様に従い、対局開始後は変更できない。「すぐ遊ぶ」と再戦にも選択した設定を適用する（FS-014）。
- ONのシングルスで4人全員が生存中に適用する。誰かが脱落した後は解除する。投了等も同じ脱落処理に統一する。
- 異なる2人が標的 `B` への攻撃状態を継続している間、残る第三者 `A` による新たな `B` への攻撃を禁止する。単に3人の駒が同時に利いているかで判定しない（PDF p2〜4）。
- `A` の一手が複数の相手への攻撃になることがある。攻撃先ごとに判定し、着手直後に `A→B` 等の関係を開始する。
- 攻撃状態は、開始後に攻撃者以外の3人全員がそれぞれ1回以上着手した直後に解除する。王手で飛ばされた手番は着手に数えず、単純な3手経過では解除しない。攻撃に使った駒が取られても、状態は継続する（PDF p6〜10、動画08:01〜16:34）。
- 状態が継続中に同じ相手へ改めて攻撃した場合、解除までに必要な3人の着手記録をリセットして開始し直す。攻撃に該当しない手を指しただけでは、既存の状態を解除しない。
- 脱落した人を攻撃者または標的とする関係を解除する。TetraBoard では4人生存条件が崩れた時点で制限全体を無効にする。

#### 攻撃から除外する応手と取り返し

- 着手者自身が王手に応じる手は、別の王手・捕獲・逃げ道封鎖を生んでも、全相手について攻撃に数えない。自王の安全を守る通常の合法手判定は行う（PDF p11、動画16:34）。
- 自駒を取られてから最初の自分の手番で、取られたマスにある相手駒を取り返す手も、全相手について攻撃に数えない。途中で第三者が元の捕獲駒を取って入れ替わっていても適用する。その手番で取り返さず、後の手番で取る場合は通常判定となる（PDF p12、動画18:38）。
- これらは新しい攻撃状態を作らない例外であり、以前の攻撃状態を消す処理ではない。

#### 攻撃の4分類

| 分類             | 攻撃とする着手                                       | 除外・帰属                                                                                                                      |
| ---------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 王手             | 着手によって相手王への新しい王手を発生させる         | 第三者の飛車の空き王手でも、攻撃者はその利きを作った着手者（PDF p13〜14）                                                       |
| 捕獲             | 王以外の自駒で相手の飛車・龍・金・銀・成銀を捕獲する | 歩・と金の捕獲と、王による捕獲はこの分類では攻撃にしない（PDF p15〜16）                                                         |
| 新しい取りの狙い | 自分の駒を相手駒へ新たに利かせ、下表の条件を満たす   | 互いに利き合う必要はない。第三者の駒だけに空き利きを作る手はこの分類では攻撃にしない（PDF p17〜22）                             |
| 王の周囲の封鎖   | 王以外の新しい駒の利きを、相手王の周囲に作る         | 相手自身の駒の占有マスを除く。他人の駒の占有マスや既に敵駒が利くマスも含める。第三者の駒の空き利きも着手者の攻撃（PDF p23〜26） |

「新しい取りの狙い」の駒種別判定は PDF p17 の表を基準とする。下表の「守り」は標的駒に対する標的側の駒の利きである。機械判定について次の補完を採用する（FS-010）。

- 王から標的駒までの距離は `max(abs(dx), abs(dy))` とし、斜めも1マスとして数える。
- 標的駒への守りは候補手を反映した盤面で調べる。幾何的な利きを使い、動かすと自王が危険になる駒も守りに数える。
- 利かせる駒の飛車の行には龍を含める。

| 利かせる駒   | 王から3マス以上の歩・と金 | 王から2マス以内の歩・と金（守りあり） | 同（守りなし） | 金・銀・成銀（守りあり） | 同（守りなし） | 飛車・龍 |
| ------------ | ------------------------- | ------------------------------------- | -------------- | ------------------------ | -------------- | -------- |
| 歩・と金     | 対象外                    | 攻撃                                  | 攻撃           | 攻撃                     | 攻撃           | 攻撃     |
| 金・銀・成銀 | 対象外                    | 対象外                                | 攻撃           | 攻撃                     | 攻撃           | 攻撃     |
| 飛車・龍     | 対象外                    | 対象外                                | 攻撃           | 対象外                   | 攻撃           | 攻撃     |
| 王           | 対象外                    | 対象外                                | 対象外         | 対象外                   | 対象外         | 対象外   |

- 同じ自駒で同じ相手駒への取りを維持するだけなら、新しい攻撃に数えない。別の相手駒へ新たに取りを作った場合は、その対象で判定する（PDF p19）。盤上駒の移動・成りでは同一性を保ち、捕獲でその盤上駒の識別を終える。捕獲後に打ち直した駒は新しい駒として扱う（FS-011）。
- 「新しい取りの狙い」から始まった攻撃状態が続いている間、その標的駒へ追加で利きを作る手は、別の対局者が指しても、この分類の新しい攻撃には数えない。他の標的や他の攻撃分類は別に判定する（PDF p20）。
- この免除を受けた着手の直後に元の攻撃状態が解除されても、済んだ着手を後から攻撃に変えない（PDF p21、動画34:18〜37:16）。
- 王の周囲は、王が隣接マスへ動く移動形を基準にする。既に敵の利きがあるマスも数えるため、安全な王の合法移動先だけには限定しない（PDF p23、動画38:38〜42:37）。
- 同じ駒が王の周囲の封鎖を維持する手は、塞ぐマスの数が増えても新しい攻撃には数えない（PDF p25、動画42:37〜44:24）。同じ王以外の駒が、着手前後とも相手王の周囲の対象マスのどこかへ利いているなら維持とし、対象マスが全て入れ替わっても新しい攻撃に数えない（FS-011）。
- 4分類のどれかに該当すれば、その相手への攻撃となる。捕獲の分類で対象外でも、別の駒への取りや別王への王手を同時に作れば、その分類で攻撃となり得る。

#### 一手撃破と選択肢がない場合

- 禁止対象の相手を一手で撃破する着手は許可する（PDF p2〜3）。TetraBoard では持ち駒移転や撃破数による順位へ結び付けない。
- ある相手を攻撃する以外に着手がない場合、その相手への攻撃制限を解除する（PDF p4）。二歩や自王の王手放置等の通常の禁止手を許可する例外ではない。
- 例外と履歴更新は下記の判定順に従う（FS-012）。
- 資料の競技運用は指摘後に局面を戻す方式だが、TetraBoard では FS-004 の不正着手拒否を適用する。受理前に検査し、違反手を棋譜へ確定してから巻き戻す機能は設けない。

#### 機械判定と履歴更新の順序

1. 三人攻撃禁止を除く通常の移動・成り・打ち駒・自王の安全・打ち歩詰めの規則で、通常合法手の集合を求める。
2. 各候補手について、着手前の盤面・攻撃履歴と候補手適用後の盤面を使い、4分類と応手・取り返し・維持・同一標的への追加免除を調べる。
3. 標的ごとに、他の2人がその標的への攻撃状態なら第三者の新しい攻撃を除外する。ただし、その標的を攻撃しない通常合法手が0件なら、その標的の制限を外す。ある標的への例外で、他の標的への違反まで許可しない。
4. 一手撃破は、候補手で禁止対象の標的を直ちに詰ませる場合だけ免除する。仮の詰み判定には三人攻撃制限を含めない。王手への応手は攻撃から除外されるため、応手の探索と追加禁止の探索を循環させない。別の相手を詰ませただけでは免除しない。
5. 三人攻撃に違反しない候補を合法手とする。選ばれた手を受理した後、既存の攻撃状態に他3人の着手を記録し、解除条件を満たした状態を消し、今回の新しい攻撃状態を開始・更新する。候補の禁止判定は解除前の状態で行い、禁止手の仮履歴は保存しない。
6. 攻撃を開始・再開始する関係には、今回の攻撃の分類、③の対象となった標的駒、解除待ちの陣営を記録する。同一標的免除の参照先は座標ではなく盤上駒として追跡する。捕獲された標的を同じマスの別駒と取り違えない。
7. 着手者について、直前の自手番終了後から今回までに自駒を取られたマスの集合を、取り返し免除の対象とする。複数マスがあればどれを取り返しても免除する。今回の自手番を完了したら本人の集合を空にし、今回の捕獲で取られた側へ対象マスを登録する。拒否した操作で免除を消さない。
8. 脱落判定と手番の確定を続ける。誰かが脱落した場合、または三人攻撃が作用しない設定・モードの場合は、追加の攻撃履歴を判定に使わない。

### 手番、詰みと脱落を処理する順序

ここは外部資料だけでは一意に決まらないため、FS-005・FS-006 として開発者が承認した TetraBoard の処理順である。着手の受理前に上記の三人攻撃の機械判定を行う。

1. 手番中の合法な移動・打ち駒を確定し、捕獲と成りを反映する。
2. その盤面について、生存中の全王の王手状態と応手を調べる。王手中で、合法な応手が1手もない陣営を詰みとする。応手は他陣営の助けを仮定せず、その陣営が次に1手指して自王の王手をすべて解けるかで判定する。
3. 複数陣営が詰んでいる場合、**誰かの駒の利きを消す前の同じ盤面**で詰みの集合を確定し、一括で脱落させる。一人ずつ利きを消して他の詰みを取り消さない。
4. 終局条件を満たせば結果を確定する。継続する場合、脱落者の利きを除いて王手状態を再計算する。盤上駒は同じマスに残るため、利きの消失だけで新たな王手は発生しない。
5. 生存者に王手が残っていれば、直前の着手者から通常順で次に当たる王手中の陣営へ手番を移す。王手がなければ通常順で次の生存陣営へ移す。脱落者は飛ばす。
6. 選ばれた陣営が王手なしで合法手0件なら、詰みとは別の「合法手なし」で脱落させる。パスにはせず、そこを起点に次の手番を選び直す。外部の王手が残っていればその王手中の陣営を優先する。
7. 実際に指せる次の手番と終局状態が確定した後に、千日手を判定する。継続する場合だけ次の手番者を計時する。

- 王手で手番を飛ばされた人に、後から補填の手番を与えない。
- 詰みで脱落した陣営を次の手番選択の起点にしない。例えば南の着手で東が詰んで脱落し、ほかに王手が残っていなければ、次は南の次に当たる西の手番となる。
- 複数人への王手に対する手番の予約列は保持しない。各着手・脱落後の実際の盤面から再計算する。王手が解消された人へ優先手番を与えない。
- 自分の手番が来る前でも、詰みであることが確定した時点で脱落する。誰も王を取る操作を行わない。
- 王手なしで合法手がない陣営の判定は、その陣営が手番として選ばれた時点で行う。他人の着手で指せるようになる可能性があるため、手番外に即脱落させない。
- 詰み・合法手なしの自動処理中には、その陣営へ思考時間を与えない。手番を飛ばされている人の時計も進めない。
- 手番外の退室・通信切れによる脱落では、まず盤面の脱落処理と全王の詰み・終局を判定する。現在の手番者が生存していれば、その手番・時計を保つ。手番者が脱落した場合は、その陣営を起点に王手優先で次の手番を選ぶ。

### 脱落者の駒とシングルスの順位

- 詰み、合法手なし、README で定める投了・退室・時間切れ・通信切れのすべてに、同じ盤面・持ち駒処理を適用する（FS-003）。
- 脱落した陣営の王は、そのマスに固定した裏王へ変わる。利きを持たず、移動・捕獲・通過できない障害物となる。自王の安全判定の対象から外す。
- その他の盤上駒は移動も攻撃もしない駒として、そのまま残す。成り状態も保持する。生存者は通常の移動で捕獲でき、捕獲後は不成の持ち駒になる。
- 脱落者の持ち駒はルール上破棄し、生存者へ譲渡しない。破棄直前の種類・枚数を表示専用に保持し、持ち駒台へ残す。詰み・合法手なし・投了・退室・時間切れ・通信切れのすべてに適用し、選択・ドラッグ・駒打ちはできない。表示用枚数は合法手・CPU評価・千日手判定に含めない。撃破数による得点は行わない。三人攻撃の一手撃破解除に必要な判定は行うが、資料に記された撃破者への駒移転や得点を追加しない。
- 脱落者を手番から除き、その時点で未確定の下位から順位を確定する。4人生存時の1人脱落は4位、3人時は3位、2人時は2位である。
- 同じ盤面から同時に詰んだ陣営は同順位とする。脱落直前の生存者が `n` 人、同時脱落が `k` 人なら、その `k` 人は `n - k + 1` 位となる。例: 4人中2人が同時に詰めば両者3位、残り2人で1位・2位を争う。
- 一括処理後に生じた別の脱落は次の処理群として順位を決める。退室や通信期限等の外部イベントはサーバーで確定した処理順に従い、同時詰みの一括処理と混同しない。
- 生存者が1人になればその人を1位として終局する（FS-002）。生存者0人となる一括処理では勝者なしの引き分けとし、その処理群を同順位にする。

### 千日手と引き分け

以下は FS-007 として承認された TetraBoard の規則であり、四人将棋の共通規則とは断定しない。

- 初期局面を1回目として、同一局面が4回出現した時点で自動的に引き分けとする。
- 同一局面の比較には、全盤上駒のマス・所属・駒種・成り・裏王、生存陣営、各生存者の持ち駒の駒種別枚数、次の手番を含める。時計、接続状態、着手番号、直前の着手表示は含めない。
- 三人攻撃禁止がONで作用する間は、攻撃関係、開始理由、解除待ちの陣営、③の標的駒、取り返し免除の対象マスも比較に含める。盤面が同じでも合法手を変える履歴が異なるなら同一局面ではない。駒の内部IDの数値自体ではなく、履歴が現在のどの駒を指すかという対応を比較する。OFF・ダブルス・誰かの脱落後は、作用しない攻撃履歴を比較対象に含めない（FS-013）。
- 着手と自動脱落をすべて処理し、次に操作可能な手番が定まった局面だけを数える。途中の仮想盤面を数えない。投了・退室等でも最終的に継続する局面が確定したなら数える。
- 詰み・脱落による勝敗確定を千日手より先に処理する。
- 連続王手による反復も引き分けとし、王手を続けた人を特定して反則負けにしない。これは本将棋の連続王手の千日手とは異なる。
- シングルスでは引き分け時点の生存者全員を同率1位にし、すでに確定した脱落者の順位を保持する。ダブルスでは両チーム引き分けとする。
- 持将棋の点数計算、入玉宣言、手数上限、局面を戻した指し直しは設けない。合意による引き分けは次節に定める。

### 合意による引き分け

- 対局中、生存者は自分の手番で引分提案・取消を行える。提案は着手・手番変更後も継続し、自分の手番で取り消すか脱落するまで保持する。
- 提案・取消は着手ではなく、盤面・手番・手数・直前の着手・攻撃履歴を変えない。時計を停止・リセットせず、千日手の出現数も増やさない。提案状態は同一局面の比較対象に含めない。
- 生存者全員が提案状態になれば、終局理由を合意（`agreement`）として引き分ける。脱落で生存者が減った場合も再判定する。詰み・合法手なし等の自動脱落と通常の終局を先に処理し、対局が続く場合だけ全員同意を判定する。
- シングルスは生存者全員を同率1位とし、確定済みの脱落者順位を保持する。ダブルスは両チーム引き分けとする。履歴・棋譜・戦績・ランキングは既存の千日手と同じ扱いで保存・集計する。
- 現行Lv1/Lv2 CPUは自分の手番で、生存する人間が1人以上かつ全員が提案中なら提案する。そうでなければ既存の提案を取り消す。終局しなければ同じ手番で通常の着手処理を続ける。CPUから独自の提案は行わない。
- 次局は全員の提案状態を解除して開始する。盤面の巻き戻しや手数上限、持将棋の点数計算は追加しない。

### ダブルス

- 南・北と西・東がそれぞれチームになる。FS-008 の割り当てでチームを決め、事前のチーム指定は設けない（FS-009）。
- 味方の盤上駒は捕獲できず、飛車等の移動を遮る。
- 味方の駒の利きは自王の王手・詰み・王の逃げ先判定に含めない。味方の利きのあるマスへ王を移動できる。
- 自分の王を危険にする手は禁止する。一方、味方王と敵飛車の間の自駒を動かして味方へ王手を発生させる手は許可する。その王手・詰みを通常どおり判定する。
- 持ち駒は個人ごとに管理する。味方への譲渡・共同の持ち駒・味方の持ち駒を使う着手は設けない。二歩も本人の不成の歩だけで判定する。
- 一方のチームの誰かが詰み・合法手なし・投了・退室・時間切れ・通信切れで脱落したら、そのチームの敗北として直ちに終局する。
- 同じ盤面から両チームに詰みの陣営が含まれた場合は引き分け。片方のチームの2人だけが同時に詰んだ場合はそのチームの敗北。先に確定した通常の脱落で終局した後、別の外部イベントで結果を変更しない。
- 結果はチームの勝ち・負け・引き分けとし、個人の1〜4位は付けない。
- 真ダブルスのように裏王の陣営が操作を続ける方式は採用しない。
- 三人攻撃禁止は敵3人の攻撃を制限する規則として扱う。通常ダブルスでは敵が2人で、味方への攻撃を数えないため成立しない。
- 共通チャットでの味方への相談を許可し、チーム専用チャットや相談による時計停止は設けない。外部大会の助言禁止規定をサービスへ自動的に持ち込まない。

### エンジンが保持するルール状態

- ルールの版、対局モード、三人攻撃禁止のON／OFF、参加者と4方向の対応、チーム
- 盤上の各駒の所属・駒種・成り・座標、裏王
- 各陣営の持ち駒、生存・脱落状態
- 現在の手番、確定順位、脱落順・同時脱落群・脱落理由

王手状態は盤面・生存者・チームから、合法手一覧は盤面・持ち駒・手番・設定・攻撃履歴を含むルール状態から算出する。手番の予約列は状態に持たない。持ち時間と接続期限は共通仕様に従ってルーム側で管理し、時間切れ等の確定済みイベントをエンジンへ渡す。詰みは独立した自動脱落イベントとし、着手数は移動・打ち駒を受理したときだけ増やす。CPUも同じ合法手一覧を使い、思考途中の状態を保存しない。

シングルス解析用の完全状態は、版付き初期値と連番イベントを既存エンジンで再実行して復元する。表示frameから除く反復辞書も保持し、ON/OFF・攻撃履歴・引分提案を識別する。`@tetraboard/four-shogi/analysis` の [独立API契約](../four-shogi-ai-engine.md#完全解析状態の復元api186) と [実装案内](../development.md#四人将棋エンジン) を参照する。解析の仮遷移は対局状態・保存棋譜・順位の正本を更新しない。

以下はCPUの採用仕様であり、2026-10-08の強化指示を反映する。対局の合法手・手番・順位のルールは変更しない。CPUはシングルス・通常ダブルスと三人攻撃禁止ON／OFFに対応する。

- 公開APIは `chooseCpuAction(state, level, random = Math.random): FourShogiAction | null`、レベルの型は `CpuLevel = 1 | 2` とする。終局済み、または合法手がない場合はnullを返す。入力状態を変更せず、CPU用の状態項目を追加しない。

- Lv2は同じ着手確定処理で合法候補を進め、即座にシングルス1位（千日手の同率1位を含む）またはダブルスのチーム勝利となる手を優先する。入力状態と基底の反復履歴は変更しない。
- 敵の応手で自分（ダブルスでは自チーム）が直ちに脱落する場合は、敵が別の撃破を選ぶと予測できても危険と判定する。
- 探索開始局面がシングルスの三人・四人生存時は各手番者が本人の評価を最大化するMaxⁿ探索、二人生存時とダブルスは実際の手番者の敵味方に従うαβ探索を使う。探索法は1回の選択内で固定する。毎手の手番は着手後のエンジン状態から取得し、固定交互の手番や仮のパスを作らない。
- すべての根候補を浅く評価し、静的上位24候補を中心に最大6手先まで反復深化する。内部節点では王手・捕獲・成りを並べ替えに使い、上位6候補を中心に探索する。王手・捕獲は候補数で除外せず、王手中はすべての応手を残す。根候補でも王手・捕獲は上位24件の外側まで残す。最終評価が同じなら初手の静的評価、さらに同じなら序盤候補、元の列挙順の順で使う。
- 序盤候補は初期配置から各陣営が中央歩を1段進める最初の4手の系列を、両モード・三人攻撃ON/OFFで合法性確認して構成する。盤面・持ち駒・手番・攻撃履歴・設定が一致した局面だけに使い、評価が同点の場合に優先する。外部棋譜由来の定跡や棋力の保証とは扱わない。
- 思考量の既定上限は2048単位。着手確定と内部節点の生成を各1単位、合法手列の生成後に16候補ごと1単位を計上する。時計による同期計算の打切りは使わない。上限到達時は最後に完了した深さの手を返し、初回の評価中なら評価できた合法候補、評価できなければ最初の合法候補を返す。
- 通常の深さの境界でも王手・直前の捕獲・次の自手番では最大2手の戦術延長を行う。延長も同じ思考量上限に含める。
- 探索キャッシュは1回の選択内・最大2048件に限定し、局面、確定順位、引分提案、枝の反復回数、残り深さと延長数を区別する。αβで打ち切った境界値を完全な評価値として再利用しない。
- 探索枝の反復回数は枝ごとに分離し、基底履歴の読取りを1回の探索内で共有する。探索履歴を保存しない。三人攻撃・詰み・同時脱落・千日手は実対局と同じ確定処理で扱う。

静的評価の駒の価値は次のとおりとする。生存する陣営の盤上駒と個人の持ち駒を資産として合計し、脱落者の残った駒と持ち駒は数えない。持ち駒には不成の価値を使う。

| 駒   | 不成 | 成り |
| ---- | ---: | ---: |
| 王   |    0 |    — |
| 歩   |  100 |  500 |
| 銀   |  400 |  500 |
| 金   |  500 |    — |
| 飛車 |  800 | 1000 |

利きを陣営ごとに集計し、盤上駒の可動性を1マス3点、未成歩の前進を1段6点で評価する。盤上駒が敵に狙われて守りがなければ駒価値の70%、守りがあれば相手の最安攻撃駒との価値差の45%を危険として減点する。自手番ならその40%、取りを狙う敵の手番なら100%、それ以外は75%を使う。幾何的な利きは評価の特徴であり、合法な捕獲の保証にはしない。

王手中は300点、盤内の王の隣接マスに敵の利きがあれば1マス35点を減点する。敵の利きがなく自駒2枚以上の利きがある隣接マスは12点を加える。脱落駒とダブルスの味方を敵の利きに含めない。王手は応手の並べ替えで優先するが、選択時は探索後の損得を比較する。

- シングルスの生存者は `5000 × 脱落者数 + 自分の資産・配置評価 - 相手評価の平均 × 0.6 - 最も優勢な相手評価 × 0.4` で評価する。順位が確定した陣営は1位1000000、2位-1000000、3位-2000000、4位-3000000とする。
- ダブルスは資産・配置・王の安全を合わせた自チームの評価から相手チームの評価を引く。味方は同じ値、相手は符号が反対となる。終局時は勝利1000000、引分0、敗北-1000000とする。

Lv2は候補の選択と計算予算によって読み落とす可能性があり、最大深さまで常に到達するとは限らない。処理量上限は実行時間の保証ではない。オンラインルームはCPUの選択結果を保存し、次のAlarmで期限・局ID・revision・手番を再確認して着手を確定する。持ち時間は同期計算前から確定までを含む。実装計画と受入基準は [AIの検証](../four-shogi-ai.md) を参照する。

### ローカル検討用CPU

P1-4cの致命応手ガードは起動時に明示する実験機能で、既定はOFFです。通常のMaxNを置き換えず、その後に初手込み最大4実手の有限生存を検査します。本人の将来手は存在量化、相手の合法手は全称量化します。OBSERVEは判定の記録だけ、EXPERIMENTALは首位が同じ地平で証明済みunsafe、代替が証明済みsafeの場合だけ代替を優先します。unknown・一本道の脱落証拠・未検査をunsafeとみなさず、終局の単独勝利を覆しません。同じ判定では元の順位を保ちます。これは敵対的相手モデルでの有限生存であり、実戦の相手の選択・長期安全・勝利の保証ではありません。[実験条件と採否](../four-shogi-ai.md#p1-4c致命応手ガード)を参照してください。

2026-10-28承認の[ローカル検討アプリ](../../README.md#四人将棋のローカル検討アプリ)は、公開Lv1/Lv2と別の `@tetraboard/four-shogi/study-search` を使います。対象はTetraBoard rulesVersion 1のシングルス・三人攻撃禁止ON/OFFです。全員が自分の単独1位を目指し、終局の主効用は単独1位だけ1、それ以外0です。主効用が完全に同じ場合だけ順位を副比較します。生存人数・撃破数そのものを目的に加点しません。ルール・公開レベル・旧CPUの選択結果は変更しません。

2026-10-29の二段階探索 `local-root-maxn-v6`（strategy=dual）は設定の「主要候補を深掘りする（旧v6・実験）」で選べます。既定はv5（strategy=adaptive）の幅広い検討です。v6は最初に通常深さ3、2秒未満の予算では深さ2まで広く比較し、その結果を別に保持します。広い比較の上位最大3候補を、同じ深さの一組として深掘りします。深い組の全候補が完成するまで最後の完成組を表示し、浅い評価と深い評価を同条件として混ぜません。

深い検討の各節点では、すべての合法応手を正本で一手進めて、その実手番者自身の静的効用で並べます。最初は相手の上位2手・自分の上位3手、王手中は最低4応手を深く読み、それ以外は一手の確認に留めます。王手・捕獲・成りという分類だけで無制限に深掘りしません。一手の地平では対象の全応手を比較し、捕獲/成り直後の戦術延長ではv5同様に王手・捕獲・成りと静かな合法手1つへ絞ります。仮のパスや未確定盤面をPVへ入れません。

2026-10-29のP0診断では、v6のdeep末端が直接静的評価を返し、既存の戦術延長判定を迂回する実装不整合を確認しました。また、自分の重要な成り継続手が静的上位K手の外へ落ちる例も確認しました。旧v6 `dual` は比較基準としてそのまま残します。測定用の `dual-promotions`（`local-root-maxn-v6-p0-2`）は自手番・残り通常深さ2以上のdeep節点で上位K手を保持し、除外された成りの静的最上位を最大1手追加します。相手の候補幅や評価係数は変えません。[診断結果と未確定事項](../four-shogi-ai.md#p0v6戦術不一致12展開の診断2026-10-29)を参照してください。

最初の深さ9到達後は、直前の主要最善候補を残して広い比較から別の最大2候補を巡回し、相手幅を1ずつ最大8、自分幅を1ずつ最大10へ広げます。3段階ごとに目標深さも1増やします。広げ直しの途中は、直前の深さ9の結果を浅い再検討結果で上書きしません。深い候補の静的指標が広い比較時より200点以上下がる場合は、同じ深さで別候補を一度再検討します。これも割当の判断であり、異なる深さの最終評価の直接比較ではありません。

測定用の `dual-extensions`（`local-root-maxn-v6-p0-3`）はdeepの一手の地平でも既存の延長判定を通します。終局は延長せず、既定の追加2手を各経路で消費します。`dual-combined`（`local-root-maxn-v6-p0-23`）は成り保持とこの末端延長の両方を使い、設定の「成りと末端延長を改善する（v6・実験）」で選べます。追加深さを通常深さへ加算して表示せず、旧v6と独立した版として測定・保存します。評価係数とv5既定は維持します。

P0-5の測定用 `dual-continuations`（`local-root-maxn-v6-p0-5`）は成り保持に加え、自手番・残り通常深さ2以上で、選択済み候補に含まれない王手筋を持つ最上位の1手を補います。王手筋は対象王、王手駒の種類/成り、王から見た方向で区別し、距離だけ違う同方向の王手で枠が埋まる場合を補います。元の上位K手を除去せず、成り保持と合わせて最大2手追加します。探索した各手番者自身の効用で比較する原則と、合法手・評価係数は維持します。

P1-3の明示設定 `taskPartition=replies` は、旧v6 `dual` とP0-5 `dual-continuations` のdeep探索だけで応手を並列分配します。根の通常深さ4以上で、選別済みの独立した非終局応手が2〜16手ある場合に根直下を分割します。`splitMinDepth`（4〜256、既定4）で分割の開始だけを遅らせる比較ができます。閾値未満も同じ候補・深さで通常の根分配を続けます。通常探索と同じ選別集合・深さ・延長条件を使い、全子タスクの完成後に実手番者の4人評価ベクトルを元の順序で比較し、同点は元の合法手番号で決めます。LMRを含むbroad段階や他方式、単一プロセスは従来の根分配です。v5既定と王手情報共有の既定OFFを維持します。保存する探索版には `-p1-3-replies` を付け、元のP0-5と区別します。時間切れの未完成応手を同深さの完成候補に混ぜません。 比較用の明示設定 `replyCacheBudget=roots` は、独立したdeep応手を始める時だけ状態参照キャッシュを `floor(元の上限 × min(1, 3 / プロセス数))` へ縮小します。元の全状態数の上限・広い比較・完成枝キャッシュは維持し、保持枠の縮小で候補や延長を削りません。8プロセス・8192MiBの通常設定では各4096→1536状態、4プロセスでは8192→6144状態です。1/2プロセスの上限は変えません。既定 `replyCacheBudget=workers` は従来枠です。縮小は高負荷例のRSS上限停止を解消できず、既定採用していません。root分配と既定v5にはこの縮小を適用しません。保持状態数はRSSの厳密な保証ではなく、既存のRSS監視と停止も維持します。

P0-6の測定用 `dual-quiescent`（`local-root-maxn-v6-p0-6`）はdeep末端で、いずれかの生存王への王手、直前の捕獲/成りの駒への取り返しの可能性、歩以外の最小駒価値以上の敵駒を現在の実手番者が取れる幾何的な可能性を延長対象とします。利きは延長開始の保守的な目安で、実際の候補はすべて正本の合法手です。自手番であることだけ、安定した捕獲/成り直後であることだけでは延長しません。

王手中は全合法回避手を残します。それ以外の延長節点は、取り返し優先の捕獲1手、王手優先の別の戦術手1手（王手がなければ成り）、実際の静かな合法手1手の最大3手を順序付けから選びます。仮パスや現在局面の静的評価を合法な着手候補として比較せず、選んだ実着手の先で実手番者の効用を比較します。既定の延長2手を経路ごとに消費し、通常深さとは別に記録します。選択探索であり、未探索の王手/交換の安全性や詰みの不存在を証明しません。広い比較段階は旧v6と同じです。`dual-refined`（`local-root-maxn-v6-p0-56`）はP0-5とP0-6を併用します。v5既定と旧4方式は維持します。

表示と保存では広い比較の深さ/候補数と、主要候補の深さ/候補数・基本応手幅・拡張段階を区別します。履歴を省略した手順や全応手への成立証明を作らず、PV上の自手番到達も予想として扱います。v6の20秒比較では12局面中7局面で深さ9、次々回の自手へのPV到達は10局面でした。固定Lv2三体との各32局では単独1位がv5の4局から8局へ増えましたが、1秒の戦術一致が82/88件から76/88件へ減り、事前の採用条件を満たさないためv5を既定に残します。少数系列の工程比較であり、全局面での深さ9到達や棋力向上を認定しません。[条件と根拠](../four-shogi-ai.md#二段階探索v6の比較と採否2026-10-29)を参照してください。

探索は4/3/2人生存とも各実手番者自身の効用を比較するMaxⁿです。実際の次手番は正本の確定処理から取得し、補填手番や仮のパスを作りません。2026-10-29承認の探索版 `local-root-maxn-v5` は全根候補を浅く比較した後、通常の根幅24を基準に、深さdで静かな上位max(5, ceil(24/(d-1)))手と下位から巡回する最大2手、すべての王手・捕獲・成りを再検討します。候補割当には過去反復の評価を使いますが、完成比較として公開する候補はその反復の同じ通常深さへそろえます。初回の浅い評価だけで下位候補を永久に除外しません。

内部は上位6手と王手・捕獲・成りを残し、王手中は全応手を残します。残り通常深さ3以上で、王手中ではなく、並べ替え後の3手目以降にある静かな手は1手浅く確認し、手番者の暫定最善以上なら元の深さで再探索します。この短縮は安全な枝刈りの証明ではなく選択探索です。通常深さの地平で王手・捕獲直後・成り直後・自手番を追加で調べます。捕獲/成り直後で王手中でも自手番でもない延長節点では、王手・捕獲・成りに加え、静かな合法手を最低1手残します。最大通常深さ256・戦術延長2手を既定とし、表示は比較深さ、進行中の深さ/完了候補数、PV上の次の自手番への到達回数を区別します。選択深さを全合法手の網羅や2巡先の安全証明として扱いません。

v5は空いた子プロセスへ根一手のタスクを動的に割り当て、可能なら同じ根を前の担当へ戻します。ジョブ内の状態参照キャッシュを入替式にし、葉の評価だけで内部節点を追い出しません。葉の評価は別の弱参照キャッシュで、その局面参照が生存している間だけ再利用します。既定の実プロセスでは1プロセスあたりmin(8192, max(256, floor(メモリMiB/プロセス数*4)))状態、直接探索APIでは4096状態です。完成枝のキャッシュも同じ上限とし、完全状態（攻撃/反復履歴・直前手など）と残り深さ・延長条件が同一の場合だけ再利用します。局面変更をまたぐキャッシュ再利用は今回含めません。RSS合計の既存の監視を維持し、プロセス共有キャッシュを作りません。

v6系では同じ探索contextの不変状態参照に対する王手情報も弱参照で共有します。盤面だけのキーや履歴を省略した同一視はしません。v5では20秒測定でメモリ上限停止が増えたため、この王手共有を既定で使わず、比較用APIの`reuseChecks:true`だけで有効にします。v6系も`reuseChecks:false`で無効化できます。王手判定の幾何計算・合法手の集合・探索幅・評価係数は維持します。

選択根の直後の合法応手による即脱落検査は各根タスクの通常探索前に行います。表示用の資産危険検査は浅い全体評価の上位5候補だけ、各128work・次の実自手番または最大8手までです。v5の動的分配では深さ2の対象タスクの探索後に検査し、検査も終えた同深さの全タスクがそろってから公開します。固定workの再現確認に使う直接探索APIの反復は、v4と同じ深さ2公開後の検査境界を保ちます。対象外・期限・取消・未着手は未確認を保ち、表示用検査が候補の評価やPVを上書きすることはありません。評価版 `local-sole-first-pressure-v1` と効用を維持します。

測定CLIの `strategy=legacy` は探索v4の固定分配・1024状態で新規登録を止めるキャッシュ・根の静的選定・旧延長/同値処理を残します。`profile=baseline` は右優先/追加評価の有無の比較であり、旧探索方式の指定とは別です。過去v4の条件・結果は測定記録に保持します。

「右」は画面の回転や生存人数によらず、南→東、西→南、北→西、東→北に固定します。元の右隣が脱落したら右優先を解除し、別の生存者へ付け替えません。右の王へ新たな王手をかける手を内部の手順序で180点優先し、同じ予算で早く調べます。初回の浅い探索は元の列挙番号を保持して右への新規王手から調べ、その後は有望さと担当キャッシュを考慮したタスク割当を使います。完成候補では、確定単独勝ち・直後の脱落危険・主効用・副順位を先に比較し、それらが完全に同じ場合だけ右への新規王手を優先します。比較用baselineは根の右優先と同評価時の右優先を適用しません。v5はその後に初手の静的評価、さらに同じなら元の列挙順で比較します。不成と成りが読み筋末尾で同評価でも、初手の成りの利得を比較できます。これは探索後の不利な評価や即脱落を上書きする着手義務ではありません。逆王手・複数王手・同時詰みも正本で処理し、右への王手だけで必ず自手番へ戻るとは扱いません。

マジックの検討では、右の王への王手を伴う第三者の駒取りを「候補」とし、その実際の読み筋で右への手番移動・次の自手番への復帰・資産増加を確認したものを「この読み筋で成立」と区別します。後者も全応手に対する成立証明ではありません。次の実自手番または自分の脱落/終局まで、別の合法応手による脱落・飛車損・盤上駒と持ち駒の資産減少を検査し、根拠手順を残します。指定workや手数の地平で打ち切った場合は未確認とし、取り返せる位置に別の駒があるだけで安全と断定しません。単独即勝ちを優先し、直後に自分が脱落する合法応手が見つかった候補は危険として比較します。駒損回避は目的達成のための評価であり、勝ちにつながる捨て駒を一律禁止しません。

静的評価は共通AIの駒・持ち駒・配置・王の安全を使い、他者間の相互圧力を0.06倍・合計最大150点の余裕として加えます。相手から自分への圧力が相互圧力を上回る部分は加点しません。自手番外で他者への王手があり、自分が王手中ではない場合は、敵に狙われる自駒の価値の12%を手番が回らない危険として減点します。圧力は王への利き400、ほかの駒は駒価値の20%か200の小さい方を陣営間で合計した特徴です。幾何的な利きは争いの目安で、三人攻撃禁止のルール上の攻撃関係や相手の意図を推測で置き換えません。

4方向の未校正指標と暫定順位、読み筋・候補ごとの完了深さと資源条件を表示します。非終局の主指標は共通AIと同じ単調変換を用い、勝率％や合計100%の配分へ変換しません。読み筋の各手は実方向付きで正本から再生できるものに限ります。手番外の人の想定手は同じPV上で次にその人の実手番が来た位置から示します。手番が来る前に読みが終わる場合は未到達とし、その人へ仮の手番を渡して候補を作りません。比較が未完了なら評価付き候補を空にし、期限時は確保した合法手を未評価の代替として区別します。

席をフォーカスした検討は、現在の完全状態から他者の合法な予測着手を正本で進め、対象席の最初の実手番に達した局面で解析します。手番を仮に差し替えたり、王手で飛ばされた人の着手を補ったりしません。予測版 `local-focus-projection-v1` は各他者が本人の効用を選ぶ小予算Maxⁿを使い、既定256work/手・最大深さ2・根幅8・内部幅4・延長0、最大12手・250ms以内とします。投射は検討全体の時間枠にも含めます。実際に到達しなかった場合、対象の脱落や終局を含む理由を返し、未来局面の評価/推奨を捏造しません。

元の実局面と予測後の解析対象、相手予測のprefixと対象の候補PVを区別します。他者の予測を前提とする形勢や想定手は条件付きであり、相手の全応手を調べた結果ではありません。対象が既に実手番で、予測prefixが空かつ両局面が同一の場合だけ、対象の推奨を現在局面へ直接採用できます。実際の着手が届いたら旧予測を取り消し、確定局面から解析し直します。

Macの並列実行・保存・観戦は[構成](../architecture.md#四人将棋のローカル検討)で扱います。棋力の正式判定と条件は[測定記録](../four-shogi-ai.md#ローカル検討cpuの測定と採否)を参照します。2026-10-28の追加指示により正式再計測・合格判定は機能実装から分離しました。2026-10-29承認の効率改善は固定局面・戦術・短い対局で別途比較します。時間/プロセス数の増加による棋力向上、勝率の校正、公開Lv2の置換をこの実装だけで認定しません。

三人攻撃禁止の「三人」は一人の王に三方向から王手をする意味ではなく、複数の対局者による攻撃状態の制限である。基本ルールの王手優先や自王への王手放置禁止と混同しない。

脱落者の持ち駒破棄、同時詰みの一括判定・同順位、四人用の反復引き分け、全脱落原因の統一は、資料間の違いや説明不足を補うために開発者が承認した TetraBoard の仕様である。

## 戦績用の撃破数

シングルスでは、受理された着手によって新たに詰んだ相手の人数を、その着手者の撃破数へ加算する。同じ着手で2人が詰めば2と数える。空き王手・複数の利きが関係する場合も、その着手を受理した本人へ帰属させ、過去の攻撃者へ分配しない。CPUも同じ方法で対局記録へ数える。

投了・退室・時間切れ・通信切れ・合法手なしは撃破に含めず、ダブルスでは数えない。この値は保存と戦績表示のためだけに使い、シングルスの順位、千日手の同率1位、ダブルスの勝敗を変更しない。本人戦績には開始時の4人全員が人間だったシングルスの累計「撃破数」を表示し、過去のCPU戦も累計から除外する。CPU戦の対局記録・棋譜と保存済み撃破数は保持する。四人将棋シングルスのランキングでも、同じ累計撃破数を集計する。戦績・ランキングの対象条件は README の共通仕様に従う。導入前・導入時に進行中だった対局の撃破数や棋譜を補完しない。

## シングルスの完全優勝と戦法別戦績

完全優勝は本人が他の3人全員を上記の定義で撃破し、単独1位になった局だけを数える。2人撃破と相手1人の投了などによる優勝、千日手・合意による引き分けは完全優勝に含めない。撃破率は累計撃破数を対局数で割った平均人数で、最大3.000とする。順位・優勝・ゲームの終了条件は変更しない。

本人の受理された着手で戦型が不成立から成立したとき、その局で使用した戦型として記録する。同じ戦型は1局で1回、同時・順次に複数戦型を使った場合は各戦型へ局の最終順位を1回ずつ加算する。判定は既存の全16戦型・解析版3を使い、通知の表示や接続状況には依存しない。開始時の4人全員が人間のシングルスだけに成立履歴を初期化し、導入前・導入時進行中の局は補完しない。本人のアカウント参加・終局保存などの条件と表示項目はREADMEに従う。
