# 四人五目並べのルール

この文書は四人五目並べ（ゲームID `four-gomoku`）のゲーム固有ルールと表示・CPUの採用仕様の正本です。2026-10-11に開発者がシングルス・ダブルス、禁手なし、順位制、満盤・脱落の裁定、UI・戦績と初回範囲を承認しました。仕様PR #152のマージ後、承認済み計画に沿って実装しています。マージ・本番公開は開発者の承認後に行います。

サービスへの追加範囲は[README](../../README.md#四人五目並べ)、Goal・ContextProviders・Constraints・Done Whenとコミット計画は[開発文書](../development.md#四人五目並べの実装計画)を参照します。認証、参加資格、準備・開始、時計、通信、チャット、スタンプ、保存再試行はREADMEの共通仕様を適用します。

## 盤、色と着手

- 15×15の225交点、黒・白・赤・青の4色を使い、空の盤から開始します。人間とCPUを合わせて4席で開始します。
- 基準座標は左上A1が `{x:0,y:0}`、右下O15が `{x:14,y:14}` です。石はマスの中ではなく交点に置きます。
- 開始・再戦ごとに4色を重複なくランダムに割り当て、黒から黒→白→赤→青の循環順で進めます。初手の位置は自由で、色の交換手順はありません。
- 自分の手番に空点へ自色の石を1個置きます。置いた石は移動・裏返し・捕獲をしません。任意・自動のパス、成立した着手の取消・待ったは設けません。
- 全色で禁手を設けません。三三・四四・長連を拒否せず、禁手のON／OFF設定も追加しません。通常の五目並べの黒だけの禁手設定は、四人版に引き継ぎません。
- 縦・横・斜め2方向の計4方向で連続5個以上を完成条件とします。6個以上でも成立し、連の両端が他陣営の石や盤端でも成立します。空点や他陣営の石で連は途切れます。
- 盤外、既に石のある交点、手番違い、手番から外れた人、待機・終局後の着手は受理せず、盤面・手数・直前手を変えません。期限・資格・通信の不正は共通仕様に従います。

## シングルス

- 4人がそれぞれ独立して競い、自分の色だけの連続5個以上で完成とします。ほかの3色を混ぜて数えません。
- 最初の完成者だけで終局せず、1〜4位の順位を決めます。全員の順位が確定した時点で終局します。
- 連続5個以上を完成した人に、その時点で未確定の最上位の順位を与え、以降の手番から外します。通常は最初の完成者が1位、次が2位です。勝ち抜けた人の石は元の色で残し、ほかの人の連をつなぐ石にはしません。
- 投了（自分の手番のみ）、退室、時間切れ、通信切れの復帰期限切れでは本人だけ脱落し、石を元の色で残して続行します。その人の手番を飛ばし、残存者の連をつなぐ石にはしません。
- 脱落者には、その時点で未確定の最下位の順位を与えます。4人継続中の最初の脱落は4位、次は3位です。既に完成者がいても上位の順位を取り消しません。
- 手番外の脱落では現在の手番・時計を維持し、手番中の脱落では次の継続者へ移します。残る人が1人になった場合は、その人の順位を確定して終局します。
- 最後の1人は、五目の完成を待たずに残った1つの順位を与えます。3人が順に完成すれば最後の人は4位、3人が脱落すれば最後の人は1位です。
- 勝ち抜け・脱落した人の計時とCPU思考を止めます。在室したまま残りの対局を見られ、退室・切断後の席保持には共通仕様を適用します。勝ち抜け後の通信切れを、順位を変更する脱落として扱いません。
- 満盤時に複数人の順位が未確定なら、その人たちを最上位の未確定順位で同順位・引き分けとして終局します。既確定順位は保持し、石数・抽選・延長で単独順位を付けません。1位確定後に3人が残れば全員2位、誰の順位も確定していなければ全員1位です。
- 順位を確定した理由を「五目完成」「投了」「退室」「時間切れ」「通信切れ」「残り1人」「満盤」で区別します。満盤の同順位と、完成や脱落で確定した順位を取り違えません。

| 進行例 | 最終順位 |
| --- | --- |
| 黒が完成、白が完成、赤が完成 | 黒1位、白2位、赤3位、青4位 |
| 黒が完成、赤が投了、白が完成 | 黒1位、白2位、青3位、赤4位 |
| 黒が完成、その後に満盤 | 黒1位、白・赤・青は同率2位（満盤） |
| 赤が投了、完成者が出ずに満盤 | 黒・白・青は同率1位（満盤）、赤4位 |

## ダブルス

- 4人・4色を使い、味方2色を同じ陣営として数えた連続5個以上でチーム勝利とします。同色だけの連続5個以上も成立します。相手チームの石や空点は連を分断します。
- 黒・赤と白・青をチームにします。開始時のランダムな色の割当てでチームを決め、事前のチーム指定は設けません。黒→白→赤→青の手番順はシングルスと同じです。
- チームの連が完成した時点で終局します。シングルスの勝ち抜けをチーム戦へ適用せず、結果はチームの勝ち・負け・引き分けとして表示します。
- どちらか1人が投了・退室・時間切れ・通信切れで脱落した時点で、そのチームの敗北・相手チームの勝利として終局します。味方だけで続行せず、個人の1〜4位は付けません。石はそのまま残し、脱落した本人と理由を記録します。
- どちらも完成せず満盤になった場合は両チームの引き分けです。勝敗はチーム2人へ同じように適用します。チームと担当色を開始時に保存し、再戦の抽選で前局の棋譜を変更しません。
- 共通チャットで味方との相談を認め、チーム専用チャットや相談による時計停止は設けません。既存の四人ゲームの共通導線を使います。

## 判定順と記録

1. 参加資格、局ID、更新番号、手番と、READMEの時間切れ・切断期限を検査します。期限ちょうど以降の操作は、着手より期限処理を優先します。
2. 着手の条件を検査し、受理した場合だけ石を置き、着手番号と直前手を更新します。
3. 今回置いた石を含む全4方向の連を調べます。シングルスでは完成による順位確定、ダブルスではチーム勝利を処理します。
4. シングルスで未確定者が1人になった場合は残った順位を与えます。シングルスの全順位確定、またはダブルスの勝敗確定なら即時終局します。未終局で225交点が埋まった場合は、ダブルスは引き分け、シングルスは未確定者を最上位の未確定順位で同順位・引き分けとします。最後の着手で完成した連と残り1人の順位確定を満盤より先に処理します。
5. 継続する場合だけ、手番から外れた人を飛ばして次の人へ進めます。空点があれば禁手による合法手なしは発生しません。

同時刻の時間切れ・切断はREADMEの共通期限処理に従います。1回の着手で複数方向の連が成立しても、同じ人に複数の順位を与えません。勝ち抜け・脱落済みの人に後から退室や期限切れが発生しても、確定済みの順位や勝敗を上書きしません。途中の順位確定と対局全体の終局を区別し、終局記録の保存・集計・結果の自動表示は全体の終局で行います。途中の局面・順位・棋譜は各着手時に永続化し、再接続やルーム復元でも保持します。

## CPU

- CPU Lv1（よわい）／Lv2（ふつう）を初回から提供します。「すぐ遊ぶ」は選択レベルのCPU3人と準備完了のホストを配置し、ホストが開始します。待機中の追加・削除・個別レベル変更は既存と同じです。
- Lv1は盤上の石の近くを中心とした合法な候補からランダムに選びます。近傍候補がない場合は全空点へ戻り、空点があるのにパス・脱落させません。
- Lv2は自分または自チームの完成手を優先し、次に相手の完成を防ぐ手、連の発展を評価します。シングルスは継続中の相手ごと、ダブルスは相手チームの混色で脅威を判定します。勝ち抜け・脱落による実際の手番順を考慮し、既存の2人用CPUを人数だけ変更して使いません。
- 完成手・防御手の確認を近傍候補の都合で省略しません。複数の脅威を防ぎきれない場合も合法手を返します。特定の他プレイヤーを勝たせるための協調は行わず、シングルスでは自身の順位、ダブルスではチームの勝利を評価します。
- ルール判定は人間・CPU・サーバー・棋譜再生で共有します。探索量には上限を設け、入力盤面と永続棋譜を変更しません。Lv1の乱数を制御できるようにし、Lv2の同評価の選択を決定的にします。
- 共通の最低2秒待機と、計算時間を含む時計を適用します。候補を保存し、適用前に局・更新番号・手番・期限を再確認します。計算中の時間切れ、勝ち抜け、脱落、再戦、閉鎖で古い候補を適用しません。
- 採用値は近傍距離2、探索幅12、深さ2手、最大156局面です。Lv1は近傍がなければ全空点から選びます。Lv2は全空点で完成・防御を先に確認し、競合する脅威は実際に次に回る敵を優先します。次の手番では味方が評価を最大化し、敵が最小化する応手を読みます。5点窓の自陣営石数0〜5に対する重みは0・1・10・200・10,000・1,000,000、次手の完成は±10,000,000、同評価は上の行・左の列を優先します。評価は自身の連の発展から継続中の最強の敵の発展を引きます。敵石・勝ち抜け／脱落者の残石は連を遮ります。CPUテストでは各敵色への防御・混色の攻防・入力不変・決定性・探索上限を確認します。多人数の先まで完全には読み切らず、同期思考を抑えるための上限です。

## 盤面とプレイヤー表示

- 木の色の盤、淡いラベンダーの背景、濃い紫の主要操作を通常の五目並べとそろえます。石は黒・白・赤・青です。共通ヘッダーと意味を持つ警告色は既存に従います。
- カードは四人リバーシと同じ配置を使います。PCは手前・左・対面・右、スマートフォンは左下・左上・右上・右下です。対局者は本人を手前、観戦・公開棋譜は黒を手前、本人用保存棋譜は本人を手前とし、黒→白→赤→青の循環順を保ちます。
- 初回待機は空の盤を表示します。待機・再戦待機のカードは現在のメンバー・準備状態を表示し、前局の担当色を付けません。対局中は勝ち抜け・脱落でもカードを詰めず、時計の代わりに確定順位・理由を表示します。ダブルスではチームと脱落状態が分かるようにします。画面上端の常設の「チーム：黒・赤 対 白・青」案内は表示しません。
- 本人の手番に交点を1回タップ・クリックすると着手します。選択後の確定ボタンは設けません。送信待ち・切断・本人確認中は重複操作を止めます。
- 上と左に小さなA〜O・1〜15の座標を表示します。下と右の余白を狭め、交点間隔と操作領域を広げます。各色の最後の石に輪を表示し（最大4個）、全体で最新の石は太い輪と中央の点で区別します。輪と点は黒・赤・青石では白、白石では黒とし、色だけに頼らず形でも最新手を伝えます。棋譜を戻すと各色の輪もその時点の最後の石に戻ります。完成した連を紫の枠で示し、6個以上では連全体、複数方向なら全ての成立した連を示します。順位・チーム・勝敗は文言でも伝えます。
- 空点全ての合法手マーク、ヒント、石への手数の常時表示とその設定は設けません。禁手の操作・説明・拒否toastもありません。
- 観戦・保存棋譜では四人ゲーム共通の90度回転を使います。座標は同じ交点に対応させ、カードの文字は読める向きに保ちます。本人の対局とルーム内の本人の直前局には回転操作を設けません。
- 個人の勝ち抜けでは、対局全体の結果ダイアログを自動表示しません。全体の終局後、結果の自動表示・再表示と再戦待機への遷移はREADMEの共通仕様に従います。

## 棋譜、結果と保存

- 対局開始時のモード・4色と参加者の対応・チーム・時間設定・規則バージョン、受理した着手と外部脱落、途中の順位確定、最終結果を保存します。禁手設定は持ちません。CPU戦も履歴・棋譜の保存対象です。
- ルーム内の直前局、本人用保存棋譜、公開棋譜で同じ表記と盤面を使います。対局中の棋譜一覧は設けません。
- 着手は「1: 黒 H8」「5: 赤 H7」の形式で、受理した着手だけを数えます。投了・退室・時間切れ・通信切れは独立項目とし、着手番号を増やしません。完成による順位は、その着手の局面へ反映します。
- 終局後は最終局面から、既存の前後ボタンとSelectで開始局面まで移動できます。巻き戻しでは選択局面までに成立した連・順位・脱落だけを表示し、未来の情報を表示しません。
- シングルスでは参加者ごとの順位と確定理由、ダブルスではチームの勝敗と終局理由を表示します。石数を得点や順位の判定には使いません。
- 再戦待機中の入退室・設定変更は前局の盤面・担当色・結果を変更しません。保存・再送・部屋閉鎖後の保持は既存仕様を使います。

## 戦績とランキング

- シングルスは既存の四人ゲームと同じ「対局数」「優勝数・優勝率」「2位数・2位率」「3位数・3位率」「4位数・4位率」を表示します。1〜2位を勝利とする別の勝数・敗数は設けません。
- 保存された順位へ1回加算し、満盤の同順位も該当順位に加算します。既存の集計定義に従い、満盤で全員が同率1位になった場合も各人の優勝数へ加算します。結果・棋譜では満盤による引き分けだったことを保持します。
- ダブルスは「対局数」「勝数・勝率」「敗数・敗率」とし、チームの勝敗を2人へ適用します。引き分けの行は設けず、対局数と率の分母に含めます。
- 開始時4人とも人間の終局・保存済み対局をモード別に集計します。未引き継ぎのゲスト参加・観戦・未終局・保存待ちは戦績へ含めず、相手のゲストは人間として扱います。CPUを1人でも含む対局は戦績・ランキングへ含めず、履歴・棋譜は保存します。
- 結果からの登録・ログインによる今回の対局の引き継ぎと同じ席での再戦は、[READMEの共通仕様](../../README.md#終局後の登録と継続再戦) に従います。
- ランキングはシングルスの優勝数、ダブルスの勝数を上位3人、詳細で各項目と対局数を上位10人まで表示します。同数の順位・表示条件・アカウント条件はREADMEの共通仕様に従います。
- 率は既存同様に小数3桁、0局は `.000` とします。戦績・ランキングとマイページの棋譜には両モードの切り替えを設けます。バッジ・戦法別戦績は追加しません。

## 初回の対象外

禁手とその設定、盤サイズ変更、開局制限・色の交換、パス、待った、ヒント、合意引き分け提案、バッジ、戦法別戦績・戦型通知、外部AIは含めません。通常の五目並べのルール・禁手設定は変更しません。

## 規則の根拠と承認範囲

- [Gomocupの説明](https://gomocup.org/detail-information/)をフリースタイル五目並べの連続5個以上という完成条件の根拠とします。四人の順位・混色チーム戦の統一規則があるとは扱いません。
- 2026-10-11の開発者回答で、初回から両モード、全順位確定まで継続、禁手なし・オプションなし、脱落者の石を残す続行、各局の色抽選、通常版と同じテーマ・操作、CPU・棋譜・集計の初回対応、味方2色の混色5連が承認されました。
- 同日の追加回答で、勝ち抜け者の石を残す上位／下位からの順位確定、満盤の同順位・引き分け、ダブルスの1人脱落によるチーム敗北が承認されました。戦績は訂正後の最終回答で、既存四人ゲームと同じ順位別の件数・率に確定しました。
- 四人化の裁定、時計・接続・投了、UI・CPU・集計はTetraBoardの採用仕様です。一般規則の名目で未決定の裁定を追加しません。
