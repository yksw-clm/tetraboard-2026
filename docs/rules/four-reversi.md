# 四人リバーシルール

> ステータス: 主要ルール・進行エンジン実装済み。CPU Lv2強化・採用測定済み / 最終更新日: 2026-10-11

## この文書の目的

TetraBoard の四人リバーシで採用するルールを定義する。ゲームエンジンと UI で同じ判定を再現できることを最終目標とする。

四人リバーシには基準とする外部ルールを設けず、この文書で合意した内容を TetraBoard の正式ルールとする。

「確定ルール仕様」を TetraBoard における四人リバーシの正本とする。ルーム、通信切れ、持ち時間、チャットの共通仕様は [README](../../README.md#ゲーム共通仕様) を参照する。後段の決定経緯と決定ログは採用理由を残すための参考情報であり、内容が競合する場合は確定ルール仕様を優先する。

## 確定ルール仕様

### 盤と色

- 8 × 8 の盤を使う。
- 石は黒、白、赤、青の 4 色を使う。
- 通常の手番順は、黒、白、赤、青の順とする。

### 対局モードとチーム

- 四人リバーシの対局部屋のプレイヤー枠は4人とする。
- シングルスとダブルスの両方を採用する。
- 作成時にシングルスかダブルスを選び、待機中はホストが変更できる。「すぐ遊ぶ」にも作成時に選んだモードを適用する。
- シングルスでは 4 人全員を互いに相手とする。
- ダブルスでは黒と赤、白と青をそれぞれチームとする。
- ダブルスのチーム分けは対局開始時のランダムな色の割り当てによって決め、事前のチーム指定は行わない。
- ダブルスでも、自分以外の色は味方を含めて通常どおり挟み、自分の色へ返す。チームによる特別な返し方は設けない。
- 全滅手はチーム合計ではなく継続中のプレイヤーそれぞれの石数で判定し、味方を含む自分以外の継続中のプレイヤーを 0 枚にする手を禁止する。

### CPU

- 人間とCPUを合わせて4席で対局する。CPUは人間と同じ合法手・手番・持ち時間・終局規則に従う。
- レベル1（よわい）は、合法手から一様にランダムで選ぶ。
- レベル2（ふつう）は、計算量を制限した多人数探索と局面別・チーム別評価で選ぶ。同点なら盤面を上から左から走査して最初の手を選ぶ。2026-10-11に下記の強化仕様を確定し、多人数探索・空き6マス以下の全読み・応手モデルによる終局予測と、WorkerのAlarmによる2段階適用を実装し、最終採用測定が成功した。
- レベル3（つよい）は将来の実装とする。
- 作成時のCPUレベル選択と最低2秒の待ち時間はREADMEの共通仕様に従う。自動パスは従来どおり即座に処理する。

#### Lv2の採用仕様

2026-10-11の開発者の「前回の方針を実装したい、最新developで仕様を確定する」という指示に基づく。対局ルールは変更しない。実装計画と受入基準は [四人リバーシAI強化](../four-reversi-ai.md) を参照する。

- 公開API `chooseCpuMove(state, level, random = Math.random): Position | null` と `CpuLevel = 1 | 2` を維持する。終局済み・合法手なしはnull、Lv1は合法手から一様ランダム、Lv2は乱数を使わない。同じ入力・探索設定なら同じ手を返し、入力状態を変更しない。
- シングルスの3〜4色継続時は、各手番者が本人の評価を最大化するMaxⁿ探索を使う。2色継続時とダブルスは、実際の手番者の敵味方に従うαβ探索を使う。ダブルスの味方は同じチーム評価、相手はその符号を反転した評価を持つ。
- 2026-10-11の追加承認に基づき、空き7マス以上・シングルス3〜4色継続時だけMaxⁿへ終局予測を追加する。まず最大2048単位（総予算が小さければその上限）の通常探索を行い、残り予算で根の全合法候補から仮対局を終局まで進める。全手番者の選択を、本人の着手と実際の次手番者の最良応手を比較する二手読みで予測する。自身の次の着手も同じモデルを使う。
- 応手モデルは各色の石数＋合法手数×3＋角×25＋角以外の辺の石×5を使い、脱落色は-10000、終局は(5-順位)×10000＋最終石数とする。これは短い配置評価で選ぶ応手の仮定であり、その他の辺が安全だという評価を通常探索へ追加しない。公開状態・時計・乱数・過去コミットのコード・外部通信は使わない。
- 全根候補の予測が完了したときだけ、Maxⁿが選んだ手より予測順位が良い候補へ補正する。予測順位が同じなら通常探索の選択を保ち、遠い将来の石数差だけで覆さない。補正候補同士は終局の順位・石数、同点なら元の列挙順で比較する。中断時は通常探索の結果を保つ。予測は全枝の全読みではなく、相手の選択がモデルと異なる場合の結果や勝利を保証しない。
- 合法手と着手確定は実対局と共有する。全滅手禁止は味方を含む各継続色に適用し、脱落色を保護しない。手番は着手後のエンジン状態から取得する。自動パスを仮の着手や固定交互の手番へ置換せず、味方・本人の連続手番も扱う。探索で投了・通信切れ・時間切れを仮定しない。
- 通常探索は全根候補を1手進めて評価し、反復深化する。採用設定は最大6着手、総思考量65536単位、内部節点の軽い配置評価の上位6候補とする。並べ替え時だけ合法手数の再生成を省き、探索した局面の評価には合法手数を含める。根候補は件数で除外しない。内部の合法な角への着手と唯一の合法手は上位6件の外側でも残す。すべての着手が石を返すため、返す手を一律に探索延長・候補制限除外の対象にしない。
- 思考量は候補の着手確定1回につき1単位、合法候補生成1回につき1単位と、走査した空きマス8件ごと1単位、静的評価1回につき1単位を計上する。評価内で合法候補を生成するときも計上する。全色の合法手数は石数と1回の空点走査を共有し、着手後盤面を生成せずに数える。この共有生成も1回と空点8件ごとの単位を計上する。予算は各作業の前に確認し、公開入口で最初の合法手を確保するための1回の盤面走査は診断へ別に記録する。同期計算中の時刻による打切りは使わない。
- 予算到達時は最後に全根候補を評価し終えた深さの結果を返す。1手評価も完了しなければ評価済みの最良合法候補、未評価なら最初の合法候補を返す。同じ評価の候補は元の上から左への列挙順で決め、並べ替え順やキャッシュの有無で変えない。
- 空き6マス以下では、通常探索に先行して候補幅を制限しない終局までの探索を行う。全枝の結果、またはαβで必要な範囲を確定した場合だけ全読み完了と扱う。同じ思考量上限を使い、未完了ならその事実を診断へ記録して通常探索の完了結果または合法な代替手を返す。Maxⁿの全読みは各相手が本人の評価を最大化するモデルであり、相手全員の共謀に対する勝利保証とはしない。
- シングルスの終局評価は順位を最優先し、同順位なら本人の最終石数を比較する。初期スコアは1位1000000、2位0、3位-1000000、4位-2000000に本人の石数を足す。同率順位は同じ順位スコアを使い、脱落者に石数を足さない。ダブルスは勝利1000000・引分0・敗北-1000000に自チームと敵チームの石数差を足す。通常終局以外で石数差を定義できない場合は勝敗スコアだけを使う。
- 途中の静的評価は、各色の石数・合法手数・角・角から同色で連続する辺の石・空点に隣接する石・空き角の近傍の石を使う。辺の安定評価は角から保証できる範囲に限り、角との重複と2方向からの二重計上を除く。その他の辺を一律に安全と扱わない。空点に8近傍で隣接する石は各石1回だけ数える。
- 空き角の斜め隣（Xマス）と辺方向の隣（Cマス）を特徴として数え、下表の係数で評価する。採用設定ではXマスを減点し、Cマスの係数は0とする。角が埋まったら、その角についてのX/Cマスの計上を解除する。配置による減点は合法な角取得の保証ではなく、探索で相手の実際の角取得・全滅禁止まで確認する。

採用した静的評価の係数は次のとおり。初期係数と調整結果は [採用判断](../four-reversi-ai.md) に記録する。盤上の石数が24以下を序盤、25〜48を中盤、49以上を終盤とする。安定した辺の石に角は含めない。

| 特徴1件当たり | 序盤 | 中盤 | 終盤 |
| --- | ---: | ---: | ---: |
| 本人の石 | 1 | 1 | 1 |
| 本人の合法手 | 3 | 3 | 3 |
| 本人の角 | 25 | 25 | 25 |
| 角から保証できる同色の辺の石 | 5 | 5 | 5 |
| 空点に隣接する本人の石 | 0 | 0 | 0 |
| 空き角のXマスの本人の石 | -5 | -5 | -5 |
| 空き角のCマスの本人の石 | 0 | 0 | 0 |

- シングルスは本人の特徴評価から他の継続色の特徴評価の平均を引く。脱落色は平均から除外し、確定した脱落順位は上記の終局スコアを使う。ダブルスは味方2色の特徴評価の合計から敵2色の合計を引く。途中評価は絶対値100000未満に収め、終局順位・勝敗の差を静的係数で逆転させない。
- キャッシュは通常探索と終局予測を合わせて1回の選択内・最大2048件とし、盤面・モード・手番・脱落順・連続パス・残り深さ・全読みと通常探索の区別を含める。αβで打ち切った境界値を完全な評価として再利用しない。予測の評価値と選択手は別のキャッシュへ保存する。探索統計・キャッシュはルール状態、通信、保存棋譜へ追加しない。診断は通常探索の完了深さ・中断、予測した根候補数・仮対局着手数・全候補の予測完了・選択の採用元を区別し、予測完了を全読み完了として報告しない。
- 初期係数と探索設定は調整用測定で比較できる。通常探索の処理量512／1024／2048／4096／16384／32768／65536／131072／262144、最大深さ4／6／8、内部幅6／8／12を候補とし、既定値の変更は理由・棋力・性能・重要問題の結果とともに採用コミットでこの正本へ反映する。全読みの対象を空き4マスから増やす場合も同様とする。2026-10-11の追加承認で、棋力・性能基準を維持したまま処理量の比較上限を4096から262144へ拡張した。モード・勝敗・同点時の選択順・受入基準は調整で変更しない。
- Workerは四人リバーシのLv1・Lv2ともAlarmで選択結果を保存し、次のAlarmで期限と選択元の局面を再確認してから確定する。最低2秒・思考時間の計時・期限優先を維持する。通常GET・WebSocket処理では探索・保存選択の適用を起動しない。局面の照合は内部情報で行い、公開のRoom・着手コマンドへrevisionを追加しない。

上限は処理量の制限であり、実行時間の保証ではない。上級者相当の棋力や本番速度は、別途実測なしに認定しない。

### 色の割り当てと表示

- 対局開始ごとに参加者を黒、白、赤、青へランダムに割り当て、黒を初手とする。再戦時も改めて割り当てる。
- 初回待機中は初期盤面を表示する。終局後は同じ部屋で再戦を待ち、前局の最終局面を選択した棋譜モードに入る。棋譜では開始局面・着手・自動パス・投了・退室・時間切れ・通信切れによる脱落を順に確認でき、着手番号は石を置いたときだけ増やす。待機中は石を置く操作と合法手のマーク表示を無効にする。前局の結果は「結果」ボタンから確認でき、棋譜と結果は次の対局開始まで保持する。再戦の開始条件はREADMEの共通仕様に従う。
- ダブルスでも参加者へ4色を重複なくランダムに割り当て、黒・赤と白・青をチームとする。
- 待機中・再戦待機中のカードはホストを先頭に、入室した順（CPUは追加した順）で時計回りに配置する。空いた席を詰め、ホスト交代時は後任を先頭にして他の参加者の相対順序を保つ。ルーム内の直前局棋譜では盤面は前局、カードは現在の待機メンバー・準備状態を表示し、前局の担当色は表示しない。
- 対局中のカードは、担当色を黒→白→赤→青の時計回り順で配置する。プレイヤー画面では自分を手前にし、自分の色から同じ循環順で左、対面、右へ配置する。スマートフォンでは手前を左下、左を左上、対面を右上、右を右下に対応させる。待機中も本人を手前にするが、他のカードは入室順で配置する。
- 対局中の観戦画面の初期表示では黒を手前、白を左、赤を対面、青を右にする。本人が現在の対局に含まれない場合も黒を基準にする。対局中の退室・切断・脱落でカードを詰めず、担当色と配置を保持する。待機中の観戦画面はホストを手前にする。
- 保存済み棋譜の閲覧画面の初期表示では、本人を手前（スマートフォンでは左下）にして、担当色を黒→白→赤→青の時計回り順に配置する。保存された開始時の席番号はホストの識別に使い、表示順には使わない。盤面とカードの石数・脱落表示は選択局面に追従し、未来の脱落を表示しない。脱落者の石数は表示せず、担当色は残す。最終局面のシングルスの順位は保存結果を使い、ダブルスの勝敗は「結果」から確認する。通信・閲覧資格・操作制限はREADMEの保存済み棋譜の仕様に従う。
- 盤面自体には担当色による方向差を設けない。観戦と保存済み棋譜では閲覧者が盤面とカードの配置を時計回り90度ずつ回転できる。表示だけを回転し、基準座標・担当色・棋譜の座標は変えない。参加者の対局画面と、参加者がルーム内で見る直前局の棋譜では回転操作を表示しない。
- 対局中はプレイヤーと色の対応を保持する。
- 直前に着手したマスをオレンジの枠で表示する。投了・脱落・自動パスでは枠を移動させず、次の着手で更新する。自分の手番で着手できるマスには丸い点を表示する。初回待機中の初期盤面ではどちらも表示しない。棋譜モードでは選択した局面の直前の着手枠を表示し、合法手の点は表示しない。

### 初期配置

座標は、盤を正面から見て上から下を行 `1`〜`8`、左から右を列 `A`〜`H` とする。

| 色  | 初期位置      |
| --- | ------------- |
| 黒  | `D3 E4` |
| 白  | `D5 E6` |
| 赤  | `D4 C5` |
| 青  | `F4 E5` |

`K = 黒、W = 白、R = 赤、B = 青` とすると、初期盤面は次のとおりとなる。

........
...K....
...RKB..
..RWB...
....W...

### 石を置く条件と返し方

- 空きマスに石を 1 枚置き、縦、横、斜めのいずれかの方向で、1 枚以上の他色の石を自分の石で挟める手だけを候補手とする。
- 1 方向の中に複数の他色が連続していても、その列の先に自分の石があれば、間にある石をすべて自分の色へ返す。
- 複数方向で挟んだ場合は、該当するすべての石を同時に返す。
- 置いた石自身は、全滅手の判定を含む石数の計算に加える。

### 全滅手の禁止

- 候補手を適用した結果、自分以外のいずれかの継続中のプレイヤーの石が 0 枚になる場合、その手を全滅手として禁止する。
- 石を置いた後、全方向の石を返し終えた盤面を使って判定する。
- 1 手で複数人の石が 0 枚になる場合も禁止する。
- 全滅手は合法手として数えない。
- 脱落済みの色は保護対象に含めず、その石が 0 枚になる手を許可する。

### パス

- プレイヤーが自分の意思でパスすることはできない。
- 手番開始時に全滅手を除く合法手を判定し、合法手が 1 手もない場合に限り、システムが即座にその手番をパスする。
- 自動パス中は、そのプレイヤーの持ち時間を動かさない。
- 自動パスは着手数として数えず、対局画面で通知する。
- 通信切れからの復帰待ち中でも、合法手がなければ通常どおり自動パスする。
- 誰かが合法手を指した時点で、連続パス数を 0 に戻す。

### 通常の終局条件

- 盤がすべて埋まった時点で終局する。
- 盤に空きマスが残っていても、継続中の全プレイヤーが 1 回ずつ連続して自動パスとなった場合は終局する。途中離脱がなければ、黒、白、赤、青の 4 色連続パスとなる。
- 全滅手は禁止されるため、通常進行中にいずれかの色が 0 枚になったことを終局条件にはしない。

### 通常終局時の順位と勝敗

- シングルスは、終局時の石数が多い順に順位を決める。
- 石数が同じプレイヤーは同順位とし、その人数分だけ次の順位を飛ばす。例: 20、20、15、9 枚の場合は 1 位、1 位、3 位、4 位とする。
- ダブルスは、黒・赤チームと白・青チームについて、チーム 2 人の石数の合計が多い側を勝者とする。
- チーム合計が同じ場合は引き分けとする。
- 対局終了時、シングルスでは順位、ダブルスでは勝敗を表示する。石数は最後まで在籍したプレイヤーについてのみ表示し、脱落者の石数は表示しない。

### 投了と脱落時の処理

- README の共通仕様で定めた投了・脱落には、以下のゲーム固有の敗北・順位処理を適用する。
- シングルスでは、脱落者をその時点で未確定の最下位とし、その色を以降の手番から除外する。4 人継続時の脱落者は 4 位、3 人継続時は 3 位、2 人継続時は 2 位となる。
- 脱落色の盤上石は除去せず、通常どおり挟んで返せる石として残す。その色の石が後から 0 枚になってもよい。
- 脱落時点の石数は保持しない。
- 手番外のプレイヤーが脱落した場合、現在の手番は変更しない。手番中のプレイヤーが脱落した場合は、色順で次の継続中のプレイヤーへ手番を移す。
- 残るプレイヤーの順位は通常終局時の石数で決定する。継続中のプレイヤーが 1 人になった場合は、その時点で 1 位として終局する。
- 連続パスによる終局判定では脱落色を飛ばし、継続中の全プレイヤーが連続して自動パスした場合に終局する。
- ダブルスでは、1 人が脱落した時点でそのチームの敗北として終局する。

### 引き分けとダブルスの相談

- 四人リバーシには、プレイヤーによる引き分け提案機能を設けない。
- シングルスで石数が同じ場合は同順位として扱い、引き分け結果とはしない。
- ダブルスで両チームの合計石数が同じ場合に限り、引き分けとする。
- ダブルスでは共通チャットでの味方との相談を許可し、チーム専用チャットは設けない。

### 対局中に保持するルール状態

- 対局モードとダブルスのチーム
- プレイヤーと黒、白、赤、青の対応
- 盤面（継続中のプレイヤーの石数は盤面から算出する）
- 現在の手番、脱落順、連続自動パスした色（継続色は脱落順から算出する）
- 直前の着手座標（初期盤面はなし）
- 確定順位、最後まで在籍したプレイヤーの終局時の石数、勝敗、終局理由

## 決定経緯

以下は TetraBoard のルールを選択した経緯を残すための参考情報である。

### 優先度 A: ゲームの骨格

#### FR-001 対局モードとチーム

- 案 A: シングルスとダブルスの両方を採用し、ダブルスは黒・赤対白・青とする。
- 案 B: 当面はシングルスだけを採用する。
- **決定: 案 A。シングルスとダブルスを採用し、ダブルスは黒・赤対白・青とする。**
- ダブルスでも味方を含むすべての他色を通常どおり挟んで返し、チームは主に勝敗集計へ適用する。

#### FR-002 終局条件

- **決定: 盤がすべて埋まった場合、または継続中の全プレイヤーが連続して自動パスとなった場合に終局する。**
- 全滅手は禁止されるため、石が 0 枚になったこと自体を通常の終局条件にはしない。

#### FR-003 順位、勝敗、同数

- **決定: シングルスは石数順とし、同数なら同順位として次の順位を飛ばす。**
- ダブルスはチーム 2 人の合計石数で勝敗を決め、同数なら引き分けとする。
- 結果画面では、最後まで在籍したプレイヤーの石数のみを表示する。

### 優先度 B: 全滅手とパスの境界

#### FR-004 ダブルスにおける全滅手

- **決定: 味方を含む「自分以外の継続中の誰か」が 0 枚になる手を禁止する。**
- チーム合計ではなく、継続中の各プレイヤーの石数で全滅を判定する。脱落色は保護しない。

#### FR-005 合法手探索と連続パス

- **決定: 通常の挟み条件を満たしても、全滅手になるマスは合法手一覧から除外する。**
- 全滅手しか候補がないプレイヤーは、合法手なしとして即座に自動パスする。
- 自動パス中は持ち時間を動かさず、着手数には含めず、対局画面で通知する。
- 誰かが合法手を指した時点で連続パス数を 0 に戻し、その後、継続中の全プレイヤーが連続して自動パスになったとき終局する。

### 優先度 C: 色の表示と脱落時の扱い

#### FR-006 プレイヤーへの色の割り当て

- **決定: 対局開始ごとに参加者を 4 色へランダムに割り当て、黒を初手とする。**
- 再戦時も改めて割り当てる。
- ダブルスでは対局開始時に色をランダムに割り当て、黒・赤の組と白・青の組をチームとする。
- 対局中と保存済み棋譜は黒→白→赤→青の時計回り順で表示する。プレイヤーと本人用の保存済み棋譜は本人、公開棋譜は黒、対局中の観戦は黒を手前にする。待機・再戦待機は入室順とし、プレイヤーは本人、観戦はホストを手前にする。
- 対局中はプレイヤーと色の対応を保持する。

#### FR-007 脱落時の順位と盤面

- **決定: 共通仕様による投了・脱落に、四人リバーシ固有の順位・敗北処理を適用する。**
- シングルスの脱落者はその時点で未確定の最下位とし、その色を以降の手番から除外する。
- 脱落色の石は通常どおり返せる状態で盤上に残し、全滅手の保護対象から除外する。
- 脱落時点の石数は保持せず、結果画面にも表示しない。
- 継続中のプレイヤーが 1 人になったら、そのプレイヤーを 1 位として終局する。
- ダブルスは 1 人が脱落した時点で、そのチームの敗北として終局する。

#### FR-008 引き分け提案とダブルスの相談

- **決定: 四人リバーシには引き分け提案機能を設けない。**
- ダブルスの通常終局時にチーム合計が同数なら引き分けとするが、合意による引き分けは扱わない。
- ダブルスでは共通チャットでの相談を許可し、チーム専用チャットは設けない。
