# Notion のタスク管理

タスクは Notion のデータベース「TetraBoardタスク管理」だけで管理する。GitHub Issues には起票しない。操作は Notion の MCP ツール（fetch、query-data-sources、create-pages、update-page）で行う。

- データベース: https://app.notion.com/p/4172355fed848091a6eede97df3b86b2
- データソース: `collection://4172355f-ed84-80eb-9e95-000b05a7bd3d`
- ロードマップ: https://app.notion.com/p/4172355fed84814da64fd9a71630acc7

スキーマは変わりうる。プロパティ名と選択肢は、書き込む前に fetch で確かめる。

## プロパティの使い方

| プロパティ | 使い方                                                           |
| ---------- | ---------------------------------------------------------------- |
| ID         | 自動採番。`TB-123` の形でブランチ名と PR タイトルに入れる        |
| ステータス | 下の流れに従う                                                   |
| フェーズ   | 改善計画のフェーズ。凍結中も続ける不具合修正と法務対応は「保守」 |
| モジュール | 触る範囲。複数可                                                 |
| 優先度     | 高・中・低                                                       |
| 工数レベル | 1（数十分）〜5（数日、分割が必要）                               |
| 依存タスク | 先に終わっている必要があるタスク                                 |
| PR         | PR の URL。PR を作った時点で入れる                               |
| 説明       | 一覧で読む 1〜2 文の要約。詳細は本文に書く                       |

## ステータスの流れ

| ステータス  | 意味                                       | 変える時点                                   |
| ----------- | ------------------------------------------ | -------------------------------------------- |
| Backlog     | 置いてあるだけ。設計も分解もまだ           | 起票時の既定                                 |
| Todo        | 設計と受け入れ条件が本文にあり、着手できる | 設計を書き終えたとき                         |
| In Progress | 実装中                                     | Codex を呼ぶ直前、または自分で書き始めるとき |
| In Review   | PR があり、開発者の承認待ち                | PR を作ったとき                              |
| Done        | マージ済み                                 | マージを確かめたとき                         |
| Cancelled   | やらないと決めた                           | 理由を本文に 1 行書いてから                  |

## 起票と更新の手順

1. 起票の前に、同じ内容のタスクがないか query-data-sources で検索する。
2. 工数レベル 5 のタスクは、着手前に 1 PR で終わる大きさへ分ける。
3. Todo にする前に、本文を下の形で書く。Codex に渡す依頼文はこの本文から作るので、本文だけで作業できる内容にする。
4. ステータスを変えるたびに、Notion を更新する。PR を作ったら PR の URL を入れる。

## 本文の形

```markdown
## 背景

なぜやるのか。関連する ADR や仕様書の場所。

## やること

変更する範囲と、変更後の振る舞い。触ってよいファイルやパッケージ。

## 受け入れ条件

- 確かめられる形で書く（どのテストが通る、どの画面で何が見える）。

## やらないこと

範囲外にするもの。

## 未決

開発者の判断が必要な点。なければ「なし」。
```

未決が残っているタスクは Todo にしない。開発者に確認してから進める。
