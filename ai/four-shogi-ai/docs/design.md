# 独立Python四人将棋AIの設計契約

2026-11-06に開発者がフェーズ01のレビュー案を承認し、既存AI計画の廃止・全面置換を指示しました。この文書は新計画の契約です。ゲームの仕様正本は[四人将棋ルール](../../../docs/rules/four-shogi.md)、進捗は[Notion](https://app.notion.com/p/4102355fed8480f089c1e9f3df630c43)で管理します。

## 目標・初期スコープ

人間が4人そろわないときもランダムマッチを成立させ、プレイヤーの棋力に合う複数の棋風を用意します。`ai/four-shogi-ai` でPythonルールを独立実装し、評価・探索・学習モデルを新規開発します。TSエンジンは比較用で、Pythonの通常実行から呼びません。

初期対応はシングルス・TetraBoard rulesVersion 1・三人攻撃禁止ON/OFFです。OFFで基礎遷移を照合してからONの履歴・例外へ進み、両方の合格をルール互換の条件にします。ダブルスは拒否します。連盟規則との一致や棋力を、この互換性から認定しません。

フェーズ01は環境、入力データ契約、状態・結果・ルールAPIの設計、TSとの比較方法までです。02では第1段階のOFFに続けて、第2段階でONの攻撃履歴・例外・反復キーを実装しました。自己対局、評価・探索、モデル、オンラインAPIは後続です。未実装APIの空の実装は公開しません。

## 交換データと版

初期の交換入力は既存 `AnalysisReplayInput` と同じ形式です。参照基準はdevelop `4bd07132f8bc2f67ac40a33308db6b14bcfd56d1` の [TS入力検査](../../../packages/four-shogi/src/analysisInput.ts)、[状態型](../../../packages/four-shogi/src/types.ts)、[再生](../../../packages/four-shogi/src/replay.ts)です。比較を実行するときは実際のTS/Pythonコミットも記録します。

| 項目                        | 値・検証                                                         |
| --------------------------- | ---------------------------------------------------------------- |
| schemaVersion               | 1。交換形式の版                                                  |
| ruleProfileId               | `tetraboard-four-shogi-singles-v1`                               |
| rulesVersion                | 1。別実装を作るだけではゲームのルール版を変えない                |
| initial                     | mode=`singles`、players、threePlayerAttackProhibitedを必須とする |
| players                     | south/west/north/eastに異なる空でない文字列。対局ごとの不透明ID  |
| threePlayerAttackProhibited | booleanを明示。既定ONを入力検査で補わない                        |
| events                      | `{index, event}` の配列。indexは0から連続                        |
| eventOffset                 | 0〜提供イベント数。省略時は全件。着手数ではなく適用件数          |

未知フィールド・不足項目・未知版・未知プロフィール・ダブルス・不正なイベントを拒否します。eventOffsetより後のイベントも形状を検査します。JSONの整数値1と1.0は同じ意味で受理し、booleanは数値として受理しません。入力はJSONへ変換可能なデータを前提とします。

`parse_replay` はfrozen dataclassとtupleへ変換し、入力の可変dict/listを保持しません。`replay_to_dict` は独立した交換用dict/listを返します。直接dataclassを構築する呼出し元は型と不変条件を満たす責任を持ち、外部入力は必ずparse_replayを通します。形式検証では手番違い・盤面上の違法手・終局後操作を判定しません。

失敗は `ReplayInputError(code, message, event_index)` です。codeは `invalid_input / unsupported_version / unsupported_profile / unsupported_mode / non_contiguous_events / invalid_offset`。イベントの内容拒否と欠番では0始まりの位置を返します。説明文の一致は互換条件にしません。複数同時違反の全てを列挙する契約ではなく、TS入力検査と同じ順序で最初の失敗を返します。

## 着手・イベント

| 種別           | JSONの内容                                                                               |
| -------------- | ---------------------------------------------------------------------------------------- |
| 移動           | `action: {type: "movePiece", from: {x,y}, to: {x,y}, promote: boolean}`                  |
| 打ち駒         | `action: {type: "dropPiece", pieceKind: "rook" / "gold" / "silver" / "pawn", to: {x,y}}` |
| 着手イベント   | `{type: "action", side, action}`                                                         |
| 外部脱落       | `{type: "eliminate", side, reason: "resigned" / "left" / "timeout" / "disconnected"}`    |
| 引分提案・取消 | `{type: "drawProposal", side, proposed: boolean}`                                        |

座標は南を手前にした左上(0,0)〜右下(8,8)、盤配列はboard[y][x]。実方向を維持し、表示の回転を反映しません。王・角・桂・香の打ち駒、パス、自動詰みイベントの入力は存在しません。詰み・合法手なし・千日手・合意終局はルールが導出します。

外部脱落はTetraBoardが確定したイベントを受け取ります。投了は自手番のみ、退室・時間切れ・通信切れは手番外も扱います。引分提案・取消は自手番の生存者のみで、手数や反復回数を増やしません。これらの意味検証はON／OFF共通のルール層で実装済みです。

## 完全なルール状態

内部表現の変更は可能ですが、次の情報を欠落させません。盤面だけのスナップショットや表示frameを実戦の完全状態として受理しません。

| 状態       | 内容・不変条件                                                                            |
| ---------- | ----------------------------------------------------------------------------------------- |
| 設定       | rulesVersion=1、singles、三人攻撃禁止、4方向の参加者対応。対局中に設定を変えない          |
| 盤         | 9×9。駒ID・所属・king/rook/gold/silver/pawn・成り。裏王は脱落者の王として識別             |
| 持ち駒     | 方向別・rook/gold/silver/pawnの非負整数。脱落時に破棄。表示用の破棄枚数をルールへ混ぜない |
| 進行       | playingなら生存する実手番とresult=null、finishedならturn=nullと結果                       |
| 脱落       | 方向・理由・同時脱落群・確定順位。生存者は脱落一覧から求める                              |
| 攻撃       | 攻撃者・標的・分類・標的駒ID・解除待ちの方向。各人の実際の着手で更新                      |
| 取り返し   | 方向別の対象マス。最初の自手番の免除を再現する                                            |
| 駒の同一性 | 移動・成りではID保持、捕獲で盤上ID終了、打ち直しは新ID。次のIDも状態に保持                |
| 引分       | 生存者の提案集合。千日手キーには含めない                                                  |
| 反復       | 確定局面キーと全出現数。初期局面を1回と数え、4回で引き分け                                |
| 直前手     | 着手者・action・移動駒・捕獲駒と着手数。提案・外部脱落で着手数を増やさない                |

順位は同時詰みの群を固定してから更新します。結果は `last_player / no_survivors / repetition / agreement` と4方向のstandings（side, rank）です。終局順位から探索報酬を勝手に確定せず、単独勝ち・同率1位を識別できる情報を残します。

遷移は通常合法手 → 三人攻撃制限 → 着手確定 → 全王の詰み集合 → 一括脱落 → 通常終局 → 王手優先の実手番 → 合法手なしの脱落 → 継続時の合意確認・反復記録／判定という正本の処理を再現します。詳細と優先関係はルール正本を参照し、固定4手の巡回や手番予約で代用しません。

## ルールとAIのAPI

| 入口                              | 契約                                                                 |
| --------------------------------- | -------------------------------------------------------------------- |
| create_initial_state(options)     | 固定された担当方向から初期状態を返す。乱数・接続は扱わない           |
| legal_actions(state)              | 現在の実手番の合法手。終局時は空。順序を仕様上の強さに使わない       |
| apply_event(state, event)         | 成功時は新状態・捕獲・新しい脱落、拒否時は理由。入力不変             |
| replay(input)                     | initialからeventOffsetまで再実行し、完全状態か失敗イベント位置を返す |
| choose_action(state, budget, rng) | 合法手と診断を返す。詳細な予算・取消・結果契約は探索フェーズで確定   |

4つのルールAPIはON／OFFに対応し、`choose_action` は未実装です。第1段階のON実行拒否を撤去し、三人攻撃による着手拒否には `three_player_attack` を返します。JSONの版と入力形式は変更しません。

`State` と成功・失敗結果はfrozen dataclassです。`legal_actions` はtuple、`apply_event` は `TransitionSuccess`（`ok=True`、state・captured・eliminations）または `TransitionFailure`（`ok=False`、reason）を返します。提案も同じ成功形式で、捕獲なし・脱落なしです。`replay` は検証済み `ReplayInput` を取り、状態か `ReplayExecutionError`（code=`event_rejected`、event_index、reason）を返します。Pythonの型付き値を直接構築する呼出側は型と不変条件を守り、外部JSONは必ず `parse_replay` に通します。

入力の形状エラーとルールによる拒否を区別します。拒否で盤面・履歴・実手番・手数を変えません。Python側で合法と判定した手も、オンライン統合ではTetraBoardが再検査して確定します。

## 差分比較と再現

01では再生入力の形式検査を実TS入力検査器と比較します。02で以下のON／OFF比較を実装しました。

1. TS/Pythonのコミット・交換形式／ルール／比較器の版・ON/OFF・初期値・イベント列を記録する。同じseedだけでは言語間の乱数一致を仮定しない。
2. 初期局面と各イベント前後で合法手集合を比較する。移動元・移動先・成り／駒種のキーでソートし、列挙順は無視する。
3. 盤・持ち駒・手番・脱落群／理由／順位・結果・直前手・手数・提案・攻撃／取り返し履歴・反復辞書全体を比較する。
4. 駒IDは現在の盤上駒への対応に正規化する。反復キーは構造へ戻して比較し、作用する攻撃履歴を落とさない。TSのstateHashの一致だけを合格条件にしない。
5. 最初の不一致のイベント位置、フィールドのパス、両側の値、完全な再生入力を保存する。生成例の失敗は縮小し、固定回帰例へ追加する。

固定例は初期36枚・4方向・捕獲／成り／打ち駒・打ち歩詰め／裏王・王手優先／同時詰み・外部脱落4種・合法手なし・千日手・提案／取消／全員合意・拒否後の不変を含めます。ONは攻撃4分類、応手／取り返し／同一標的免除、実着手による解除、再攻撃、一手撃破、標的別の選択肢がない例外、脱落後の解除を含みます。

正本とTSに差があれば、最小再現と根拠を示して開発者へ確認します。TSの誤りをPythonへ複製して合格にしません。ルール修正時は既存保存棋譜の互換性も確認します。
