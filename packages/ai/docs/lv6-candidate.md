## 探索と識別

ゲームの裁定は[四人リバーシのルール正本](../../../docs/rules/four-reversi.md)、表示と操作は[widget仕様](../../../README.md#ローカルai解析widget)に従います。

| 項目         | 既存Lv5                                  | Lv6（測定時は候補A） |
| ------------ | ---------------------------------------- | -------------------- |
| profile ID   | `lv5-v1`                                 | `lv6-candidate-a-v1` |
| 最大試行数   | 2048                                     | 8192                 |
| 最大着手適用 | 65536                                    | 262144               |
| 時間上限     | 2000ms                                   | 2000ms               |
| 探索         | 既存の多人数MCTS、一様rollout、係数1.414 | 同じ                 |
| 報酬         | 単独1位だけ1、他は0                      | 同じ                 |
| 根候補順     | 訪問数・本人の単独1位率・行列順          | 同じ                 |

試行数は開始回数の上限で、実際に完走した回数は診断へ記録します。着手適用・時間上限が先ならその時点で終了し、未完走試行を参考評価へ加えません。2秒は協調停止の探索上限で、HTTP応答の厳密なSLAではありません。時間上限付きの結果は再現性保証外です。

候補は `configs/local-analysis-profiles-v1.json` に置き、公開Serviceの `profiles-v1.json` の5件と上限を維持します。候補のhashは時間上限を含むconfigを再帰的キー順にしたJSONのSHA-256です。Lv5は既存hashと既存探索を維持し、従来どおりローカルで2秒上限を追加します。応答ではprofile ID・hash・実効予算・要求ID・局面を照合します。任意profile・seed・予算は要求できません。

widgetは初期選択をLv5とし、タブ内のcontrollerで選択を保持します。ページ再読み込みで初期化します。切替時は現在要求を取り消し、世代を更新して候補を消し、本人手番なら新しいprofileで同じ局面を自動解析します。相手手番は手動解析とし、切替前の応答を表示しません。表示名は「Lv6」です。内部profile ID・設定hashは本評価と同じものを使用します。

## 予備測定

リポジトリルートから明示的に実行します。

```sh
bun run --cwd packages/ai study:lv6:preliminary
```

このコマンドはrelease Benchmarkをビルドし、予備seed `6000000`・`6000001`、焦点席「候補A・Lv5」、残り2席「Lv1・Lv2」「Lv3・Lv3」「Lv4・Lv5」、4回転・1並列で計24局を実行します。Lv5と候補Aはwidgetと同じ2秒上限を使い、同席のLv5にも同じ設定を使います。予備対局全体は最大30分で中断し、終了・中断時は子プロセスを残しません。本評価を開始する経路はありません。

出力先はGit対象外の `results/local-analysis/preliminary-<時刻>-<binary hash>/` です。manifestへソースのファイル別hash・binary hash・commit・dirty状態・profile/hash・実効予算・seed・席順・実行環境を保存し、実行binaryをコピーします。各seedの全12局とsummaryが完了した場合だけ完了記録を残します。失敗・中断は部分ログと `failed.json` を保持し、成功・採用扱いせず、自動再実行しません。

集計は元slot 0・1の焦点席だけを使い、残り席の同じLv5を合算しません。平均順位、単独・同率を含む1位率、相手構成別成績、判断時間p95・最大、時間中断数、試行・着手適用、プロセス最大RSS・CPU時間を保存します。時間見積もりは実測の1局平均壁時計時間×2304局とし、計画用に30%の余裕も併記します。この余裕は統計的な区間ではありません。予備は4回転なので、全24席順の局面差や端末負荷による誤差があります。

Benchmarkの乱数は既存どおり、対局seedと元slotのstreamを使って対局中継続します。widgetは各要求でseed 0・stream 0のAgentを新規生成します。この測定は同じ探索設定のCPU比較であり、widgetの各要求と同じ乱数列の再生ではありません。Benchmarkの通常4人開始・脱落なしの棋譜には既存のルール識別子v1を使い、Engine版を併記します。widgetの脱落後はルール識別子v2／局面版2のAPI検証で別に確認します。

- 今回は1比較・本評価1回なので95%区間を使います。10比較向けの99.5%区間をそのまま流用しません。候補追加・再調整・再評価の際は、未使用seedと多重比較の扱いを先に決めます。
- 途中の好成績で終了・採用せず、失敗・未完了・精度不足は保留にします。予備結果を本評価へ合算しません。平均順位の優位性を人間相手の棋力・クラウド性能へ読み替えません。
