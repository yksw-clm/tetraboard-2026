# Rust AI基盤の四人リバーシルール

確認元はTetraBoard developの`5c39ead7e5335a7a2da32aeec54f9ab209ff4275`です。正本は[四人リバーシルール](../../../docs/rules/four-reversi.md)、比較対象は`packages/four-reversi/src/engine.ts`と`moves.ts`およびそのテストです。この文書はRust実装の対応範囲を示し、ゲームの正本を新設するものではありません。

## 対応する確定ルール

対象は4人シングルスです。フェーズ0〜3は脱落なしを対象とし、フェーズ4で既存の脱落規則へ対応しました。脱落部分の確認元はPhase3の親コミット`f032b937d04f31c7316ece980294cf6883d36140`と、その時点のTypeScriptルール・正本です。盤は8×8、座標は左上A1が`{ x: 0, y: 0 }`、右下H8が`{ x: 7, y: 7 }`です。色と手番順は黒→白→赤→青、初手は黒です。以下の記号は黒K・白W・赤R・青B・空点`.`です。

```text
........
........
...K....
...RKB..
..RWB...
....W...
........
........
```

初期の各色は2枚、盤上8枚です。空点へ1枚置き、縦横斜めの8方向で自分の石に挟まれた1枚以上の他色をすべて返します。同じ列の他色が混在していても返し、複数方向は同時に適用します。辺を越える返しや、空点で途切れた列の返しはありません。

全方向を返した結果、継続中の他色が0枚になる手は禁止です。複数色を同時に0枚にする手も禁止し、合法手一覧から除外します。着手による盤上石数の増加は1枚です。

自発的なパスはありません。着手後、色順に合法手を確認し、合法手のない色を即座に自動パスします。誰かの着手で直前の連続パスを解除します。3色がパスして本人に戻る場合もあります。パスは着手数に含まず、直前の着手座標も変更しません。

満盤なら直ちに終局します。空点が残っていても継続中の全色が連続パスしたら終局します。満盤の場合は追加のパスを作りません。終局後の手番はnull、合法手は空、着手は`game_finished`で拒否します。通常初期局面からは最大56着手です。

得点は終局の石数です。自分より石数の多い人数に1を加えた順位とし、20・20・12・12枚なら1・1・3・3位です。同順位の表示順は黒→白→赤→青の相対順を維持します。シングルスは同順位として扱い、引き分け結果にはしません。

不正手は、終局済み→範囲外→占有済み→反転なし→他色の全滅の順に拒否理由を返します。成功・失敗とも元の局面を変更しません。

## 脱落への対応

`State::eliminate(color)`は時計・投了・通信切れなどの外部イベントを受けます。原因の判定はWorkerの責務です。脱落順を保存し、盤上の石は残したまま手番と全滅保護の対象から除きます。非手番の脱落では手番を変えず、手番の脱落なら次の継続色から合法手を探します。連続パスから脱落色を除き、着手時だけパスをリセットします。継続者が1人なら`last_player`で終局します。

通常終局では継続者を石数順・競技順位で並べ、脱落者を脱落の逆順で後ろへ置きます。脱落者のstoneCountは省略します。重複脱落は`already_eliminated`、終局後は`game_finished`で拒否し、入力を変更しません。固定`elimination-v1.json`の6ケースを両言語で比較します。

## 状態とバージョン

Engineは盤面、現在の手番、着手数、直前の着手、連続パス色、終局理由と4色の順位・石数を保持します。参加者ID、席の抽選、時計、通信、対局保存、レーティングは保持しません。Benchmarkでは各色に1つずつAgentを割り当て、その対応をログへ残します。

`four-reversi-singles-v1`は脱落なしの対応範囲と確認元を表すRust側のルール識別子です。Engine 0.2.0で脱落を含む`four-reversi-singles-v2`を追加し、ServiceのAPI v2では局面版2と組み合わせます。API v1およびAPI v2のルールv1／局面版1は脱落入力を拒否し、旧契約を維持します。既存サービスの通信・保存データへこの識別子を追加したり、既存のルール版を変更したりしません。ランダム対局の計測ログは版1、フェーズ1の設定・比較用ログは版2です。ルール自体は共通です。

## 未実装と未確定の区別

ダブルスの黒赤対白青は既存正本で確定していますが、Rustでは未実装です。投了・脱落後の手番と全滅保護・順位はフェーズ4で対応しました。時計、参加者、棋譜保存、勝敗の最終権限は既存Game Roomに置きます。ダブルスや脱落状態を、脱落なしシングルスへ暗黙に変換しません。フェーズ0〜3の比較Benchmarkは従来どおり脱落なしの完走を測定します。

今回の対象ルールには、調査時点で未確定事項や正本との矛盾はありません。今後発見した不一致は、正本・確認元コミット・固定fixtureを照合し、未確定事項として開発者へ報告します。AI Serviceの通信契約は[フェーズ2](phase2.md)と[フェーズ3](phase3.md)、Lv4・Lv5の採用条件と測定結果は[フェーズ3](phase3.md#benchmarkと採用判定)を参照してください。人間相手の棋力、解析評価指標、学習・推論・ホスティングの採用は未決定です。
