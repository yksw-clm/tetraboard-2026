# フェーズ4.5：CPU評価と実力推定の較正仕様

2026-11-08に承認されたフェーズ4.5-Aで文書化した、未実装のCPU測定・実力推定の仕様です。この較正を[四人リバーシのレート戦](../../../docs/matchmaking.md#四人リバーシのレート戦未実装)に引き継ぎます。

現在の機能は[フェーズ4のランダムマッチ](../../../docs/matchmaking.md)、ゲームの裁定は[四人リバーシのルール正本](../../../docs/rules/four-reversi.md)に従います。[フェーズ3](phase3.md)の測定結果は当時の条件に対する記録として維持します。この較正は四人リバーシ・シングルス・3分切れ負けを対象とします。

ローカルwidget専用のLv6は、このLv1〜5較正の対象へ追加しません。独立した比較計画と採用結果は[Lv6の仕様・測定](lv6-candidate.md)を参照します。

## 評価対象と結果の識別

対象は`configs/profiles-v1.json`の`lv1-v1`〜`lv5-v1`です。比較時点のprofile ID、設定hash、Agent ID、実効探索予算、Engine版、ルール版・局面版、実装コミット、ソース・binary・lockfileのhashを固定します。測定環境のOS・CPU・並列度も保存します。未コミットのソースを測る場合は、コミットだけでなくファイル別hashで内容を識別します。

較正結果は変更不可の較正版で管理し、対象の組合せと有効な測定範囲を保持します。設定・実装・探索予算を変えたCPUは再測定します。profile名やレベル名が同じという理由だけで旧結果を流用せず、未測定の名前に強さを割り当てません。

主な保存情報は次のとおりです。これは後続実装で満たす情報の契約であり、この段階ではCLI・HTTP・DBの形式を変更しません。

| 保存する情報     | 必須の内容                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| 測定manifest     | 対象の識別情報、seed集合、相手構成、元slotと色の対応、実行環境、測定規則版、較正版                     |
| 対局ログ         | 合法手・全着手・パス・最終結果・失敗理由、思考時間・探索量、使用したprofileと実効予算                  |
| 集計結果         | 完了・未完了・失敗件数、累計実行時間、平均順位・順位分布・優勝率、相手構成別・色別成績、区間と判定理由 |
| CPU参照値        | profileの代表μ・運用用σ、色別の推定結果、較正版、識別情報、予測精度、採用または保留の状態              |
| 運用時の対局記録 | 対局由来、集計規則版、較正版、推定方式版、実際のCPU識別情報、代替手使用の有無                          |
| 人間の内部推定   | μ・σ・有効対局数・参照版・最終更新対象。非公開で管理                                                   |

## CPU対局の測定条件

主指標は**平均順位**とし、小さい方を優位とします。1〜4位の順位分布、同率を含む優勝率、単独優勝率、同率優勝率、相手構成別・色別成績、石数を併記します。競技順位方式を維持し、例えば同率1位は1・1・3・4位です。評価の都合で平均順位へ別の順位を入力したり、単独優勝だけを主指標にしたりしません。

5 profileの全10ペアを焦点2席として比較します。ペア内はprofile ID昇順で元slot 0・1へ置き、残り2席は下表の3構成を等しい重みで扱います。焦点席と同じprofileが残り席にもあっても、平均順位差の比較は焦点席だけを使います。

| 構成             | 元slot 2・3 |
| ---------------- | ----------- |
| 弱い側を含む構成 | Lv1・Lv2    |
| 中間の構成       | Lv3・Lv3    |
| 強い側を含む構成 | Lv4・Lv5    |

本測定は元slotの全24順列を使います。同じprofileの席も元slotと乱数streamを区別し、同じ4人対局や席順違いの対局を独立な試行数として統計検定へ足しません。乱数系列・固定予算・棋譜の再現条件は既存Benchmarkに従います。

| 段階     | seed集合             | 席順数 | 計画局数 | 用途                                     |
| -------- | -------------------- | -----: | -------: | ---------------------------------------- |
| 予備測定 | 2,000,000〜2,000,003 |  4回転 |      480 | 実行・記録の確認、所要時間の見積もり     |
| 較正用   | 3,000,000〜3,000,031 |     24 |   23,040 | CPU参照値の作成                          |
| 本評価用 | 4,000,000〜4,000,031 |     24 |   23,040 | 主指標・参照値の評価。参照値を更新しない |

局数は`10ペア × 3構成 × seed数 × 席順数`です。予備測定を含む計画総数は46,560局です。予備測定を本評価へ加えず、本評価用seedで設定を調整しません。再評価では使用済みseedを記録し、未使用の本評価用区間を割り当てます。

### 時間上限と再開

ローカル測定は最大4並列とし、測定・較正・集計の**累計実行時間は12時間まで**です。中断中の時間は除外し、再開時も同じmanifestの累計へ加算します。並列実行中の時間は壁時計で数え、4プロセスのCPU時間の合計と混同しません。速度の採否に使う計測は1並列で別に記録します。

完了単位は1 seed・1比較ペアの全相手構成・全席順とし、manifestが一致する完了単位だけを再利用します。単位が途中のログは部分結果として保持しますが、本評価の区間・採用判定には加えません。中断・時間上限・不足を成功扱いせず、完了数と予定数を示して判定保留にします。予定した本評価用データを完走する前の途中集計で採用しません。時間上限を自動延長したり、結果を見て精度目標を緩めたりしません。

不正手・進行異常・再現性の不一致は0件を必須とします。発生した対局を除外して成功率を出さず、失敗理由と部分結果を保存して、その実行の採用判定を止めます。

### 区間と強弱の判定

再標本化の単位はseedです。1 seedに属する全相手構成・全席順をまとめ、構成を等重みにした焦点席の平均順位差を求めます。AとBの差は`Bの平均順位 − Aの平均順位`と定義し、正ならAが優位です。32 seedブロックを復元抽出する10万回のbootstrapを行います。系列は既存と同じChaCha8方式で固定し、区間用seedを9,500,000、後述の参照値再計算用seedを9,500,001としてmanifestへ記録します。

95%区間は2.5・97.5パーセンタイル、10比較の強弱認定に使う99.5%区間は0.25・99.75パーセンタイルとします。分位点は既存の`study.rs`と同じく、昇順n件の`ceil(n × p)`番目（1始まり・最小1）を使います。bootstrap区間は有限標本の近似として扱い、他の相手集団や人間相手の性能を保証しません。

| 判定     | 条件                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 精度目標 | 平均順位差の95%区間の幅が0.20順位以下                                                    |
| Aが優位  | 精度目標を満たし、99.5%区間の下限が+0.10を超え、3相手構成の点推定もすべて正              |
| Bが優位  | 精度目標を満たし、99.5%区間の上限が−0.10未満で、3相手構成の点推定もすべて負              |
| 同程度   | 精度目標を満たし、99.5%区間全体が−0.10〜+0.10の範囲内                                    |
| 相性依存 | 精度目標を満たすが、相手構成によって差の正負が逆転する                                   |
| 判定保留 | 精度不足、閾値をまたぐ区間、計画の未完了、失敗など、上記で強弱・同程度を認定できない場合 |

レベル名に合わせて判定を並べ替えません。一つの数値に収まらない相性は、構成別の結果とともに保持します。

## 実力推定の方式と参照値

基準実装は[OpenSkill 5.0.1](https://github.com/philihp/openskill.js/tree/v5.0.1)のPlackett–Luceモデルです。[固定版の定数](https://github.com/philihp/openskill.js/blob/v5.0.1/src/constants.ts)、[順位更新](https://github.com/philihp/openskill.js/blob/v5.0.1/src/rate.ts)、[MITライセンス](https://github.com/philihp/openskill.js/blob/v5.0.1/LICENSE)を参照します。Rustが対局を実行し、較正とWorkerの実力推定は同じTypeScriptの計算規則を使う方針です。Aでは依存を追加しません。Workersで利用できない場合や評価未達の場合は採用を保留し、別方式へ無断で変更しません。

| 項目                   | 固定値・扱い                                                          |
| ---------------------- | --------------------------------------------------------------------- |
| 初期平均μ              | 25                                                                    |
| 初期不確かさσ          | 25/3                                                                  |
| β                      | 25/6                                                                  |
| 人間の更新時のτ        | 25/300                                                                |
| オフラインCPU更新時のτ | 0                                                                     |
| その他のオプション     | OpenSkill 5.0.1の既定値に固定                                         |
| 順位入力               | 4人を各1人の参加者として、Game Roomが確定した順位を入力。同順位を維持 |
| 石数差                 | 実力更新への追加加点には使わない                                      |

### CPU参照値の作成

較正用データをseed・比較ペア・相手構成・席順の順に1回走査します。CPUを`profile × 色`の20仮想個体として扱い、各対局の更新前の4個体から同時に更新結果を求めます。同じprofileが複数席にいても別の色の個体であり、最後の席の結果だけで共通profileを上書きしません。

profileの代表μは4色のμの平均です。ヨミの代表μが25になるよう、全profileの代表μを同じ量だけ平行移動します。これはCPU集団内の相対尺度を固定する操作であり、人間の強さを25へ較正した意味ではありません。色別の値も残し、代表値が色による違いを示さない場合の確認に使います。

較正用のseedブロックを2,000回再標本化し、それぞれ初期値から同じ規則で再計算します。復元抽出された回数だけ各seedブロックを複製し、seed順（同じseedの複製は連続）、ブロック内は比較ペア・相手構成・席順の順に並べます。各profileについて正規化後の代表μの標準偏差を求め、**その値と1の大きい方**を運用用σとします。モデル内部の事後σ、運用用σ、平均順位差の信頼区間は別項目として記録し、同じ精度の指標とは表現しません。

運用中のCPU参照値は較正版ごとに固定し、人間との1局ごとに自動で書き換えません。未評価・保留・識別情報の不一致を含む参照値は、可変補充の候補へ加えません。比較ペアが判定保留でも、個別CPUの結果と参照値の予測精度は記録しますが、保留をレベル順の優位性へ読み替えません。

### 参照値の評価

本評価用データでは参照値を固定し、運用時と同じprofileの代表μ・運用用σを使って、2参加者を入力する`predictWin`で相対順位の予測を検証します。Aが上位なら正解値1、同順位なら0.5、下位なら0とし、予測値との二乗誤差を用います。各4人対局内の6比較を平均してから対局・構成・seedを集計し、6比較を6局とは数えません。

基準は常に0.5と予測した場合の同じデータ上の誤差です。同順位では基準誤差も0となるため、基準値を一律0.25とは置きません。改善量は`基準誤差 − 参照値の誤差`とし、seedブロックの10万回bootstrapによる95%区間の下限が0を超えることを、参照値全体の採用条件とします。profile別・構成別・色別の誤差も併記します。未達なら較正済みの扱いを保留します。

4参加者を入力した`predictWin`の値を、そのまま単独優勝確率や対人勝率として表示しません。[固定版の予測処理](https://github.com/philihp/openskill.js/blob/v5.0.1/src/predict-win.ts)と、ゲームでの単独・同率優勝の定義を区別します。

## 人間との較正と採用状態

CPU間の較正と、人間の尺度への較正は別の状態として保持します。初回公開では後者を**暫定**と明示します。開発環境で予備検証を行い、まず組合せを変えずに推定を実行し、その後、本番の実対局で予測と実結果の一致を継続評価します。較正用データの当てはまりだけで人間相手の較正完了を宣言しません。

人間の推定は、レート戦の保存済み結果から更新します。対局IDと推定方式版・較正版を識別して再送でも一度だけ適用します。CPU参照値は固定し、人間側の更新を保存します。投了・時間切れ等はルール正本の確定順位を使います。

CPUが代替手を使った局は、その事実を記録し、CPU較正と人間の内部実力更新から外します。Game Roomが合法な終局として保存した場合の戦績・ランキング・バッジへの反映は維持します。

有効対局数10局未満、またはσがβより大きい人間は、対人の組合せでは暫定参加者として扱います。公開レートの認定は5局です。内部のμ・σは非公開とし、認定中の進捗は本人に表示します。実力値はサーバーで管理し、AI Serviceに渡すのは着手計算に必要な情報です。アカウントの連携・退会は既存の本人資格と保存方針に合わせます。

較正版や方式を更新する場合は版を分け、同じ記録から再計算できる状態を保ちます。公開レートの換算式とランク境界は、CPU較正と開発環境での試験結果をもとに決めます。

## 運用性能と費用の判断基準

性能評価は[レート戦](../../../docs/matchmaking.md#四人リバーシのレート戦未実装)と同じ3分時計・実Serviceで行い、版とprofile hashの一致、合法手、脱落後の進行を確認します。クラウド上の性能はその環境で測定します。

| 確認                       | 採用・公開判断の目標                                                               |
| -------------------------- | ---------------------------------------------------------------------------------- |
| 正常負荷                   | 2同時対局                                                                          |
| warm応答                   | p95が1秒以内                                                                       |
| cold応答                   | p95が4秒以内                                                                       |
| 正常負荷の代替手への退避率 | 1%以下。退避をServiceの成功応答と扱わない                                          |
| 過負荷                     | 4・8同時対局で、不正手・二重進行・保存破損なく対局を継続または安全に中止できること |
| 公開の前提                 | ヨミが運用基準を満たすこと。未達なら公開保留                                       |

測定件数・局面・冷起動の条件・分位点の計算方法・同時実行数・失敗件数・入出力を記録します。ソフトウェア・配備条件・探索予算を変えて目標へ合わせる場合は、識別情報を更新して再測定します。

費用の目安は**追加月額5 USD・税抜以内**です。既存契約の基本料金は除き、開発・本番AI、付随するWorkers・Durable Objects・D1・通信・ログの増分を、同じ請求期間の既存利用量と合わせて見積もります。[Containers公式料金](https://developers.cloudflare.com/containers/platform/pricing/)の枠をServiceごとの無料枠として重複計上しません。これは請求を強制停止する上限や追加費用ゼロの保証ではなく、超過見込みなら構成・公開条件を再検討する判断基準です。

本番AIは開発用と分離し、初期案はlite・上限1台・アイドル停止を基本とします。本番用設定・Secret・停止手順と費用見積もりをレビュー可能にしてから公開承認を得ます。削除済み検証用Workerの再作成、上位instance・常時起動・新しい契約への切替は、この文書だけでは実施しません。
