# TetraBoard

## 概要

TetraBoardは、四人用を中心としたボードゲームをブラウザですぐに遊べるオンライン対局サービスです。

最初に提供するゲームは四人リバーシです。四人全員を集めなくても遊べるようにCPU（BOT）を用意し、1人でのプレイから、友人を招待した対人戦まで同じ仕組みで楽しめることを目指します。

初期の主な対象は、リバーシなどのボードゲームが好きで、少し変わったゲームを気軽に試したい人です。ユーザー登録やアプリのインストールを必要とせず、初めて訪れた人が迷わず対局を始められる体験を重視します。

旧TetraBoardとは別のプロジェクトとして開発し、当面は旧版を置き換えません。新しい土台の品質と利用状況を確認しながら、将来のゲーム追加や移行を判断します。

## 必要な仕様への案内

利用者向けの仕様とゲーム共通仕様は、この文書の対象箇所から確認します。ゲーム固有のルールとCPUの採用仕様は各ゲームのルール正本を参照してください。

新しいAI開発基盤は [packages/ai](packages/ai/README.md) に置きます。フェーズ0〜4で四人リバーシ・シングルスのRustエンジン、Lv1〜5候補、比較Benchmark、[外部AI Service接続](packages/ai/docs/phase2.md)と[ランダムマッチ](docs/specs/matchmaking.md)を実装しています。ランダムマッチでは脱落後もRustのヨミ（Lv3）を使い、通常ルームのCPUは従来の設定に従います。四人将棋・四人リバーシ・将棋・リバーシのレート戦を開発・本番向けに構成します。本番はゲーム別の専用AIコンテナを使い、外部AIはレート戦だけに限定します。通常ルーム・大会は従来CPUを維持します。本番公開は[公開前検証と承認](docs/runbooks/deploy.md#本番aiと4ゲーム同時公開)の後に行います。既存AIを新しいAgentへ流用せず、棋力は[比較条件](packages/ai/docs/phase1.md)と[フェーズ3の評価](packages/ai/docs/phase3.md)、実測結果で判断します。

## プロジェクトのきっかけ

開発者は幼い頃から、パソコンで文章やファイルを作ったり、ゲームを開発したりして、それを誰かに使ってもらうことに喜びを感じてきました。

プログラミングを学び始めてからは、クイズゲームやRPG、配信で利用できるしりとり・山手線ゲームの支援ツール、四人オセロなどを制作しました。友人や小さな配信コミュニティがそれらを使い、楽しんでくれた経験が、Webエンジニアを目指す原点になっています。

一方、旧TetraBoardの開発では多くをAIに任せた結果、コードや設計を自分自身で十分に理解できず、「自分が作ったものを使ってもらう」という実感も薄くなってしまいました。

TetraBoardを新しく作り直すのは、単に旧版のコードを整理するためではありません。自分で考え、理解し、納得して作った遊びをもう一度誰かに届けるための再出発です。

## プロジェクトの目的

TetraBoardのプロダクトとしての目的は、プレイヤーを集めにくい四人用ボードゲームを、一人でも複数人でも気軽に始められるオンラインの遊び場として提供することです。遊ぶ人だけでなく、観戦する人も含めて、ゲームをきっかけに人が集まり、楽しめる場所を目指します。

開発プロジェクトとしては、次の状態を目指します。

- 開発者が主要な仕様と設計を自分の言葉で説明できる
- 技術やライブラリを採用した理由を理解している
- 機能数よりも、初めて訪れた人が遊び終え、再び遊びたくなる体験を優先する
- 継続的な利用を確認したうえで、将来の収益化につなげる

## 読み込み・処理中・エラーの表示

ロビー・ルーム・保存済み棋譜の画面全体を読み込む間は、ロビーと同じ背景の中央にスピナーと案内文を表示します。ゲームが判明している場合はそのゲームのテーマを使い、未取得の場合は共通の緑を使います。ルームが見つからない場合を含むルーム・棋譜のエラーも、中央に案内文と戻る・再試行などの操作を表示します。

利用者向けWebで遅延読み込みに失敗した場合は、移動先URLが確定してから、タブを閉じるまで一度だけ自動で再読み込みします。再発時や保存領域を利用できない場合は「画面を読み込めませんでした。アプリが更新された可能性があります。再読み込みしてください。」と「再読み込み」を表示します。再読み込みでは現在のパス・クエリ・ハッシュを保ち、認証や参加資格の保存データは削除しません。初回ロビーの失敗では紹介HTMLを残して同じ復旧操作を案内します。通常の予期しないエラーにも共通の日本語エラー画面と手動の再読み込みを用意しますが、自動更新はしません。この対応を読み込んだタブから有効で、管理画面は対象外です。

Webの操作ボタンは、作成・参加・棋譜への移動・更新・送信・保存などの処理中に、押したボタンの文字とアイコンをスピナーに置き換えます。ボタンの寸法と読み上げ名を保ち、重複操作を防ぎます。失敗時は再操作でき、入力値や取得済みデータの保持方針は維持します。初回取得や条件切り替えの案内は表示し、自動更新や別の操作による無効化ではスピナーを表示しません。

総合ロビーとゲーム別ロビーでは、公開ルーム・最近の対局・大会一覧と、ゲーム別ランキングの初回取得中に、表示後の行やカードに近い形のスケルトンを表示します。スケルトンは動かさず、読み込み状態は各一覧につき一つの案内で伝えます。更新や絞り込みの操作には既存の案内を使います。

## 総合ロビーの確定仕様

2026-10-13に開発者がUIモックと以下の本実装仕様を承認しました。目的は、全ゲームの募集を見つけやすくして対人戦の割合を改善し、再び遊ぶ相手や約束を見つけられる環境を作ることです。承認済みのモックを実データ・認証・D1保存・管理画面へ接続しました。以下は採用仕様です。本番反映は開発環境の確認とリリース承認後に行います。実装は[開発文書](docs/development.md#総合ロビーの実装)、受入検証は[テスト方針](docs/testing.md#総合ロビーの確認)を参照します。

### トップページと承認済みUI

`/` はサービス全体の入口となる総合ロビーです。ブランド見出し・紹介文、ゲーム一覧、公開ルーム、全ゲームの大会一覧、公開チャット（β）、最近行われた対局の順に表示します。767px以下では大会一覧を最近の対局の下へ移します。各ゲームのURLは維持します。

紹介文の最終行に小さなXアイコンと `@tetraboard` を控えめな色で表示し、[TetraBoard公式X](https://x.com/tetraboard)を新しいタブで開きます。

- ゲーム一覧は盤面図とゲーム名を一つのカードリンクにし、四人将棋・四人リバーシ・四人五目並べ・将棋・リバーシ・五目並べの順に表示します。768px以上は6列で全件、767px以下は盤面図と余白を小さくした3列のカードで初期6件まで表示します。7件以上のときだけ「残り○ゲームを表示」で同じ一覧内に全件を展開でき、「閉じる」で先頭6件へ戻します。6件以下では開閉操作を表示しません。ゲーム追加時は共通カタログの新規登録を既存6ゲームの末尾へ取り込み、初期表示の件数を増やしません。展開状態はページ内で保持し、再読み込み・再訪時は折りたたみます。ルーム作成のゲーム選択ダイアログは件数を制限せず全件を表示します。初期配置の専用の軽量画像を共用し、対局用の盤面・駒・ゲームエンジンを読み込みません。五目並べと四人五目並べは同じ空の盤画像です。
- 総合ロビーのゲームカードは、四人将棋・四人リバーシ・将棋・リバーシにトロフィー付きの「レート戦」マークを表示します。環境の受付が無効なら「受付停止中」を添え、取得中・取得失敗では受付状況を確認中・不明と表示します。カード全体からゲーム別ロビーへ移動します。
- 登録者にはゲーム名の下に本人の整数レートを表示します。認定中は「認定中 2/5局」、有効局がない場合は「認定前 0/5局」とし、認定中の数値レートは表示しません。四人ゲームはシングルスのレートです。受付停止中も保存済みレートを表示します。未ログイン・ゲストには本人レートを表示せず、一覧の下に一度だけログイン案内を置きます。ルーム作成のゲーム選択ダイアログにはレート情報を表示しません。
- 対応ゲームの受付状態と本人レートは一つのリクエストで取得し、キャッシュしません。総合ロビーを開いた時、本人の切替・認証確認後、非表示からの復帰時に取得します。取得中はレート欄の高さを確保した静止スケルトンを使い、失敗では「取得できませんでした」と再取得操作を表示します。1ゲームの取得失敗でも他ゲームの情報を表示し、失敗を認定前・未対応・受付停止として扱いません。
- 公開ルーム見出しの「ルームを作る」はゲーム選択ダイアログを開き、選択したロビーへ移動して既存の作成ダイアログを一度だけ開きます。移動だけではルームを作成しません。「更新」も見出し行へ置き、専用の行は使いません。
- 公開ルームは768px以上で2列、767px以下で1列です。一覧の最大高さはPCで480px、スマートフォンで400pxとし、超過分は領域内で縦スクロールします。少数件は内容に応じた高さにします。公開チャットは一覧の下に残し、入力欄・送信ボタンの高さ48pxとチャット履歴の内部スクロールを維持します。
- 公開ルームの人数フィルターは「すべて／四人用／二人用」、初期は「すべて」です。現在の参加人数ではなくゲームの定員でサーバーから取得し直します。「参加できるルームのみ」は初期オフで、取得済みの全ルームから待機中かつ空席のある部屋を画面内で絞り込みます。このチェックの切替では再取得や読み込み表示を発生させません。条件はブラウザへ保存せず、切替時は一覧の先頭へ戻ります。
- 公開ルームカードは総合・ゲーム別で共用し、盤面図、ゲーム名・モード、持ち時間・秒読み、対局種別に応じたルーム名、5桁の部屋番号、募集状態、参加者全員のアイコン、人数、観戦・参加操作を表示します。募集状態は「募集中／満員／対局中」です。満員・対局中の参加ボタンは無効にし、観戦はすべての部屋で利用できます。大会ルームは直接参加の代わりに「大会へ」を表示します。
- 人間のアイコンは入室時の席の画像を使い、既存席をプロフィール変更へ追従させません。CPUは既存のロボット、画像なし・読み込み失敗の人間は仮アイコン、空席は破線の丸で表示します。各参加者のアイコンから既存のプレイヤー情報カードを開き、CPUにはレベルを表示します。空席と退会者は操作対象にしません。退会受付後の本人画像・プロフィール参照は匿名化し、遅れた索引更新からも復活させません。「募集中」は薄いテーマ色の背景に濃い本文色で表示します。
- チャット見出しの下には「現在β版として試験公開しています。」と既存のフィードバック画面への「使ってみた感想を送る」を表示します。発言は小さいアイコン・名前・本文を同じ行から表示し、長文は折り返します。自分の発言の背景、時刻と操作欄の位置、投稿欄の文字数表示を維持します。

### 公開ルームの取得と参加

- 総合・ゲーム別の新一覧は同じ公開索引を使い、「対局前で空席あり → 対局前で空席なし → 対局中」、同分類では公開情報の更新日時降順・ルーム番号降順に並べます。ゲーム・定員条件をサーバーで適用し、20件ずつ最後のページまで取得します。モードと参加可能条件は取得済み全件へ画面内で適用し、絞り込み後の件数を表示します。既存APIのモード・参加可能条件は維持します。
- 全ページの取得成功後に一覧を一括更新します。ゲーム別ロビーは最初の3件だけ表示し、「すべてのルームを見る」で取得済み全件を同じページ内へ展開します。追加取得用の「もっと見る」は置きません。モード・参加可能条件の切替では通信せず、3件表示と先頭位置へ戻ります。0件なら選んだ条件に合うルームがないことを表示します。
- 前面で表示中は10秒ごとに全ページを自動更新し、非表示中は取得を中断して停止、復帰時は先頭から再取得します。自動更新ではカード・0件表示・スクロール位置を保ち、手動の「更新」だけスピナーを表示します。取得の重複・古い条件の応答による巻戻りを防ぎます。更新途中の失敗では前回の全件・選択条件・位置を保持し、初回途中失敗では部分一覧を出さず、エラーと再試行を案内します。
- 参加は既存の名前・プロフィール・参加資格・同意のダイアログと通信を使い、選択したルーム番号を表示します。観戦には名前入力を求めません。「ルーム番号で参加」の入力入口は置かず、公開一覧と招待URLから参加します。部屋番号の識別表示と既存の内部APIは維持します。
- 一覧取得後の満室化・対局開始・閉鎖・番号再利用は、対象ルームの現在状態と世代をサーバーで再検証し、参加できない理由を表示します。ゲームの定員・準備・開始・再戦と、アカウントの同時参加制限は維持します。

### 最近行われた対局

全6ゲームの保存済み終局を横断して最新20件表示します。開始日時の降順、同時刻は対局UUIDの降順という既存の順序を維持し、未終局・保存途中は除外します。初期はCPU戦・ゲスト戦・両モードを含め、「対人戦のみ」で開始時にCPUがいない対局へ絞ります。ゲストは人間として扱います。公開ルームの定員フィルターはこの一覧に適用しません。

カードにゲーム名のバッジ・モード・日時・参加者・結果・手数とCPU有無（「CPUあり／対人戦」）を示し、既存の公開棋譜へ移動します。初回と手動の「更新」だけで取得し、自動更新や追加取得はしません。相対日時・更新失敗時の保持・条件切替の読み込みは[既存仕様](#最近行われた対局と公開棋譜)に従います。

### 公開チャットβの投稿と更新

| 項目           | 採用仕様                                                                     |
| -------------- | ---------------------------------------------------------------------------- |
| 閲覧           | 未ログインでも可能                                                           |
| 投稿           | 名前設定済みのゲスト、またはログインとプロフィール設定を完了した登録者       |
| 本文           | テキストと絵文字、1件100文字以内。見た目の文字単位で数え、URL投稿は禁止      |
| 送信間隔       | アカウントごとに10秒。総合ロビー・全大会・複数タブ・端末を通じて共通に適用   |

| 履歴取得       | 初回は最新50件、過去分を追加取得可能                                         |
| 更新           | 前面で表示中は5秒ごと、非表示中は停止、復帰時に再取得                        |

- 名前未設定の利用者は「名前を設定して投稿」からニックネームを確定してゲストとして利用を開始できます。閲覧・ダイアログ表示・取消ではアカウントを作成しません。名前の確定とCookieの保存確認後に投稿欄を表示し、本文は送信操作で投稿します。ゲストの既定名を本人が確定するまでは投稿できません。
- 翌日の募集などにも使える会話として扱い、予約枠や対局開始時刻の保証は設けません。ルームチャットの在室要件・3秒間隔・直近100件・閉鎖時削除とは独立させます。
- 最新付近を表示中だけ新着へ自動追従します。過去の発言を読んでいる間は位置を保ち、新着件数と最新へ戻る操作を表示します。過去分の追加取得でも閲覧位置を保ち、日付の区切りと正確な日時を確認できる表示を用意します。
- サーバーの確定応答を受けてから発言を表示し、入力を消します。失敗時は入力を残し、応答喪失後の再送でも同じ投稿を重複保存・表示しません。日本語入力の変換中にEnterで送信しません。投稿目的のログイン・プロフィール設定から `/` へ戻り、入力途中の本文を保持します。
- 期限到達した投稿は取得時点から閲覧対象外にします。毎時の削除処理は失敗時に再試行し、保存上限超過も処理します。画面表示中の期限到達・運営削除・退会による削除は次回同期で反映します。
- ルーム添付、募集文テンプレート、予約、メンション、通知音は初回範囲に含めません。

### 公開チャットβの運営と退会

- 送信者を非表示にする操作は閲覧者のブラウザ内に保存し、その送信者の発言をまとめて隠します。表示名ではなく公開用の送信者識別子で区別し、内部アカウントIDは公開しません。通報は本人確認済みのゲスト・登録者が行い、直近1時間で1アカウント5件まで受け付けます。同じ発言への再通報は重複登録せず、件数を増やしません。
- 管理画面に公開チャット専用の通報一覧、投稿削除、アカウントの公開チャット投稿停止・解除を追加します。既存の管理者認証を使い、一般利用者に管理APIや通報証拠を公開しません。ルーム内チャットの運営機能をこの変更で拡張しません。
- 運営が公開チャット全体の投稿受付を停止・再開できます。停止中も履歴閲覧・公開ルーム・対局は利用でき、状態を投稿欄に表示します。投稿停止はWebの無効化だけでなくサーバーで拒否し、各状態変更は次回同期で反映します。
- 通報証拠は通報から7日を上限に管理者だけが閲覧します。通常履歴から削除済みの投稿も、期限内の通報証拠として必要な範囲で保持します。期限到達時の閲覧除外・毎時削除と退会者情報の扱いは既存の通報方針に従います。
- 退会受付後は本人の投稿を一般の取得対象から直ちに除外し、公開チャットの通常投稿を削除対象に追加します。削除処理を再試行でき、遅延した投稿や同期で復活させません。ルーム内チャットの匿名化方針と公開チャット本文の削除方針を区別します。
- 公開範囲、投稿資格、通常投稿と通報証拠の保存期間、退会時の削除、送信者非表示の端末保存をプライバシーポリシー・利用規約へ反映してからβを公開します。

- 「CPUと遊ぶ」はCPU3人との待機室を作り、ホストが「対局開始」を押してから始めます。作成とCPU対戦では名前未設定のゲストは名前を入力し、設定済みゲスト・登録者はプロフィールを確認します。モード・時間の初期値はシングルス・5分＋30秒です。入力値はロビー表示中保持し、ゲスト名は登録からの復元入力を優先し、なければ共通の保存済みゲスト名を使います。
- 「CPUと遊ぶ」と「ルームを作る」のダイアログでは、説明と公開案内を見出しのすぐ下にまとめます。CPU対戦の戦績に関する注意書きも、表示する場合は同じまとまりに置きます。
- CPU対戦ダイアログでは、本人のアカウント情報がある場合に「CPUを含んだ対局は、戦績に反映されません。」を表示します。通常の作成・参加ダイアログには表示しません。参加者欄は設定済みのゲスト名に「ゲスト」を添え、ニックネーム入力の補足は「1〜10文字」とします。
- 公開ルームは[共通のカードと取得仕様](#公開ルームの取得と参加)に従い、1列で初期3件からページ内展開します。「すべて／シングルス／ダブルス」と「参加できるルームのみ」を表示し、初期はすべて・チェックなしです。
- 最近の対局は3件の簡潔な行表示を維持し、勝者・モード・相対日時・参加者を表示して公開棋譜へ進めます。「もっと見る」で共通ダイアログを開き、最大20件の棋譜カードと対人戦フィルター・更新・再試行を表示します。ダイアログはゲームのテーマを使います。集計条件・順序・更新失敗時の保持は[最近の対局仕様](#最近行われた対局と公開棋譜)に従います。
- ランキングはシングルス優勝数の上位3人を固定表示し、モード・指標切替と更新は「もっと見る」の詳細ダイアログで行います。
- 下部のゲーム紹介、「不具合・ご意見」「お知らせ」、規約と著作権表記を維持します。ボタン・カード・ダイアログ等はHeroUI、本文は既存の緑テーマを使います。

## 通常リバーシ

3番目のゲームとして `/games/reversi` に「リバーシ」のロビーを提供します。ゲーム切り替えは四人リバーシ、四人将棋、リバーシ、将棋の順です。通常リバーシは黒白2人で対局し、シングルス・ダブルスの区別を設けません。開発環境ではLv2にEgaroucidを使う接続を検証できます。ゲーム固有のルールは[通常リバーシのルール正本](docs/rules/reversi.md)に記載します。

- ロビーの構成は四人リバーシとそろえ、四人リバーシより少し薄い緑を使います。「CPUと遊ぶ」の説明は「CPUと対戦します。」とし、作成・CPUと遊ぶ・ルーム設定にモード選択を表示しません。公開ルームは定員2人、2つの席マークを表示し、モード欄を設けません。
- 「CPUと遊ぶ」は作成者が準備完了、作成時に選んだレベルのCPUが1人の待機室へ進みます。人間とCPUの合計2席、接続中の人間全員が準備完了になってから、ホストが対局開始を押します。CPUの追加・削除・レベル変更も利用できます。
- ルームは盤面の上に相手、下に自分のプレイヤーカードを配置し、左右には配置しません。スマートフォンも上下配置です。初回待機中の観戦者はホストを下、対局中・公開棋譜は黒を下にします。観戦・保存棋譜では180度ずつ回転できます。本人の対局とルーム内の本人の直前局棋譜は回転しません。
- マイページのゲーム選択にリバーシを追加し、モードタブを表示しません。戦績は対局数、勝数・勝率、敗数・敗率です。引き分けは対局数と率の分母に含め、引き分けの行は表示しません。率は既存と同じ小数3桁（`.500` など）で、0局は `.000` です。通常リバーシのバッジは未実装とし、マイページとプレイヤー情報カードのバッジ欄は非表示です。
- ランキングはモードタブなしでレート／勝利数の上位3人を10秒ごとに切り替えます。詳細ではレート／勝利数／対局数の上位10人を表示します。同数の順位と表示条件は既存ランキングと共通です。
- 戦績・ランキングは対人戦とレート戦を集計します。相手がゲストでもアカウント参加者は集計対象です。通常ルームのCPU戦は履歴・棋譜に保存します。
- 公開ルーム、招待、観戦、チャット、効果音、持ち時間・秒読み、準備・開始、再戦、最近の対局、本人・公開棋譜、プレイヤー情報カード、遊び方、お知らせ、検索向け紹介に対応します。最近の対局の絞り込みは「対人戦のみ」です。ゲーム本文、マイページ、棋譜、ダイアログにも薄い緑を使い、共通ヘッダーは共通テーマを使います。
- 共通仕様にある「4人」「CPU3人」「全ゲーム」は、通常リバーシではゲームの定員2人、CPU1人、全6ゲームとして適用します。投了・退室・時間切れ・30秒の切断期限切れは本人の敗北として終局します。投了は自分の手番のみです。初期時間設定は5分＋30秒です。終局と保存待ち、再戦・閉鎖後の保存再試行、認証・参加資格・アカウントの席制限は既存の共通仕様に従います。
- ロビーを検索対象に追加し、ゲーム固有の初期HTML、紹介、メタ情報、canonicalとサイトマップを生成します。ルーム・アカウント・棋譜は検索対象外です。

通常リバーシのレート戦は登録者向けです。1人5分切れ負けで対人を優先し、15秒で相手がいなければ暫定レートが近いCPUを補充します。最初の有効な5局が認定戦です。[通常リバーシのレート戦の仕様](docs/reversi-rated-match.md)

## 通常将棋

4番目のゲームとして `/games/shogi` に「将棋」のロビーを提供します。通常将棋は2人・モードなしです。ゲーム固有ルールの正本は[通常将棋のルール](docs/rules/shogi.md)です。

将棋ロビーの「レート戦」からダイアログを開き、登録者は現在のレートまたは認定戦の進捗を確認して参加できます。1人10分切れ負けで対人戦を優先し、15秒で相手が見つからなければCPUとの組合せを試みます。CPU枠が埋まっている間も、対人戦を探しながら枠の空きを待ちます。成立を検知すると自動で入室し、全員の接続から5秒後に対局を開始します。最初の有効な5局を認定戦とし、認定後も対人戦と補充CPU戦で一つの公開レートを更新します。マイページの将棋の戦績欄にも現在のレートまたは認定進捗を表示します。参加の有効化は環境ごとに設定します。[将棋のレート戦の仕様](docs/shogi-rated-match.md)

レート戦の対局結果には、名前の右に対局後のレートと増減を表示します。認定中は認定状況を、CPUは固定の基準レートを表示します。

- 四人将棋より薄い黄色・クリーム系のテーマを、ロビー・マイページ・ルーム・棋譜・ダイアログへ適用します。共通ヘッダーは既存色です。ロビーの正方形の初期盤面プレビューは通常将棋の40枚を表示します。対局・観戦・棋譜の盤とマスは[四人将棋と共通の描画](#四人将棋のルーム画面)を使います。

- 待機中のホスト向け「ルーム設定」ボタンは共通ダイアログを開きます。ボタンのアイコンとラベルは中央揃えです。右上の閉じるボタン・「キャンセル」・Escapeで閉じ、未適用の編集は破棄します。シングルス／ダブルスはルーム作成と同じ説明付きカードで選びます。追加するCPUのレベル選択は「CPUを追加」のすぐ左に8px間隔で置き、右寄せします。CPUレベルのホバー背景は薄いテーマ色を使います。
- モード・時間・CPUの追加／削除／レベル・ゲーム固有の設定はダイアログ内の下書きとして編集し、「適用」で全項目をまとめて送信します。サーバーはホスト権限・待機状態・定員・CPU・編集開始時のルーム情報を確認し、すべて有効な場合だけ一度に反映します。編集中に入退室や他の設定変更があった場合は、下書きを保持して「設定を読み直す」を案内し、古い編集で上書きしません。
- 適用中は選択内容を保持し、適用ボタンにスピナーを表示して編集・閉じる操作をロックします。一時的な無効化による透明度の切り替えを抑えます。成功時はダイアログを閉じ、拒否・送信失敗・切断では下書きと再操作の導線を保持します。準備解除・盤面・CPUの増減はサーバー確定後に反映します。

- スマートフォンではカードの幅・高さを保ち、空き高さが足りないときは盤面だけを中央で縮小し、正方形を維持します。カードと盤面の間隔は2pxとし、自動パス通知の高さも確保します。通常ルームと保存済み棋譜に適用します。
- タブレット・スマートフォンには「盤面／ルーム／チャット」のタブを設け、状況カードをその上に常に表示します。チャットの入力と閲覧位置はタブを切り替えても保持します。
- 初回の待機中は操作できない初期盤面を表示します。終局後は自動で棋譜モードに入り、前局の最終局面を表示します。待機中に石を置いたり、合法手のマークを表示したりはしません。対局中と保存済み棋譜のカードは黒→白→赤→青の時計回り順にし、観戦・公開棋譜は黒、対局者と本人用の保存済み棋譜は本人を手前にします。待機・再戦待機は入室順を維持します。着席と担当色の関係は[四人リバーシのルール](docs/rules/four-reversi.md#色の割り当てと表示)に従います。
- プレイヤーカードは同じ幅・高さと8pxの角丸でそろえ、最大10文字の名前と王冠を省略・折り返しせず一行で表示します。長い名前は表示幅に合わせて文字サイズを調整します。入室時のアカウントアイコン（アカウント参照のない旧ゲスト・読み込み失敗は仮アバター）、ホストの王冠、CPUの「CPU Lv1」などの名前と青いロボットのアバターを表示します。接続中は緑、切断中は黄の丸いバッジを表示し、空席は薄いグレーにします。
- 対局中は直前に着手したマスをオレンジの枠で示し、自分が着手できるマスに丸い点を表示します。最終手の枠は再読み込み・観戦でも表示し、初期盤面では表示しません。
- 待機中のカードには初期持ち時間（持ち時間なしの場合は秒読み時間）と、準備済みの場合だけ緑の「準備完了」を表示します。石数と担当色は対局中だけ表示します。脱落後もカードを残し、時計の代わりに「4位（退室）」などの確定順位と脱落理由（退室・時間切れ・投了・通信切れ）を表示します。理由は再読み込み・途中からの観戦でも保持し、旧データで記録がない場合は順位だけを表示します。再戦待機になったら順位・石数・色を消して初期表示へ戻します。
- 時計は標準の文字の太さで、通常20px、スマートフォンでは18pxを基本に、狭いカードでは縮小します。基本時間を黒、秒読みを黄色で表示します。対局中は現在の手番者のカードをオレンジ色の枠で示し、枠の周囲のぼかしをゆっくり明滅させます。対局者・観戦者とも、実際の時間切れまで残り5秒以下になると時計と枠を赤にし、枠を太くしてぼかしの明滅を速めます。秒読みなしの持ち時間にも適用し、秒読みがある場合は持ち時間の終了5秒前には強調しません。残り0秒もサーバーが手番交代・脱落・終局を確定するまで強調を維持し、手番外・待機・棋譜では強調しません。動きを減らす端末設定では赤色を維持してアニメーションを止めます。時計音と強調の確定仕様は[時間切れ5秒前の通知](docs/specs/room.md#時間切れ5秒前の通知)を参照してください。
- 状況カードは高さ48pxの1行です。初回待機中は盤面上の半透明カードに「待機中」と参加者数（CPU込み）を表示し、状況カードには準備・開始などの操作を置きます。自分の手番は左から「投了」、ゲーム固有の操作、右端にスタンプを表示します。手番の強調はプレイヤーカードの枠に表示し、動きを減らす端末設定では枠の色と太さで示します。ルーム・チャットタブを開いている間は盤面タブに「手番」を表示し、手番は読み上げでも通知します。他の手番では左に「○○の番です。」、右端にスタンプを表示し、幅が足りない場合は名前を省略表示します。ライブ対局の時計はプレイヤーカードに表示します。再戦待機の「結果」は結果ダイアログを開きます。全ゲームで対局者・観戦者とも、ログイン状態に関係なく、画面上で終局を検知してから1秒後に結果を自動表示します。各対局につき1回で、閉じた後は「結果」から再表示できます。終了済みの部屋への初回入室・再読み込みでは自動表示しません。1秒後に他のダイアログが開いている場合は、その局の自動表示を取り消します。次局開始・退室・閉鎖でも保留を取り消します。
- 棋譜カードは「←」、局面を選ぶSelect、「→」で構成します。PCでは盤面・プレイヤー領域の右下へ重ねて配置し、棋譜の有無で盤面とプレイヤーカードの位置・寸法を変えません。タブレットでは状況カードの「結果」の右に表示します。スマートフォンでは状況カードの「棋譜」を押すと、前後ボタンとSelectを状況カードに接する上側のパネルに表示します。パネルは終局直後は閉じており、開閉しても選んだ局面を保ちます。タブ切替中も操作できます。最初は「開始局面」、着手は「5: 赤E6」の形式で表示します。自動パス・投了・退室・時間切れ・通信切れによる脱落も独立した項目とし、着手番号は増やしません。終局後は最後の項目を選び、次の対局開始時に棋譜モードを解除します。局面の選択は閲覧者ごとに独立しています。
- 全ゲームの棋譜Selectは選択中・候補とも短い一行表示とし、幅が足りない場合だけ省略記号を使います。読み上げ名は省略しません。着手は「5: 赤E6」「1: ▲7六歩」「122: 北6九金打」、外部脱落・パスは「南 投了」「北 通信切れ」「赤 パス」の形式です。「開始局面」「最終局面（棋譜なし）」は保持し、通常ルームと保存済み棋譜で同じ表示を使います。
- 接続中・再接続中・操作エラーの通知は全ゲームのルーム上部中央へ重ね、盤面・カード・タブの位置や寸法を変えません。上端の安全領域から8px、左右8px以上を空け、最大幅480px内で長い文を折り返します。クリックを透過し、ダイアログとSelect候補の下に表示します。
- ルーム内の棋譜モードでも盤面は前局、プレイヤーカードは現在の待機メンバー・入室順・準備状態を表示します。前局の担当色はカードに表示しません。プレイヤーカードの下には棋譜の手数・手番・4色の石数を表示せず、選択局面は棋譜Select、直前の着手は盤面の枠で示します。
- 再戦待機では前局の盤面を表示します。ホストの状況カードには左から「準備完了」（準備済みの場合は「準備取消」）、「対局開始」、「結果」を並べます。幅360px以上では状況カードの文字ボタンを広めに取り、幅360px未満では状況カードの操作が1行に収まるように詰めます。
- 直前1局の棋譜は次局開始または部屋の閉鎖まで保持し、再読み込み・再接続でも最後の局面から復元できます。待機中の設定変更や入退室で棋譜を書き換えません。導入前に開始済みだった対局は最終局面のみを表示し、過去の着手は補完しません。
- ホストの「対局開始」は状況カードの準備操作の隣に置きます。スマートフォンでは準備・開始ボタンに状況カードの余った横幅を割り当てます。開始条件を満たすまで無効にします。モード、持ち時間・秒読み、CPUの設定は待機中のルーム情報から開く共通ダイアログにまとめます。時間の初期設定は5分＋1手30秒です。
- 観戦者には、待機中で空席がある場合に状況カードの「参加する」を表示し、名前未設定のゲストはニックネーム入力、設定済みのゲスト・登録者はプロフィールの確認から参加できます。満室・対局中も含めて状況カードの右側に「観戦中」と回転ボタンをこの順で表示します。対局中は左側に手番者名を表示します。準備・開始・投了は表示せず、ロビーへ戻る導線を表示します。投了と対局中の退室はダイアログで確認します。
- ルーム情報の「ルームを共有」は全閲覧者が使えます。[確定したルーム共有仕様](docs/specs/room-sharing.md#利用者に見える仕様)のダイアログを開き、ルームURLのコピーとXでの対戦相手の募集ができます。コピー成功は3秒のtoastで通知し、失敗時はURL欄から手動コピーできます。
- 招待リンクを開いた未参加者には、待機中で空席がある場合に参加ダイアログを1回だけ自動表示します。表示履歴は同じタブ・同じルーム世代ごとに保持します。「観戦する」や閉じる操作で観戦を続けられます。更新やタブ切替、ロビーとの往復で再表示せず、後から状況カードの「参加する」で開けます。ブラウザの保存領域が利用できない場合は、更新後の表示履歴を保持できません。入力中の満室化・対局開始や通信エラーは日本語で案内し、送信中は重複送信と閉鎖を防ぎます。
- 新しい他の人のチャット投稿とシステムログは、チャット表示中も3秒間のtoastで通知します。自分の投稿、初回・再接続時の履歴、非表示の送信者、重複受信は通知しません。
- チャットの最下部を見ていれば新着に追従し、途中を読んでいれば位置を保持します。「↓」ボタンで最新位置に移動できます。日本語変換中のEnterでは送信しません。

ロビー・ルームのダイアログは、右上から12pxの位置に44×44pxの閉じるボタンを表示します。ダイアログ表示中は背景ページ全体をぼかし、スマートフォンのキーボード表示中も背景が鮮明に露出しないようにします。ダイアログ本体はキーボードを除く表示領域内でスクロールできます。

観戦と保存済み棋譜では、回転ボタンを押すたびに盤面・駒・持ち駒・プレイヤーカードの配置を時計回り90度回し、4回で元に戻します。カードの文字は読める向きを保ち、ゲームの座標や所属は変更しません。保存済み棋譜の状況カード右側には回転ボタンを置き、タブレット・PCではその左に「棋譜閲覧中」を表示します。初期方向は既存の観戦／本人方向とし、回転は画面内だけで保持します。手数変更・タブ切替・再接続・同じルームの次局開始では維持し、再読み込み・別ルームや別棋譜への移動・観戦から参加への切替で初期方向へ戻ります。参加者の対局画面と、参加者がルーム内で見る直前局の棋譜には回転操作を表示しません。

## ローカルAI解析widget

四人リバーシ・四人将棋のシングルス参加者向けに、自分のChromeで使うローカル拡張を提供します。通常の対人戦・CPU戦・大会、他の参加者の脱落後にも対応します。四人将棋は三人攻撃禁止ON／OFFを扱います。利用する場のAI助言の扱いは、その対局・大会の取り決めに従います。導入・更新は[拡張の案内](apps/local-ai-widget/README.md)を参照してください。

macOS版Chromeでは、初回に`bun run --cwd apps/local-ai-widget setup:native`で補助プログラムを登録すると、widgetからAIサービスを起動・停止・再起動できます。ローカルtokenは拡張へ自動設定します。状態は約3秒ごとに更新し、別の方法で起動したプロセスは終了させません。Chrome終了や拡張との接続終了時は、補助プログラムが起動したAIも終了します。従来の端末からの手動起動も利用できます。

初期状態は無効です。「AI起動」後、有効化したタブの本人手番で自動検討し、着手まで同じ局面の探索を蓄積します。相手手番は、その手番の人から見た候補を手動検討できます。探索結果は約1秒ごとに取得し、最大3候補を表示します。「検討停止」は候補を消し、同じ局面では自動再開しません。「解析・再解析」で新しく開始できます。「AI停止」はAIサービスごと終了し、「再起動」は候補を破棄して本人手番の検討を再開します。最後に有効化した1タブだけを対象とします。局面変更・本人脱落・終局・次局・切断・本人変更・遷移・タブ非表示で探索と結果を破棄し、復帰後は最新受信の局面から再開します。

四人リバーシはLv6と同じ評価・一様rollout・単独1位報酬のMCTSへ一本化し、Lv5／Lv6の選択欄を設けません。探索木・乱数状態・訪問数を保持し、総時間・総試行数では打ち切りません。木は最大65,536ノードを保持し、上限後も既存木とrolloutで試行を続けます。候補順は訪問数優先で、盤上には①②③をクリック透過で重ねます。参考評価は推奨手後の探索内・単独1位率です。対人勝率や予測順位ではなく、同率1位を含めず、4色の合計を100%へ正規化しません。

四人将棋は既存Rust版Lv3の評価と探索を基に反復深化し、ローカル検討では時間・作業量・深さ6の上限を外します。最後に完了した深さの候補を表示し、途中の異なる深さの評価を混ぜません。widgetには移動元・移動先・駒種・成り／不成・駒打ち、参考評価値と完了深さを表示します。盤上には移動元から移動先への矢印と候補番号を重ねます。駒打ちは移動先の番号と候補欄の「飛打」などで示します。同じ移動先の番号はまとめ、操作を透過します。評価値は手番の陣営から見た参考値で、勝率へ換算しません。

検討はMacのloopback専用Rustサービスで行います。四人将棋は進行中の棋譜を読み取り専用APIから取得し、初期局面から再生して受信局面と照合します。途中有効化・再読み込みにも対応し、履歴不足・局面不一致を推測で補いません。盤面の座標や駒・石が受信局面と合わない場合は盤上表示を消し、widget内に案内します。拡張からの進捗取得が15秒途絶えた探索も停止します。

観戦・保存棋譜・ダブルス・自動着手・読み筋は対象外です。対局の時計・着手・勝敗・保存は既存のWebとWorkerが担当します。継続検討の棋力は未測定で、[過去のLv6測定](packages/ai/docs/lv6-candidate.md)とは条件が異なります。公開CPUの設定は変更しません。Workerの対応版の反映と、ローカルサービス・拡張・対局ページの更新が必要です。

## 四人将棋のルーム画面

`/rooms/:id` をリバーシと共有し、設定のゲームに応じて対局画面を表示します。招待、準備、設定、時計、チャット、再接続、観戦、結果、再戦の操作は共通です。将棋のルームとダイアログには黄色テーマを使います。

- 盤全体を正方形とし、四辺に等しい余白を取り、正方形のマスを9×9に並べます。木目画像を背景に使い、読み込み中や失敗時は木色を表示します。罫線と4つの目印はマスの境界に描き、駒と着手候補の丸はマスの中央に置きます。 上と右の木目の余白に、棋譜と同じ筋の数字（1〜9）と段の漢数字（一〜九）を各マスの中心に合わせて表示します。盤面を回転すると座標の位置も回転します。クリック・タップとドラッグの着地は同じマスで判定し、外周の余白と盤外では着手しません。768px以上ではカードと持ち駒を上下左右へ配置し、767px以下では上2席・持ち駒・盤面・持ち駒・下2席の順にします。外側の1280pxの配置とタブはリバーシと共通です。
- 入室・観戦・保存済み棋譜の表示時に、木目画像と上下各9種類の全18駒画像を先読み・デコードします。準備状態はページ内で共有し、準備済みの駒は着手・捕獲・成り・打ち駒・ドラッグで描画し直しても文字表示へ戻りません。再戦・回転・棋譜でも再利用します。初回準備中は操作・通信・時計を止めません。失敗した画像はページ内で自動再試行せず、再読み込みで再試行します。
- 駒画像の読み込み・デコード中と失敗時は、同じ寸法の薄い木色の枠に「王・飛・金・銀・歩・龍・成銀・と金・裏王」を表示します。文字の向きは駒の向きに合わせ、画像の準備後は文字を消して従来の画像だけを表示します。盤上・持ち駒・ドラッグ・成り選択・観戦・棋譜に適用し、画像待ちで操作や時計を止めません。
- 768px以上のプレイヤーカードは4席とも側列から決めた同じ幅・高さ60pxにします。上下のカードと持ち駒は横並びの組として盤面領域全体の中央に置き、間隔を含めて横方向にはみ出さないようにします。
- 768px以上では、縦向きタブレットでも4席を盤の上下左右に置きます。対局・観戦・ルーム内棋譜・保存済み棋譜では、左右の席の間に収まり、上下のカード・持ち駒と状況・棋譜操作欄が見える最大の正方形を盤面に使います。
- スマートフォンではプレイヤーカードの幅と高さ48pxを保ち、空き高さが足りないときは盤面だけを中央で縦横比を保って縮小します。持ち駒も盤上の駒と同じ縮尺で小さくし、空の領域を含めて高さを追従させます。カード・持ち駒の上下の内側余白は1px、カードと持ち駒・盤面との間隔は2pxにします。通常ルームと保存済み棋譜に適用します。
- 対局者は自陣営が下、観戦者の初期方向は南が下です。座標と駒の向きを変換し、対局中のカードも担当方向へ配置します。待機中は入室順で本人を下へ置きます。終局後は次局開始まで前局の閲覧方向を保ちます。
- 持ち駒は種類ごとに1枚を表示し、2枚以上に枚数を付けます。0枚は非表示、空の領域も高さを保ちます。盤上・持ち駒・ドラッグ中の駒は盤の内寸から求めた同じ縮尺を使います。
- 詰み・合法手なし・投了・退室・時間切れ・通信切れで脱落した後も、脱落時の持ち駒の種類・枚数を持ち駒台に残します。表示専用で、選択・ドラッグ・駒打ち・生存者への譲渡はできません。対局・観戦・終局後・棋譜で表示し、再読み込み・再接続でも保持します。棋譜では選択局面に追従し、次局へ引き継ぎません。導入前の脱落済み進行局で失われた枚数は推測せず、完全な旧棋譜ではイベント再生から表示します。
- 持ち駒は画面幅にかかわらず、同じ陣営の盤上駒と向きをそろえます。閲覧方向を基準に、自分側は上向き、左側は右向き、対面は下向き、右側は左向きです。スマートフォンでは左下が上向き、左上が右向き、右上が下向き、右下が左向きとなり、観戦・棋譜の回転にも追従します。駒種の並び順は向きとは分け、スマートフォンの上2席は左から飛・金・銀・歩、下2席は左から歩・銀・金・飛です。PCは下が左から歩・銀・金・飛、上が左から飛・金・銀・歩、左が上から歩・銀・金・飛、右が上から飛・金・銀・歩です。持ち駒領域は淡い木目調にします。
- クリック・タップで選択し、合法な移動先を緑の丸、三人攻撃による禁止候補を赤い丸で表示します。禁止候補しかない駒・持ち駒も選択できますが、赤い丸には着手できません。同じ移動先で成り・不成の一方が合法なら緑を優先し、合法な選択だけを実行できます。マウス・タッチを8px以上動かすとドラッグになり、元の駒画像を隠して追従する駒だけを表示します。選択・ドラッグ中は持ち駒の枚数を維持します。同じ駒の再選択・Escapeで解除し、盤外・不正な場所・ポインター取消では着手しません。操作できる駒だけタッチのスクロールを抑止し、マウスでホバーすると少し浮き上がる表現を付けます。選択中の盤上・持ち駒は、ホバーが外れても浮いた状態を保ち、選択を解除すると元へ戻ります。浮き上がりは即時に切り替え、この表現には駒画像への影やアニメーションを使いません。
- 成り・不成の両方が合法なら、移動先の中央を境に左へ成り駒、右へ不成駒を盤上と同じ大きさで表示します。盤端では2枚全体を盤内へ寄せます。選択外の画面内クリック・タップは成りを確定し、背後の操作は実行しません。Escapeは取消、候補が1つなら直接送信とします。キーボードはTabで二択を移動し、Enter・Spaceで確定できます。
- 未確定の成り選択は同じタブで再読み込み・再接続後も復元します。部屋世代・本人・局ID・局面revision・陣営を照合し、認証と最新の合法手の確認後に表示します。復元だけでは送信しません。確定・取消・局面更新・次局開始・脱落・参加資格変更で破棄します。保存領域が使えない場合、その場の選択は操作できますが再読み込み後の復元は保証しません。送信中は重複操作を防ぎ、成り選択中も時計は進みます。
- 合法な着手の送信直後は、駒の移動・捕獲・成り・持ち駒の増減を本人の画面へ先に反映し、移動先を破線の枠で未確定として示します。手番・時計・王手・脱落・勝敗はサーバーの確定情報に従います。同じ局ID・revisionの通知では送信待ちを維持し、新しい局面の受信で確定表示へ切り替えます。拒否・送信失敗・切断では未確定表示を解除し、再接続後は最新局面と認証に従って復帰します。古い選択は復元しません。観戦・棋譜には未確定表示を適用しません。
- 着手送信待ちが3秒以上続いた場合だけ「着手を送信中…」を表示します。完了・拒否・切断・次局開始・画面離脱で解除し、次の着手には時間を持ち越しません。文言と拒否理由は既存の接続通知と同じ上部中央の絶対位置へ表示し、盤面・カード・タブの配置を変えません。接続・再接続と操作エラーを優先し、その間は送信中通知を表示しません。
- 本人の確定着手で16戦型（地下鉄飛車の単独判定と右玉の派生を除く掲載形）が不成立から成立したとき、本人側2段目の中央に名称を2秒表示します。[判定条件](docs/rules/four-shogi.md#戦型の成立判定)は共有エンジンを使い、未確定着手とサーバーの付加解析結果では表示しません。「地下鉄飛車・下段金寄せ」と「地下鉄飛車・融通無碍」はそれぞれ1戦型として判定・通知します。同時に新たに成立した未通知の名称は定義順に「・」で連結します。同じタブの同じ局では各戦型を1回だけ通知し、初回取得・再読み込み・再接続・局面取得の飛びは通知せず基準にします。記録は部屋世代・本人・局・解析版ごとに区別し、次局で置き換えます。保存領域が利用できない場合も、その画面内で重複を抑止して操作を継続します。
- 戦型名は水平な白文字と濃い半透明背景で盤内に重ね、盤幅に合わせて縮尺します。2秒のうち最初の180msでふわっと現れ、最後の240msでふわっと消えます。位置・大きさは動かさず、OSで動きを減らす設定の場合はフェードを省略します。クリック・タップを透過し、フォーカスを移動せず、控えめな読み上げ通知だけを使います。選択・ドラッグ・成り選択、切断・脱落・終局・次局開始では即時に消し、再演しません。別の戦型が成立したときは最新の名称へ置き換え、フェードを最初から始めます。観戦・待機・ルーム内棋譜・保存済み棋譜では表示しません。盤面・カード・持ち駒の寸法と配置は変えません。
- 王手、裏王、脱落理由・確定順位、直前の移動元と移動先を表示します。直前の移動元はマスの暗い茶色の背景、移動先はオレンジ（`#ffad32`）の3pxの内側枠だけでハイライトし、打ち駒は移動先だけを表示します。背景・枠・ホバーの装飾はマス内に描き、罫線と目印は装飾の上に表示します。観戦・通常ルームの棋譜・保存済み棋譜でも選択局面と盤面回転に追従します。三人攻撃禁止は待機中のホストが変更でき、モードまたはこの設定を変更すると人間の準備を解除します。対局中は固定し、再戦へ引き継ぎます。
- 自分の手番では「投了」の右隣の「引分提案」で同意を表明し、提案中は「引分取消」で取り消せます。提案中はプレイヤーカードの方角の右に「引分」バッジを表示します。操作で手番・手数は進めず、時計も停止・リセットしません。提案は着手・手番変更・再接続後も保持し、生存者全員が提案状態になれば引き分けて再戦待機へ戻ります。脱落による通常の終局を優先し、対局が続く場合は残った生存者で再判定します。CPUは自分の手番で、生存する人間全員の提案・取消に合わせます。生存する人間が0人なら新たに提案しません。結果・戦績は千日手と同じ扱いとし、提案・取消も手数を増やさない棋譜イベントとして保存します。保存済み棋譜のバッジは選択局面に追従し、再戦待機のカードは準備状態を表示します。
- 5分＋1手30秒を使い、CPU Lv1・Lv2を選べます。Lv1は合法手からランダム、Lv2は計算量を制限した多人数探索で選びます。対局ごとに担当方向を抽選し直します。ルール・王手優先・撃破後の手番は将棋正本とエンジンに従います。
- 直前1局の棋譜は移動・捕獲・打ち駒・成り・外部脱落と自動詰みを振り返れます。脱落理由・同時脱落の群・順位は局面データとカード・結果表示で保持し、棋譜Selectには詰み・合法手なし・同時脱落・順位の付加説明を表示しません。終局後は最終局面を選択し、再読み込み・再接続で復元できます。次局開始または部屋閉鎖で削除します。
- 将棋の終局データと棋譜を恒久保存し、マイページの戦績・棋譜と将棋ロビーのランキングへ反映します。保存・取得・集計はゲーム別に扱います。

## ゲストアカウントの確定仕様（#234）

- 全6ゲームの作成・CPUと遊ぶ・公開一覧／招待・観戦からの参加と大会エントリーの確定時、および公開チャット利用開始の名前確定時だけ、ゲストアカウントを自動作成する。閲覧・観戦・入力ダイアログの表示では作成しない。
- 名前未設定のゲストには確定前に名前入力を必須にする。キャンセル時は参加しない。自動名「ゲストxxxxx」と本人による名前設定済みフラグを区別する。番号・名前は重複を許し、本人は内部IDで識別する。
- 全6ゲームの初回のルーム作成・CPUと遊ぶ・公開一覧／番号／招待／観戦からの参加では、名前入力欄の左に6種類からランダムに選んだプリセットアイコンを表示する。右下に重ねたシャッフルボタンで、現在の画像以外の5種類からランダムに変更できる。ボタンの表示は矢印アイコンだけとし、ツールチップ・読み上げ名は「アイコンをランダムに変更」、変更結果は画像名で読み上げる。タップ範囲は44px四方を確保する。変更せず進んだ場合も表示中の画像を使い、名前と同時にプロフィールへ保存してから入室する。送信中は変更できない。アイコンは全ゲーム・次回の入室でも共用し、後からマイページで選び直せる旨を案内する。
- 初回アイコンの変更だけではゲストを作成・更新しない。確定前に閉じたアイコンの下書きは破棄し、保存失敗では選択を保持する。プロフィール保存後のルーム作成・参加失敗では保存済みの名前・アイコンを保持する。別タブなどで先に保存されたプロフィールと入力内容が異なる場合は、保存済みの内容を表示し、再確認後に進む。名前設定済みのゲストと登録者には保存済みのプロフィールを表示し、このシャッフル操作は出さない。大会エントリー・公開チャットの初回設定はこの変更の対象外とする。
- 名前は前後空白を除いて見た目の文字単位で1〜10文字。既存の端末保存名を初期値にできるが、確定前は設定済みにしない。全ゲーム共通でサーバーへ保存し、次回は入力不要。マイページの「プロフィールを編集」から共通ダイアログを開いて名前を変更できる。ゲストのダイアログでは名前とプリセットアイコンを編集でき、IDは読み取り専用で表示する。画像アップロード・ID変更・ひとこと・お気に入りゲームの設定にはGoogleまたはDiscordとの連携が必要な旨を案内する。Google・Discordの連携ボタンと同意文はマイページのプロフィールカードに表示する。表示用IDは `guest_` とランダムな14桁の英小文字・数字を組み合わせて自動発行し、登録者のIDも含めて重複を防ぐ。マイページ・ヘッダー・ホバー等で開くプロフィールカードに `@ID` を表示する。ゲストのままではID変更と画像アップロードを保存できない。表示用IDはアカウント・本人資格・同意と同時に確定し、取得時には補完しない。IDは識別用で、ログイン・復旧の資格にはしない。
- ゲストのプロフィール編集も、登録者と同じ名前・アイコン・ID・ひとこと・お気に入りゲームの項目を表示する。名前とプリセットはそのまま編集できる。画像アップロード・ID変更・ひとこと・お気に入りは連携が必要で、操作すると編集ダイアログの上に共通のアカウント連携ダイアログを開く。ID・ひとことは読み取り専用とし、クリック・Enter・Spaceで案内を開く。案内を閉じる・Escapeでは案内だけを閉じ、編集画面と下書きを保持する。
- 連携案内はGoogle・Discordのボタン、対象機能の説明と同意文を表示する。プロフィールからは「編集中の名前とアイコンを保存してから連携します」と案内し、名前と選択プリセットの保存に成功してからOAuthへ進む。入力・保存の失敗ではOAuthを開始せず、保存・連携開始の失敗は案内内に表示して再試行できる。保存・OAuth開始中は両ダイアログの操作と閉鎖を防ぐ。連携完了後の初回設定、新規連携の保持・既存アカウントへの統合先優先は既存の流れを使う。
- ゲストの本人確認は専用HttpOnly Cookieで最終利用から180日保持する。登録者の7日セッションは維持する。Cookie削除・期限切れ・別ブラウザ／端末では連携前のゲストを復旧できず、その旨を案内する。認証障害を未認証として新規作成しない。アカウント・記録の自動削除は初回実装では行わない。
- ゲストもマイページ・本人履歴・戦績・ランキング・バッジを利用でき、登録者と同じ集計条件とする。通常ルームのCPU戦は履歴・棋譜だけ。ルームのプレイヤーカードには「ゲスト」を常時表示せず、ホバー・フォーカス・クリックで開くプロフィールカードには「ゲスト」と表示する。ランキング・大会などの既存のゲスト表示は維持する。
- ゲストにはログアウト操作を提供せず、サーバーもゲストのログアウトを拒否する。登録者はログアウトできる。
- Google／Discordの新規連携ではゲストの内部アカウントID・表示用ID・名前・記録を保持する。初回設定には引き継いだ表示用IDを初期表示し、登録後のID変更は登録者仕様に従う。プロバイダーの名前・画像は公開プロフィールへ転記しない。
- 既存登録アカウントへの統合はOAuth認証後、対象と全ゲームの記録引き継ぎを確認してから実行する。統合先のプロフィールを優先する。同じ参加の二重加算・同じ対局の複数席取得は禁止する。履歴・戦績・バッジ・大会成績・公開プロフィールの本人対応を整合させる。完了前にゲストを削除せず、完了後は元ゲストの認証を失効させ単独利用できなくする。
- 既存登録者へのログイン後は、対局の有無にかかわらず元ゲストへ自動復帰しない。「引き継ぐ」「引き継がずにログインする」を明示し、後者では元ゲストの認証と引き継ぎ手続きを失効させる。未統合のアカウント・記録は自動削除しない。確認を終えないままログアウトした場合も失効させる。認証成功後に残すゲスト資格は引き継ぎ確認にだけ使用し、登録者のセッション期限切れでもゲスト本人として復帰させない。OAuthの取消・失敗では元ゲストの認証を維持する。
- 公開チャットの投稿・再送台帳・通報の本人対応も統合先へ移す。送信者を非表示にするための公開識別子は過去投稿で保持する。送信間隔は両者の最新投稿から、投稿停止はどちらかが停止中なら停止として引き継ぎ、過去投稿の送信者識別子からの運営操作も統合先に適用する。同じ発言への重複通報は1件にまとめて最新の通報時刻を保持し、通報回数をリセットしない。統合先の退会時は引き継いだ投稿・送信者情報も削除対象に含める。
- 対局中・マッチング待機中の連携／統合を制限する。終局後の結果からの連携では、検証済みの同じ席に限り保持して進められる。同じ大会に統合先もエントリー済みなら自動合算せず競合として扱う。
- ゲストも大会の順位・表彰対象。1アカウント1エントリー・全ルーム共通1席制限を適用する。別ブラウザの複数ゲストを完全には防げない。名前設定済みゲストも公開チャットの投稿・通報を利用でき、送信間隔・通報上限・投稿停止を登録者と同じ条件で適用する。管理権限は登録者専用とする。
- 既存の禁止行為・通報・利用停止方針をゲスト名にも適用する。新しい自動不適切名判定は追加しない。
- 導入前のゲスト記録を名前や端末保存名で一括取得しない。既存の「終局後に今回の1局を引き継ぐ」経路は互換性を保つ。新しいゲストには全記録を保持できる連携案内へ切り替える。
- 規約・ポリシーへゲストの記録保存・認証期限・復旧条件・連携と統合を反映する。管理画面でゲストと登録者を区別する。

## Google・Discord認証とプロフィール

Google・Discordによる新規登録・ログイン、プロフィール設定、ログアウトを提供します。ログイン中はサーバーが取得した本人のプロフィールでルームへ参加します。本人の対局履歴と戦績はマイページに表示し、公開ランキングはロビーに表示します。

登録者の認証セッションの有効期間は7日、更新間隔は1日です。ゲストは専用Cookieで180日保持します。有効なセッションで通常のアカウント確認や認証を使うAPIへアクセスし、更新時期に達している場合は、DBの期限とブラウザのCookieを更新します。期限切れのセッションを延長することはありません。

- `/login` はヘッダー下で最大560pxのカードを上下左右中央に配置し、低い画面では上からスクロールできます。見出し、登録メリット3項目、認証ボタン、初回設定の説明、戻る操作の順です。「バッジを集めよう」の説明の下にゲーム名付きのバッジ例を表示します。見出し・ボタンは中央、説明文は左揃えにします。初回設定・マイページの配置は維持し、管理画面向けは一般向けメリットとDiscordボタンを表示しません。
- ロビーのヘッダー右上に「登録・ログイン」を表示し、`/login` へ移動します。登録案内とログイン画面には公式アイコン付きの「Googleで続ける」を共通表示し、そこから登録・ログインでき、アカウントがない場合は新しいユーザーが作成される旨を案内します。
- アカウントを持たない旧ゲスト向けの登録案内は [終局後の登録と継続再戦](#終局後の登録と継続再戦) に従い、今回のゲスト対局を引き継げる結果ダイアログだけに置きます。「自分の戦績を残そう」「棋譜を振り返ろう」を表示し、バッジ対象の四人ゲームでは「バッジを集めよう」とゲーム別バッジ例を加えます。CPU戦・ダブルス等の集計条件を説明し、例を本人の獲得状態として表示しません。
- 結果ダイアログでは、今回ゲスト参加した本人だけに登録案内を表示します。結果自体の自動表示は共通のルーム仕様に従い、ログイン状態や参加・観戦に関係なく各対局につき1回です。×・Escape・背景クリックで閉じられます。アカウントを持たない旧ゲスト向けの登録案内は「今はしない」でも閉じられます。
- ヘッダーなど通常の登録導線は元のロビーと旧形式の復帰情報に対応し、作成・参加を自動実行しません。通常ログインの保存不能・破損・期限切れはマイページへ戻します。終局後の専用導線は別のタブ内資格で本人確認・席切替・復帰を処理します。
- 結果からの専用登録では今回の1局と同じ席を引き継ぎます。ヘッダーや直接URLからの通常ログインでは既存のゲスト席・過去局を変更しません。
- 新規ユーザーは `/account/setup` でプロフィールを作成します。設定未完了でログイン中の場合は、ほかの画面を開いても初回設定へ誘導します。認証プロバイダーから取得した名前・画像は新規プロフィールへ自動で設定しません。
- 名前は前後の空白を除いて1〜10文字（絵文字などは見た目の文字単位）です。IDは英数字と `_` の3〜20文字で、大文字は小文字へ統一します。先頭の `@` は入力でき、保存時に除いて表示時に付けます。IDは大文字・小文字を区別せず重複を拒否します。名前の重複は許可します。
- プリセットはTetraBoard独自の将棋駒2種・石4種の6種類です。既存・新規のゲストと登録者は、アップロード画像も保存済みプリセットもなければ内部アカウントIDから固定の自動アイコンを表示します。アカウントを作成しない閲覧者、参照先のない旧ゲスト、CPU、退会者には割り当てません。自動割り当ての候補と順序は固定し、再読み込み・新規連携・将来のプリセット追加で変えません。既存プロフィールの一括更新は行いません。
- 初回設定とプロフィール編集は、アイコンの下に6種類のプリセットを並べます。ゲストも選択でき、プレビュー・枠・チェックで選択を表示し、名前などと一緒に保存します。保存前に閉じた変更は破棄し、保存失敗時は下書きを保持します。登録者はアップロード画像と切り替えられ、アップロード画像の削除では最後に保存したプリセット、未選択なら自動アイコンへ戻します。画像処理・保存中は選択と閉鎖を防ぎます。新規連携ではゲストの選択を保持し、既存登録者との統合では統合先を優先します。
- アイコンは自動割り当て・プリセット選択・連携後の画像アップロードに対応します。JPEG・PNG・WebPの5MB以下の画像を選択し、中央を正方形に切り抜いて256×256のWebPへ変換します。変換後は1MB以下とし、サーバーでも容量・形式・寸法を検証します。
- Google・Discordとの連携済みユーザーは、任意の「ひとこと」と「お気に入りゲーム」を初回設定・プロフィール編集で設定できます。ひとことは前後空白を除いて見た目の文字単位で30文字以内、改行なしとし、絵文字に対応します。お気に入りは全6ゲームから重複なしで最大3つ選び、共通ゲーム一覧の順序で表示します。名前・アイコンなどと一緒に保存し、空欄・選択解除して保存すると削除します。未設定項目は表示せず、既存ユーザーへの自動設定は行いません。
- ひとこと・お気に入りは未ログインでも公開プレイヤー情報カードで閲覧でき、マイページのプロフィールカードにも表示します。カードのアイコン・名前・IDの並びを維持し、その直下にアイコンを指すひとことの吹き出し、お気に入りゲームのタグ、既存の戦績・バッジを並べます。お気に入りのタグはゲームごとの淡い色・20pxの盤面アイコン・名前を表示し、幅が足りなければ折り返します。設定画面は24pxの盤面アイコンと名前を2列で並べ、359px以下は1列にします。選択状態はゲーム色の枠とチェックで示し、3つ選択済みでも未選択ゲームの色・名前を読める濃さを保ちます。ひとことは通常テキストとして折り返して表示します。お気に入りは戦績・棋譜の表示ゲームを変更しません。各画面のカードは現在の設定を取得し、対局の席・棋譜には新項目を保存しません。統合では統合先を優先し、退会受付後は公開しません。
- 名前・ID・アイコン・ひとこと・お気に入りゲームの変更／削除は、フォームの保存でまとめて反映します。入力エラー・ID重複・通信エラーでは入力を保持し、保存中の連打を防ぎます。外部URLのアイコンは使用せず、既存・移行データに含まれていても未設定として扱います。置換・削除した旧アイコンはルームで使われている間保持し、参照がなくなったらR2から削除します。失敗時は毎時の処理で再試行します。ブラウザにキャッシュされた画像は最大1時間残る場合があります。
- ログイン済みのヘッダーには、アイコン・名前・`@ID` のDropdownを表示します。スマートフォン幅ではアイコンと開閉アイコンを表示し、登録者のメニューは「マイページ」「ログアウト」の2項目です。ゲストのメニューには「マイページ」だけを表示します。
- `/account` の本文先頭にプロフィールカードを置き、左にアイコン、右に名前と `@ID`、右上に「プロフィールを編集」を表示します。スマートフォンでは編集ボタンを上段に分け、名前・IDは省略せず折り返します。その下に、ゲームのアイコンと名前を付けた全6ゲームのボタンを横に並べ、選択中のボタンを強調します。画面幅が足りないときはボタンを折り返します。次の段に共通の「シングルス／ダブルス」タブを配置します。651px以上では幅240pxで左にそろえ、650px以下では本文の幅いっぱいに表示します。
- 全6ゲームのロビーで、ログイン済み・プロフィール設定済みユーザーがアカウントメニューの「マイページ」から移動した場合は、移動元のゲームを初期選択します。戦績・棋譜・本文テーマを同じゲームにそろえます。選択情報のない直接アクセスなどではゲームの初期値は四人リバーシです。新しく開いた際の四人ゲームのモードはシングルスとし、ロビーの作成フォームのモードは引き継ぎません。通常リバーシ・通常将棋・五目並べにはモード選択を表示しません。戦績や棋譜が0件でも選択したゲームを維持し、移動後もゲーム・モードを切り替えられます。再読み込み・履歴移動・棋譜往復では現在の選択を復元します。ロビー以外の導線と認証・初回設定・認証後の復帰動作は維持します。
- マイページの本文はヘッダーと同じ最大1148pxで中央に配置し、左右余白も650px以下は20px、それより広い場合は24pxにそろえます。1024px以上では戦績カードを幅560px、間隔20pxで左に、残りの幅を使う棋譜カードを右に並べます。1024px未満は同じ幅で縦に並べ、棋譜を下に表示します。
- 編集ボタンから共通ダイアログを開きます。登録者は初回設定と同じフォームで名前・ID・アイコン・ひとこと・お気に入りゲームを編集します。アイコン中央の半透明のカメラボタンで画像を選択し、画像がある場合は下に「アイコンを削除」を表示します。保存成功時は閉じて表示とヘッダーを更新し、保存前に閉じると変更を破棄します。画像変換中・保存中は操作と閉鎖を防ぎます。 ファイル選択などから戻った際のログイン再確認中や通信失敗でも編集内容を保持し、セッション失効が確認された場合はログインへ誘導します。ログアウトは認証セッションを失効し、ロビーへ戻ります。
- 未ログインで初回設定・マイページを開くとログインへ誘導します。認証状態の取得失敗を未ログインとみなさず、再試行を案内します。OAuthの失敗やキャンセルも日本語で案内します。
- 戦績・本人の対局履歴・四人将棋の戦法別戦績・本人の保存棋譜で401を受けた場合は、ログイン状態を再確認します。同時の401は確認を共有し、同じアカウントで有効なら失敗した取得を一度だけ自動で再試行します。追加履歴は同じ取得位置を維持します。再失敗時は手動の再試行を案内します。ログイン状態の喪失が確認された場合はヘッダーを同期し、ログイン画面へ移動して「ログイン状態が失われました。もう一度ログインしてください。」と表示します。通常の未ログインアクセスではこの喪失案内を表示しません。
- ログイン状態の確認は10秒で打ち切り、通信失敗・タイムアウト・503を未ログインとみなしません。取得済みデータと名前・ID・画像・ひとこと・お気に入りゲームの下書きを保持し、再試行を案内します。別アカウントへの変更時は本人の取得済みデータと下書きを破棄し、新しい本人のデータを取得します。古い認証・データ取得応答で現在の状態を上書きしません。

Google・Discordの公式アイコン付き「Googleで続ける」「Discordで続ける」を共通表示します。レート戦の連携案内では縦に並べ、それ以外は利用可能幅480px以上では左Google・右Discordの等幅2列、それ未満は同じ順で縦に並べます。開始中は両方を無効にし、選んだボタンだけ処理中にします。Discordはメールを取得できるアカウントを対象とし、取得できない場合は理由とGoogleの選択肢を案内します。メール一致でGoogle・Discordを自動統合せず、既存アカウントとの競合時は最初の登録方法でログインするよう案内します。登録者同士のプロバイダー追加連携は提供しません。ゲストからの連携・統合は[ゲストアカウントの確定仕様](#ゲストアカウントの確定仕様234)に従います。管理画面向けはGoogleだけを表示・許可します。

認証はBetter Authと既存D1を使い、D1の接続名は `APP_DB` とします。画像は専用R2 `tetraboard-2026-objects-prod` に保存します。旧版の登録アカウントはGoogle識別子、内部ID、名前、公開IDを保持して移行します。開発者本人の旧アカウントは内部IDとGoogle識別子で除外し、本人は新版の既存アカウントを利用します。ゲストユーザー、旧ルーム、旧セッションとプロバイダーの秘密トークンは移しません。旧棋譜・戦績は通常のアカウント移行に含めず、別途承認された棋譜だけを手動移行します。再ログイン時はGoogle識別子で本人を確認し、メールの一致だけでアカウントを自動統合しません。移行は差分・確認結果の承認後に実施します。手順は [開発手順](docs/development.md#google認証とアカウント移行) に記します。

## 終局後の登録と継続再戦

全6ゲームに適用します。

### ゲストアカウントの連携案内

- 全体が終局した局にゲストアカウントで参加した本人に、結果の下で「アカウントを連携しよう」と案内します。「再戦」「棋譜を見る」はダイアログの最下部に配置します。大会では「次の対局」を使います。再戦は準備を確定する操作につなぎ、ホストは通常どおり対局を開始します。棋譜はルーム内で開きます。
- 対人戦では、GoogleまたはDiscordとの連携で過去の戦績・棋譜・獲得したバッジを引き継げると伝えます。バッジ対象ゲームではそのゲームの例を1つ表示します。CPU戦では、別端末でも同じアカウントで遊べることと、バッジや戦績などのアカウント機能を案内します。
- カードの「Googleで続ける」「Discordで続ける」から退室せずに認証を開始できます。同意文は連携ボタンの下に表示します。連携せずに再戦や棋譜の閲覧に進めます。
- 認証前に本人Cookie・参加資格・前局・ルーム世代を検証し、次局開始が先に確定した場合は処理を始めません。認証中は本人の準備を解除して席を最初の開始から10分保持します。初回設定または既存アカウントとの統合確認を完了すると、全記録を引き継いだアカウントで同じ参加者ID・ホスト権を保って結果に戻ります。対象の既存アカウントが別の席を持つ場合は先にその席の退室が必要です。
- 認証前の中止や認証開始失敗では保持を解除し、ゲストの席と資格を維持します。保持期限を過ぎた場合は席の復帰と連携済みの記録を区別して案内します。マイページから通常の連携を始める場合は既存の退室条件に従います。

### アカウントを持たない旧ゲストの互換仕様

2026-10-13に承認した、導入前のアカウントを持たないゲストの今回の対局の引き継ぎと同じ席での継続再戦の互換仕様です。

- 作成・CPUと遊ぶ・公開一覧／招待・観戦からの参加フォームには登録案内を置きません。共通ナビのアカウント入口と規約・公開情報の説明は維持します。登録案内は、全体が終局した局にゲスト参加した本人の結果ダイアログだけに表示します。観戦者や途中脱落だけでは表示しません。
- 結果から新規登録・既存ログインを始めた本人に、その1局を引き継ぎます。過去ゲスト局の一括取得はしません。対人戦では「この対局を、自分の記録に残そう」「登録・ログインすると、今回の戦績と棋譜がマイページに追加されます。」、CPU戦では今回の棋譜の追加と戦績・ランキングの対象外であることを案内します。公開棋譜にも登録プロフィールが表示されることを認証前に伝えます。
- 同じタブの保存領域へ登録復帰情報と新参加資格を保存・読戻しできてから開始します。保存不能ならOAuthへ移動せず、ゲスト利用を継続できます。通常ログインの保存不能時の扱いは維持します。
- OAuth前にサーバーが参加資格、部屋世代、直前局、本人のゲスト席、再戦待機を確認します。本人の準備を解除して「登録手続き中」を確定し、席・参加者ID・ホスト権・最後の人間だけの部屋も保持します。登録待ち中は本人の準備変更と次局開始を拒否し、参加者に登録待ちと残り時間を表示します。次局開始が先に確定した場合は登録を開始せず、対局を中断しません。
- 席の特別な保持は最初の登録開始から10分、今回の局の引き継ぎ受付は1時間です。同じ対局・席で取消や再試行をしても延長しません。明示取消後は新しい処理として再開し、取消済みの処理から席を変更しません。期限はサーバー時刻で判定し、期限と同時刻は失効です。
- 認証コールバックで本人と当該セッションを固定し、プロフィール・同意完了後に同じ席をアカウント参加へ切り替えます。名前・アイコンを更新し、参加者ID・席・ホスト権を維持します。旧資格と旧接続を失効させ、新資格に切替確定時から通常の接続猶予30秒を与えます。再送で猶予を延長せず、本人の再接続・準備とホストの開始操作で再戦します。次局以降は開始時から登録アカウントの記録になります。
- 全ルーム1アカウント1席を維持します。別席を持つ場合は自動退室させず、そちらを退室して再試行するよう案内します。今回の記録と現在席の切替は別々の進捗を表示し、切替未完了を再戦可能とは表示しません。
- OAuthを開始できなかった場合は登録待ちを解除します。認証画面での取消・失敗後は、再試行するか手続きを中止してゲストへ戻れます。初回設定中にも「登録を中止してゲストに戻る」を用意し、当該処理で認証したセッションだけを終了します。作成済みアカウントは削除せず次回ログインで設定を再開できます。別タブの別アカウントをログアウトさせません。
- 取消・保持期限切れでは通常の接続判定へ戻します。接続中なら準備未完了のゲスト席、切断中なら元の切断時刻から30秒で判定します。期限超過なら席解放・ホスト交代・必要に応じ部屋閉鎖を行います。解放済み席、新しい部屋世代、進行中の次局を遅延応答で変更しません。通信失敗で結果不明なら状態を照会し、ゲストへの自動降格はしません。
- 今回の局は席切替と独立して引き継ぎます。期限内に受付済みの記録は保存遅延で失わせず、部屋閉鎖・番号再利用後も再試行します。保存待ちは「反映待ち」と表示し、席切替済みなら再戦できます。元の結果へ戻れない場合も今回の記録への案内を表示します。
- 戦績・バッジの集計条件は、対局を引き継いだ本人にも適用します。通常ルームのCPU戦は履歴・棋譜のみです。同じ参加分の複数アカウントへの取得、同じアカウントによる同局の複数席取得、再送の重複加算を禁止します。公開・本人・相手の履歴とプレイヤーカードは同じ本人対応と現在のプロフィールを参照します。ゲーム手順・結果・日時・設定は書き換えません。

## 終局データの保存・対局履歴

- CPU戦の対局履歴・棋譜・記録された撃破数は集計対象外でも残します。待機中にCPUを追加しても、開始前に全員削除すれば対人戦として集計します。取得時に集計するため、DB移行・データ削除・再保存は不要です。
- この機能の導入後に開始したすべての対局を、ゲストのみの対局も含めて終局時に保存します。導入前の対局・導入時に進行中の対局を補完せず、終局していない対局は履歴へ追加しません。人間の参加者が全員退室または復帰期限切れになり、未決着で打ち切った対局は保存しません。退室・通信切れでルール上終局した場合は保存します。
- 開始日時、部屋の識別子、ゲーム・モード・時間設定、開始時の定員分の参加者の名前・担当色または担当方向・席順・人間／CPU区分・CPUレベル・内部アカウントIDを保存します。終局時に終了日時、結果、最終盤面、脱落理由、着手・自動パス・脱落を含む棋譜を保存します。将棋は規則バージョン・初期化情報・連番イベントと方向別の撃破数を保存します。参加資格やチャットは保存対象に含めません。保存済み棋譜を含め時間設定は必須とし、時間設定が不明な旧棋譜は保存・公開対象に含めません。
- 終局と同時に対局ごとの保存待ちを永続化します。D1への保存が失敗しても再戦・退室を妨げず、5秒後に再試行します。再戦開始・退室・部屋閉鎖・部屋番号再利用後も保存待ちを保持し、同じ対局の再送で重複や結果の上書きを発生させません。履歴の期限削除は行いません。
- `/account` の棋譜は本文上部の共通ゲームボタンとモードタブで切り替えます。ゲーム・モードの初期選択は、上記のマイページの仕様に従います。開始時に本人のアカウントで参加した対局を開始日時の新しい順に表示し、20件ずつ「もっと見る」で追加します。同時刻は対局UUIDの降順です。結果から本人へ引き継いだゲスト対局も同じ履歴に含めます。観戦と未引き継ぎのゲスト対局は含めません。
- 棋譜カードを縦に並べ、開始日時・ゲーム名のバッジ・モード・手数を表示します。日時は閲覧端末の時間帯で年月日・時分を表示します。シングルスは順位・24pxアイコン・名前を2列でコンパクトに表示し、1位は「優勝」とします。同順位・順位の飛びを保持し、同順位内はリバーシでは黒・白・赤・青、将棋では南・西・北・東の順です。ダブルスは勝利チーム・敗北チームの順に2人ずつ表示し、引き分けは両チームに表示します。
- アカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。未引き継ぎのゲスト・CPUと、退会者ではない参照先のないアカウントの名前は開始時のものを使います。引き継いだ参加分は現在の本人プロフィールを使います。退会者の名前・画像・本人参照は [退会仕様](docs/specs/privacy.md#アカウント削除) に従って除去します。アカウントの画像未設定時は自動プリセット、参照先がない場合は仮アバター、CPUは青いCPUアバターを表示します。履歴のために過去のアイコン画像を保持しません。通常のプロフィール変更では保存した名前や棋譜を書き換えず、次回取得時に反映します。退会時は本人の保存名・アカウント参照を除去します。
- 「棋譜を見る」から `/account/matches/:matchId` の棋譜閲覧画面へ移動します。読み込み・空一覧・失敗と再試行を表示し、追加取得に失敗しても表示済みのカードを残します。ゲーム・モードごとの取得済み一覧を保持し、「更新」で選択中の一覧を先頭から再取得します。戦績・棋譜で共通のゲーム選択とゲームごとのモードを保持し、再読み込み・棋譜からマイページへ戻った場合も復元します。

### 本人棋譜の絞り込み

棋譜カードの見出し・更新ボタンの下に既存の共通タブUIで「すべて／レート戦／対人戦／CPU戦」の4択を置き、初期値は「すべて」とします。スマートフォンでも文字を省略せず4択を表示し、「レート戦にはCPU補充局を含みます。」を補足します。ゲーム・モードと組み合わせて本人の棋譜だけを絞り込み、戦績・ランキングの集計は変更しません。

- レート戦は成立記録で判定し、認定戦・CPU補充局・AI障害などによるレート更新対象外の局も含めます。
- 対人戦はレート戦以外で開始時の定員全員が人間の対局です。ゲスト・大会戦も含めます。
- CPU戦はレート戦以外で開始時にCPUが1人以上いた対局です。CPU補充のレート戦は「レート戦」にだけ含めます。
- 旧ランダムマッチは開始時の参加者で対人戦・CPU戦に分類し、成立記録が矛盾するなど分類できない記録は「すべて」にだけ含めます。既存の「レート戦／大会戦／通常対局／種別不明」の表示ラベルは維持します。
- 保存済みの全対象棋譜からサーバー側で絞り込み、開始日時・対局UUIDの降順で20件ずつ取得します。条件を変えた場合はその条件の先頭へ戻し、別条件の追加取得位置を流用しません。画面内ではゲーム・モード・フィルターごとの一覧と追加取得位置を保持し、再選択時に再利用します。「更新」は現在条件を先頭から取得し直します。
- 選択はゲーム・モードを切り替えても維持し、棋譜から戻った場合・再読み込みでもブラウザ履歴から復元します。アカウント切り替え時は「すべて」へ戻し、別人の選択や一覧を引き継ぎません。
- 絞り込み後が0件なら「この条件に一致する棋譜はありません。」、レート戦非対応のゲーム・モードなら「このゲーム・モードにはレート戦がありません。」と表示します。「すべて」の0件は既存の「まだ対局履歴がありません。」です。取得失敗を0件として扱わず、追加取得失敗時は既存カードを残して同じ条件・追加位置で再試行します。別条件・古い要求の応答を現在の一覧へ混ぜません。

## 最近行われた対局と公開棋譜

- ゲーム別ロビーでは、そのゲームの保存済み終局を最新3件の簡潔な行で表示し、「もっと見る」からゲームのテーマを使う共通ダイアログ内に最大20件の棋譜カードを表示します。ロビーのプレビューは1行4.5remで常に3行分を確保し、少ない場合は余った行を空白にします。長い結果・日時・参加者名は各1行で省略し、詳細では全文を確認できます。ページ内展開は行いません。CPU戦・ゲスト戦・両モードを含め、開始日時の新しい順、同時刻は対局UUIDの降順とします。保存途中・未終局の対局は表示しません。総合ロビーは全ゲームを横断した最新20件を表示します。
- ゲーム別は詳細ダイアログ内、総合ロビーは見出し下の「対人戦のみ」にチェックすると、開始時の参加者全員（ゲームの定員2人または4人）が人間だった対局の最新20件を表示します。ゲストも人間として扱い、CPUが1人でも含まれる対局は除外します。初期状態はチェックなしで、外すとCPU戦も表示します。選択は現在のロビー表示中だけ保持し、再読み込み・ゲーム切替でチェックなしに戻ります。
- ゲーム別の詳細ダイアログは、マイページと共通のモード・日時・参加者・結果・手数の棋譜カードを縦に並べ、内容が多い場合はダイアログ内でスクロールします。ゲーム名のバッジは省略し、総合ロビーとマイページでは表示します。総合ロビーの棋譜カードは幅320pxを基本に狭い画面では一覧幅に収め、間隔12pxで折り返さず横一列に並べます。一覧内だけで横スクロールし、左右に続きがある場合は共通の矢印ボタンを重ねて表示します。
- 最近の対局カードの開始日時は、経過1時間以内なら「〇分前」、1時間を超えて24時間以内なら「〇時間前」を整数切り捨てで表示します。1分未満は「0分前」、ちょうど1時間は「60分前」、ちょうど24時間は「24時間前」です。24時間を超える日時と端末時計より未来の日時は端末の時間帯の年月日・時分を表示します。正確な日時は日時部分のツールチップで確認でき、相対表示は1分ごとに更新します。マイページでは引き続き年月日・時分を表示します。
- 表示時と「更新」で取得し、ゲーム別は詳細ダイアログ内で更新・再試行を行います。総合ロビーは取得成功後に最新が見える左端へ戻します。自動更新・追加取得は行いません。空一覧・取得失敗・再試行を表示し、更新失敗時は既存カードと位置を保持します。
- チェック切替時は旧条件のカードを消して再取得し、読み込み中も条件を切り替えられます。失敗時は選択した条件を保って再試行を案内し、旧条件のカードは表示しません。対人戦の対局が0件なら「対人戦の対局履歴がありません。」を表示します。
- 「棋譜を見る」は `/matches/:matchId` を開き、未ログイン・プロフィール設定前でも閲覧できます。既存の保存済み対局も公開対象です。本人用の `/account/matches/:matchId` は引き続き本人限定です。
- 公開棋譜は局面の指定（[掲示板の仕様](docs/specs/board.md#棋譜の局面の添付)）がなければ最終局面から表示し、リバーシは黒、将棋は南を手前にします。「あなた」は表示せず、局面選択・回転・結果表示を利用できます。「ロビーへ戻る」は対局のゲームへ戻ります。画面の上端に、そのゲームを遊び始める帯を表示します（[公開棋譜から遊び始める](docs/specs/result-sharing.md#公開棋譜から遊び始める)）。参加・ルーム通信・チャットは行いません。公開棋譜画面は検索対象外です。

## 保存済み棋譜の閲覧

終局後の結果から、Xへ共有できます。[対局結果のX共有と棋譜OGP](docs/specs/result-sharing.md)を参照してください。

将棋の棋譜表記は、終局後のルーム内棋譜・本人用保存棋譜・公開棋譜で共用します。通常将棋は「1: ▲7六歩」「2: △3四歩」、四人将棋は「1: 南5六歩」の形式です。先手／南を手前にした固定座標で、右から筋の数字1〜9、上から段の漢数字一〜九を使います。参加者・観戦者の視点や盤面回転で表記を変えません。対局進行中の棋譜一覧は設けません。

駒名は「王・飛・角・金・銀・桂・香・歩」、成駒は「龍・馬・成銀・成桂・成香・と」です。新たな成りに「成」、成る手も合法なのに成らない手に「不成」、すべての打ち駒に「打」を付けます。全対局者を通じた直前の着手と同じ移動先は「同」とし、提案・取消・外部脱落を挟んでも直前手を参照します。曖昧な移動は着手者基準の「上・寄・引・直・左・右」や複合語で識別します。通常の補助語で区別できない四人将棋の龍の縦移動だけ「直」を使います。詳しい条件は[通常将棋の棋譜表記](docs/rules/shogi.md#棋譜表記)と[四人将棋の棋譜表記](docs/rules/four-shogi.md#棋譜表記)を参照してください。▲・△の読み上げ名は先手・後手を明記し、省略しません。

- `/account/matches/:matchId` は開始時に本人のアカウントで参加した対局、または結果から本人へ引き継いだ保存済み対局だけを閲覧できます。未ログインはログインへ誘導し、他人の対局と存在しない対局は同じ閲覧不可の案内を表示します。取得失敗は空の棋譜として扱わず、再試行を案内します。
- 通常ルームと同じレイアウトを使い、棋譜を表示します。開始局面・着手・自動パス・各脱落を矢印とSelectで移動できます。最初の表示・再読み込み・別対局への移動では、局面の指定（[掲示板の仕様](docs/specs/board.md#棋譜の局面の添付)）があればその局面、なければ最終局面から表示します。
- 将棋の棋譜は100イベントずつ取得し、対局ID・規則バージョン・初期化情報・総件数・連続番号を検証してエンジンで再生します。再現した最終状態と保存済みの最終状態が一致しない場合は閲覧を開始せず、エラーと再試行を案内します。保存データを取得後、局面の操作はブラウザ内だけで行います。オンラインルームの取得・参加確認・WebSocket接続は行わず、既存の参加資格を変更しません。部屋閉鎖や番号再利用後も同じ対局を閲覧できます。
- 開始時の参加者・担当色または担当方向を表示し、本人用の初期表示では本人を手前（スマートフォンでは左下）に配置します。リバーシのカードは黒→白→赤→青の時計回り順にし、保存された席番号はホストの識別に使います。アカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。未引き継ぎのゲスト・CPUと、退会者ではない参照先のないアカウントの名前は開始時のものを使います。引き継いだ参加分は現在の本人プロフィールを使います。退会者の名前・画像・本人参照は [退会仕様](docs/specs/privacy.md#アカウント削除) に従って除去します。カードの石数・脱落表示は選択局面に追従し、未来の脱落を表示しません。将棋の初期表示は本人の担当方向を下へ配置し、持ち駒・成り駒・裏王・王手・最終手と選択局面の順位・脱落理由を表示します。同時脱落の群は局面データとカード・結果表示で保持し、棋譜ラベルには付加説明を併記しません。脱落者の石数、接続バッジ、準備状態、時計は表示しません。
- 全ゲームの結果ダイアログは、シングルスを順位色付きの順位バッジ・担当色の石と石数または方角・アイコン・名前の順に表示し、バッジには脱落理由を付けません。同順位と順位の飛びを保持します。リバーシは担当色の石と石数を表示し、脱落者は担当色と「脱落」だけを表示します。結果の順位欄と石色・石数欄は一定の幅を確保し、石数の桁数や脱落表示に関係なくアイコンと名前の開始位置をそろえます。ダブルスも担当色の石と石数または方角をアイコンの前に置き、勝利・敗北チームの順に2人ずつ並べ、引き分けは両チームに表示し、個人順位を付けません。終局理由とリバーシのチーム合計石数も表示します。
- 四人将棋の結果では、各人の方角・アイコン・名前の右側に撃破対象の列を設けます。各行の「撃破：」は表示せず、シングルスでは一覧の上に1つ、ダブルスでは各チームの一覧の上に1つ、共通の列見出し「撃破」を表示します。PC・スマートフォンとも、撃破対象のアイコンと名前を着手順に1人ずつ縦に並べ、見出しと全行・全対象のアイコンの左端を同じ列にそろえます。順位・方角・本人のアイコン・名前の領域を確保し、長い名前は省略せず欄内で折り返します。両モードで受理された着手によって新たに詰んだ相手だけを表示し、同時詰みは全員を含めます。空き王手も着手者へ対応付けます。外部脱落と合法手なしは含めず、戦績の撃破数集計は変更しません。表示は棋譜の選択局面・盤面回転に依存せず最終結果を使います。対象がない場合は撃破欄に「なし」、棋譜の取得中・失敗時は別の案内と再試行を表示します。ルーム内・本人の保存棋譜・公開棋譜で同じ表示を使います。
- ルーム内の前局結果は、その局の名前・担当色／方角・アイコン・CPU情報を保持します。結果から同じ席を登録ユーザーへ切り替えた場合だけ、本人の表示名・アイコンも更新します。退室後も次局開始・部屋閉鎖まで画像を保持し、現在の席にも必要な画像参照は解放しません。旧データで表示情報がない場合は同じプレイヤーIDの在室者情報、なければ仮アイコンを使います。保存済み棋譜のアカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。
- スマートフォン・タブレットの保存済み棋譜では、状況カードに前後ボタンと局面Select、「結果」、回転操作を左から並べます。PCでは「結果」と回転操作を含む状況カードを盤面とプレイヤーカードの下に置き、前後ボタンと局面Selectは盤面領域の右下に配置します。スマートフォンとPCの「結果」ボタンは幅64px以上とし、押すと保存された最終結果を開きます。結果は自動表示しません。着手操作と合法手の点は無効にし、直前の着手枠は選択局面に追従します。
- 準備・開始・参加・投了・退室・招待・ルーム設定・CPU操作は表示しません。ルーム情報は元の部屋番号、ゲーム、モード、持ち時間を表示し、「マイページへ戻る」を設けます。回転ボタンは状況カードの右端に表示します。
- 将棋の保存棋譜の盤面・ルーム情報・結果ダイアログには黄色テーマを使います。マイページの本文は選択中ゲームのロビーと同じ背景・テーマを使い、ゲームボタン・プロフィール編集ダイアログにも同じテーマを適用します。共通ヘッダー・アカウントメニューは緑のままにします。
- PC（1280px以上）のチャット領域には「棋譜閲覧ではチャットを利用できません。」を表示します。1280px未満は「盤面／ルーム」の2タブだけを表示し、タブ切替で局面の選択を保持します。

## 対局種別の表示

- 対局の成立方法を「レート戦」「大会戦」「通常対局」のラベルで表示します。色だけに依存せず、高さ約20pxの文字付きラベルとし、レート戦は青系、大会戦は紫系、通常対局はグレー系の淡い背景を使います。ラベル自体は操作対象にしません。
- 総合ロビー・ゲーム別ロビー・大会詳細のルームカードでは、ゲーム名・モードと同じ情報行へ追加します。「募集中／満員／対局中」、部屋番号、参加人数・CPU、参加・観戦・大会への操作は維持します。狭い幅では情報行だけを自然に折り返します。
- ルームカードの名前は、大会戦が「大会1局目」、レート戦が「レート戦 #1」、通常対局が「○○の部屋」です。大会は大会全体、レート戦はゲーム別に、導入後に部屋を準備する順で1から数えます。本人の対局数や共通ラウンドを意味せず、日付・再起動・設定変更でリセットしません。本番・開発は別々に採番します。
- 通し番号は準備時に固定し、再試行でも維持します。開始前の中止などで欠番を許容し、再利用しません。導入前の予約には追加せず「大会戦」「レート戦」と表示します。右上の5桁の部屋番号と種別ラベルは維持します。大会・レート戦の名前は操作対象にせず、参加者アイコンから情報を開けます。番号付きの名前は共通ルームカードだけに適用し、ルーム情報・共有文・棋譜の名称は変更しません。
- 総合ロビーの最近の対局、ゲーム別ロビーの最近3件と詳細ダイアログ、マイページの棋譜カードに同じラベルを表示します。棋譜カードでは日時・ゲーム・モードの情報行、最近3件ではモード・日時の行へ置きます。「対人戦／CPUあり」と種別は別の情報として併記します。
- 公開・本人用の保存済み棋譜は、盤面下の操作欄で種別を常時確認できます。スマートフォンでも種別ラベルは隠しません。ルーム内の直前局は、棋譜の局面操作欄に表示します。盤面・参加者・結果と局面操作は従来どおりです。
- 認定戦・CPU補充入りも、レート戦として成立した対局は「レート戦」です。AI障害などでレート更新対象外となった局も種別を変えません。通常ルームのCPU戦と、レート戦導入前の旧ランダムマッチは「通常対局」です。レートの更新有無や現在の受付状態で種別を判定しません。
- 過去の保存済み対局も、成立時のレート戦記録と大会台帳を確認して判定します。棋譜JSONや対局結果を書き換えません。判定情報が欠ける旧応答や記録の矛盾は「種別不明」とし、通常対局と決めつけません。取得失敗は既存のエラー・再試行で扱います。

## 戦績の表示

- `/account` のゲームボタンとモードタブの下に「戦績」と「棋譜」のカードを表示し、両方の表示を同時に切り替えます。ゲーム・モードの初期選択は、上記のマイページの仕様に従います。ゲームごとのモードと取得済み戦績を保持します。
- 本人がアカウントで参加したか結果から引き継ぎ、終局結果がD1へ保存された対局をゲーム・モード別に集計します。対人戦は開始時の参加者全員がゲームの定員を満たした人間の対局で、対戦相手のゲストも人間として扱います。
- 四人リバーシ・四人将棋のシングルスと、通常リバーシ・通常将棋では、保存記録でレート戦と識別できる局も集計します。過去の認定戦・CPU補充局・AI障害で代替手を使って終局した局も、人間のアカウント参加者に1局ずつ加算します。人間だけのレート戦も1局として扱います。認定・レート更新の条件とは別です。通常ルームのCPU戦とCPU入りの旧ランダムマッチは対象外です。
- 対局数・順位・勝敗・引き分け・各率・四人将棋の撃破数と完全優勝数に同じ条件を適用します。観戦・未引き継ぎのゲスト参加・未終局・保存待ちの対局は含めません。棋譜一覧の取得件数には依存しません。戦績タイトルの下に、対象ゲーム・モードでは「対人戦/レート戦を集計」、それ以外では「対人戦のみ集計」と表示します。
- シングルスは「対局数」「優勝数・優勝率」「2位数・2位率」「3位数・3位率」「4位数・4位率」を表示します。同順位は保存された順位に1回加算し、同率1位も優勝として数えます。
- 将棋のシングルスは「完全優勝数」「撃破数」「撃破率」も表示します。完全優勝数は本人が他の3人全員を撃破して単独1位になった対局数で、通常の優勝数の内数です。保存済みの過去対局も対象にします。撃破率は累計撃破数を対局数で割った1局あたりの平均撃破人数で、最大3.000です。受理された着手で新たに詰んだ相手1人につき着手者へ1を加算し、同時に2人を詰ませれば2です。CPUによる撃破も対局記録へ含めます。投了・退室・時間切れ・通信切れ・合法手なしとダブルスは数えず、順位・勝敗の判定には使いません。
- ダブルスは「対局数」「勝数・勝率」「敗数・敗率」を表示します。引き分けの行は表示しませんが、引き分けも対局数と率の分母に含めます。
- 戦績は角丸の外枠・薄い横の区切り線を持つ2列の表で表示します。縦罫線は設けず、先頭行にはゲームテーマに沿った淡い背景を付け、数値はラベルより少し大きく表示します。各セルはラベル幅をそろえて数値の左端を列ごとに縦にそろえ、ラベルと数値を間隔を空けすぎず横に並べます。ラベルが折り返す場合も数値は先頭行にそろえます。先頭行は左に「対局数」、四人将棋シングルスだけ右に「完全優勝数」を置き、他のゲーム・モードの右セルは空欄にします。続く行は左に件数、右に対応する率を置きます。戦法別戦績のダイアログも同じ表を使い、使用対局数の右セルは空欄にします。
- 各率は該当件数をそのモードの集計対象の対局数で割り、小数第4位を四捨五入します。先頭の0と `%` を付けず、`.000`・`.333`・`.500`・`1.000` のように小数3桁で表示します。対局数ゼロは各件数0・各率 `.000` とします。
- ゲームの初回選択時にそのゲームの両モードを取得し、戦績タイトル右側の「更新」で選択中ゲームの両モードを再取得します。取得失敗はゼロ件とせず再試行を案内し、更新の失敗時は取得済みの戦績を保持します。

### 四人将棋シングルスの戦法別戦績

- 通常戦績の下に全16戦法のカードを掲載図の順で横一列に並べます。内部No01〜16と既存の戦法IDを固定対応させ、Noは画面に表示しません。カード幅は180px、間隔は12pxとし、一覧内だけで横スクロールします。
- 集計対象の対人シングルスとレート戦（CPU補充を含む）で、本人の確定着手により不成立から成立した戦法を使用経験として記録し、終局・保存後に名前と盤面図を表示します。未経験は「???」と共通の画像プレースホルダーで操作不可とし、読み上げにも実名を含めません。通常ルームのCPU戦・ダブルスでは解放しません。
- 経験済みカードはクリック・タップ・Enter・Spaceで黄色テーマのダイアログを開きます。使用対局数、優勝数・優勝率、2〜4位の数・率だけを表示し、各率の分母はその戦法の使用対局数です。同率1位も優勝へ加算します。完全優勝数と撃破項目は通常戦績に表示します。
- 同じ戦法は1局で1回だけ数え、複数の戦法が成立した局はそれぞれに結果を加算します。戦法別の対局数の合計は通常戦績の対局数と一致しない場合があります。名前は省略せず折り返し、画像は高さ120pxの領域に縦横比を保って全体を表示します。
- 戦法別戦績は保存済みの戦法使用記録を集計します。戦法使用の記録がない過去局・導入時進行中の局は棋譜から補完しません。集計開始時点・集計期間は画面に表示しません。
- 将棋シングルスの選択時に取得・保持し、「更新」で通常戦績と戦法別戦績を更新します。読み込み・失敗を0件や未経験とせず、再試行を案内します。更新失敗時は取得済み表示を保持し、ゲーム・モード切替ではダイアログを閉じます。

### バッジ獲得通知

- 四人リバーシ・四人将棋の登録ユーザーとゲストアカウントの本人に、対人戦またはレート戦のシングルスによる星1の初獲得と星2・星3への昇格を画像付きtoastで通知します。星3以降の累計増加は通知しません。対象条件・閾値・優勝・撃破・完全優勝の定義は既存と共通です。

- アプリ共通の通知管理で、ルームからロビー・マイページへの遷移でも表示中・待機中の通知を引き継ぎます。チャット・招待コピーの既存toastも同じ領域を使い、表示時間は従来の3秒を維持します。バッジ通知は既存toastが終わってから取得します。

- ログアウト・アカウント切替では本人の画面内通知を直ちに解除し、古い取得応答を反映しません。サーバーの未表示通知は本人用として保持し、別アカウントに表示しません。

## ランキングの表示

- 各ロビーのランキングは対象ゲームの保存済み対局だけを集計します。四人将棋シングルスでは、既存の戦績用の累計撃破数もランキングにします。撃破の数え方・帰属・導入前の扱いは[ルール正本](docs/rules/four-shogi.md#戦績用の撃破数)に従います。他ゲームとダブルスには撃破数の項目を表示しません。
- ロビーには初期状態で、レート対応4ゲームはレート、四人五目並べはシングルスの優勝数、五目並べは勝利数の上位3人を表示し、PCは1行3rem、767px以下は1行2.75remで常に3行分を確保します。少ない場合は余った行を空白にし、各行は区切り線と縦中央揃えで表示します。長い名前は1行で省略し、詳細では全文を確認できます。
- 四人将棋・四人リバーシ・将棋・リバーシは、見出し下にレート／優勝数（二人ゲームはレート／勝利数）のコンパクトなタブと自動切替の停止／再開ボタンを置きます。タブの見た目は高さ32px、操作範囲は44px以上で、選択中はゲームテーマ色を使います。左がレート、右が優勝数（二人ゲームは勝利数）で、レートを初期選択します。四人ゲームはシングルスと表示し、五目並べ・四人五目並べは従来の指標と集計範囲の固定表示です。
- 両ランキング取得済みかつレート対象者がいる場合、表示完了から10秒ごとにレート／優勝数を交互に切り替えます。一覧全体を100msでフェードアウトし、切替後に下4pxから150msで表示します。手動操作も同じ演出を使い、連続操作は最後の選択を優先します。動きを減らす設定では演出を省きます。タブの自動切替でフォーカスを移動せず、一覧を毎回読み上げません。
- マウスのホバー・カード内フォーカス・プレイヤー情報表示・ランキング詳細表示・ブラウザ非表示・演出中はタイマーを停止し、解除後に10秒を数え直します。タッチはホバー扱いしません。明示的な停止は再開操作まで保持し、選択と停止は再訪時に初期化します。切替だけでは通信しません。
- 「もっと見る」はロビーの選択から詳細ダイアログを開きます。詳細は手動操作だけで、モードと優勝数／勝利数・レート・対局数・四人将棋シングルスの撃破数を切り替え、各上位10人を表示します。レートは対応4ゲームのシングルスだけで、ダブルスへの切替では勝利数、対応ゲームでシングルスへ戻るときはレートを選択します。詳細の選択でロビーの選択は変えません。
- 件数ランキングは全期間の保存済み対局を戦績と同じゲーム・モード別条件で集計します。掲載する本人は開始時にゲストまたは登録アカウントで参加したか結果から引き継いだ、現在の設定済みアカウントに限ります。詳細に集計範囲と、対戦相手のゲスト・CPU補充のレート戦も対象となることを説明します。
- レートランキングは認定5局を完了し、プロフィール設定済みの登録者の最新の公開整数レートを使います。ゲスト・退会者・統合済みアカウントは除外し、四人ゲームはシングルスだけです。CPU補充局も既存のレート更新に従って反映し、最高到達値・期間別・活動期限・追加の最低局数は設けません。受付停止中も表示します。件数ランキングの集計条件・並び順は維持します。
- 優勝数は確定順位1位を数え、同率優勝も加算します。勝利数はダブルスでは所属チーム、二人用では本人の勝利を数えます。引き分けは対局数に含めます。優勝数／勝利数は1回以上、対局数は1局以上、撃破数は1人以上の人を掲載します。
- 値の降順で、同数は同順位として人数分だけ次の順位を飛ばします。同順位内は現在の公開IDの昇順にし、境界で同数でも表示人数は最大3人／10人です。
- 名前・アイコンは取得時の最新プロフィールを表示します。アカウントの画像未設定時は自動プリセット、読み込み失敗時は仮アバターを使います。内部アカウントIDや棋譜はランキングで公開しません。
- 未ログインでも閲覧できます。ロビー表示時に件数とレートを並列取得し、詳細内の「更新」で両方を更新します。取得状態・失敗・再試行は独立し、初回は3行のスケルトン、レート0件は「まだ認定を完了したプレイヤーがいません。」と表示します。更新失敗時は取得済みデータを保持し、取得失敗を0件として扱いません。

## プレイヤー情報カード

将棋・リバーシ・四人将棋・四人リバーシのレート戦では、情報パネルの戦績の直後に「対局前レート 1550」、認定前は「対局前レート 認定中」を表示します。補充CPUはその局に割り当てた「基準レート 1552」を表示します。対局前レートは成立時に固定して棋譜へ引き継ぎ、認定5局目は認定中、6局目から数値を表示します。認定前の数値と進捗、レートのランク・増減は追加しません。過去のレート戦は保存済みの更新前レート・認定局数・CPU割当記録を使い、復元できない登録者は「対局前レート 記録なし」と表示します。現在値で補いません。

ランキングなど特定の対局に結び付かない入口では、登録者の「現在のレート 1550」または「現在のレート 認定中」を表示します。通常ルーム・大会・それらの棋譜、ゲスト、レート非対応ゲームにはレート欄を表示しません。数値は既存の表示と同じ整数への四捨五入を使います。追加するのは情報パネル内の表示だけで、盤面横のカード・盤面・持ち駒・操作欄の寸法と配置は維持します。

全ゲームの公開ルームのホストと参加者全員、ランキングと詳細、大会順位表、総合ロビーの最近の対局・ゲーム別ロビーの最近の対局ダイアログ・本人履歴の棋譜カード、通常ルーム・公開／本人用棋譜のプレイヤーカードは、アイコンまたは名前からプレイヤー情報を確認できます。空席・ホストなし・退会者は対象外です。

- 登録者は現在のアイコン・名前・公開IDと、表示元のゲーム・モードの戦績をコンパクトな1行の文章で表示します。通常の将棋・五目並べ・リバーシと四人ゲームのダブルスは `20局 12勝7敗1分 (.600)` の形式、四人リバーシ・四人五目並べのシングルスは `43局 3優勝 (.070) 平均2.53位` の形式、四人将棋シングルスは `83局 22優勝 (.265) 平均2.13位 51撃破` の形式です。四人将棋ダブルスに撃破数は表示しません。幅に収まらない場合は文章を折り返し、項目別の縦並びにはしません。
- 平均順位は保存済み順位の加重平均を小数2桁に四捨五入して表示し、同順位も保存済み順位を使います。0局は「平均—位」とします。未ログインでも閲覧でき、戦績はマイページと同じ集計条件で、小数3桁に四捨五入した率を表示します。旧Workerで不足する敗数・引き分け数・平均順位・撃破数は推測せず省略し、取得済みの対局数・優勝数／勝数・率を表示します。別モードへの切替や過去名の補足は表示しません。
- アカウントを持たない旧ゲストは名前・仮アイコンと「ゲスト／ID・戦績なし」、ゲストアカウントは登録者と同じ戦績・バッジに加えて「ゲスト」のラベル、CPUはアイコン・レベルと「戦績集計対象外」を表示します。参照先のないアカウントはゲストとせず、プロフィールを表示できない旨を案内します。退会者以外の保存棋譜は従来の保存名へのフォールバックを維持します。退会者は [退会仕様](docs/specs/privacy.md#アカウント削除) の表示とし、保存名へ戻しません。
- ホバーは300ms後、キーボードフォーカスは即時に開きます。トリガーとカードの両方からポインター・フォーカスが離れて150ms後に閉じ、カードへ移動すれば閉鎖を取り消します。クリック・タップ・Enter・Spaceでは表示を固定し、外側の操作・閉じるボタン・Escapeで閉じます。同時に開くカードは1枚です。
- ホバー／フォーカスではフォーカスを奪いません。明示操作ではカードへ移し、閉じる操作・Escapeでは元へ戻します。Escape後は同じホバー・フォーカスのまま再表示せず、ランキング詳細内のEscapeは情報カードだけを閉じます。画面遷移・背景スクロール・表示元の消失でも閉じます。
- カードは幅280pxを基本として左右16px内へ収め、画面端では配置を反転します。名前・IDは折り返し、元のカードや盤面の寸法を変えません。
- 戦績はカードを開くときだけ取得し、成功結果をページ内で最大60秒再利用します。プロフィール保存成功時は本人、終局検知時は対象ゲームのキャッシュを無効化します。元の棋譜の名前・画像は次回取得時に反映し、自動同期しません。取得失敗を0件やゲスト扱いせず再試行を表示します。

## 共通UIとスタイル

共通ヘッダーは768px以上でロゴ、ホーム、遊び方、直近ゲーム、アカウント、設定を表示します。767px以下は上部にロゴと設定、下部にホーム・遊び方・直近ゲーム・アカウントの固定タブを表示します。アカウントタブはゲスト・登録者の実効プロフィール画像を使い、未ログイン・画像読み込み失敗では従来の人型アイコンを表示します。下部safe areaと本文の余白を確保し、操作対象を44px以上にします。ロビー・アカウント・情報・大会ページへ適用し、対局・観戦・棋譜には追加しません。「お知らせ」は既存のフッター等から開けます。総合ロビーと各ゲームロビーのフッターには「© 2026 chaossi · TetraBoard」を表示します。

総合ロビーの最近の対局、ゲーム別の最近の対局ダイアログと本人の対局履歴は共通カードを使い、ゲーム別ロビーのプレビューは簡潔な行表示を使います。総合ロビーと本人の対局履歴ではゲーム名をルームカードと共通のバッジで表示し、ゲーム別の対局ダイアログではゲーム名のバッジを省略します。長い参加者名だけ小さくし、必要に応じて折り返して順位や他の名前との重なりを防ぎます。手数には保存済み最終局面の着手カウンターを使い、投了・時間切れなどのイベント数を手数として数えません。応答に手数がない場合は表示を省略します。

HeroUIを継続使用し、ヘッダー・ボタン／ボタン風リンク・入力欄・カード・ダイアログ・タブ・アイコンを `apps/web/src/shared/ui/` にまとめます。色・文字・枠線・角丸・影は既存ロビーを基準とした緑の共通テーマを使い、ゲーム部分と大会の開催中表示には対象ゲームのテーマを適用し、共通ヘッダーでは大会リンクだけを対象にします。レイアウト・余白・操作状態は部品内のTailwindクラスで指定します。ログイン・初回設定・マイページも同じ共通部品を使います。

画面全体の配置・背景・盤面サイズ・レスポンシブ境界を維持します。ロビーヘッダーは共通部品にし、ルームには追加しません。CSSはTailwind／HeroUIの読み込み、共通テーマと最小リセット、背景・石の陰影、ダイアログ表示中のぼかし、アニメーション定義に限定し、ページ別CSSは使用しません。

直近ゲームはゲームロビーまたは四人将棋のルールページを開いた時に更新し、有効なGameIdを `localStorage` の `tetraboard:last-lobby-game` へ保存します。未保存・破損時は四人リバーシ、保存領域を使えない場合はメモリ内で保持します。別タブの変更にも同期し、表示名・盤面図・移動先は共通カタログから導出します。四人将棋のルールページでは、共通ヘッダーと下部タブから四人将棋ロビーへ移動できます。対局・観戦・棋譜を開いても更新しません。共通ナビの「遊び方」は `/how-to-play` の[サイト利用ガイド](#サイトの利用ガイド)、各ゲーム右上は既存のルール説明ダイアログです。サイトの利用ガイドは直接アクセスや再読み込みにも対応します。リンクの現在地とキーボード操作を維持します。

プレイヤーカードは4席とも親レイアウトから決めた同じ幅・高さを使います。高さは768px以上で60px、スマートフォンで48pxに固定し、盤面の縮小では変えません。スマートフォンの上下paddingは1pxとし、中央揃えによる追加の外側余白を残しません。アバターは通常32px／スマートフォン26pxで、右下の接続バッジを表示します。最大10文字の名前と王冠は一まとまりで実測し、省略・折り返しせず表示します。画面幅変更・フォント読込・タブ再表示でも再計測します。

名前・アバター・下段情報の領域を固定し、準備完了の有無や時計／順位の切替で他要素の位置・寸法を変えません。石と石数・順位の縮小はカード幅だけで決め、脱落状態では変えません。320pxを含む指定幅で、10文字名＋王冠・2桁の石数・最長の脱落理由が同時に収まる設計とします。

### サイトの利用ガイド

`/how-to-play` は「TetraBoardの使い方」として、ゲーム共通の基本操作、大会、アカウントと設定を実画面のスクリーンショット付きで案内します。ゲーム選択・CPU対戦・友達の招待・公開ルームへの参加と観戦・対局画面・棋譜と記録・大会参加・アカウントと設定の8章で構成し、目次から各章へ移動できます。スマートフォンの操作を中心に、PCの画面配置も補足します。閲覧にログインやプロフィール設定は不要です。

初期HTMLには8章の本文と11枚のスクリーンショットを出力し、JavaScriptなしで読めるようにします。本番では検索対象にし、正規URLの `https://tetraboard.net/how-to-play` をサイトマップに掲載します。titleは「遊び方ガイド｜CPU対戦・友達の招待・大会への参加 | TetraBoard」、descriptionは「TetraBoardの使い方を画面のスクリーンショットで解説します。ゲームの選び方、CPU対戦、招待URLで友達と遊ぶ方法、公開ルームへの参加と観戦、棋譜の見方、大会への参加、アカウントの設定まで案内します。」です。構造化データのパンくずは「ホーム > 遊び方ガイド」です。

操作例は四人リバーシを中心とし、大会は四人将棋を使います。個別ゲームの駒・石の動かし方や勝敗ルールは各ゲームの「遊び方」で説明し、共通ガイドとは分けます。スクリーンショットは操作例であり、現在の募集状況や大会開催状況を示すものではありません。

通常ルームはCPU戦もホストの「対局開始」で始まり、人間同士では全員の「準備完了」が必要です。友達へ招待URLを送った部屋も公開対象です。大会はエントリー確定後、開催中に「対局する」で待機し、4人が入室するとカウントダウン後に自動開始します。ゲストも記録を保存でき、CPU戦は履歴・棋譜に残ります。Google・Discordへの連携は、Cookie削除や別端末でも記録を使うための案内として説明します。

## 管理画面

`apps/admin` は運営のための独立した React アプリで、`/admin` で開きます。Google でログインした本人のアカウントを、サーバーの `ADMIN_ACCOUNT_IDS`（内部 `user.id` の JSON 配列）で限定し、HTML・アセット・管理 API で確かめます。権限の設定がないときと認証の障害は 503、未認証の API は 401、別のアカウントは 403 を返します。管理の応答はキャッシュしません。

画面は、分析の「KPI」と、運営の「公開チャット」「掲示板」「フィードバック」「お知らせ」「大会」です。掲示板の運営は[掲示板の仕様](docs/specs/board.md#通報と運営)にあります。管理メニューは PC では左側に、スマートフォンとタブレットでは画面選択欄に表示します。

KPI の定義と計測の仕組みは [計測の仕様](docs/specs/analytics.md) にあります。訪問数・ページビュー・表示速度は、Cloudflare のダッシュボードの Web Analytics で見ます。

## フィードバック受付とお知らせ

ゲスト・登録者・プロフィール未完了の利用者は、全ロビー、全ゲームのルーム情報、ルーム・棋譜の取得エラー画面、直接URL `/feedback` から「不具合・ご意見」を送れます。ルームではダイアログで開き、入力中も接続・対局・時計は進みます。公開要望一覧、投票、個別返信、投稿履歴、メール通知は提供しません。投稿原文と画像は管理者だけが閲覧し、受付番号から内容を取得する機能はありません。

ルーム情報の「不具合・ご意見」は、押せることが伝わるように共通のsecondaryボタンを使い、枠線と背景を持つ全幅のボタンとして表示します。

### 終局後の星評価

全6ゲームで、ゲスト・登録ユーザーの参加した局が全体として終局し、本人が結果ダイアログを閉じた後に、星1〜5の評価と任意コメントを送れるダイアログを表示します。観戦者と途中脱落だけでは表示しません。CPU戦・対人戦、投了・時間切れを含む終局が対象です。評価は必須、コメントは既存受付と同じ数え方で2,000文字以内です。スキップや閉じる操作で回答せずに戻れます。入力中も接続・対局・時計は進みます。

表示済みの記録は同一オリジンのブラウザのlocalStorageに保存し、全ゲーム・ゲスト・登録ユーザーで共有します。送信の成否や回答の有無にかかわらず、再戦・再読み込み・ログイン後も再表示しません。導入前の対局経験は判定せず、表示記録がない既存利用者も対象です。別端末・別ブラウザ・保存データの削除後は別扱いです。保存領域の読取・書込ができない場合は自動表示を省略します。文章はlocalStorageへ保存しません。

星評価は既存の非公開フィードバック受付へ「その他のご意見」として保存し、同じ認証・送信上限・180日の保存期限・削除を適用します。投稿者のゲスト／ユーザー区分は送信時のサーバー認証、CPU戦／対人戦は終了した局の参加構成を使います。CPUが1人でも参加した局はCPU戦です。送信失敗では星・コメントを保持し、同じ入力の再試行は重複登録しません。星評価と対戦区分がない既存投稿を、星ゼロや対人戦として補完しません。

管理画面の一覧・詳細に星評価・コメント・投稿者区分・対戦区分を表示し、投稿者・対戦区分・星評価で絞り込めます。星評価は管理者だけが閲覧できます。

### 任意の不具合・ご意見

- 種別は不具合・機能の要望・その他のご意見。種別と内容は必須で、対象は開いた画面のゲームを初期選択します。内容は1〜2,000文字、期待・目的は任意500文字、再現手順は不具合だけに任意1,000文字まで。前後の空白を除き、Unicodeコードポイントで数えます。
- JPEG・PNG・WebPを任意で1枚添付できます。元画像5MiBまで、長辺1,600px以内に縮小した静止WebPは1MiBまで。変換後のプレビューと取り消しを提供し、画像内の名前・チャットは利用者が隠してから添付します。自動撮影・画像編集は行いません。
- 不具合では技術情報の添付を初期ONにし、取り消しと内容確認が可能です。画面種別、対象ゲーム、ブラウザ、画面サイズ、ビルド識別子、ルームでは部屋ID・世代・将棋の局IDを送ります。リバーシは既存の公開状態に局IDがないためnullです。URL全文・招待クエリ・参加資格・チャット・盤面は送信しません。
- 通信・保存・認証失敗時は入力と画像を保持します。同じ画面では閉じて開き直しても保持し、送信成功か画面離脱で破棄します。ブラウザの永続ストレージには文章・画像を保存しません。送信完了はD1と任意画像の保存が完了した場合だけ表示し、同じ送信の再試行は重複登録しません。
- 投稿から180日で本文・画像・技術情報・投稿者識別・編集履歴を閲覧・集計から外し、毎時処理で削除します。削除失敗は次回再試行します。運営による削除は直ちに非表示にし、画像などの物理削除は同じ定期処理で行います。長期の開発課題は個人情報を除いて手動でIssueへ整理します。投稿者の退会時は180日期限前でも [退会仕様](docs/specs/privacy.md#アカウント削除) に従って原文・画像等を削除します。
- 受付は登録者ならアカウント、ゲストなら専用Cookieのブラウザを識別します。計測Cookieとは共有しません。同じアカウント・ブラウザは10分の固定窓に5件、24時間の固定窓に20件、同一IPは10分の固定窓に30件まで。窓はUTCのUNIX時刻を基準に切り替えます。IP原文を保存せず、専用secretで識別値をハッシュ化します。Cookie・端末変更、登録前後は同一人物として統合しません。

管理画面の `/admin/feedback` では50件ずつ新着順に表示し、種別・対象・対応状況・優先度・テーマで絞り込めます。詳細・添付画像・更新・削除を含め、既存の管理者認証で保護します。初期状態は「未確認」・優先度「通常」です。確認中・対応予定・対応中・完了・見送り・迷惑投稿、優先度高・通常・低、テーマ1つ、運営メモ、関連GitHub Issueを記録できます。見送りは理由、完了は本番公開の確認を必須とします。同時編集は更新番号で検出し、編集者・日時・変更前後を記録します。運営は原則翌日までに新着を確認しますが、利用者への修正期限は約束しません。

テーマ別に過去180日の投稿数とアカウント・ブラウザ単位の報告者数を表示します。運営・テスト投稿と迷惑投稿は初期除外し、内部投稿は明示的に含められます。未確認件数、最古の未確認の経過時間、初回確認時間の中央値も表示します。投稿数だけで開発順を決めず、困りごとの深刻さ・利用と継続・実装負担を合わせて判断します。投稿数は売上見込みではありません。

公開後30日でテーマと確認速度を見直し、次の改善を選びます。課金や売上測定は今回追加しません。

## お知らせの管理とロビー掲載

お知らせは既存のロビーフッターやロビーの告知から開きます。共通ヘッダーはホーム・遊び方・直近ゲームに加え、設定ボタンのすぐ左にお知らせのベルを表示します。`/updates` は公開記事の日付・種別・タイトル・説明文の冒頭を20件ずつ表示し、「もっと見る」で次のページへ進みます。`/updates/:id` は説明文全体と一覧へ戻るリンクを表示します。ゲスト・プロフィール未設定の利用者も閲覧でき、一覧・詳細は検索対象に含めません。取得失敗時は再試行を案内し、非公開・存在しない記事は見つからない案内を表示します。

管理画面の `/admin/announcements` では公開・非公開を含む記事を50件ずつ表示し、新規作成と編集ができます。記事はタイトル（必須1〜80文字）、説明文（必須1〜2,000文字）、日付、種別（改善・新機能・大会告知・その他）、公開状態、ロビー掲載先を持ちます。文字数は前後の空白を除いてUnicodeコードポイントで数え、説明文の改行を保持します。HTML・Markdown・画像は扱わず、投稿原文・個人情報・画像を転載しません。新規記事は非公開・掲載先なし・種別その他で、日付は日本時間の当日です。

日付は表示と並び順に使用し、公開予約には使いません。公開記事は日付・登録日時・IDの降順に並べ、編集しても登録日時を変更しません。管理者が内容・公開状態・掲載先を「保存」でまとめて反映します。保存失敗と同時編集の競合では入力を保持し、最新データを明示的に読み直すと保存済み内容へ置き換えます。記事と掲載先は一括保存し、権限を失った場合は管理データを破棄します。削除機能は設けず、公開終了には非公開を使います。

ロビー掲載先は四人リバーシ・四人将棋・リバーシを複数選択でき、未選択なら公開一覧だけに掲載します。公開状態と掲載先は独立して管理します。全ゲームのロビーはタイトル・説明・遊び方の下、対局開始ボタンの上に、対象となる公開記事の最新1件を表示します。PCでも本文の全幅を使い、スマートフォンでは操作ボタンの直前です。小さめの文字と余白のコンパクトな告知枠とし、「お知らせへ」はPCでは右側、スマートフォンではタイトルの横に置きます。タイトル、前後の空白と改行を正規化した説明文の最初の行、「お知らせへ」リンクだけを表示し、リンクは該当記事の詳細へ移動します。画面幅による折り返しは許可します。対象なし・取得中・取得失敗では枠と余白を出さず、対局操作を妨げません。ゲーム切り替えで以前のゲームの記事を残しません。

記事はD1で管理し、デプロイなしで更新できます。変更は次の画面表示・再読み込みから反映し、自動更新は行いません。既存の改善のお知らせはID・日付・内容を維持して公開記事へ移し、初期のロビー掲載先は設定しません。記事管理では固定表示・公開予約・自動掲載終了・大会の参加受付は提供しません。本人の既読は下記のベル機能で管理します。大会の受付・管理は[大会専用の仕様](docs/specs/tournament.md#四人将棋大会の確定仕様)として実装します。

### ベルのお知らせ一覧と既読

2026-11-07に開発者が以下の仕様を承認しました。

- PC・スマートフォンとも共通ヘッダーの設定のすぐ左にベルを置き、全体・個別のいずれかに未読があれば赤丸を表示します。件数は表示しません。対局画面にベルは追加しません。狭い画面でも操作領域を保つため、429px以下の開催中大会リンクはトロフィーだけにし、大会名と残り件数は読み上げ名で伝えます。
- ベルは共通ダイアログで一覧を開き、「運営からのお知らせ」「大会結果」「バッジ」のラベル、タイトル、日本時間の通知日時、未読の表示を付けます。一覧の更新は更新アイコンだけの枠付きボタンとし、読み上げ名を「お知らせを更新」にします。「すべて既読にする」は文字付きの枠付きボタンで表示し、更新・一括既読・詳細から戻るボタンは高さ36pxのコンパクトな表示にそろえ、更新・戻るのアイコンは16pxとします。通知番号の新しい順に20件ずつ追加取得し、記事の日付の変更では並べ直しません。分類タブ・削除操作・任意の相手への手動送信は提供しません。
- 項目を選ぶと同じダイアログ内で全文・表彰内容・バッジ画像と獲得または昇格内容を表示し、元記事・大会結果・該当ゲームを選択したマイページへのリンクを置きます。ダイアログの「お知らせ」見出しと閉じるボタンは上部に固定し、長い一覧・詳細は本文領域だけをスクロールします。詳細の「一覧に戻る」は左矢印だけのボタンとして下部の操作欄に固定し、読み上げ名も「一覧に戻る」とします。一覧へ戻ると項目とスクロール位置を保持し、選択した項目へフォーカスを戻します。閉じるとベルへフォーカスを戻します。
- 全体通知は記事の初回公開時だけに1件生成します。編集・再公開は通知を増やさず、非公開中は一覧・詳細・未読判定から外します。ロビーの告知・記事一覧・既存URLは維持します。
- 大会結果の確定と同時に、登録ユーザーとゲストアカウントの表彰対象者本人へ通知します。同率優勝・同率準優勝は全員が対象です。同率優勝で2位が存在しない場合や対局不成立では準優勝通知を作りません。結果待ち・途中順位では生成しません。
- バッジは既存の対象条件で、保存が確定した初獲得と星2・星3への昇格を本人へ通知します。同じ対局の複数獲得は1件にまとめます。画像内の累計は獲得時点の値です。既存のバッジtoastを維持し、toast表示済みとベルの既読を別に扱います。大会結果のtoast・通知音は追加しません。
- 一覧を開くだけでは既読にせず、詳細の表示成功後に記録します。記事詳細を既存URLから直接開いた場合も同じ記事を既読にします。「すべて既読にする」は操作時に取得済みの通知番号上限までを対象とし、未取得の古いページも含めます。その上限より後の新着は未読で残します。
- 登録ユーザー・ゲストアカウントの既読は本人単位でサーバーへ保存し、同じアカウントの別端末でも共有します。アカウントのない閲覧者には全体通知だけを表示し、既読をブラウザへ保存します。保存できない場合は画面内で反映し、再読み込み後に保持できない旨を案内します。
- ヘッダー表示中かつ本人確認後に最新20件を裏で先読みします。取得済みならベルを開いた瞬間に一覧を表示し、裏で最新情報を確認します。先読みが完了していない初回だけ読み込み表示にします。項目の詳細も取得済みの本文からすぐ表示し、先読み自体では既読にしません。同じ本人の画面遷移・閉じて再表示・認証再確認では最新20件をメモリに保持し、再読み込みや本人切替では破棄します。
- ヘッダー表示中かつページ前面表示中は30秒ごとに未読を確認し、新着の番号上限が変われば先読みも更新します。ベルを開いたとき・表示復帰・オンライン復帰にも未読を確認し、一覧はベルを開いたとき・更新操作・追加取得で読み直します。重なった取得は共用し、裏の再取得中も表示済みの項目を選択できます。失敗時は既存表示と赤丸を保持し、空一覧と区別して再試行できます。取得中に確定した既読を古い応答で戻しません。非公開化を再取得または既読保存で確認した通知は表示から外します。通知通信は10秒で中止し、対局を妨げません。
- 個別通知・既読情報は期限なしで保持します。新規登録時は引き継ぎ、既存アカウントとの統合では双方の履歴を移し、同じ元イベントはまとめて既読を優先し、その他の未読を維持します。ログアウト・認証確認中・本人切替では個別表示を隠し、古い応答を破棄します。退会時は通知・既読を削除し、遅延保存による復活を防ぎます。
- 導入時点の公開記事は履歴へ含めて既読相当とし、過去の大会結果・バッジ通知は追加生成しません。旧バッジtoastの未表示分は維持します。既存の非公開記事は過去の公開履歴を判定できないため、導入後の公開を初回公開とします。初めて利用する人は、その時点の全体記事を既読基準にしますが、本人宛の通知は既読にしません。

## MVP機能

初期MVPは四人リバーシを対象としました。四人将棋もオンライン対局へ接続し、全ゲームで共通のルーム機能を利用します。全ゲームの終局保存・本人の戦績と棋譜・ゲーム別ランキングを利用できます。

### 対局

- 四人リバーシの合法手、手番、パス、終局、順位の判定
- 持ち時間の表示と時間切れによる脱落
- 「CPUと遊ぶ」から、1人とCPU 3体で始められる対局
- 人間とCPUを組み合わせた1〜4人での対局
- CPUによる合法手の選択と、最低限の局面評価
- 対局終了後の再戦
- 同じ部屋で、直前1局を次局開始まで振り返る棋譜モード
- 終局データ・棋譜の保存と、マイページでの本人の対局履歴・戦績

### オンライン機能

- ニックネームを使ったゲスト参加と、ログイン中のアカウント参加
- 対局部屋の作成
- URLを使った招待
- 公開ロビーでの対局部屋の一覧表示・参加・観戦
- ゲーム別の最近の対局一覧と、保存済み棋譜の公開閲覧
- モード別の優勝数／勝利数・対局数ランキング
- 席へのCPUの追加と削除
- 盤面と手番のリアルタイム同期
- 対局中の通信切れからの復帰
- 対局の観戦
- 対局部屋の共通チャット

### 初めて利用する人のための機能

- 四人リバーシのルール説明
- 石を置ける場所や現在の手番の分かりやすい表示
- PCとスマートフォンの両方に対応した画面
- エラー発生時の分かりやすい案内
- 簡単なフィードバックの送信
- 対局の開始、完了、エラーを把握するための計測

### MVPに含めないもの

- 駒落ち・追加の対局モード
- レーティング
- 他プレイヤーの戦績閲覧
- 課金
- 高度なCPUや機械学習による思考

### 四人将棋のゲームエンジン

四人将棋のルール正本と調査資料は [四人将棋ルール](docs/rules/four-shogi.md) に記す。独立した `@tetraboard/four-shogi` パッケージに、シングルス・通常のダブルスと三人攻撃禁止のON／OFF切り替えを実装している。初期化、合法手、王手、着手、脱落、順位・勝敗、千日手を純粋な関数で扱い、状態はJSONで保存・復元できる。CPUは合法手からランダムに選ぶLv1と、駒の価値・王の安全・次の手番の応手を評価するLv2を利用できる。Lv2は探索する候補と応手を制限するため、読み落としがある。使い方と確認方法は [開発ドキュメント](docs/development.md#四人将棋エンジン) を参照する。エンジンとCPUはオンラインルームへ接続し、時刻・接続期限はルーム側で管理する。 オンライン対局の千日手履歴は必要な局面キーだけをSQLiteから取得し、変更分を保存する。対局の長さに比例した全件読み取りを各手で行わない。

## KPI・KGI

### KGI

1か月のMVP開発におけるKGIは、次の状態を実現することです。

> ユーザーが自力で四人リバーシの対局を最後まで完了し、その一部が7日以内にもう一度対局する。

最低成功ラインは次のとおりです。

- 初回対局完了者が10人以上いる
- 7日以内の再対局者が3人以上いる
- 完了対局が合計30局以上ある

開発者との個人的なつながりの有無を問わず集計します。

### KPI

| 観点     | 指標                              | 1か月目の最低目標 |
| -------- | --------------------------------- | ----------------: |
| 流入     | 訪問者                            |              30人 |
| 対局開始 | 訪問から対局を開始した割合        |           40%以上 |
| 対局完了 | 開始した対局の完了率              |           70%以上 |
| 継続     | 初回対局完了者の7日以内の再対局率 |           20%以上 |
| 利用量   | 完了対局数                        |          30局以上 |
| 満足度   | 「また遊びたい」と回答した割合    |           70%以上 |
| 品質     | 対局を続行不能にする重大障害      |   最終検証時に0件 |

利用者が少ない初期段階では割合が大きく変動するため、KPIは割合だけでなく実数も併せて評価します。最初の1か月は売上を成功条件にせず、継続して遊ばれる価値があることを確認した後に収益化を検討します。
