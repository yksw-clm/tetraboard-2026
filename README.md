# TetraBoard

## 概要

TetraBoardは、四人用ボードゲームをブラウザですぐに遊べるオンライン対局サービスです。

最初に提供するゲームは四人リバーシです。四人全員を集めなくても遊べるようにCPU（BOT）を用意し、1人でのプレイから、友人を招待した対人戦まで同じ仕組みで楽しめることを目指します。

初期の主な対象は、リバーシなどのボードゲームが好きで、少し変わったゲームを気軽に試したい人です。ユーザー登録やアプリのインストールを必要とせず、初めて訪れた人が迷わず対局を始められる体験を重視します。

旧TetraBoardとは別のプロジェクトとして開発し、当面は旧版を置き換えません。新しい土台の品質と利用状況を確認しながら、将来のゲーム追加や移行を判断します。

## プロジェクトのきっかけ

開発者は幼い頃から、パソコンで文章やファイルを作ったり、ゲームを開発したりして、それを誰かに使ってもらうことに喜びを感じてきました。

プログラミングを学び始めてからは、クイズゲームやRPG、配信で利用できるしりとり・山手線ゲームの支援ツール、四人オセロなどを制作しました。友人や小さな配信コミュニティがそれらを使い、楽しんでくれた経験が、Webエンジニアを目指す原点になっています。

一方、旧TetraBoardの開発では多くをAIに任せた結果、コードや設計を自分自身で十分に理解できず、「自分が作ったものを使ってもらう」という実感も薄くなってしまいました。

TetraBoardを新しく作り直すのは、単に旧版のコードを整理するためではありません。自分で考え、理解し、納得して作った遊びをもう一度誰かに届けるための再出発です。

## プロジェクトの目的

TetraBoardのプロダクトとしての目的は、プレイヤーを集めにくい四人用ボードゲームを、一人でも複数人でも気軽に始められるオンラインの遊び場として提供することです。遊ぶ人だけでなく、観戦する人も含めて、ゲームをきっかけに人が集まり、楽しめる場所を目指します。

開発プロジェクトとしては、次の状態を目指します。

- 開発者が主要な仕様と設計を自分の言葉で説明できる
- 技術やライブラリを採用した理由を理解している
- 機能数よりも、初めて訪れた人が遊び終え、再び遊びたくなる体験を優先する
- 継続的な利用を確認したうえで、将来の収益化につなげる

## 読み込み・処理中・エラーの表示

ロビー・ルーム・保存済み棋譜の画面全体を読み込む間は、ロビーと同じ背景の中央にスピナーと案内文を表示します。ゲームが判明している場合はそのゲームのテーマを使い、未取得の場合は共通の緑を使います。ルームが見つからない場合を含むルーム・棋譜のエラーも、中央に案内文と戻る・再試行などの操作を表示します。

Webの操作ボタンは、作成・参加・棋譜への移動・更新・送信・保存などの処理中に、押したボタンの文字とアイコンをスピナーに置き換えます。ボタンの寸法と読み上げ名を保ち、重複操作を防ぎます。失敗時は再操作でき、入力値や取得済みデータの保持方針は維持します。初回取得や条件切り替えの案内は表示し、自動更新や別の操作による無効化ではスピナーを表示しません。

## 四人リバーシのロビー

`/games/four-reversi` は四人リバーシ専用のロビーです。本番のトップURL `/` はクエリを保持してHTTP 308でこのロビーへ転送します。開発環境・画面内遷移では履歴を置き換えて転送します。

両ゲームのロビーではヘッダー直下に「四人リバーシ／四人将棋」の切り替えリンクを表示します。現在のURLに対応するゲームを選択表示し、PCではコンパクトな横並び、スマートフォンでは幅を2等分・高さ44px以上にします。アカウント画面やルーム画面にはこの切り替えを表示しません。

公開ルームの初回取得中は読み込み案内を表示します。10秒ごとの自動更新中は一覧・0件表示を保ち、読み込み案内やスピナーを表示しません。手動の「更新」では一覧・0件表示を保ち、その上に読み込み案内と更新ボタン内のスピナーを表示します。取得中は定期更新をスキップし、手動更新を中断しません。成功時は最新の一覧へ更新し、失敗時は取得済みデータを保ってエラーを案内します。

- タイトル「四人リバーシ」の左に初期盤面図を表示します。スマートフォンでも盤面図を表示し、「遊び方」はタイトル下の行に配置します。
- ロビーは768px以上で上段に操作カードとランキングを等幅2列、その下に公開ルームと最近行われた対局を表示します。767px以下では操作カード、公開ルーム、最近行われた対局、ランキングの順に縦並びにします。読み上げ・キーボード操作の順も表示順と一致させます。
- 操作カードは「一人で遊ぶ」「すぐ遊ぶ」「みんなで遊ぶ」「ルームを作る」「ルーム番号で参加」の順です。各ボタン内はタイトルと小さい説明の2段とし、「CPU3人と対戦」「友達を招待して、一緒に対戦」「5桁の番号を入力して合流」をそれぞれ基本1行で表示します。
- 主な入口は「すぐ遊ぶ」とし、公開ルームがなくてもCPU対戦やルーム作成から遊び始められます。CPU対戦の説明は「すぐ遊ぶ」ボタン内に置き、操作エリアには盤面図を表示しません。
- 作成・参加ボタンを押すと、必要な項目を入力するダイアログを開きます。
- 作成と「すぐ遊ぶ」では、ゲストはニックネームを入力し、ログイン中はアカウントの名前・アイコンを確認します。対局モードと持ち時間・秒読みを選択します。モードの初期値はシングルス、時間は5分＋30秒です。番号からの参加では5桁のルーム番号を入力し、ゲストはニックネームも入力します。公開一覧からの参加では選択したルーム番号を表示します。入力値はロビーを表示している間保持します。ゲスト名の初期値には、登録からの復元入力があればそれを使い、なければ両ゲーム共通の保存済みゲスト名を使います。
- 「すぐ遊ぶ」は待機室へ進み、ホストが「対局開始」を押してから対局を始めます。ログイン中のダイアログではCPU対戦の説明の直下に「CPUを含んだ対局は、戦績に反映されません。」と「ランキングにも反映されません。終局した対局の履歴・棋譜は保存されます。」を常時表示します。ゲストと通常の作成・参加ダイアログには表示しません。
- 公開ルーム一覧の「ルーム」欄はホストのアイコンと太字の名前、その下にグレーのルーム番号を表示します。対局モード、CPUを含む席数（`2/4`など）、対局前／対局中の状態を表示し、「満室」の文字は表示しません。席数の右に4つの丸ぽちを並べ、左から人間は緑、CPUは青、空席はグレーで示します。人間・CPUの内訳のテキストは表示せず、読み上げ用ラベルで伝えます。対局中の席数は開始時の構成です。対局前で空席のある部屋には参加でき、すべての部屋を観戦できます。観戦にニックネーム入力は不要です。
- スマートフォンの公開ルーム一覧は最大400pxとし、それを超えた分は一覧内で縦スクロールします。少数件は内容に応じた高さにします。見出し・更新・エラー・補足・「もっと見る」はスクロール領域の外に残し、PCの一覧には高さ制限を設けません。
- 「遊び方」はロビー内のダイアログで説明します。下部に「不具合・ご意見」「改善のお知らせ」と最新のお知らせを表示します。公開ルームの下に、そのゲームの「最近行われた対局」を表示します。

ロビーのボタン・カード・ダイアログ・入力欄・モード選択・対局状態表示にはHeroUIを使います。作成・すぐ遊ぶ・待機ルームのラジオ選択は丸・文字・間の余白を操作でき、未選択の丸は白背景とテーマの文字補助色の1px枠線で表示します。淡い灰緑の背景と緑のアクセントを共通のテーマとし、「すぐ遊ぶ」を主な操作として配置します。
- PCとスマートフォンに対応し、スマートフォンでは操作・公開ルーム・最近行われた対局・ランキングを縦に並べ、公開ルームをカードで表示します。

## 四人将棋のロビー

`/games/four-shogi` に四人将棋のロビーUIを表示します。レイアウトと入力・遊び方のダイアログを四人リバーシと共通化し、見出し・説明・遊び方を将棋に合わせます。

- タイトル「四人将棋」の左に、既存の盤・駒画像を使った9×9・36枚の初期盤面図を表示します。南を手前に固定し、盤画像の縦横比458:500を保ち、左へ7度傾けて影を付けます。幅は768px以上で88px、767px以下で56pxにします。盤面図は装飾で操作できず、入力中のモードには連動しません。スマートフォンでも表示し、「遊び方」はタイトル下の行に配置します。

- 「すぐ遊ぶ」「ルームを作る」「ルーム番号で参加」から入力ダイアログを開けます。ゲストは名前、ログイン中はプロフィールを確認し、作成時はモードと持ち時間・秒読み、参加時はルーム番号を入力できます。初期モードはシングルスです。
- ロビーの配置はリバーシとそろえ、768px以上では上段に操作カードとランキング、その下に公開ルームと最近行われた対局を表示します。767px以下では操作・公開ルーム・最近行われた対局・ランキングの順に並べます。
- 作成・すぐ遊ぶ・参加・観戦と公開一覧を利用できます。公開一覧はゲーム別に取得します。三人攻撃禁止は作成時に変更でき、既定値はONです。
- ランキングのカードと詳細ダイアログはリバーシと共通のUIを使い、モード・集計項目を切り替えられます。将棋の保存済み対局だけを集計して取得し、更新・再試行に対応します。詳細ダイアログも黄色テーマを使います。
- 入力値は将棋ロビーを表示している間保持し、編集中の入力や設定はゲームを切り替えたときにリバーシへ引き継ぎません。ゲスト名の初期値には、登録からの復元入力があればそれを使い、なければ両ゲーム共通の保存済みゲスト名を使います。
- 「遊び方」は[四人将棋のルール正本](docs/rules/four-shogi.md)に沿って、駒・成り・持ち駒、王手優先、勝敗、禁止手、三人攻撃禁止の既定値ONと切り替えについて説明します。
- ロビーの背景はクリーム色、主要ボタンは黄色と濃い茶色の文字、アクセントは濃い琥珀色にします。入力・遊び方・ランキングのダイアログも同じ色にします。共通ヘッダー・ロゴ・アカウントメニューは緑のままにし、エラーやフォーカスなど意味を持つ色も維持します。

## ゲームロビーの検索向け紹介と配信

Googleの日本向け・日本語の自然検索で「四人将棋」「四人リバーシ」から、それぞれのロビーへ来てもらうことを目指します。検索対象は `/games/four-shogi` と `/games/four-reversi` の2ページです。専用ルールページは設けません。

両ロビーは操作・公開一覧・最近の対局・ランキングの下、フッターの前に「ゲーム概要」「遊び始め方」「主要ルール」を常時表示します。「4人将棋」「4人リバーシ」も本文で別表記として伝え、詳しいルールは既存の「遊び方」で案内します。説明はルール正本に合わせ、対局の操作順序・レイアウト・認証・参加資格を維持します。

ビルド時に共通の紹介部品から、見出し・紹介・両ロビーへの通常リンクを持つ初期HTMLを生成します。対局画面の遅延読み込みが完了してからReact画面へ置き換え、失敗時は紹介と再読み込みの案内を残します。認証情報・ルーム一覧・ランキングは事前生成しません。

初期HTMLと画面内遷移の両方で、ゲーム固有のtitle・description・canonical・robotsをそろえます。titleは「TetraBoard | 四人将棋をブラウザでオンライン対戦」「TetraBoard | 四人リバーシをブラウザでオンライン対戦」、正規URLは `https://tetraboard.net` 配下の末尾スラッシュなしです。末尾スラッシュ・生成indexへの直接アクセスはクエリを保持して正規URLへ308転送します。サイトマップにはこの2ページだけを掲載し、robots.txtはクロールを許可します。

ルーム・ログイン・アカウント・公開／本人棋譜・お知らせ・フィードバック等の他画面はHTMLとHTTPヘッダーで `noindex` とし、ロビーのメタ情報を残しません。管理画面の認証と検索除外は維持します。noindexはアクセス制御の代わりにしません。未知の画面URLと存在しない資産はHTTP 404とし、両ロビーへの案内を返します。API・WebSocket・旧URL・旧ホストの転送は維持します。

検索順位・検索結果のURL選択・反映時期はGoogleが決めます。ローカル検証・GitHub CI・承認後の本番配信確認・Search Console送信・公開前基準値の記録をSEO整備の完了とし、検索1位と流入増加の達成は別に確認します。公開・計測の手順は [開発手順](docs/development.md#ロビーのseo生成と成果確認) を参照してください。

## 四人リバーシのルーム画面

`/rooms/:id` は対局者と観戦者で共有するルーム画面です。HeroUIのカード・ボタン・タブ・ダイアログ・通知を使います。

- PC（1280px以上）は盤面とプレイヤーカードを左、ルーム情報・状況カード・チャットを右に表示します。タブレット（768〜1279px）は盤面の上下左右にカードを配置します。スマートフォン（767px以下）は盤面の上に2枚、下に2枚を配置します。
- 両ゲームのPC版は左右列の高さを独立させ、ルーム設定の開閉で盤面・プレイヤーカードの位置と大きさを変えません。右列が画面の高さを超える場合は右列で縦スクロールし、チャットは残り高さを使います。チャット領域の最小高さは140pxとし、履歴内のスクロールも維持します。
- 待機中のホスト向け「ルーム設定」は、背景・枠線・設定アイコン・右端の開閉矢印を持つ行全体から展開します。追加するCPUのレベル選択を「CPUを追加」のすぐ左に8px間隔で置き、右寄せします。追加ボタンは高さ32pxで表示します。
- 設定送信中は選択した対局形式・時間・CPUレベル・三人攻撃禁止の値だけを先に表示し、操作をロックしたまま一時的な無効化による透明度の切り替えを抑えます。設定欄の固定した高さの行に「設定を更新中…」を表示し、応答後はサーバーの確定値に従います。拒否・送信失敗・切断では確定値へ戻します。準備解除・盤面・CPUの増減はサーバー確定後に反映し、設定の開閉状態は更新でリセットしません。
- スマートフォンではカードの幅・高さを保ち、空き高さが足りないときは盤面だけを中央で縮小し、正方形を維持します。カードと盤面の間隔は2pxとし、自動パス通知の高さも確保します。通常ルームと保存済み棋譜に適用します。
- タブレット・スマートフォンには「盤面／ルーム／チャット」のタブを設け、状況カードをその上に常に表示します。チャットの入力と閲覧位置はタブを切り替えても保持します。
- 初回の待機中は操作できない初期盤面を表示します。終局後は自動で棋譜モードに入り、前局の最終局面を表示します。待機中に石を置いたり、合法手のマークを表示したりはしません。対局中と保存済み棋譜のカードは黒→白→赤→青の時計回り順にし、観戦・公開棋譜は黒、対局者と本人用の保存済み棋譜は本人を手前にします。待機・再戦待機は入室順を維持します。着席と担当色の関係は[四人リバーシのルール](docs/rules/four-reversi.md#色の割り当てと表示)に従います。
- プレイヤーカードは同じ幅・高さを保ち、最大10文字の名前と王冠を省略・折り返しせず一行で表示します。長い名前は表示幅に合わせて文字サイズを調整します。入室時のアカウントアイコン（未設定・ゲストは仮アバター）、ホストの王冠、CPUの「CPU Lv1」などの名前と青いロボットのアバターを表示します。接続中は緑、切断中は黄の丸いバッジを表示し、空席は薄いグレーにします。
- 対局中は直前に着手したマスをオレンジの枠で示し、自分が着手できるマスに丸い点を表示します。最終手の枠は再読み込み・観戦でも表示し、初期盤面では表示しません。
- 待機中のカードには初期持ち時間（持ち時間なしの場合は秒読み時間）と、準備済みの場合だけ緑の「準備完了」を表示します。石数と担当色は対局中だけ表示します。脱落後もカードを残し、時計の代わりに「4位（退室）」などの確定順位と脱落理由（退室・時間切れ・投了・通信切れ）を表示します。理由は再読み込み・途中からの観戦でも保持し、旧データで記録がない場合は順位だけを表示します。再戦待機になったら順位・石数・色を消して初期表示へ戻します。
- 時計は基本時間を黒、秒読みを黄色で表示し、秒読みの表示が9秒以下になったら赤と穏やかなアニメーションで知らせます。動きを減らす端末設定ではアニメーションを止めます。
- 状況カードは待機中に参加者数（CPU込み）と準備操作、自分の手番にオレンジの「あなたの番です。」と時計・投了、他の手番に名前と時計を表示します。再戦待機では参加者数の代わりに「結果」を表示し、押すと結果ダイアログを開きます。結果は自動では開きません。
- 棋譜カードは「←」、局面を選ぶSelect、「→」で構成します。PCでは盤面・プレイヤー領域の右下へ重ねて配置し、棋譜の有無で盤面とプレイヤーカードの位置・寸法を変えません。タブレット・スマートフォンでは状況カードの「待機中です。」と「結果」の間に表示し、タブ切替中も操作できます。最初は「開始局面」、着手は「5: 赤E6」の形式で表示します。自動パス・投了・退室・時間切れ・通信切れによる脱落も独立した項目とし、着手番号は増やしません。終局後は最後の項目を選び、次の対局開始時に棋譜モードを解除します。局面の選択は閲覧者ごとに独立しています。
- 両ゲームの棋譜Selectは選択中・候補とも短い一行表示とし、幅が足りない場合だけ省略記号を使います。読み上げ名は省略しません。着手は「5: 赤E6」「122: 北D9金打」、外部脱落・パスは「南 投了」「北 通信切れ」「赤 パス」の形式です。「開始局面」「最終局面（棋譜なし）」は保持し、通常ルームと保存済み棋譜で同じ表示を使います。
- 接続中・再接続中・操作エラーの通知は両ゲームのルーム上部中央へ重ね、盤面・カード・タブの位置や寸法を変えません。上端の安全領域から8px、左右8px以上を空け、最大幅480px内で長い文を折り返します。クリックを透過し、ダイアログとSelect候補の下に表示します。
- ルーム内の棋譜モードでも盤面は前局、プレイヤーカードは現在の待機メンバー・入室順・準備状態を表示します。前局の担当色はカードに表示しません。プレイヤーカードの下には棋譜の手数・手番・4色の石数を表示せず、選択局面は棋譜Select、直前の着手は盤面の枠で示します。
- スマートフォンでは棋譜カードを小さくし、「待機中です。」「棋譜カード」「結果」を一行に配置します。状況カードは棋譜の有無にかかわらず同じ高さに保ちます。
- 直前1局の棋譜は次局開始または部屋の閉鎖まで保持し、再読み込み・再接続でも最後の局面から復元できます。待機中の設定変更や入退室で棋譜を書き換えません。導入前に開始済みだった対局は最終局面のみを表示し、過去の着手は補完しません。
- ホストの「対局開始」は状況カードの準備操作の隣に置きます。開始条件を満たすまで無効にします。モード、持ち時間・秒読み、CPUの設定は待機中のルーム情報内にまとめます。時間の初期設定は5分＋1手30秒です。
- 観戦者には、待機中で空席がある場合に状況カードの「参加する」を表示し、ゲストはニックネーム入力、ログイン中はプロフィールの確認から参加できます。満室・対局中も含めて状況カード下段の左に「観戦中」、右に時計回り90度の回転ボタンを表示します。参加できる待機ルームでは中央に「参加する」を残します。準備・開始・投了は表示せず、ロビーへ戻る導線を表示します。投了と対局中の退室はダイアログで確認します。
- ルーム情報の「招待リンクをコピー」は全閲覧者が使えます。成功は3秒のtoastで通知し、自動コピーできない場合は手動コピー用のURL欄を表示します。
- 招待リンクを開いた未参加者には、待機中で空席がある場合に参加ダイアログを1回だけ自動表示します。表示履歴は同じタブ・同じルーム世代ごとに保持します。「観戦する」や閉じる操作で観戦を続けられます。更新やタブ切替、ロビーとの往復で再表示せず、後から状況カードの「参加する」で開けます。ブラウザの保存領域が利用できない場合は、更新後の表示履歴を保持できません。入力中の満室化・対局開始や通信エラーは日本語で案内し、送信中は重複送信と閉鎖を防ぎます。
- 新しい他の人のチャット投稿とシステムログは、チャット表示中も3秒間のtoastで通知します。自分の投稿、初回・再接続時の履歴、非表示の送信者、重複受信は通知しません。
- チャットの最下部を見ていれば新着に追従し、途中を読んでいれば位置を保持します。「↓」ボタンで最新位置に移動できます。日本語変換中のEnterでは送信しません。

ロビー・ルームのダイアログは、右上から12pxの位置に44×44pxの閉じるボタンを表示します。ダイアログ表示中は背景ページ全体をぼかし、スマートフォンのキーボード表示中も背景が鮮明に露出しないようにします。ダイアログ本体はキーボードを除く表示領域内でスクロールできます。

観戦と保存済み棋譜では、回転ボタンを押すたびに盤面・駒・持ち駒・プレイヤーカードの配置を時計回り90度回し、4回で元に戻します。カードの文字は読める向きを保ち、ゲームの座標や所属は変更しません。保存済み棋譜の状況カード下段は左に「棋譜閲覧中」、右に回転ボタンを表示します。初期方向は既存の観戦／本人方向とし、回転は画面内だけで保持します。手数変更・タブ切替・再接続・同じルームの次局開始では維持し、再読み込み・別ルームや別棋譜への移動・観戦から参加への切替で初期方向へ戻ります。参加者の対局画面と、参加者がルーム内で見る直前局の棋譜には回転操作を表示しません。

## 四人将棋のルーム画面

`/rooms/:id` をリバーシと共有し、設定のゲームに応じて対局画面を表示します。招待、準備、設定、時計、チャット、再接続、観戦、結果、再戦の操作は共通です。将棋のルームとダイアログには黄色テーマを使います。

- 盤・駒PNGを使用し、盤画像の縦横比を保ちます。768px以上ではカードと持ち駒を上下左右へ配置し、767px以下では上2席・持ち駒・盤面・持ち駒・下2席の順にします。外側の1280pxの配置とタブはリバーシと共通です。
- 駒画像の読み込み・デコード中と失敗時は、同じ寸法の薄い木色の枠に「王・飛・金・銀・歩・龍・成銀・と金・裏王」を表示します。文字の向きは駒の向きに合わせ、画像の準備後は文字を消して従来の画像だけを表示します。盤上・持ち駒・ドラッグ・成り選択・観戦・棋譜に適用し、画像待ちで操作や時計を止めません。
- 768px以上のプレイヤーカードは4席とも側列から決めた同じ幅・高さ60pxにします。上下のカードと持ち駒は横並びの組として盤面領域全体の中央に置き、間隔を含めて横方向にはみ出さないようにします。
- スマートフォンではプレイヤーカードの幅と高さ48pxを保ち、空き高さが足りないときは盤面だけを中央で縦横比を保って縮小します。持ち駒も盤上の駒と同じ縮尺で小さくし、空の領域を含めて高さを追従させます。カード・持ち駒の上下の内側余白は1px、カードと持ち駒・盤面との間隔は2pxにします。通常ルームと保存済み棋譜に適用します。
- 対局者は自陣営が下、観戦者の初期方向は南が下です。座標と駒の向きを変換し、対局中のカードも担当方向へ配置します。待機中は入室順で本人を下へ置きます。終局後は次局開始まで前局の閲覧方向を保ちます。
- 持ち駒は種類ごとに1枚を表示し、2枚以上に枚数を付けます。0枚は非表示、空の領域も高さを保ちます。盤上・持ち駒・ドラッグ中の駒は盤の内寸から求めた同じ縮尺を使います。
- スマートフォンの上2席の持ち駒は下向きで左から飛・金・銀・歩、下2席は上向きで歩・銀・金・飛です。PCは下と上が同じ並び、左は上から歩・銀・金・飛で右向き、右は上から飛・金・銀・歩で左向きです。持ち駒領域は淡い木目調にします。
- クリック・タップで選択し、合法な移動先を緑の丸、三人攻撃による禁止候補を赤い丸で表示します。禁止候補しかない駒・持ち駒も選択できますが、赤い丸には着手できません。同じ移動先で成り・不成の一方が合法なら緑を優先し、合法な選択だけを実行できます。マウス・タッチを8px以上動かすとドラッグになり、元の駒画像を隠して追従する駒だけを表示します。選択・ドラッグ中は持ち駒の枚数を維持します。同じ駒の再選択・Escapeで解除し、盤外・不正な場所・ポインター取消では着手しません。操作できる駒だけタッチのスクロールを抑止し、マウスでホバーすると少し浮き上がる表現を付けます。選択中の盤上・持ち駒は、ホバーが外れても浮いた状態を保ち、選択を解除すると元へ戻ります。
- 成り・不成の両方が合法なら、移動先の中央を境に左へ成り駒、右へ不成駒を盤上と同じ大きさで表示します。盤端では2枚全体を盤内へ寄せます。選択外の画面内クリック・タップは成りを確定し、背後の操作は実行しません。Escapeは取消、候補が1つなら直接送信とします。キーボードはTabで二択を移動し、Enter・Spaceで確定できます。
- 未確定の成り選択は同じタブで再読み込み・再接続後も復元します。部屋世代・本人・局ID・局面revision・陣営を照合し、認証と最新の合法手の確認後に表示します。復元だけでは送信しません。確定・取消・局面更新・次局開始・脱落・参加資格変更で破棄します。保存領域が使えない場合、その場の選択は操作できますが再読み込み後の復元は保証しません。送信中は重複操作を防ぎ、成り選択中も時計は進みます。
- 合法な着手の送信直後は、駒の移動・捕獲・成り・持ち駒の増減を本人の画面へ先に反映し、移動先を破線の枠で未確定として示します。手番・時計・王手・脱落・勝敗はサーバーの確定情報に従います。同じ局ID・revisionの通知では送信待ちを維持し、新しい局面の受信で確定表示へ切り替えます。拒否・送信失敗・切断では未確定表示を解除し、再接続後は最新局面と認証に従って復帰します。古い選択は復元しません。観戦・棋譜には未確定表示を適用しません。
- 着手送信待ちが3秒以上続いた場合だけ「着手を送信中…」を表示します。完了・拒否・切断・次局開始・画面離脱で解除し、次の着手には時間を持ち越しません。文言と拒否理由は既存の接続通知と同じ上部中央の絶対位置へ表示し、盤面・カード・タブの配置を変えません。接続・再接続と操作エラーを優先し、その間は送信中通知を表示しません。
- 本人の確定着手で16戦型（地下鉄飛車の単独判定と右玉の派生を除く掲載形）が不成立から成立したとき、本人側2段目の中央に名称を2秒表示します。[判定条件](docs/rules/four-shogi.md#戦型の成立判定)は共有エンジンを使い、未確定着手とサーバーの付加解析結果では表示しません。「地下鉄飛車・下段金寄せ」と「地下鉄飛車・融通無碍」はそれぞれ1戦型として判定・通知します。同時に新たに成立した未通知の名称は定義順に「・」で連結します。同じタブの同じ局では各戦型を1回だけ通知し、初回取得・再読み込み・再接続・局面取得の飛びは通知せず基準にします。記録は部屋世代・本人・局・解析版ごとに区別し、次局で置き換えます。保存領域が利用できない場合も、その画面内で重複を抑止して操作を継続します。
- 戦型名は水平な白文字と濃い半透明背景で盤内に重ね、盤幅に合わせて縮尺します。2秒のうち最初の180msでふわっと現れ、最後の240msでふわっと消えます。位置・大きさは動かさず、OSで動きを減らす設定の場合はフェードを省略します。クリック・タップを透過し、フォーカスを移動せず、控えめな読み上げ通知だけを使います。選択・ドラッグ・成り選択、切断・脱落・終局・次局開始では即時に消し、再演しません。別の戦型が成立したときは最新の名称へ置き換え、フェードを最初から始めます。観戦・待機・ルーム内棋譜・保存済み棋譜では表示しません。盤面・カード・持ち駒の寸法と配置は変えません。
- 王手、裏王、脱落理由・確定順位、直前の移動元と移動先を表示します。直前の移動元はマスの暗い茶色の背景、移動先はマスの枠だけでハイライトし、打ち駒は移動先だけを表示します。背景・枠・ホバーの装飾は盤画像の罫線の内縁まで広げ、線を覆わず余白を最小にします。観戦・通常ルームの棋譜・保存済み棋譜でも選択局面と盤面回転に追従します。三人攻撃禁止は待機中のホストが変更でき、モードまたはこの設定を変更すると人間の準備を解除します。対局中は固定し、再戦へ引き継ぎます。
- 自分の手番では「投了」の右隣の「引分提案」で同意を表明し、提案中は「引分取消」で取り消せます。提案中はプレイヤーカードの方角の右に「引分」バッジを表示します。操作で手番・手数は進めず、時計も停止・リセットしません。提案は着手・手番変更・再接続後も保持し、生存者全員が提案状態になれば引き分けて再戦待機へ戻ります。脱落による通常の終局を優先し、対局が続く場合は残った生存者で再判定します。CPUは自分の手番で、生存する人間全員の提案・取消に合わせます。生存する人間が0人なら新たに提案しません。結果・戦績は千日手と同じ扱いとし、提案・取消も手数を増やさない棋譜イベントとして保存します。保存済み棋譜のバッジは選択局面に追従し、再戦待機のカードは準備状態を表示します。
- 5分＋1手30秒を使い、CPU Lv1・Lv2を選べます。対局ごとに担当方向を抽選し直します。ルール・王手優先・撃破後の手番は将棋正本とエンジンに従います。
- 直前1局の棋譜は移動・捕獲・打ち駒・成り・外部脱落と自動詰みを振り返れます。脱落理由・同時脱落の群・順位は局面データとカード・結果表示で保持し、棋譜Selectには詰み・合法手なし・同時脱落・順位の付加説明を表示しません。終局後は最終局面を選択し、再読み込み・再接続で復元できます。次局開始または部屋閉鎖で削除します。
- 将棋の終局データと棋譜を恒久保存し、マイページの戦績・棋譜と将棋ロビーのランキングへ反映します。保存・取得・集計はゲーム別に扱います。

## Google認証とプロフィール

Googleによる新規登録・ログイン、プロフィール設定、ログアウトを提供します。ログイン中はサーバーが取得した本人のプロフィールでルームへ参加します。本人の対局履歴と戦績はマイページに表示し、公開ランキングはロビーに表示します。

- ロビーのヘッダー右上に「登録・ログイン」を表示し、`/login` へ移動します。「Googleで続ける」から登録・ログインでき、アカウントがない場合は新しいユーザーが作成される旨を案内します。
- 両ゲームの作成・すぐ遊ぶ・番号／一覧からの参加・招待／観戦からの参加で、ゲストのニックネーム欄にGoogle登録の案内を表示します。Googleボタンから直接認証を開始でき、ゲスト参加も継続できます。棋譜の保存を案内し、CPUを含まない対人戦だけが戦績・ランキングの集計対象であることを伝えます。
- 未ログインの対局者が画面上で終局を迎えると、登録案内を含む結果ダイアログをタブ内で両ゲームを通じて1回だけ自動表示します。表示済み状態は同じタブの再読み込みでも保持し、保存不能時はページ内のメモリで抑止します。観戦・ログイン済み・認証確認中／取得失敗・終局済み部屋の初回閲覧では自動表示しません。他のダイアログの終了を待ち、次局開始・退室・閉鎖で保留を取り消します。「結果」からは手動で開けます。「今はしない」・×・Escape・背景クリックで閉じられます。
- 登録導線からの認証では、元のロビーまたは部屋世代付きURLと参加フォームの入力を同じタブに1時間保存します。認証と初回プロフィール設定の完了後、元の画面・ダイアログ・入力を一度だけ復元します。作成・参加・退室・席変更を自動実行しません。認証開始失敗は入力を保って再試行でき、OAuth取消・失敗では「元の画面へ戻る」を表示します。保存不能・破損・期限切れは既存のマイページへの遷移に戻します。登録導線を使わない直接ログインの完了先はマイページです。
- 登録で既存のゲスト席やゲスト対局をアカウントへ紐付けません。在室中の登録では、記録するには登録後にアカウントで参加し直す必要があることを案内します。部屋の閉鎖・満室・対局開始・席の復帰期限は既存の判定に従います。
- 新規ユーザーは `/account/setup` でプロフィールを作成します。設定未完了でログイン中の場合は、ほかの画面を開いても初回設定へ誘導します。Googleから取得した名前・画像は新規プロフィールへ自動で設定しません。
- 名前は前後の空白を除いて1〜10文字（絵文字などは見た目の文字単位）です。IDは英数字と `_` の3〜20文字で、大文字は小文字へ統一します。先頭の `@` は入力でき、保存時に除いて表示時に付けます。IDは大文字・小文字を区別せず重複を拒否します。名前の重複は許可します。
- アイコンは任意です。JPEG・PNG・WebPの5MB以下の画像を選択し、中央を正方形に切り抜いて256×256のWebPへ変換します。変換後は1MB以下とし、サーバーでも容量・形式・寸法を検証します。
- 名前・ID・アイコンのアップロード／変更／削除は、フォームの保存でまとめて反映します。入力エラー・ID重複・通信エラーでは入力を保持し、保存中の連打を防ぎます。外部URLのアイコンは使用せず、既存・移行データに含まれていても未設定として扱います。置換・削除した旧アイコンはルームで使われている間保持し、参照がなくなったらR2から削除します。失敗時は毎時の処理で再試行します。ブラウザにキャッシュされた画像は最大1時間残る場合があります。
- ログイン済みのヘッダーには、アイコン・名前・`@ID` のDropdownを表示します。スマートフォン幅ではアイコンと開閉アイコンを表示し、メニューは「マイページ」「ログアウト」の2項目です。
- `/account` は左にアイコン、右に名前と `@ID`、右上に「プロフィールを編集」を表示します。スマートフォンでは編集ボタンを上段に分け、名前・IDは省略せず折り返します。戦績はプロフィールと同じカード内にモード別の集計を表示し、棋譜は独立カードに本人の対局履歴を表示します。ヘッダー下の本文先頭には、左に選択中のゲーム名と下向き矢印を持つDropdown、右に枠・背景のある「ロビーへ」を配置します。「ロビーへ」は選択中ゲームのロビーへ移動します。共通の「シングルス／ダブルス」タブは651px以上ではDropdownのすぐ右、650px以下ではその下に全幅で配置し、戦績・棋譜を同時に切り替えます。
- マイページの本文はヘッダーと同じ最大1148pxで中央に配置し、左右余白も650px以下は20px、それより広い場合は24pxにそろえます。1024px以上ではプロフィール＋戦績カードを幅560px、間隔20pxで左に、残りの幅を使う棋譜カードを右に並べます。1024px未満は同じ幅で縦に並べ、棋譜を下に表示します。
- 編集ボタンから共通ダイアログを開き、初回設定と同じフォームで名前・ID・アイコンを編集します。アイコン中央の半透明のカメラボタンで画像を選択し、画像がある場合は下に「アイコンを削除」を表示します。保存成功時は閉じて表示とヘッダーを更新し、保存前に閉じると変更を破棄します。画像変換中・保存中は操作と閉鎖を防ぎます。 ファイル選択などから戻った際のログイン再確認中や通信失敗でも編集内容を保持し、セッション失効が確認された場合はログインへ誘導します。ログアウトは認証セッションを失効し、ロビーへ戻ります。

## 終局データの保存・対局履歴

- CPU戦の対局履歴・棋譜・記録された撃破数は集計対象外でも残します。待機中にCPUを追加しても、開始前に全員削除すれば対人戦として集計します。取得時に集計するため、DB移行・データ削除・再保存は不要です。
- この機能の導入後に開始したすべての対局を、ゲストのみの対局も含めて終局時に保存します。導入前の対局・導入時に進行中の対局を補完せず、終局していない対局は履歴へ追加しません。人間の参加者が全員退室または復帰期限切れになり、未決着で打ち切った対局は保存しません。退室・通信切れでルール上終局した場合は保存します。
- 開始日時、部屋の識別子、ゲーム・モード・時間設定、開始時の4人の名前・担当色または担当方向・席順・人間／CPU区分・CPUレベル・内部アカウントIDを保存します。終局時に終了日時、結果、最終盤面、脱落理由、着手・自動パス・脱落を含む棋譜を保存します。将棋は規則バージョン・初期化情報・連番イベントと方向別の撃破数を保存します。参加資格やチャットは保存対象に含めません。承認されたFirebase旧棋譜の手動移行に限り、未記録の時間設定を `null` として保存し、棋譜画面の持ち時間・秒読みを「不明」と表示します。通常のルーム作成・対局では時間設定を必須とします。
- 終局と同時に対局ごとの保存待ちを永続化します。D1への保存が失敗しても再戦・退室を妨げず、5秒後に再試行します。再戦開始・退室・部屋閉鎖・部屋番号再利用後も保存待ちを保持し、同じ対局の再送で重複や結果の上書きを発生させません。履歴の期限削除は行いません。
- `/account` の棋譜は本文上部の共通ゲームDropdownとモードタブで切り替えます。ゲームの初期値は四人リバーシ、モードはシングルスです。開始時に本人のアカウントで参加した対局を開始日時の新しい順に表示し、20件ずつ「もっと見る」で追加します。同時刻は対局UUIDの降順です。観戦やゲスト参加は本人の履歴へ紐付けません。
- 棋譜カードを縦に並べ、開始日時と「四人リバーシ・シングルス」などのゲーム・モードを表示します。日時は閲覧端末の時間帯で年月日・時分を表示します。シングルスは順位・24pxアイコン・名前を2列でコンパクトに表示し、1位は「優勝」とします。同順位・順位の飛びを保持し、同順位内はリバーシでは黒・白・赤・青、将棋では南・西・北・東の順です。ダブルスは勝利チーム・敗北チームの順に2人ずつ表示し、引き分けは両チームに表示します。
- アカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。ゲスト・CPUと参照先のないアカウントの名前は開始時のものを使います。アイコン未設定・参照先がない場合は仮アバター、CPUは青いCPUアバターを表示します。履歴のために過去のアイコン画像を保持しません。保存した名前や棋譜は書き換えず、プロフィール変更は次回取得時に反映します。
- 「棋譜を見る」から `/account/matches/:matchId` の棋譜閲覧画面へ移動します。読み込み・空一覧・失敗と再試行を表示し、追加取得に失敗しても表示済みのカードを残します。ゲーム・モードごとの取得済み一覧を保持し、「更新」で選択中の一覧を先頭から再取得します。戦績・棋譜で共通のゲーム選択とゲームごとのモードを保持し、再読み込み・棋譜からマイページへ戻った場合も復元します。

- チェック切替時は旧条件のカードを消して再取得し、読み込み中も条件を切り替えられます。失敗時は選択した条件を保って再試行を案内し、旧条件のカードは表示しません。人間4人の対局が0件なら「人間4人の対局履歴がありません。」を表示します。

## 保存済み棋譜の閲覧

- `/account/matches/:matchId` は開始時に本人のアカウントで参加した保存済み対局だけを閲覧できます。未ログインはログインへ誘導し、他人の対局と存在しない対局は同じ閲覧不可の案内を表示します。取得失敗は空の棋譜として扱わず、再試行を案内します。
- 通常ルームと同じレイアウトを使い、最終局面から棋譜を表示します。開始局面・着手・自動パス・各脱落を矢印とSelectで移動できます。再読み込みや別対局への移動では最終局面から表示します。
- 将棋の棋譜は100イベントずつ取得し、対局ID・規則バージョン・初期化情報・総件数・連続番号を検証してエンジンで再生します。再現した最終状態と保存済みの最終状態が一致しない場合は閲覧を開始せず、エラーと再試行を案内します。保存データを取得後、局面の操作はブラウザ内だけで行います。オンラインルームの取得・参加確認・WebSocket接続は行わず、既存の参加資格を変更しません。部屋閉鎖や番号再利用後も同じ対局を閲覧できます。
- 開始時の参加者・担当色または担当方向を表示し、本人用の初期表示では本人を手前（スマートフォンでは左下）に配置します。リバーシのカードは黒→白→赤→青の時計回り順にし、保存された席番号はホストの識別に使います。アカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。ゲスト・CPUと参照先のないアカウントの名前は開始時のものを使います。カードの石数・脱落表示は選択局面に追従し、未来の脱落を表示しません。将棋の初期表示は本人の担当方向を下へ配置し、持ち駒・成り駒・裏王・王手・最終手と選択局面の順位・脱落理由を表示します。同時脱落は同じ群として棋譜ラベルへ併記します。脱落者の石数、接続バッジ、準備状態、時計は表示しません。
- 両ゲームの結果ダイアログは、シングルスを順位色付きの順位バッジ・担当色の石と石数または方角・アイコン・名前の順に表示し、バッジには脱落理由を付けません。同順位と順位の飛びを保持します。リバーシは担当色の石と石数を表示し、脱落者は担当色と「脱落」だけを表示します。結果の順位欄と石色・石数欄は一定の幅を確保し、石数の桁数や脱落表示に関係なくアイコンと名前の開始位置をそろえます。ダブルスも担当色の石と石数または方角をアイコンの前に置き、勝利・敗北チームの順に2人ずつ並べ、引き分けは両チームに表示し、個人順位を付けません。終局理由とリバーシのチーム合計石数も表示します。
- 将棋の結果では、各人の方角と、その右側に「撃破」ラベル・撃破対象のアイコンと名前を着手順に並べます。対象欄は右側の領域内で折り返し、名前を省略しません。両モードで受理された着手によって新たに詰んだ相手だけを表示し、同時詰みは全員を含めます。空き王手も着手者へ対応付けます。外部脱落と合法手なしは含めず、戦績の撃破数集計は変更しません。表示は棋譜の選択局面・盤面回転に依存せず最終結果を使います。対象がない場合は「撃破：なし」、棋譜の取得中・失敗時は別の案内と再試行を表示します。
- ルーム内の前局結果は、その局の名前・担当色／方角・アイコン・CPU情報を保持します。退室後も次局開始・部屋閉鎖まで画像を保持し、現在の席にも必要な画像参照は解放しません。旧データで表示情報がない場合は同じプレイヤーIDの在室者情報、なければ仮アイコンを使います。保存済み棋譜のアカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。
- 状況カードは「対局終了」を表示し、「結果」で保存された最終結果を開きます。結果は自動表示しません。着手操作と合法手の点は無効にし、直前の着手枠は選択局面に追従します。
- 準備・開始・参加・投了・退室・招待・ルーム設定・CPU操作は表示しません。ルーム情報は元の部屋番号、ゲーム、モード、持ち時間を表示し、「マイページへ戻る」を設けます。状況カード下段には「棋譜閲覧中」と回転ボタンを表示します。
- 将棋の保存棋譜の盤面・ルーム情報・結果ダイアログには黄色テーマを使います。マイページの本文は選択中ゲームのロビーと同じ背景・テーマを使い、ゲームDropdown・プロフィール編集ダイアログにも同じテーマを適用します。共通ヘッダー・アカウントメニューは緑のままにします。
- PC（1280px以上）のチャット領域には「棋譜閲覧ではチャットを利用できません。」を表示します。1280px未満は「盤面／ルーム」の2タブだけを表示し、タブ切替で局面の選択を保持します。

## 戦績の表示

- `/account` のプロフィールカード内に「戦績」を表示し、本文上部の共通ゲームDropdownとモードタブで棋譜と同時に切り替えます。ゲームの初期値は四人リバーシ、モードはシングルスです。ゲームごとのモードと取得済み戦績を保持します。
- 開始時の4人全員が人間で、本人がアカウントで参加し、終局結果がD1へ保存された対局だけをゲーム・モード別に集計します。対戦相手のゲストは人間として扱います。CPUを1人でも含む対局は過去の保存済み対局も集計から除外し、対局数・順位・勝敗・引き分け・各率・将棋の累計撃破数に同じ条件を適用します。観戦・本人のゲスト参加・未終局・保存待ちの対局は含めません。棋譜一覧の取得件数には依存しません。戦績タイトルの下に「対人戦のみ集計」と表示します。
- シングルスは「対局数」「優勝数・優勝率」「2位数・2位率」「3位数・3位率」「4位数・4位率」を表示します。同順位は保存された順位に1回加算し、同率1位も優勝として数えます。
- 将棋のシングルスは「完全優勝数」「撃破数」「撃破率」も表示します。完全優勝数は本人が他の3人全員を撃破して単独1位になった対局数で、通常の優勝数の内数です。保存済みの過去対局も対象にします。撃破率は累計撃破数を対局数で割った1局あたりの平均撃破人数で、最大3.000です。受理された着手で新たに詰んだ相手1人につき着手者へ1を加算し、同時に2人を詰ませれば2です。CPUによる撃破も対局記録へ含めます。投了・退室・時間切れ・通信切れ・合法手なしとダブルスは数えず、順位・勝敗の判定には使いません。
- ダブルスは「対局数」「勝数・勝率」「敗数・敗率」を表示します。引き分けの行は表示しませんが、引き分けも対局数と率の分母に含めます。
- 各率は該当件数をそのモードの集計対象の対局数で割り、小数第4位を四捨五入します。先頭の0と `%` を付けず、`.000`・`.333`・`.500`・`1.000` のように小数3桁で表示します。対局数ゼロは各件数0・各率 `.000` とします。
- ゲームの初回選択時にそのゲームの両モードを取得し、戦績タイトル右側の「更新」で選択中ゲームの両モードを再取得します。取得失敗はゼロ件とせず再試行を案内し、更新の失敗時は取得済みの戦績を保持します。

### 四人将棋シングルスの戦法別戦績

- 通常戦績の下に全16戦法のカードを掲載図の順で横一列に並べます。内部No01〜16と既存の戦法IDを固定対応させ、Noは画面に表示しません。カード幅は180px、間隔は12pxとし、一覧内だけで横スクロールします。
- 集計対象の対人シングルスで本人の確定着手により不成立から成立した戦法を使用経験として記録し、終局・保存後に名前と盤面図を表示します。未経験は「???」と共通の画像プレースホルダーで操作不可とし、読み上げにも実名を含めません。CPU戦・ダブルスでは解放しません。
- 経験済みカードはクリック・タップ・Enter・Spaceで黄色テーマのダイアログを開きます。使用対局数、優勝数・優勝率、2〜4位の数・率だけを表示し、各率の分母はその戦法の使用対局数です。同率1位も優勝へ加算します。完全優勝数と撃破項目は通常戦績に表示します。
- 同じ戦法は1局で1回だけ数え、複数の戦法が成立した局はそれぞれに結果を加算します。戦法別の対局数の合計は通常戦績の対局数と一致しない場合があります。名前は省略せず折り返し、画像は高さ120pxの領域に縦横比を保って全体を表示します。
- 戦法別戦績は導入後に開始した対局だけを対象とし、導入時進行中の局・過去棋譜を補完しません。集計開始時点・集計期間は画面に表示しません。
- 将棋シングルスの選択時に取得・保持し、「更新」で通常戦績と戦法別戦績を更新します。読み込み・失敗を0件や未経験とせず、再試行を案内します。更新失敗時は取得済み表示を保持し、ゲーム・モード切替ではダイアログを閉じます。

- ゲームごとに独立した累計を使い、達成済みの最高ランクを各種類1枚表示します。星3は金色の画像内に現在の累計を重ね、獲得後も数字が増えます。数字は省略しません。
- マイページはプロフィールと戦績の間に、対局数・優勝数・撃破数・完全優勝の順でコンパクトに表示します。未獲得もグレーの星1画像と「未獲得」、条件・現在値を表示します。未獲得と星1・2は現在値と次の星の目標、星3は累計を表示し、全段階の閾値一覧と残り件数の重複表示は設けません。ゲーム切替・戦績更新に追従し、取得失敗を未獲得や0件としません。バッジ画像はドラッグできません。
- ユーザー情報カードは表示元のゲームで獲得済みのものだけを小さく表示し、名前・星・累計を画像以外にも表示します。「獲得条件」を開くと条件を確認できます。ゲスト・CPUと獲得済みバッジがない登録者にはバッジ欄を表示しません。
- マイページ・ユーザー情報カードとも、シングルス選択中だけ表示します。連続優勝、装備選択、獲得通知・演出は提供しません。獲得日時・履歴は保存せず、既存戦績から判定します。過去記録にない撃破情報などは補完しません。

## ランキングの表示

- 各ロビーのランキングは対象ゲームの保存済み対局だけを集計します。将棋の集計項目はリバーシと同じで、撃破数のランキングは設けません。
- ロビーのランキングは「シングルス／ダブルス」のタブで切り替え、初期値はシングルスです。シングルスは優勝数、ダブルスは勝利数の上位3人について、順位・アイコン・名前・値をコンパクトに表示します。
- 「もっと見る」で詳細ダイアログを開き、ロビーの選択モードを引き継ぎます。モードと「優勝数／対局数」または「勝利数／対局数」を切り替え、各ランキングの上位10人を表示します。詳細内の切替でロビーのモードを変えません。
- 戦績と同じく、開始時の4人全員が人間だった保存済み対局だけを全期間・両モードで集計します。過去のCPU戦も対象外です。ゲストを含む対人戦は集計しますが、掲載する本人は開始時にアカウントで参加した現在の設定済みアカウントに限ります。観戦・未終局・保存待ちは対象外です。ロビーと詳細ダイアログに「対人戦のみ集計」と表示します。
- 優勝数は確定順位1位を数え、同率優勝も加算します。勝利数は所属チームの勝利を数えます。引き分けは対局数に含めます。優勝数／勝利数は1回以上、対局数は1局以上の人を掲載します。
- 値の降順で、同数は同順位として人数分だけ次の順位を飛ばします。同順位内は現在の公開IDの昇順にし、境界で同数でも表示人数は最大3人／10人です。
- 名前・アイコンは取得時の最新プロフィールを表示します。アイコン未設定や読み込み失敗は仮アバターを使います。内部アカウントIDや棋譜はランキングで公開しません。
- 未ログインでも閲覧できます。ロビー表示時と「更新」で全ランキングを取得し、読み込み・空一覧・失敗と再試行を表示します。更新失敗時は取得済みデータを保持します。

## プレイヤー情報カード

両ゲームの公開ルームのホスト、ランキングと詳細、最近の対局・本人履歴の棋譜カード、通常ルーム・公開／本人用棋譜のプレイヤーカードは、アイコンまたは名前からプレイヤー情報を確認できます。空席とホストなしは対象外です。

- 登録者は現在のアイコン・名前・公開IDと、表示元のゲーム・モードの対局数、優勝数／勝数、優勝率／勝率を表示します。未ログインでも閲覧できます。戦績は既存と同じ全期間の対人戦のみの集計と率の表示を使います。別モードへの切替や過去名の補足は表示しません。

- ホバーは300ms後、キーボードフォーカスは即時に開きます。トリガーとカードの両方からポインター・フォーカスが離れて150ms後に閉じ、カードへ移動すれば閉鎖を取り消します。クリック・タップ・Enter・Spaceでは表示を固定し、外側の操作・閉じるボタン・Escapeで閉じます。同時に開くカードは1枚です。
- ホバー／フォーカスではフォーカスを奪いません。明示操作ではカードへ移し、閉じる操作・Escapeでは元へ戻します。Escape後は同じホバー・フォーカスのまま再表示せず、ランキング詳細内のEscapeは情報カードだけを閉じます。画面遷移・背景スクロール・表示元の消失でも閉じます。
- カードは幅280pxを基本として左右16px内へ収め、画面端では配置を反転します。名前・IDは折り返し、元のカードや盤面の寸法を変えません。
- 戦績はカードを開くときだけ取得し、成功結果をページ内で最大60秒再利用します。プロフィール保存成功時は本人、終局検知時は対象ゲームのキャッシュを無効化します。元の棋譜の名前・画像は次回取得時に反映し、自動同期しません。取得失敗を0件やゲスト扱いせず再試行を表示します。

## 共通UIとスタイル

HeroUIを継続使用し、ヘッダー・ボタン／ボタン風リンク・入力欄・カード・ダイアログ・タブ・アイコンを `apps/web/src/shared/ui/` にまとめます。色・文字・枠線・角丸・影は既存ロビーを基準とした緑の共通テーマを使い、ゲーム部分だけに将棋の黄色テーマを適用します。レイアウト・余白・操作状態は部品内のTailwindクラスで指定します。ログイン・初回設定・マイページも同じ共通部品を使います。

画面全体の配置・背景・盤面サイズ・レスポンシブ境界を維持します。ロビーヘッダーは共通部品にし、ルームには追加しません。CSSはTailwind／HeroUIの読み込み、共通テーマと最小リセット、背景・石の陰影、ダイアログ表示中のぼかし、アニメーション定義に限定し、ページ別CSSは使用しません。

プレイヤーカードは4席とも親レイアウトから決めた同じ幅・高さを使います。高さは768px以上で60px、スマートフォンで48pxに固定し、盤面の縮小では変えません。スマートフォンの上下paddingは1pxとし、中央揃えによる追加の外側余白を残しません。アバターは通常32px／スマートフォン26pxで、右下の接続バッジを表示します。最大10文字の名前と王冠は一まとまりで実測し、省略・折り返しせず表示します。画面幅変更・フォント読込・タブ再表示でも再計測します。

名前・アバター・下段情報の領域を固定し、準備完了の有無や時計／順位の切替で他要素の位置・寸法を変えません。石と石数・順位の縮小はカード幅だけで決め、脱落状態では変えません。320pxを含む指定幅で、10文字名＋王冠・2桁の石数・最長の脱落理由が同時に収まる設計とします。

## 計測用管理画面

`apps/admin` は計測とフィードバック運営のための独立したReactアプリです。`/admin` から全体概要、四人リバーシ／四人将棋の分析、登録ユーザー一覧を確認できます。Googleログイン済みの本人のアカウントをサーバーの `ADMIN_ACCOUNT_IDS`（内部 `user.id` のJSON配列）で限定し、HTML・アセット・管理APIで確認します。指定した本人のアカウントはすべて集計の初期除外対象です。従来の1件用 `ADMIN_ACCOUNT_ID` は、配列が未設定の場合に利用できます。権限未設定・認証障害は503、未認証APIは401、別のアカウントは403です。管理応答はキャッシュしません。プロフィール編集・削除・停止、通報のオペレーション、課金は管理画面に含めません。

- 日本時間の日別／月別、期間指定、本人・テスト利用を含める切り替え、更新と再試行を提供します。初期は直近30日、月別へ切り替えたときは直近12か月です。1回の指定期間は最大3年です。
- 全体概要は訪問ブラウザ数、ページ閲覧数、表示中の滞在時間、新規登録数と登録総数を表示します。新規登録は計測開始以降だけ、登録総数と一覧は既存の登録者も含めます。ゲーム別でも登録に関する値はサービス全体です。
- 両ゲームの開始・完了・未決着の打ち切り・進行中、平均完了対局時間、延べ対局参加時間、CPU戦／対人戦、シングルス／ダブルスを表示します。対局の指標は選択期間に開始した対局の取得時点の状態です。CPU戦も含め、棋譜や通常の戦績・ランキングの集計条件は変更しません。
- 開始率は、同じゲーム・同じ日本時間の日にロビーかルームを訪問したブラウザのうち、対局を開始したブラウザの割合です。期間全体はブラウザIDを重複排除します。完了率は完了数／開始数で、進行中と打ち切りも併記します。
- 利用数とIDあたりの対局数は、登録アカウントとゲストのブラウザIDを分けます。継続率はゲーム別の計測開始後の初回完了から7日以内に別の対局を開始した割合です。同日の再戦も含み、初回完了から7日間の観測が済んだ対象だけを分母にします。期間は初回完了日で絞り、全体概要ではゲーム別コホートを合計します。分母0の率は「—」です。
- 本人と既存のテスト区分のログイン利用は初期表示で除外します。一般利用者との混在対局は対局数に残して本人の席だけを利用数・参加時間から除き、除外対象だけの対局は数えません。ログインしていない本人のゲスト利用は自動判別できません。
- Webは画面種別とゲームだけを計測し、管理画面を除外します。URL全文、招待情報、チャット、操作内容は保存しません。ランダムな計測Cookieを同一オリジンに1年間保存し、ゲストの継続をブラウザ単位で識別します。登録前後の人物統合や端末間のゲスト統合はしません。Cookie削除・保存拒否・端末変更・通信失敗で欠測や重複が生じます。
- 滞在時間は前面で表示されている時間で、操作せず盤面を見る時間も含みます。同一ブラウザのタブはWeb Locksで重複を防ぎ、未対応ブラウザはフォーカス状態で計測します。30秒ごと・非表示化・離脱時に累積時間を送り、再送で加算しません。日本時間の0時で分割します。延べ対局参加時間は対局経過時間×集計対象の人間の席数で、実際の操作時間や広告表示回数ではありません。
- 計測導入後に開始した対局だけを記録し、過去の保存対局を取り込みません。導入時に進行中の対局も補完しません。計測開始日時を表示し、計測データの期限削除は当面行いません。ブラウザの計測障害でプレイを妨げず、サーバーの対局計測は状態と同じDOトランザクションで保存待ちを確定し、D1失敗時に5秒後のAlarmで再試行します。再戦・閉鎖・番号再利用後も保存待ちを維持します。
- 登録ユーザー一覧は現在のアイコン・名前・公開ID、登録日時、設定状態を50件ずつ表示します。名前／ID検索に対応し、プロフィール未完了の登録者も表示します。メールや認証トークンは返しません。

## フィードバック受付と改善のお知らせ

ゲスト・登録者・プロフィール未完了の利用者は、両ロビー、両ゲームのルーム情報、ルーム・棋譜の取得エラー画面、直接URL `/feedback` から「不具合・ご意見」を送れます。ルームではダイアログで開き、入力中も接続・対局・時計は進みます。公開要望一覧、投票、個別返信、投稿履歴、メール通知は提供しません。投稿原文と画像は管理者だけが閲覧し、受付番号から内容を取得する機能はありません。

ルーム情報の「不具合・ご意見」は、押せることが伝わるように共通のsecondaryボタンを使い、枠線と背景を持つ全幅のボタンとして表示します。

- 種別は不具合・機能の要望・その他のご意見。種別と内容は必須で、対象は開いた画面のゲームを初期選択します。内容は1〜2,000文字、期待・目的は任意500文字、再現手順は不具合だけに任意1,000文字まで。前後の空白を除き、Unicodeコードポイントで数えます。
- JPEG・PNG・WebPを任意で1枚添付できます。元画像5MiBまで、長辺1,600px以内に縮小した静止WebPは1MiBまで。変換後のプレビューと取り消しを提供し、画像内の名前・チャットは利用者が隠してから添付します。自動撮影・画像編集は行いません。
- 不具合では技術情報の添付を初期ONにし、取り消しと内容確認が可能です。画面種別、対象ゲーム、ブラウザ、画面サイズ、ビルド識別子、ルームでは部屋ID・世代・将棋の局IDを送ります。リバーシは既存の公開状態に局IDがないためnullです。URL全文・招待クエリ・参加資格・チャット・盤面は送信しません。

- 受付は登録者ならアカウント、ゲストなら専用Cookieのブラウザを識別します。計測Cookieとは共有しません。同じアカウント・ブラウザは10分の固定窓に5件、24時間の固定窓に20件、同一IPは10分の固定窓に30件まで。窓はUTCのUNIX時刻を基準に切り替えます。IP原文を保存せず、専用secretで識別値をハッシュ化します。Cookie・端末変更、登録前後は同一人物として統合しません。

管理画面の `/admin/feedback` では50件ずつ新着順に表示し、種別・対象・対応状況・優先度・テーマで絞り込めます。詳細・添付画像・更新・削除を含め、既存の管理者認証で保護します。初期状態は「未確認」・優先度「通常」です。確認中・対応予定・対応中・完了・見送り・迷惑投稿、優先度高・通常・低、テーマ1つ、運営メモ、関連GitHub Issueを記録できます。見送りは理由、完了は本番公開の確認を必須とします。同時編集は更新番号で検出し、編集者・日時・変更前後を記録します。運営は原則翌日までに新着を確認しますが、利用者への修正期限は約束しません。

テーマ別に過去180日の投稿数とアカウント・ブラウザ単位の報告者数を表示します。運営・テスト投稿と迷惑投稿は初期除外し、内部投稿は明示的に含められます。未確認件数、最古の未確認の経過時間、初回確認時間の中央値も表示します。投稿数だけで開発順を決めず、困りごとの深刻さ・利用と継続・実装負担を合わせて判断します。投稿数は売上見込みではありません。

`/updates` には公開した新機能・改善・不具合修正の日付、対象、見出し、説明を新しい順に表示します。構造化データを機能と同じPR・公開成果物に含め、投稿原文・個人情報・画像は転載しません。公開後30日でテーマと確認速度を見直し、次の改善を選びます。課金や売上測定は今回追加しません。

## 開発と本番公開

`main` を本番として扱います。最新mainから `feat/xxx`、`fix/xxx`、`docs/xxx`、`chore/xxx` などのブランチを作り、GitHub CIと必須のローカル検証の成功後に開発者が確認してPRをマージします。mainへの直接push・force pushは行いません。非公開リポジトリの現行GitHubプランではブランチ保護を強制できないため、このルールを運用で守ります。他者レビューは必須ではありません。

通常CIは整形・lint・型チェック・単体テスト、Web・Adminのビルド、Workerの本番デプロイdry-runを実行します。コード・設定変更ではPR提出前に、ローカルで `bun run check`、`bun run build`、Workerの `deploy:dry-run` を成功させ、検証対象コミット・環境・結果・未確認事項をPRに記載します。PR提出後のコード・設定変更とmain取り込みによる変更も再検証します。文書だけの変更は同一コード・設定の直前の成功結果を再利用できます。

自動検証はBunの単体テスト、Bun＋happy-domの部品・hookテスト、Worker統合テストを使います。format確認・lint・型チェック・全テストを含む `bun run check` の目標は180秒以内です。ブラウザテストとレポート保存は廃止し、画面寸法・ブラウザ固有の入力・実画像デコードを自動検証対象から外します。ゲーム・画面の仕様は維持します。リバーシ・将棋の少数E2Eの再構築は次の作業で行い、今回は追加しません。既存のPlaywright依存は維持します。[テスト方針と移管対応表](docs/testing.md)を参照してください。

本番URLは `https://tetraboard.net`、Worker名は `tetraboard-2026`、D1名は `tetraboard-2026-prod-db` です。Worker 1つでWeb画面・管理画面・HTTP API・WebSocketを配信します。GitHub ActionsはmainのCI成功後にD1マイグレーションとデプロイを行います。CloudflareのGit連携による別の自動公開は設定しません。

初回は差分と検証結果を確認し、開発者の承認後にマージ・公開します。以後はPRのマージが本番更新の契機です。ローカルのデータは本番へ移行せず、ステージングやPRプレビューは設けません。`tetraboard-2026.chaossi-lab.workers.dev` はパスとクエリを保持して本番ドメインへ308転送します。ドメインをまたいだログイン状態・タブ内の参加資格は引き継がず、再ログイン・再入室します。旧版の `/profile` はマイページ、`/games/game-…` の棋譜と `/guest/name` はリバーシロビーへ案内します。旧ルームは移行せず、存在しない部屋には既存のエラー画面とロビーへの導線を表示します。設定・認証・確認・復旧の手順は [開発手順](docs/development.md#本番デプロイ) を参照してください。

ルーム、参加、通信、持ち時間、チャットなど、ゲームの種類に依存しない仕様はこの節を正本とします。各ゲームのルール文書には、そのゲーム固有の判定や表示だけを記します。

### 対局部屋と参加

- 未ログインでは、前後の空白を除いて1〜10文字のニックネームを使ってゲストとして参加する。ログイン中は必ず本人の設定済みプロフィールで参加し、ニックネームを別に指定しない。認証取得失敗・設定未完了では参加させない。
- ゲストで作成・参加に成功し、参加資格を保存できた場合、最新の使用名をブラウザの `localStorage` に期限なしで保存する。両ゲームの作成・すぐ遊ぶ・番号／公開一覧からの参加・招待リンク／ルーム内からの参加で、画面の再読み込み・再訪時の初期入力に使う。登録からの復元入力は空文字も含めて保存名より優先し、表示中の入力は別タブの変更で上書きしない。入力変更・キャンセル・失敗・観戦・既存参加資格での復帰では更新せず、アカウント参加・プロフィール変更・ログアウトでも保存名を変更しない。保存名が不正、または読取り不能の場合は空文字で開始し、名前の保存失敗は作成・参加を妨げない。保存は同じブラウザ・オリジン内に限り、ブラウザの保存データを削除すると失われる。
- 作成・すぐ遊ぶ・各参加導線で、入室時の名前・アイコンとアカウント・席の対応を固定する。プロフィール変更・ログアウト・別アカウントへの切替で既存席を変更せず、ゲスト席もログインによって付け替えない。アップロード画像はカードが残る間保持する。
- 同一アカウントの席は全ルームを通して1席に制限する。別タブ・別端末から参加トークンなしで参加した場合も拒否し、アカウント認証だけでは参加資格を再発行しない。退室・通信切れから30秒の復帰期限切れ・部屋閉鎖で制限を解除する。投了・時間切れ後も在室中は制限を保持し、脱落後の切断にも30秒の席保持期限を適用する。期限後の元参加資格は閲覧用として維持するが、再戦の席を復元しない。
- 同じ部屋で同じニックネームを使用できる。参加者は部屋内のプレイヤーIDで区別する。
- 部屋の作成者をホスト、部屋番号・招待リンク・ルーム画面から入室した人をプレイヤーとして識別する。有効な参加資格がない人がルームURLを開いた場合は、参加を確定するまで観戦者として扱う。招待リンクでも、有効な参加資格がある人は入力なしで本人として表示する。新規参加者の準備状態は未完了とする。
- 参加資格は部屋ごとに発行し、同じタブの再読み込みでは本人として表示する。同じタブから同じ部屋へ再度入室しても新しい席は作らない。参加資格が無効な場合は観戦者として表示する。
- 対局部屋を作成し、URLでほかの人を招待できる。部屋の公開IDには5桁の数字を使う。招待URLは `/rooms/:id?invite=<instanceId>` とし、部屋が閉鎖されるまで有効とする。閉鎖後に番号が再利用されても、招待先の識別子が一致しなければ参加・閲覧へ進めない。番号のみの通常URLは、その時点で同じ番号の部屋を参照する。
- プレイヤー枠が埋まった部屋への入室は受け付けない。枠数はゲームごとに定める。
- すべての対局部屋を公開対象とし、公開・非公開の設定は設けない。公開ロビーには待機中・対局中の部屋を表示し、待機中で空席のある部屋には参加できる。いずれの部屋も観戦できる。ロビーの表示が一時的に古い場合があるため、参加・観戦時は部屋の現在状態を確認する。
- 対応するゲームでは、待機中のホストがCPU席の追加・削除とレベル変更を行える。CPUには参加資格を発行せず、席数には人間と同じように数える。対局終了後の再戦も提供する。対応の有無、CPUの行動、再戦時の役割・色の割り当ては各ゲームで定める。
- 観戦者は対局の進行を閲覧できる。盤面の向きなど、ゲーム固有の表示は各ゲームのルール文書で定める。
- 待機中のホストとプレイヤーは準備完了・準備取消を切り替えられ、その状態をルーム内の全員に表示する。観戦者は変更できない。準備状態は本人が取り消すまで保持し、通信切れや再読み込みでは解除しない。ただし、復帰期限切れで席が解放された場合は準備状態も失われる。CPUは常に準備完了とし、人間の参加者全員が準備完了かつ接続中になった後、ホストの明示操作で対局を開始する。全員が準備完了になっても自動では開始しない。
- ログイン中のホストがCPUのいない待機ルームで「CPUを追加」を押すと、送信前に「CPUを追加しますか？」ダイアログで選択レベルと上記の戦績・ランキングの注意文を表示します。「CPUを追加」で確認した場合だけ追加し、キャンセル・閉じる・Escapeでは追加しません。CPUが既にいる場合とゲストは直接追加します。全CPU削除後の再追加でも毎回確認し、確認済み状態は保存しません。確認中に満席・対局開始・ホスト権限喪失となった場合は送信しません。ログイン取得中・失敗時は追加を止めて取得待ち・再試行を案内します。
- 待機中にホストが対局設定を変更した場合、人間全員の準備状態を解除する。CPUの準備状態は維持する。対局開始後は設定を変更できない。
- 「すぐ遊ぶ」では、作成者を準備完了にした部屋にCPUを3体配置する。作成者が対局開始を確定するまで待機する。
- 待機中に退室するか、作成・入室後または通信切れから30秒以内に接続しなかった場合は席を解放する。ホストの席が空いた場合は、残る中で最も早く入室した人へホストを引き継ぐ。人間の席がなくなった部屋は、CPUや観戦者が残っていても閉鎖する。
- 対局の状態と手番を参加者・観戦者へリアルタイムに同期する。
- 終局時にサーバーが同じ部屋を再戦の待機状態へ戻す。前局の結果は次の対局開始まで「結果」ボタンから確認でき、終局データは部屋と独立した対局履歴として保存する。退室済みの人は再戦の席に残さず、人間の準備状態を解除する。未接続者の席は元の切断時刻から30秒まで保持する。ホストが退室していれば残る最古の参加者へ引き継ぐ。終局後に人間の参加者がいなければ部屋を閉鎖する。保存済みの棋譜と終局済み対局の保存待ちは、部屋の閉鎖でも保持する。
- 待機中・対局中・再戦待機中の部屋は、入退室、設定・準備・着手、チャット投稿などの最終活動から24時間後に閉鎖する。閲覧と再接続は活動に含めない。

### 投了、通信切れと持ち時間

- 対局中の任意の投了は、自分の手番に限り実行でき、その時点で脱落する。
- 通信が途切れてから30秒以内に復帰した対局者は、同じ対局に戻れる。30秒経過時点で復帰していなければ正式な通信切れとして脱落する。
- 同じ参加資格を持つタブが接続中なら通信切れとは扱わない。復帰期限を過ぎた後の元対局者は、同じ資格で部屋を閲覧できるが、再び対局には参加できない。投了後も同様に閲覧できる。明示的に退室した場合は参加資格を失効する。
- 復帰待ちの間も対局と手番を止めない。手番中の対局者の持ち時間も通常どおり進める。切断中の対局者が30秒より先に時間切れになった場合は、その時点で脱落する。
- 対局中の退室と時間切れでも脱落する。脱落後の順位や盤面の扱いは、各ゲームのルール文書で定める。
- CPUも人間と同じ持ち時間で行動し、思考待ちと計算にかかった時間を計時する。対局中に最後の人間参加者が明示退室または30秒の復帰期限切れになった場合、脱落による終局判定を先に行い、未決着ならCPUの進行を停止して部屋を閉鎖する。投了・脱落後も在室する参加者と復帰期限内の参加者は残存扱いにする。通常の観戦者だけでは部屋を維持しない。ゲストも脱落後の切断から30秒まで在室扱いとし、期限切れで脱落を二重に処理しない。
- 持ち時間・秒読みは両ゲーム共通のルーム設定とし、持ち時間は「なし・1分・3分・5分・10分」、秒読みは「なし・10秒・30秒」から選ぶ。初期設定は1人5分＋1手30秒とする。作成・「すぐ遊ぶ」のダイアログで選び、待機中・再戦待機中はホストが変更できる。対局中は変更できない。実際に値が変わったときは人間全員の準備完了を解除し、再戦は現在の設定を引き継ぐ。
- 持ち時間を使い切った時点から、その手番に設定した秒読みを与える。以後の各手番も同じ秒読みとし、未使用分は持ち越さない。持ち時間なしでは最初の手番から秒読みになり、秒読みなしでは持ち時間を使い切った時点で時間切れとする。両方なしは禁止し、片方がなしならもう片方のなしは選択できない。サーバーもこの組み合わせとプリセット外の値を拒否する。
- 対局開始時は最初の手番者だけを計時する。着手・投了・脱落で手番が変わった時点から次の手番者を計時し、自動パスされた対局者は計時しない。期限ちょうど以降に届いた着手や投了は受け付けず、時間切れを先に確定する。復帰期限と同時刻なら時間切れを先に処理する。終局時には時計を止める。

### 効果音

両ゲームで、対局者・観戦者にライブのイベントの効果音を再生する。ON／OFF切替・音量設定は設けない。

| 音源 | 再生するタイミング |
| --- | --- |
| `join` | 自分の新規参加・ルーム作成成功、他の人間の新規参加。観戦から参加への切替も含む |
| `bot` | ルーム内でCPU追加が確定したとき。「すぐ遊ぶ」の初期CPUには鳴らさない |
| `put` | 自分の合法手の送信成功直後、他人・CPUの着手確定時 |
| `start` | 対局開始の確定時。再戦も含む |
| `end` | 終局の確定時。投了・脱落等による終局と引き分けも含む |

- 観戦者自身の入室、再読み込み・再接続、CPUのレベル変更・削除、準備変更では鳴らさない。駒選択・成り選択・不正操作・送信失敗・パス・単独の脱落・棋譜操作では着手音を鳴らさない。
- 自分の着手は確定通知で二重に鳴らさない。送信後に拒否された場合、送信時に鳴った音は取り消せない。最終着手と終局を同時に受けた場合は着手音の後に終了音を再生する。
- Web Audioを使い、対応環境では他アプリの音声と混ぜるambientを指定する。iOSの消音モードに従う。ブラウザ・OS・再生元アプリによる同時再生の挙動は実機確認が必要であり、すべての環境での継続を保証しない。
- 最初のタップ等で音声を有効化する。操作前・ページ非表示中・音源準備前のイベント、初回取得・接続復帰で取得した過去のイベントは後から再生しない。複数手をまとめて受信した場合は最新の着手音を1回だけ再生する。
- 音源読み込み・デコード・再生が失敗してもゲーム操作と通信を継続する。

### チャット

- 対局者は対局部屋の共通チャットに送信・閲覧できる。観戦者は閲覧のみできる。
- 人間の入退室、CPUの追加・削除、対局形式の変更をシステムログに記録する。一時的な切断・再接続は入退室として記録せず、明示退室と復帰期限切れによる退室は一度だけ記録する。システムログは通報・送信者非表示の対象にしない。
- チャットの利用は手番や持ち時間に影響しない。チーム内だけで使うチャットなど、ゲーム固有の扱いは各ゲームのルール文書で定める。

### チャットの保存期間とモデレーション

- チャット投稿とシステムログを合わせて対局部屋の直近100件だけを保持し、復帰した参加者にも表示する。待機中、対局中、再戦待機中に送信でき、再戦にも引き継ぐ。古いログは100件を超えたときに、残る投稿は部屋の閉鎖時に削除する。
- 新規投稿は1件100文字以内（絵文字なども見た目の文字単位で数える）、同じ送信者からは3秒に1件までとし、URLの投稿を受け付けない。暴言、嫌がらせ、個人情報の投稿、広告を禁止する。
- 保存済みの旧形式・200文字以内の過去投稿は引き続き閲覧・通報でき、新規投稿だけに100文字制限を適用する。
- 対局者と観戦者はメッセージを通報でき、自分の画面では任意の送信者の発言を非表示にできる。運営者は通報を確認し、メッセージの削除と、その対局部屋での送信停止を行える。
- 通報されたメッセージの本文、投稿時刻、部屋ID、送信者の対局内識別子は、確認のため7日間だけ保持する。7日経過時点から閲覧対象から外し、定期処理で削除する。物理削除には最大約1時間の遅れがあり得る。通常のチャットは部屋の閉鎖後に履歴として残さない。

## MVP機能

初期MVPは四人リバーシを対象としました。四人将棋もオンライン対局へ接続し、両ゲームで共通のルーム機能を利用します。両ゲームの終局保存・本人の戦績と棋譜・ゲーム別ランキングを利用できます。

### 対局

- 四人リバーシの合法手、手番、パス、終局、順位の判定
- 持ち時間の表示と時間切れによる脱落
- 「すぐ遊ぶ」から、1人とCPU 3体で始められる対局
- 人間とCPUを組み合わせた1〜4人での対局
- CPUによる合法手の選択と、最低限の局面評価
- 対局終了後の再戦
- 同じ部屋で、直前1局を次局開始まで振り返る棋譜モード
- 終局データ・棋譜の保存と、マイページでの本人の対局履歴・戦績

### オンライン機能

- ニックネームを使ったゲスト参加と、ログイン中のアカウント参加
- 対局部屋の作成
- URLを使った招待
- 公開ロビーでの対局部屋の一覧表示・参加・観戦
- ゲーム別の最近の対局一覧と、保存済み棋譜の公開閲覧
- モード別の優勝数／勝利数・対局数ランキング
- 席へのCPUの追加と削除
- 盤面と手番のリアルタイム同期
- 対局中の通信切れからの復帰
- 対局の観戦
- 対局部屋の共通チャット

### 初めて利用する人のための機能

- 四人リバーシのルール説明
- 石を置ける場所や現在の手番の分かりやすい表示
- PCとスマートフォンの両方に対応した画面
- エラー発生時の分かりやすい案内
- 簡単なフィードバックの送信
- 対局の開始、完了、エラーを把握するための計測

### MVPに含めないもの

- 通常の将棋・リバーシなどの追加ゲーム
- レーティング
- 大会管理
- 他プレイヤーの戦績閲覧
- 課金
- 高度なCPUや機械学習による思考

### 四人将棋のゲームエンジン

四人将棋のルール正本と調査資料は [四人将棋ルール](docs/rules/four-shogi.md) に記す。独立した `@tetraboard/four-shogi` パッケージに、シングルス・通常のダブルスと三人攻撃禁止のON／OFF切り替えを実装している。初期化、合法手、王手、着手、脱落、順位・勝敗、千日手を純粋な関数で扱い、状態はJSONで保存・復元できる。CPUは合法手からランダムに選ぶLv1と、駒の価値・王の安全・次の手番の応手を評価するLv2を利用できる。Lv2は探索する候補と応手を制限するため、読み落としがある。使い方と確認方法は [開発ドキュメント](docs/development.md#四人将棋エンジン) を参照する。エンジンとCPUはオンラインルームへ接続し、時刻・接続期限はルーム側で管理する。 オンライン対局の千日手履歴は必要な局面キーだけをSQLiteから取得し、変更分を保存する。対局の長さに比例した全件読み取りを各手で行わない。

## KPI・KGI

### KGI

1か月のMVP開発におけるKGIは、次の状態を実現することです。

> ユーザーが自力で四人リバーシの対局を最後まで完了し、その一部が7日以内にもう一度対局する。

最低成功ラインは次のとおりです。

- 初回対局完了者が10人以上いる
- 7日以内の再対局者が3人以上いる
- 完了対局が合計30局以上ある

開発者との個人的なつながりの有無を問わず集計します。

### KPI

| 観点 | 指標 | 1か月目の最低目標 |
| --- | --- | ---: |
| 流入 | 訪問者 | 30人 |
| 対局開始 | 訪問から対局を開始した割合 | 40%以上 |
| 対局完了 | 開始した対局の完了率 | 70%以上 |
| 継続 | 初回対局完了者の7日以内の再対局率 | 20%以上 |
| 利用量 | 完了対局数 | 30局以上 |
| 満足度 | 「また遊びたい」と回答した割合 | 70%以上 |
| 品質 | 対局を続行不能にする重大障害 | 最終検証時に0件 |

利用者が少ない初期段階では割合が大きく変動するため、KPIは割合だけでなく実数も併せて評価します。最初の1か月は売上を成功条件にせず、継続して遊ばれる価値があることを確認した後に収益化を検討します。
