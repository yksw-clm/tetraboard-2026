# TetraBoard

## 概要

TetraBoardは、四人用を中心としたボードゲームをブラウザですぐに遊べるオンライン対局サービスです。

最初に提供するゲームは四人リバーシです。四人全員を集めなくても遊べるようにCPU（BOT）を用意し、1人でのプレイから、友人を招待した対人戦まで同じ仕組みで楽しめることを目指します。

初期の主な対象は、リバーシなどのボードゲームが好きで、少し変わったゲームを気軽に試したい人です。ユーザー登録やアプリのインストールを必要とせず、初めて訪れた人が迷わず対局を始められる体験を重視します。

旧TetraBoardとは別のプロジェクトとして開発し、当面は旧版を置き換えません。新しい土台の品質と利用状況を確認しながら、将来のゲーム追加や移行を判断します。

## プロジェクトのきっかけ

開発者は幼い頃から、パソコンで文章やファイルを作ったり、ゲームを開発したりして、それを誰かに使ってもらうことに喜びを感じてきました。

プログラミングを学び始めてからは、クイズゲームやRPG、配信で利用できるしりとり・山手線ゲームの支援ツール、四人オセロなどを制作しました。友人や小さな配信コミュニティがそれらを使い、楽しんでくれた経験が、Webエンジニアを目指す原点になっています。

一方、旧TetraBoardの開発では多くをAIに任せた結果、コードや設計を自分自身で十分に理解できず、「自分が作ったものを使ってもらう」という実感も薄くなってしまいました。

TetraBoardを新しく作り直すのは、単に旧版のコードを整理するためではありません。自分で考え、理解し、納得して作った遊びをもう一度誰かに届けるための再出発です。

## プロジェクトの目的

TetraBoardのプロダクトとしての目的は、プレイヤーを集めにくい四人用ボードゲームを、一人でも複数人でも気軽に始められるオンラインの遊び場として提供することです。遊ぶ人だけでなく、観戦する人も含めて、ゲームをきっかけに人が集まり、楽しめる場所を目指します。

開発プロジェクトとしては、次の状態を目指します。

- 開発者が主要な仕様と設計を自分の言葉で説明できる
- 技術やライブラリを採用した理由を理解している
- 機能数よりも、初めて訪れた人が遊び終え、再び遊びたくなる体験を優先する
- 継続的な利用を確認したうえで、将来の収益化につなげる

## 読み込み・処理中・エラーの表示

ロビー・ルーム・保存済み棋譜の画面全体を読み込む間は、ロビーと同じ背景の中央にスピナーと案内文を表示します。ゲームが判明している場合はそのゲームのテーマを使い、未取得の場合は共通の緑を使います。ルームが見つからない場合を含むルーム・棋譜のエラーも、中央に案内文と戻る・再試行などの操作を表示します。

利用者向けWebで遅延読み込みに失敗した場合は、移動先URLが確定してから、タブを閉じるまで一度だけ自動で再読み込みします。再発時や保存領域を利用できない場合は「画面を読み込めませんでした。アプリが更新された可能性があります。再読み込みしてください。」と「再読み込み」を表示します。再読み込みでは現在のパス・クエリ・ハッシュを保ち、認証や参加資格の保存データは削除しません。初回ロビーの失敗では紹介HTMLを残して同じ復旧操作を案内します。通常の予期しないエラーにも共通の日本語エラー画面と手動の再読み込みを用意しますが、自動更新はしません。この対応を読み込んだタブから有効で、管理画面は対象外です。

Webの操作ボタンは、作成・参加・棋譜への移動・更新・送信・保存などの処理中に、押したボタンの文字とアイコンをスピナーに置き換えます。ボタンの寸法と読み上げ名を保ち、重複操作を防ぎます。失敗時は再操作でき、入力値や取得済みデータの保持方針は維持します。初回取得や条件切り替えの案内は表示し、自動更新や別の操作による無効化ではスピナーを表示しません。

## 総合ロビーの確定仕様

2026-10-13に開発者がUIモックと以下の本実装仕様を承認しました。目的は、全ゲームの募集を見つけやすくして対人戦の割合を改善し、再び遊ぶ相手や約束を見つけられる環境を作ることです。承認済みのモックを実データ・認証・D1保存・管理画面へ接続しました。以下は採用仕様です。本番反映は開発環境の確認とリリース承認後に行います。実装計画は[開発文書](docs/development.md#総合ロビーの実装計画)、受入検証は[テスト方針](docs/testing.md#総合ロビーの確認)を参照します。

### トップページと承認済みUI

`/` はサービス全体の入口となる総合ロビーです。ブランド見出し・紹介文、ゲーム一覧、公開ルーム、全ゲームの大会一覧、公開チャット（β）、最近行われた対局の順に表示します。767px以下では大会一覧を最近の対局の下へ移します。各ゲームのURLは維持します。

- ゲーム一覧は盤面図とゲーム名を一つのカードリンクにし、四人将棋・四人リバーシ・四人五目並べ・将棋・リバーシ・五目並べの順に表示します。768px以上は6列、767px以下は3列です。初期配置の専用の軽量画像を共用し、対局用の盤面・駒・ゲームエンジンを読み込みません。五目並べと四人五目並べは同じ空の盤画像です。
- 公開ルーム見出しの「ルームを作る」はゲーム選択ダイアログを開き、選択したロビーへ移動して既存の作成ダイアログを一度だけ開きます。移動だけではルームを作成しません。「更新」も見出し行へ置き、専用の行は使いません。
- 公開ルームは768px以上で2列、767px以下で1列です。一覧の最大高さはPCで480px、スマートフォンで400pxとし、超過分は領域内で縦スクロールします。少数件は内容に応じた高さにします。公開チャットは一覧の下に残し、入力欄・送信ボタンの高さ48pxとチャット履歴の内部スクロールを維持します。
- 公開ルームの人数フィルターは「すべて／四人用／二人用」、初期は「すべて」です。現在の参加人数ではなくゲームの定員でサーバーから取得し直します。「参加できるルームのみ」は初期オフで、取得済みの全ルームから待機中かつ空席のある部屋を画面内で絞り込みます。このチェックの切替では再取得や読み込み表示を発生させません。条件はブラウザへ保存せず、切替時は一覧の先頭へ戻ります。
- 公開ルームカードは総合・ゲーム別で共用し、盤面図、ゲーム名・モード、持ち時間・秒読み、ホスト名から作る「○○の部屋」、番号、募集状態、参加者全員のアイコン、人数、観戦・参加操作を表示します。募集状態は「募集中／満員／対局中」です。満員・対局中の参加ボタンは無効にし、観戦はすべての部屋で利用できます。大会ルームは直接参加の代わりに「大会へ」を表示します。
- 人間のアイコンは入室時の席の画像を使い、既存席をプロフィール変更へ追従させません。CPUは既存のロボット、画像なし・読み込み失敗の人間は仮アイコン、空席は破線の丸で表示します。各参加者のアイコンから既存のプレイヤー情報カードを開き、CPUにはレベルを表示します。空席と退会者は操作対象にしません。退会受付後の本人画像・プロフィール参照は匿名化し、遅れた索引更新からも復活させません。「募集中」は薄いテーマ色の背景に濃い本文色で表示します。
- チャット見出しの下には「現在β版として試験公開しています。」と既存のフィードバック画面への「使ってみた感想を送る」を表示します。発言は小さいアイコン・名前・本文を同じ行から表示し、長文は折り返します。自分の発言の背景、時刻と操作欄の位置、投稿欄の文字数表示を維持します。

### 公開ルームの取得と参加

- 総合・ゲーム別の新一覧は同じ公開索引を使い、「対局前で空席あり → 対局前で空席なし → 対局中」、同分類では公開情報の更新日時降順・ルーム番号降順に並べます。ゲーム・定員条件をサーバーで適用し、20件ずつ最後のページまで取得します。モードと参加可能条件は取得済み全件へ画面内で適用し、絞り込み後の件数を表示します。既存APIのモード・参加可能条件は維持します。
- 全ページの取得成功後に一覧を一括更新します。ゲーム別ロビーは最初の3件だけ表示し、「すべてのルームを見る」で取得済み全件を同じページ内へ展開します。追加取得用の「もっと見る」は置きません。モード・参加可能条件の切替では通信せず、3件表示と先頭位置へ戻ります。0件なら選んだ条件に合うルームがないことを表示します。
- 前面で表示中は10秒ごとに全ページを自動更新し、非表示中は取得を中断して停止、復帰時は先頭から再取得します。自動更新ではカード・0件表示・スクロール位置を保ち、手動の「更新」だけスピナーを表示します。取得の重複・古い条件の応答による巻戻りを防ぎます。更新途中の失敗では前回の全件・選択条件・位置を保持し、初回途中失敗では部分一覧を出さず、エラーと再試行を案内します。
- 参加は既存の名前・プロフィール・参加資格・同意のダイアログと通信を使い、選択したルーム番号を表示します。観戦には名前入力を求めません。「ルーム番号で参加」の入力入口は置かず、公開一覧と招待URLから参加します。部屋番号の識別表示と既存の内部APIは維持します。
- 一覧取得後の満室化・対局開始・閉鎖・番号再利用は、対象ルームの現在状態と世代をサーバーで再検証し、参加できない理由を表示します。ゲームの定員・準備・開始・再戦と、アカウントの同時参加制限は維持します。

### 最近行われた対局

全6ゲームの保存済み終局を横断して最新20件表示します。開始日時の降順、同時刻は対局UUIDの降順という既存の順序を維持し、未終局・保存途中は除外します。初期はCPU戦・ゲスト戦・両モードを含め、「対人戦のみ」で開始時にCPUがいない対局へ絞ります。ゲストは人間として扱います。公開ルームの定員フィルターはこの一覧に適用しません。

カードにゲーム名のバッジ・モード・日時・参加者・結果・手数とCPU有無（「CPUあり／対人戦」）を示し、既存の公開棋譜へ移動します。初回と手動の「更新」だけで取得し、自動更新や追加取得はしません。相対日時・更新失敗時の保持・条件切替の読み込みは[既存仕様](#最近行われた対局と公開棋譜)に従います。

### 公開チャットβの投稿と更新

| 項目           | 採用仕様                                                                     |
| -------------- | ---------------------------------------------------------------------------- |
| 閲覧           | 未ログインでも可能                                                           |
| 投稿           | 名前設定済みのゲスト、またはログインとプロフィール設定を完了した登録者       |
| 本文           | テキストと絵文字、1件100文字以内。見た目の文字単位で数え、URL投稿は禁止      |
| 送信間隔       | アカウントごとに10秒。総合ロビー・全大会・複数タブ・端末を通じて共通に適用   |
| 通常投稿の保存 | 投稿から7日以内、総合ロビー内で最新500件まで。いずれかを超えた古い投稿を削除 |
| 履歴取得       | 初回は最新50件、過去分を追加取得可能                                         |
| 更新           | 前面で表示中は5秒ごと、非表示中は停止、復帰時に再取得                        |

- 名前未設定の利用者は「名前を設定して投稿」からニックネームを確定してゲストとして利用を開始できます。閲覧・ダイアログ表示・取消ではアカウントを作成しません。名前の確定とCookieの保存確認後に投稿欄を表示し、本文は送信操作で投稿します。ゲストの既定名を本人が確定するまでは投稿できません。
- 翌日の募集などにも使える会話として扱い、予約枠や対局開始時刻の保証は設けません。ルームチャットの在室要件・3秒間隔・直近100件・閉鎖時削除とは独立させます。
- 最新付近を表示中だけ新着へ自動追従します。過去の発言を読んでいる間は位置を保ち、新着件数と最新へ戻る操作を表示します。過去分の追加取得でも閲覧位置を保ち、日付の区切りと正確な日時を確認できる表示を用意します。
- サーバーの確定応答を受けてから発言を表示し、入力を消します。失敗時は入力を残し、応答喪失後の再送でも同じ投稿を重複保存・表示しません。日本語入力の変換中にEnterで送信しません。投稿目的のログイン・プロフィール設定から `/` へ戻り、入力途中の本文を保持します。
- 期限到達した投稿は取得時点から閲覧対象外にします。毎時の削除処理は失敗時に再試行し、保存上限超過も処理します。画面表示中の期限到達・運営削除・退会による削除は次回同期で反映します。
- ルーム添付、募集文テンプレート、予約、メンション、通知音は初回範囲に含めません。

### 公開チャットβの運営と退会

- 送信者を非表示にする操作は閲覧者のブラウザ内に保存し、その送信者の発言をまとめて隠します。表示名ではなく公開用の送信者識別子で区別し、内部アカウントIDは公開しません。通報は本人確認済みのゲスト・登録者が行い、直近1時間で1アカウント5件まで受け付けます。同じ発言への再通報は重複登録せず、件数を増やしません。
- 管理画面に公開チャット専用の通報一覧、投稿削除、アカウントの公開チャット投稿停止・解除を追加します。既存の管理者認証を使い、一般利用者に管理APIや通報証拠を公開しません。ルーム内チャットの運営機能をこの変更で拡張しません。
- 運営が公開チャット全体の投稿受付を停止・再開できます。停止中も履歴閲覧・公開ルーム・対局は利用でき、状態を投稿欄に表示します。投稿停止はWebの無効化だけでなくサーバーで拒否し、各状態変更は次回同期で反映します。
- 通報証拠は通報から7日を上限に管理者だけが閲覧します。通常履歴から削除済みの投稿も、期限内の通報証拠として必要な範囲で保持します。期限到達時の閲覧除外・毎時削除と退会者情報の扱いは既存の通報方針に従います。
- 退会受付後は本人の投稿を一般の取得対象から直ちに除外し、公開チャットの通常投稿を削除対象に追加します。削除処理を再試行でき、遅延した投稿や同期で復活させません。ルーム内チャットの匿名化方針と公開チャット本文の削除方針を区別します。
- 公開範囲、投稿資格、通常投稿と通報証拠の保存期間、退会時の削除、送信者非表示の端末保存をプライバシーポリシー・利用規約へ反映してからβを公開します。

### 目的・対象・公開

- 同じ時間に四人将棋プレイヤーを集めて対人戦を増やし、登録と再訪につなげます。短時間の単発大会を対象とし、開催日時は管理画面で指定します。モックの「第一回」、開催日時・人数・残り時間・成績は例示で、実際の第1回の開催決定ではありません。
- 大会詳細は `/tournaments/:id` とし、公開時に開催順で1から増える数字の大会番号を付けます。番号は変更・再利用せず、下書きの内部識別子と分けます。新しく公開できるのは、既公開の最終大会の終了日時以降に開始する大会だけとし、開催順の途中への追加や時間帯の重複を認めません。前の大会で終了待ちの対局が残っていても、次の開催時間内の対局を妨げません。
- 公開した大会は直ちにエントリー受付を開始します。公開前の下書きは管理者だけが閲覧できます。公開後はURLを残し、終了後も結果を閲覧できます。初回は公開後の非公開化・削除、開催延期・中止を提供しません。公開日時と開催日時は別で、予約公開は提供しません。
- 未ログイン・プロフィール設定前でも大会詳細・ルール・順位・確定結果と対局の観戦ができます。エントリー・対局はプロフィール設定済みの登録ユーザーと名前設定済みのゲスト本人に許可します。エントリーボタンからログイン・登録・プロフィール設定へ進んだ場合だけ参加意図を保持し、同じ大会へ戻った時点で受付可否を再確認し、エントリーの確認ダイアログを開きます。ダイアログの「エントリーする」を押した時点で正式に登録し、ログイン・設定から戻っただけでは登録しません。ヘッダーの通常ログインではエントリーダイアログを自動表示しません。

## 四人将棋シングルスAIの開発計画

初期HTMLと画面内遷移の両方で、ゲーム固有のtitle・description・canonical・robotsをそろえます。6ロビーのtitleは「ゲーム名をブラウザで無料対戦 | TetraBoard」の語順に統一し、全角30字程度を目安にします。四人将棋は「四人将棋（4人将棋）」、四人リバーシは「四人リバーシ（4人オセロ）」をtitleと120字程度のdescriptionに使います。ブランド名は既定title・各title・`og:site_name` とも `TetraBoard` です。正規URLは `https://tetraboard.net` 配下の末尾スラッシュなしです。本番ホストのHTTPアクセスは画面・API・WebSocketの処理前に、パス・クエリを保持してHTTPSへ308転送します。ローカル・開発環境のHTTPはこの転送の対象外です。末尾スラッシュ・生成indexへの直接アクセスはクエリを保持して正規URLへ308転送します。サイトマップには総合ロビーとこの6ページを掲載し、全URLにページ内容の最終更新日を表す `lastmod` を付けます。robots.txtはクロールを許可します。

ルーム・ログイン・アカウント・公開／本人棋譜・お知らせ・フィードバック等の他画面はHTMLとHTTPヘッダーで `noindex` とし、ロビーのメタ情報を残しません。ルーム向けの共有メタ情報は下記の確定仕様に従います。管理画面の認証と検索除外は維持します。noindexはアクセス制御の代わりにしません。未知の画面URLと存在しない資産はHTTP 404とし、全ロビーへの案内を返します。API・WebSocket・旧URL・旧ホストの転送は維持します。

検索順位・検索結果のURL選択・反映時期はGoogleが決めます。ローカル検証・GitHub CI・承認後の本番配信確認・Search Console送信・公開前基準値の記録をSEO整備の完了とし、検索1位と流入増加の達成は別に確認します。公開・計測の手順は [開発手順](docs/development.md#ロビーのseo生成と成果確認) を参照してください。

## ルーム共有の確定仕様

2026-10-11に開発者が承認した仕様です。共有ダイアログ、Xでの募集、ルーム向けOGPを提供します。全6ゲーム（四人リバーシ・四人将棋・リバーシ・将棋・五目並べ・四人五目並べ）を共通の仕様で扱います。

### 表示のタイミングと既存ボタン

- 「みんなで遊ぶ」から「ルームを作る」で作成に成功し、作成者としてルーム画面を表示した直後に、共有ダイアログを1回だけ自動表示します。作成失敗、「CPUと遊ぶ」、参加・観戦からの入室では自動表示しません。
- 閉じた後の再読み込み・再接続・ルームへの戻りでは再表示しません。作成者以外の画面には連動して開きません。
- ルーム情報の「招待リンクをコピー」を「ルームを共有」に変更し、押すと同じダイアログを開きます。既存ボタンの幅・高さ・余白・配置と周囲のレイアウトはすべて維持します。手動表示は対局者・観戦者が利用できます。
- ダイアログは既存の共通UIとゲームのテーマを使い、右上の閉じるボタン・Escape・背景操作による閉鎖、背景のぼかし・スクロール・フォーカス制御も共通の動作に従います。

### ダイアログの内容とコピー

| 項目       | 確定内容                                                    |
| ---------- | ----------------------------------------------------------- |
| タイトル   | ルームを共有                                                |
| 説明       | リンクを送って友達を招待したり、Xで対戦相手を募集できます。 |
| URL欄      | 選択して手動コピーできる、読み取り専用のルームURL           |
| コピー操作 | ルームURLをコピー                                           |
| X操作      | Xのロゴと「Xで対戦相手を募集」                              |

共有URLは現在の環境のOriginに、既存の `/rooms/:id?invite=:instanceId` を付けたURLです。コピーとX投稿で同じURLを使い、参加資格トークンは含めません。リンクを開いた未参加者への参加案内、部屋世代の照合、参加・観戦の条件は既存仕様を維持します。

コピー成功は「ルームURLをコピーしました」のtoastを3秒表示し、ダイアログは開いたままにします。失敗時はURL欄の近くに「コピーできませんでした。URLを選択してコピーしてください。」と表示し、手動コピーと再試行ができます。コピー処理中はコピー操作の重複を防ぎます。

### Xの募集

「Xで対戦相手を募集」は投稿文を入力したXの投稿画面を別タブで開きます。利用者はX上で文章を編集して投稿を確定します。TetraBoardから自動投稿や投稿完了の判定はしません。Web Intentsを使い、XのAPI認証・アカウント連携は追加しません。

投稿文は次の4行です。`[ゲーム名]` はゲームカタログの表示名、`[ルームURL]` は上記の共有URLに置き換えます。ハッシュタグも表示名と一致させます。

```text
[ゲーム名]の対戦相手を募集中！
ブラウザですぐ遊べます。気軽に参加してください！
[ルームURL]
#[ゲーム名] #TetraBoard
```

満室・対局中は募集ボタンを無効にします。対局中は「対局中のため、現在は観戦のみできます」、待機中の満室は「満室のため、現在は参加できません」とダイアログ内に表示します。ダイアログ表示中もルームの最新状態に合わせて更新し、URLのコピーは引き続き利用できます。

### 共有カードとOGP

- ゲームごとに1200×630pxを基本とする専用画像を1枚、存在しない・期限切れのルーム向けに共通のTetraBoard画像を1枚用意します。ゲーム画像はテーマ色の背景、盤面、大きなゲーム名、TetraBoardのロゴと「ブラウザですぐ遊べる」で構成します。
- 画像にはルーム番号・プレイヤー名・空席数・「募集中」を入れません。対局中や満室でも同じゲーム画像を使います。
- 有効な共有URLのタイトルは「[ゲーム名]のルーム | TetraBoard」、説明は「ブラウザで遊べる[ゲーム名]。リンクからルームに参加・観戦できます。」、URLは `invite` を含む共有URLにします。
- 初期HTMLに `og:title`・`og:description`・`og:type=website`・`og:url`・`og:image`・画像の寸法と代替説明・`og:site_name` を設定します。X向けにもタイトル・説明・画像・画像の代替説明と `twitter:card=summary_large_image` を設定します。画像URLはその環境の絶対URLです。
- Workerが直接アクセスの初期HTMLへメタ情報を含めます。JavaScript実行やX専用のUser-Agent判定を前提とせず、ルーム番号と `instanceId` を照合したゲームの情報を使います。存在しない・期限切れ・部屋世代が異なるURLは共通カードへ戻し、別の部屋の情報を出しません。
- ルームのHTMLとHTTPヘッダーの `noindex` を維持します。開発環境のURL・画像を本番へ転送せず、サイトマップの対象は総合ロビーと6ゲームのロビーです。画面内遷移でも前の画面のメタ情報が残らないようにします。

カードの実際の表示と反映時期はXなど共有先の取得・キャッシュ・表示方式に依存します。実装のGoal・ContextProviders・Constraints・Done Whenは [開発文書](docs/development.md#ルーム共有の実装計画)、検証範囲は [テスト文書](docs/testing.md#ルーム共有の確認) を参照します。

## 四人リバーシのルーム画面

`/rooms/:id` は対局者と観戦者で共有するルーム画面です。HeroUIのカード・ボタン・タブ・ダイアログ・通知を使います。

- PC（1280px以上）は盤面・プレイヤーカード・状況カードを左、ルーム情報・チャットを右に表示します。タブレット（768〜1279px）は盤面の上下左右にカードを配置します。スマートフォン（767px以下）は盤面の上に2枚、下に2枚を配置します。
- 全ゲームのPC版は左右列の高さを独立させます。状況カードを左側の盤面・手前プレイヤーカードの下に置き、幅を盤面とそろえます。盤面・プレイヤーカード・状況カードを一つのまとまりとして上下中央に配置し、高さが足りないときは状況カードと余白の高さも差し引いて盤面を縮小します。右側にはルーム情報とチャットを配置し、状況カードが使っていた高さをチャットに割り当てます。ルーム設定はダイアログで表示し、開閉で盤面・プレイヤーカード・チャットの位置と大きさを変えません。右列が画面の高さを超える場合は右列で縦スクロールし、チャットは残り高さを使います。チャット領域の最小高さは140pxとし、履歴内のスクロールも維持します。
- 待機中のホスト向け「ルーム設定」ボタンは共通ダイアログを開きます。ボタンのアイコンとラベルは中央揃えです。右上の閉じるボタン・「キャンセル」・Escapeで閉じ、未適用の編集は破棄します。シングルス／ダブルスはルーム作成と同じ説明付きカードで選びます。追加するCPUのレベル選択は「CPUを追加」のすぐ左に8px間隔で置き、右寄せします。CPUレベルのホバー背景は薄いテーマ色を使います。
- モード・時間・CPUの追加／削除／レベル・ゲーム固有の設定はダイアログ内の下書きとして編集し、「適用」で全項目をまとめて送信します。サーバーはホスト権限・待機状態・定員・CPU・編集開始時のルーム情報を確認し、すべて有効な場合だけ一度に反映します。編集中に入退室や他の設定変更があった場合は、下書きを保持して「設定を読み直す」を案内し、古い編集で上書きしません。
- 適用中は選択内容を保持し、適用ボタンにスピナーを表示して編集・閉じる操作をロックします。一時的な無効化による透明度の切り替えを抑えます。成功時はダイアログを閉じ、拒否・送信失敗・切断では下書きと再操作の導線を保持します。準備解除・盤面・CPUの増減はサーバー確定後に反映します。

- スマートフォンではカードの幅・高さを保ち、空き高さが足りないときは盤面だけを中央で縮小し、正方形を維持します。カードと盤面の間隔は2pxとし、自動パス通知の高さも確保します。通常ルームと保存済み棋譜に適用します。
- タブレット・スマートフォンには「盤面／ルーム／チャット」のタブを設け、状況カードをその上に常に表示します。チャットの入力と閲覧位置はタブを切り替えても保持します。
- 初回の待機中は操作できない初期盤面を表示します。終局後は自動で棋譜モードに入り、前局の最終局面を表示します。待機中に石を置いたり、合法手のマークを表示したりはしません。対局中と保存済み棋譜のカードは黒→白→赤→青の時計回り順にし、観戦・公開棋譜は黒、対局者と本人用の保存済み棋譜は本人を手前にします。待機・再戦待機は入室順を維持します。着席と担当色の関係は[四人リバーシのルール](docs/rules/four-reversi.md#色の割り当てと表示)に従います。
- プレイヤーカードは同じ幅・高さを保ち、最大10文字の名前と王冠を省略・折り返しせず一行で表示します。長い名前は表示幅に合わせて文字サイズを調整します。入室時のアカウントアイコン（未設定・ゲストは仮アバター）、ホストの王冠、CPUの「CPU Lv1」などの名前と青いロボットのアバターを表示します。接続中は緑、切断中は黄の丸いバッジを表示し、空席は薄いグレーにします。
- 対局中は直前に着手したマスをオレンジの枠で示し、自分が着手できるマスに丸い点を表示します。最終手の枠は再読み込み・観戦でも表示し、初期盤面では表示しません。
- 待機中のカードには初期持ち時間（持ち時間なしの場合は秒読み時間）と、準備済みの場合だけ緑の「準備完了」を表示します。石数と担当色は対局中だけ表示します。脱落後もカードを残し、時計の代わりに「4位（退室）」などの確定順位と脱落理由（退室・時間切れ・投了・通信切れ）を表示します。理由は再読み込み・途中からの観戦でも保持し、旧データで記録がない場合は順位だけを表示します。再戦待機になったら順位・石数・色を消して初期表示へ戻します。
- 時計は基本時間を黒、秒読みを黄色で表示します。対局中は現在の手番者の実際の時間切れまで残り5秒以下になったら、対局者・観戦者のプレイヤーカードと状況カードの時計を赤と穏やかなアニメーションで強調します。秒読みなしの持ち時間にも適用し、秒読みがある場合は持ち時間の終了5秒前には強調しません。残り0秒もサーバーが手番交代・脱落・終局を確定するまで強調を維持し、手番外・待機・棋譜では強調しません。動きを減らす端末設定では赤色を維持してアニメーションを止めます。時計音と強調の確定仕様は[時間切れ5秒前の通知](#時間切れ5秒前の通知)を参照してください。
- 状況カードは待機中に参加者数（CPU込み）と準備操作、自分の手番にオレンジの「あなたの番です。」と時計・投了、他の手番に名前と時計を表示します。再戦待機では参加者数の代わりに「結果」を表示し、押すと結果ダイアログを開きます。全ゲームで対局者・観戦者とも、ログイン状態に関係なく、画面上で終局を検知してから1秒後に結果を自動表示します。各対局につき1回で、閉じた後は「結果」から再表示できます。終了済みの部屋への初回入室・再読み込みでは自動表示しません。1秒後に他のダイアログが開いている場合は、その局の自動表示を取り消します。次局開始・退室・閉鎖でも保留を取り消します。
- 棋譜カードは「←」、局面を選ぶSelect、「→」で構成します。PCでは盤面・プレイヤー領域の右下へ重ねて配置し、棋譜の有無で盤面とプレイヤーカードの位置・寸法を変えません。タブレット・スマートフォンでは状況カードの「待機中です。」と「結果」の間に表示し、タブ切替中も操作できます。最初は「開始局面」、着手は「5: 赤E6」の形式で表示します。自動パス・投了・退室・時間切れ・通信切れによる脱落も独立した項目とし、着手番号は増やしません。終局後は最後の項目を選び、次の対局開始時に棋譜モードを解除します。局面の選択は閲覧者ごとに独立しています。
- 全ゲームの棋譜Selectは選択中・候補とも短い一行表示とし、幅が足りない場合だけ省略記号を使います。読み上げ名は省略しません。着手は「5: 赤E6」「1: ▲7六歩」「122: 北6九金打」、外部脱落・パスは「南 投了」「北 通信切れ」「赤 パス」の形式です。「開始局面」「最終局面（棋譜なし）」は保持し、通常ルームと保存済み棋譜で同じ表示を使います。
- 接続中・再接続中・操作エラーの通知は全ゲームのルーム上部中央へ重ね、盤面・カード・タブの位置や寸法を変えません。上端の安全領域から8px、左右8px以上を空け、最大幅480px内で長い文を折り返します。クリックを透過し、ダイアログとSelect候補の下に表示します。
- ルーム内の棋譜モードでも盤面は前局、プレイヤーカードは現在の待機メンバー・入室順・準備状態を表示します。前局の担当色はカードに表示しません。プレイヤーカードの下には棋譜の手数・手番・4色の石数を表示せず、選択局面は棋譜Select、直前の着手は盤面の枠で示します。
- スマートフォンでは棋譜カードを小さくし、「待機中です。」「棋譜カード」「結果」を一行に配置します。状況カードは棋譜の有無にかかわらず同じ高さに保ちます。
- 直前1局の棋譜は次局開始または部屋の閉鎖まで保持し、再読み込み・再接続でも最後の局面から復元できます。待機中の設定変更や入退室で棋譜を書き換えません。導入前に開始済みだった対局は最終局面のみを表示し、過去の着手は補完しません。
- ホストの「対局開始」は状況カードの準備操作の隣に置きます。開始条件を満たすまで無効にします。モード、持ち時間・秒読み、CPUの設定は待機中のルーム情報から開く共通ダイアログにまとめます。時間の初期設定は5分＋1手30秒です。
- 観戦者には、待機中で空席がある場合に状況カードの「参加する」を表示し、名前未設定のゲストはニックネーム入力、設定済みのゲスト・登録者はプロフィールの確認から参加できます。満室・対局中も含めて状況カード下段の左に「観戦中」、右に時計回り90度の回転ボタンを表示します。参加できる待機ルームでは中央に「参加する」を残します。準備・開始・投了は表示せず、ロビーへ戻る導線を表示します。投了と対局中の退室はダイアログで確認します。
- ルーム情報の「ルームを共有」は全閲覧者が使えます。[確定したルーム共有仕様](#ルーム共有の確定仕様)のダイアログを開き、ルームURLのコピーとXでの対戦相手の募集ができます。コピー成功は3秒のtoastで通知し、失敗時はURL欄から手動コピーできます。
- 招待リンクを開いた未参加者には、待機中で空席がある場合に参加ダイアログを1回だけ自動表示します。表示履歴は同じタブ・同じルーム世代ごとに保持します。「観戦する」や閉じる操作で観戦を続けられます。更新やタブ切替、ロビーとの往復で再表示せず、後から状況カードの「参加する」で開けます。ブラウザの保存領域が利用できない場合は、更新後の表示履歴を保持できません。入力中の満室化・対局開始や通信エラーは日本語で案内し、送信中は重複送信と閉鎖を防ぎます。
- 新しい他の人のチャット投稿とシステムログは、チャット表示中も3秒間のtoastで通知します。自分の投稿、初回・再接続時の履歴、非表示の送信者、重複受信は通知しません。
- チャットの最下部を見ていれば新着に追従し、途中を読んでいれば位置を保持します。「↓」ボタンで最新位置に移動できます。日本語変換中のEnterでは送信しません。

ロビー・ルームのダイアログは、右上から12pxの位置に44×44pxの閉じるボタンを表示します。ダイアログ表示中は背景ページ全体をぼかし、スマートフォンのキーボード表示中も背景が鮮明に露出しないようにします。ダイアログ本体はキーボードを除く表示領域内でスクロールできます。

観戦と保存済み棋譜では、回転ボタンを押すたびに盤面・駒・持ち駒・プレイヤーカードの配置を時計回り90度回し、4回で元に戻します。カードの文字は読める向きを保ち、ゲームの座標や所属は変更しません。保存済み棋譜の状況カード下段は左に「棋譜閲覧中」、右に回転ボタンを表示します。初期方向は既存の観戦／本人方向とし、回転は画面内だけで保持します。手数変更・タブ切替・再接続・同じルームの次局開始では維持し、再読み込み・別ルームや別棋譜への移動・観戦から参加への切替で初期方向へ戻ります。参加者の対局画面と、参加者がルーム内で見る直前局の棋譜には回転操作を表示しません。

## ゲストアカウントの確定仕様（#234）

- 全6ゲームの作成・CPUと遊ぶ・公開一覧／招待・観戦からの参加と大会エントリーの確定時、および公開チャット利用開始の名前確定時だけ、ゲストアカウントを自動作成する。閲覧・観戦・入力ダイアログの表示では作成しない。
- 名前未設定のゲストには確定前に名前入力を必須にする。キャンセル時は参加しない。自動名「ゲストxxxxx」と本人による名前設定済みフラグを区別する。番号・名前は重複を許し、本人は内部IDで識別する。
- 名前は前後空白を除いて見た目の文字単位で1〜10文字。既存の端末保存名を初期値にできるが、確定前は設定済みにしない。全ゲーム共通でサーバーへ保存し、次回は入力不要。マイページから名前を変更できる。表示用IDは `guest_` とランダムな14桁の英小文字・数字を組み合わせて自動発行し、登録者のIDも含めて重複を防ぐ。マイページ・ヘッダー・ホバー等で開くプロフィールカードに `@ID` を表示する。ゲスト中はIDを編集できず、画像設定も提供しない。表示用IDはアカウント・本人資格・同意と同時に確定し、取得時には補完しない。IDは識別用で、ログイン・復旧の資格にはしない。
- ゲストの本人確認は専用HttpOnly Cookieで最終利用から180日保持する。登録者の7日セッションは維持する。Cookie削除・期限切れ・別ブラウザ／端末では連携前のゲストを復旧できず、その旨を案内する。認証障害を未認証として新規作成しない。アカウント・記録の自動削除は初回実装では行わない。
- ゲストもマイページ・本人履歴・戦績・ランキング・バッジを利用でき、登録者と同じ集計条件とする。CPU戦は履歴・棋譜だけ。ルームのプレイヤーカードには「ゲスト」を常時表示せず、ホバー・フォーカス・クリックで開くプロフィールカードには「ゲスト」と表示する。ランキング・大会などの既存のゲスト表示は維持する。
- ゲストにはログアウト操作を提供せず、サーバーもゲストのログアウトを拒否する。登録者はログアウトできる。
- Google／Discordの新規連携ではゲストの内部アカウントID・表示用ID・名前・記録を保持する。初回設定には引き継いだ表示用IDを初期表示し、登録後のID変更は登録者仕様に従う。プロバイダーの名前・画像は公開プロフィールへ転記しない。
- 既存登録アカウントへの統合はOAuth認証後、対象と全ゲームの記録引き継ぎを確認してから実行する。統合先のプロフィールを優先する。同じ参加の二重加算・同じ対局の複数席取得は禁止する。履歴・戦績・バッジ・大会成績・公開プロフィールの本人対応を整合させる。完了前にゲストを削除せず、完了後は元ゲストの認証を失効させ単独利用できなくする。
- 既存登録者へのログイン後は、対局の有無にかかわらず元ゲストへ自動復帰しない。「引き継ぐ」「引き継がずにログインする」を明示し、後者では元ゲストの認証と引き継ぎ手続きを失効させる。未統合のアカウント・記録は自動削除しない。確認を終えないままログアウトした場合も失効させる。認証成功後に残すゲスト資格は引き継ぎ確認にだけ使用し、登録者のセッション期限切れでもゲスト本人として復帰させない。OAuthの取消・失敗では元ゲストの認証を維持する。
- 公開チャットの投稿・再送台帳・通報の本人対応も統合先へ移す。送信者を非表示にするための公開識別子は過去投稿で保持する。送信間隔は両者の最新投稿から、投稿停止はどちらかが停止中なら停止として引き継ぎ、過去投稿の送信者識別子からの運営操作も統合先に適用する。同じ発言への重複通報は1件にまとめて最新の通報時刻を保持し、通報回数をリセットしない。統合先の退会時は引き継いだ投稿・送信者情報も削除対象に含める。
- 対局中・マッチング待機中の連携／統合を制限する。同じ大会に統合先もエントリー済みなら自動合算せず競合として扱う。
- ゲストも大会の順位・表彰対象。1アカウント1エントリー・全ルーム共通1席制限を適用する。別ブラウザの複数ゲストを完全には防げない。名前設定済みゲストも公開チャットの投稿・通報を利用でき、送信間隔・通報上限・投稿停止を登録者と同じ条件で適用する。管理権限・試用AIは登録者専用とする。
- 既存の禁止行為・通報・利用停止方針をゲスト名にも適用する。新しい自動不適切名判定は追加しない。
- 導入前のゲスト記録を名前や端末保存名で一括取得しない。既存の「終局後に今回の1局を引き継ぐ」経路は互換性を保つ。新しいゲストには全記録を保持できる連携案内へ切り替える。
- 規約・ポリシーへゲストの記録保存・認証期限・復旧条件・連携と統合を反映する。管理画面でゲストと登録者を区別する。

## Google・Discord認証とプロフィール

Google・Discordによる新規登録・ログイン、プロフィール設定、ログアウトを提供します。ログイン中はサーバーが取得した本人のプロフィールでルームへ参加します。本人の対局履歴と戦績はマイページに表示し、公開ランキングはロビーに表示します。

登録者の認証セッションの有効期間は7日、更新間隔は1日です。ゲストは専用Cookieで180日保持します。有効なセッションで通常のアカウント確認や認証を使うAPIへアクセスし、更新時期に達している場合は、DBの期限とブラウザのCookieを更新します。期限切れのセッションを延長することはありません。

## 終局後の登録と継続再戦

2026-10-13に承認した、導入前のアカウントを持たないゲストの今回の対局の引き継ぎと同じ席での継続再戦の互換仕様です。全6ゲームに適用します。#234以降のゲストアカウントは初回から全記録を保存し、連携は退室後のマイページから行います。

- 作成・CPUと遊ぶ・公開一覧／招待・観戦からの参加フォームには登録案内を置きません。共通ナビのアカウント入口と規約・公開情報の説明は維持します。登録案内は、全体が終局した局にゲスト参加した本人の結果ダイアログだけに表示します。観戦者や途中脱落だけでは表示しません。
- 結果から新規登録・既存ログインを始めた本人に、その1局を引き継ぎます。過去ゲスト局の一括取得はしません。対人戦では「この対局を、自分の記録に残そう」「登録・ログインすると、今回の戦績と棋譜がマイページに追加されます。」、CPU戦では今回の棋譜の追加と戦績・ランキングの対象外であることを案内します。公開棋譜にも登録プロフィールが表示されることを認証前に伝えます。
- 同じタブの保存領域へ登録復帰情報と新参加資格を保存・読戻しできてから開始します。保存不能ならOAuthへ移動せず、ゲスト利用を継続できます。通常ログインの保存不能時の扱いは維持します。
- OAuth前にサーバーが参加資格、部屋世代、直前局、本人のゲスト席、再戦待機を確認します。本人の準備を解除して「登録手続き中」を確定し、席・参加者ID・ホスト権・最後の人間だけの部屋も保持します。登録待ち中は本人の準備変更と次局開始を拒否し、参加者に登録待ちと残り時間を表示します。次局開始が先に確定した場合は登録を開始せず、対局を中断しません。
- 席の特別な保持は最初の登録開始から10分、今回の局の引き継ぎ受付は1時間です。同じ対局・席で取消や再試行をしても延長しません。明示取消後は新しい処理として再開し、取消済みの処理から席を変更しません。期限はサーバー時刻で判定し、期限と同時刻は失効です。
- 認証コールバックで本人と当該セッションを固定し、プロフィール・同意完了後に同じ席をアカウント参加へ切り替えます。名前・アイコンを更新し、参加者ID・席・ホスト権を維持します。旧資格と旧接続を失効させ、新資格に切替確定時から通常の接続猶予30秒を与えます。再送で猶予を延長せず、本人の再接続・準備とホストの開始操作で再戦します。次局以降は開始時から登録アカウントの記録になります。
- 全ルーム1アカウント1席を維持します。別席を持つ場合は自動退室させず、そちらを退室して再試行するよう案内します。今回の記録と現在席の切替は別々の進捗を表示し、切替未完了を再戦可能とは表示しません。
- OAuthを開始できなかった場合は登録待ちを解除します。認証画面での取消・失敗後は、再試行するか手続きを中止してゲストへ戻れます。初回設定中にも「登録を中止してゲストに戻る」を用意し、当該処理で認証したセッションだけを終了します。作成済みアカウントは削除せず次回ログインで設定を再開できます。別タブの別アカウントをログアウトさせません。
- 取消・保持期限切れでは通常の接続判定へ戻します。接続中なら準備未完了のゲスト席、切断中なら元の切断時刻から30秒で判定します。期限超過なら席解放・ホスト交代・必要に応じ部屋閉鎖を行います。解放済み席、新しい部屋世代、進行中の次局を遅延応答で変更しません。通信失敗で結果不明なら状態を照会し、ゲストへの自動降格はしません。
- 今回の局は席切替と独立して引き継ぎます。期限内に受付済みの記録は保存遅延で失わせず、部屋閉鎖・番号再利用後も再試行します。保存待ちは「反映待ち」と表示し、席切替済みなら再戦できます。元の結果へ戻れない場合も今回の記録への案内を表示します。
- 対人戦条件・順位・勝敗・撃破・戦法・バッジの条件は維持し、引き継いだ本人にも適用します。CPU戦は履歴・棋譜のみです。同じ参加分の複数アカウントへの取得、同じアカウントによる同局の複数席取得、再送の重複加算を禁止します。公開・本人・相手の履歴とプレイヤーカードは同じ本人対応と現在のプロフィールを参照します。ゲーム手順・結果・日時・設定は書き換えません。

- 既存登録者にも初回の登録者同意を求めます。規約・公開範囲への重要な変更は事前に案内し、次の登録・参加操作の前に再同意を求めます。Google取得情報を新しい目的に使う場合は、目的を説明して同意を得る前に新用途へ利用しません。

### アカウント削除

- マイページにアカウント削除を用意します。登録に使ったプロバイダーで再認証し、現在の本人との一致を確認してから、削除する情報・残る棋譜・復元不可を示す確認操作を行います。再認証の取消・失敗では削除せず、別アカウントで認証した場合は拒否します。
- 待機・対局中は退室してから削除します。切断中の保持席も対象とし、進行中の対局の退室・投了・敗北は各ゲームの既存ルールで処理します。削除のために勝敗を変更しません。再認証と削除受付の間に参加してもサーバーが在室を再検査します。
- 削除受付を永続化した時点で新規ログイン・参加・編集を止め、全端末のセッション・ルーム資格を失効させ、公開プロフィール・ランキング・管理者一覧から除外します。棋譜は直ちに「退会したプレイヤー」と仮アイコンで表示し、公開IDとプロフィールリンクを出しません。同じ対局に複数の退会者がいても席・色・方向で区別し、対局をまたぐ退会者番号を公開しません。
- メール、プロバイダー識別子とトークン、プロフィール・画像、本人の履歴索引・戦績・バッジ・同意記録を削除します。棋譜の保存名・アカウントへの紐付け、DOに残るプロフィールや保存待ち、計測の本人識別も除去します。公開棋譜・相手の履歴・ルーム内棋譜・結果に同じ退会処理を適用し、参照先なし時の旧名へのフォールバックで退会者名を復活させません。
- 対局の手順・結果・日時・設定と、相手の履歴・戦績は維持します。退会した本人はランキングと公開戦績から除外します。同じGoogle／Discordで再登録しても新しいアカウントとし、旧履歴・戦績・バッジを紐付けません。引き継いだ元ゲスト名も退会対象とし、対局IDと参加者IDで範囲を特定します。同じ参加者IDの未引き継ぎゲスト局は巻き込まず、退会後の再取得を防ぐ対応を残します。
- 本人のフィードバック原文・添付画像・技術情報・投稿者識別・個人情報を含む編集履歴は削除対象に含めます。開発課題は個人情報を除いたIssueとして扱います。ルーム内チャットとシステムログの本人名・画像・内部参照は除去し、本文中の個人情報は依頼に応じて個別確認します。公開チャットの本人の通常投稿は削除します。通報証拠は既存の7日期限を上限に管理者だけが扱い、一般画面には退会者の名前を再表示しません。
- データ除去・画像削除・プロバイダー連携解除は失敗時に再試行します。受付成功を物理削除の完了と区別し、処理中・完了の状態を提供します。受付時に発行する推測困難な削除状況確認用の資格で、セッション失効後も本人が状態だけを確認できるようにします。状況確認で旧プロフィールや削除対象の内容を返しません。外部連携解除の失敗を理由にアプリ内の利用停止を巻き戻しません。削除処理と遅延した保存・再送・アップロードが競合しても、旧名や本人索引を復活させません。
- 削除処理の再送防止・復元対策に必要な削除済み内部アカウントID、部屋・世代・プレイヤーの不透明な識別子、受付・完了時刻と状況確認資格のハッシュは、サービス運営中に非公開で保持します。削除対象索引の画像キー・解除トークンは完了時に消します。Google識別子・メールや公開プロフィールを退会履歴として無期限に残しません。バックアップ・障害ログの保存先と期限は公開前に確認し、復元時に削除を再適用します。第三者の保存や利用者の既存キャッシュまで遠隔で消せるとは説明しません。

## 終局データの保存・対局履歴

- CPU戦の対局履歴・棋譜・記録された撃破数は集計対象外でも残します。待機中にCPUを追加しても、開始前に全員削除すれば対人戦として集計します。取得時に集計するため、DB移行・データ削除・再保存は不要です。
- この機能の導入後に開始したすべての対局を、ゲストのみの対局も含めて終局時に保存します。導入前の対局・導入時に進行中の対局を補完せず、終局していない対局は履歴へ追加しません。人間の参加者が全員退室または復帰期限切れになり、未決着で打ち切った対局は保存しません。退室・通信切れでルール上終局した場合は保存します。
- 開始日時、部屋の識別子、ゲーム・モード・時間設定、開始時の定員分の参加者の名前・担当色または担当方向・席順・人間／CPU区分・CPUレベル・内部アカウントIDを保存します。終局時に終了日時、結果、最終盤面、脱落理由、着手・自動パス・脱落を含む棋譜を保存します。将棋は規則バージョン・初期化情報・連番イベントと方向別の撃破数を保存します。参加資格やチャットは保存対象に含めません。保存済み棋譜を含め時間設定は必須とし、時間設定が不明な旧棋譜は保存・公開対象に含めません。
- 終局と同時に対局ごとの保存待ちを永続化します。D1への保存が失敗しても再戦・退室を妨げず、5秒後に再試行します。再戦開始・退室・部屋閉鎖・部屋番号再利用後も保存待ちを保持し、同じ対局の再送で重複や結果の上書きを発生させません。履歴の期限削除は行いません。
- `/account` の棋譜は本文上部の共通ゲームDropdownとモードタブで切り替えます。ゲーム・モードの初期選択は、上記のマイページの仕様に従います。開始時に本人のアカウントで参加した対局を開始日時の新しい順に表示し、20件ずつ「もっと見る」で追加します。同時刻は対局UUIDの降順です。結果から本人へ引き継いだゲスト対局も同じ履歴に含めます。観戦と未引き継ぎのゲスト対局は含めません。
- 棋譜カードを縦に並べ、開始日時・ゲーム名のバッジ・モード・手数を表示します。日時は閲覧端末の時間帯で年月日・時分を表示します。シングルスは順位・24pxアイコン・名前を2列でコンパクトに表示し、1位は「優勝」とします。同順位・順位の飛びを保持し、同順位内はリバーシでは黒・白・赤・青、将棋では南・西・北・東の順です。ダブルスは勝利チーム・敗北チームの順に2人ずつ表示し、引き分けは両チームに表示します。
- アカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。未引き継ぎのゲスト・CPUと、退会者ではない参照先のないアカウントの名前は開始時のものを使います。引き継いだ参加分は現在の本人プロフィールを使います。退会者の名前・画像・本人参照は [退会仕様](#アカウント削除) に従って除去します。アイコン未設定・参照先がない場合は仮アバター、CPUは青いCPUアバターを表示します。履歴のために過去のアイコン画像を保持しません。通常のプロフィール変更では保存した名前や棋譜を書き換えず、次回取得時に反映します。退会時は本人の保存名・アカウント参照を除去します。
- 「棋譜を見る」から `/account/matches/:matchId` の棋譜閲覧画面へ移動します。読み込み・空一覧・失敗と再試行を表示し、追加取得に失敗しても表示済みのカードを残します。ゲーム・モードごとの取得済み一覧を保持し、「更新」で選択中の一覧を先頭から再取得します。戦績・棋譜で共通のゲーム選択とゲームごとのモードを保持し、再読み込み・棋譜からマイページへ戻った場合も復元します。

## 最近行われた対局と公開棋譜

- ゲーム別ロビーでは、そのゲームの保存済み終局を最新3件の簡潔な行で表示し、「もっと見る」からゲームのテーマを使う共通ダイアログ内に最大20件の棋譜カードを表示します。ロビーの3件プレビューはページ内展開しません。CPU戦・ゲスト戦・両モードを含め、開始日時の新しい順、同時刻は対局UUIDの降順とします。保存途中・未終局の対局は表示しません。総合ロビーは全ゲームを横断した最新20件を表示します。
- ゲーム別は詳細ダイアログ内、総合ロビーは見出し下の「対人戦のみ」にチェックすると、開始時の参加者全員（ゲームの定員2人または4人）が人間だった対局の最新20件を表示します。ゲストも人間として扱い、CPUが1人でも含まれる対局は除外します。初期状態はチェックなしで、外すとCPU戦も表示します。選択は現在のロビー表示中だけ保持し、再読み込み・ゲーム切替でチェックなしに戻ります。
- ゲーム別の詳細ダイアログは、マイページと共通のモード・日時・参加者・結果・手数の棋譜カードを縦に並べ、内容が多い場合はダイアログ内でスクロールします。ゲーム名のバッジは省略し、総合ロビーとマイページでは表示します。総合ロビーの棋譜カードは幅320pxを基本に狭い画面では一覧幅に収め、間隔12pxで折り返さず横一列に並べます。一覧内だけで横スクロールし、左右に続きがある場合は共通の矢印ボタンを重ねて表示します。
- 最近の対局カードの開始日時は、経過1時間以内なら「〇分前」、1時間を超えて24時間以内なら「〇時間前」を整数切り捨てで表示します。1分未満は「0分前」、ちょうど1時間は「60分前」、ちょうど24時間は「24時間前」です。24時間を超える日時と端末時計より未来の日時は端末の時間帯の年月日・時分を表示します。正確な日時は日時部分のツールチップで確認でき、相対表示は1分ごとに更新します。マイページでは引き続き年月日・時分を表示します。
- 表示時と「更新」で取得し、ゲーム別は詳細ダイアログ内で更新・再試行を行います。総合ロビーは取得成功後に最新が見える左端へ戻します。自動更新・追加取得は行いません。空一覧・取得失敗・再試行を表示し、更新失敗時は既存カードと位置を保持します。
- チェック切替時は旧条件のカードを消して再取得し、読み込み中も条件を切り替えられます。失敗時は選択した条件を保って再試行を案内し、旧条件のカードは表示しません。対人戦の対局が0件なら「対人戦の対局履歴がありません。」を表示します。
- 「棋譜を見る」は `/matches/:matchId` を開き、未ログイン・プロフィール設定前でも閲覧できます。既存の保存済み対局も公開対象です。本人用の `/account/matches/:matchId` は引き続き本人限定です。
- 公開棋譜は最終局面から表示し、リバーシは黒、将棋は南を手前にします。「あなた」は表示せず、局面選択・回転・結果表示を利用できます。「ロビーへ戻る」は対局のゲームへ戻ります。参加・ルーム通信・チャットは行いません。公開棋譜画面は検索対象外です。

## 保存済み棋譜の閲覧

将棋の棋譜表記は、終局後のルーム内棋譜・本人用保存棋譜・公開棋譜で共用します。通常将棋は「1: ▲7六歩」「2: △3四歩」、四人将棋は「1: 南5六歩」の形式です。先手／南を手前にした固定座標で、右から筋の数字1〜9、上から段の漢数字一〜九を使います。参加者・観戦者の視点や盤面回転で表記を変えません。対局進行中の棋譜一覧は設けません。

駒名は「王・飛・角・金・銀・桂・香・歩」、成駒は「龍・馬・成銀・成桂・成香・と」です。新たな成りに「成」、成る手も合法なのに成らない手に「不成」、すべての打ち駒に「打」を付けます。全対局者を通じた直前の着手と同じ移動先は「同」とし、提案・取消・外部脱落を挟んでも直前手を参照します。曖昧な移動は着手者基準の「上・寄・引・直・左・右」や複合語で識別します。通常の補助語で区別できない四人将棋の龍の縦移動だけ「直」を使います。詳しい条件は[通常将棋の棋譜表記](docs/rules/shogi.md#棋譜表記)と[四人将棋の棋譜表記](docs/rules/four-shogi.md#棋譜表記)を参照してください。▲・△の読み上げ名は先手・後手を明記し、省略しません。

- `/account/matches/:matchId` は開始時に本人のアカウントで参加した対局、または結果から本人へ引き継いだ保存済み対局だけを閲覧できます。未ログインはログインへ誘導し、他人の対局と存在しない対局は同じ閲覧不可の案内を表示します。取得失敗は空の棋譜として扱わず、再試行を案内します。
- 通常ルームと同じレイアウトを使い、最終局面から棋譜を表示します。開始局面・着手・自動パス・各脱落を矢印とSelectで移動できます。再読み込みや別対局への移動では最終局面から表示します。
- 将棋の棋譜は100イベントずつ取得し、対局ID・規則バージョン・初期化情報・総件数・連続番号を検証してエンジンで再生します。再現した最終状態と保存済みの最終状態が一致しない場合は閲覧を開始せず、エラーと再試行を案内します。保存データを取得後、局面の操作はブラウザ内だけで行います。オンラインルームの取得・参加確認・WebSocket接続は行わず、既存の参加資格を変更しません。部屋閉鎖や番号再利用後も同じ対局を閲覧できます。
- 開始時の参加者・担当色または担当方向を表示し、本人用の初期表示では本人を手前（スマートフォンでは左下）に配置します。リバーシのカードは黒→白→赤→青の時計回り順にし、保存された席番号はホストの識別に使います。アカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。未引き継ぎのゲスト・CPUと、退会者ではない参照先のないアカウントの名前は開始時のものを使います。引き継いだ参加分は現在の本人プロフィールを使います。退会者の名前・画像・本人参照は [退会仕様](#アカウント削除) に従って除去します。カードの石数・脱落表示は選択局面に追従し、未来の脱落を表示しません。将棋の初期表示は本人の担当方向を下へ配置し、持ち駒・成り駒・裏王・王手・最終手と選択局面の順位・脱落理由を表示します。同時脱落の群は局面データとカード・結果表示で保持し、棋譜ラベルには付加説明を併記しません。脱落者の石数、接続バッジ、準備状態、時計は表示しません。
- 全ゲームの結果ダイアログは、シングルスを順位色付きの順位バッジ・担当色の石と石数または方角・アイコン・名前の順に表示し、バッジには脱落理由を付けません。同順位と順位の飛びを保持します。リバーシは担当色の石と石数を表示し、脱落者は担当色と「脱落」だけを表示します。結果の順位欄と石色・石数欄は一定の幅を確保し、石数の桁数や脱落表示に関係なくアイコンと名前の開始位置をそろえます。ダブルスも担当色の石と石数または方角をアイコンの前に置き、勝利・敗北チームの順に2人ずつ並べ、引き分けは両チームに表示し、個人順位を付けません。終局理由とリバーシのチーム合計石数も表示します。
- 四人将棋の結果では、各人の方角・アイコン・名前の右側に撃破対象の列を設けます。各行の「撃破：」は表示せず、シングルスでは一覧の上に1つ、ダブルスでは各チームの一覧の上に1つ、共通の列見出し「撃破」を表示します。PC・スマートフォンとも、撃破対象のアイコンと名前を着手順に1人ずつ縦に並べ、見出しと全行・全対象のアイコンの左端を同じ列にそろえます。順位・方角・本人のアイコン・名前の領域を確保し、長い名前は省略せず欄内で折り返します。両モードで受理された着手によって新たに詰んだ相手だけを表示し、同時詰みは全員を含めます。空き王手も着手者へ対応付けます。外部脱落と合法手なしは含めず、戦績の撃破数集計は変更しません。表示は棋譜の選択局面・盤面回転に依存せず最終結果を使います。対象がない場合は撃破欄に「なし」、棋譜の取得中・失敗時は別の案内と再試行を表示します。ルーム内・本人の保存棋譜・公開棋譜で同じ表示を使います。
- ルーム内の前局結果は、その局の名前・担当色／方角・アイコン・CPU情報を保持します。結果から同じ席を登録ユーザーへ切り替えた場合だけ、本人の表示名・アイコンも更新します。退室後も次局開始・部屋閉鎖まで画像を保持し、現在の席にも必要な画像参照は解放しません。旧データで表示情報がない場合は同じプレイヤーIDの在室者情報、なければ仮アイコンを使います。保存済み棋譜のアカウント参加者の名前・アイコンは取得時の現在のプロフィールを使います。
- 状況カードは「対局終了」を表示し、「結果」で保存された最終結果を開きます。結果は自動表示しません。着手操作と合法手の点は無効にし、直前の着手枠は選択局面に追従します。
- 準備・開始・参加・投了・退室・招待・ルーム設定・CPU操作は表示しません。ルーム情報は元の部屋番号、ゲーム、モード、持ち時間を表示し、「マイページへ戻る」を設けます。状況カード下段には「棋譜閲覧中」と回転ボタンを表示します。
- 将棋の保存棋譜の盤面・ルーム情報・結果ダイアログには黄色テーマを使います。マイページの本文は選択中ゲームのロビーと同じ背景・テーマを使い、ゲームDropdown・プロフィール編集ダイアログにも同じテーマを適用します。共通ヘッダー・アカウントメニューは緑のままにします。
- PC（1280px以上）のチャット領域には「棋譜閲覧ではチャットを利用できません。」を表示します。1280px未満は「盤面／ルーム」の2タブだけを表示し、タブ切替で局面の選択を保持します。

## 戦績の表示

- `/account` のプロフィールカード内に「戦績」を表示し、本文上部の共通ゲームDropdownとモードタブで棋譜と同時に切り替えます。ゲーム・モードの初期選択は、上記のマイページの仕様に従います。ゲームごとのモードと取得済み戦績を保持します。
- 開始時の参加者全員がゲームの定員を満たした人間で、本人がアカウントで参加したか結果から引き継ぎ、終局結果がD1へ保存された対局だけをゲーム・モード別に集計します。対戦相手のゲストは人間として扱います。CPUを1人でも含む対局は過去の保存済み対局も集計から除外し、対局数・順位・勝敗・引き分け・各率・将棋の累計撃破数に同じ条件を適用します。観戦・未引き継ぎのゲスト参加・未終局・保存待ちの対局は含めません。棋譜一覧の取得件数には依存しません。戦績タイトルの下に「対人戦のみ集計」と表示します。
- シングルスは「対局数」「優勝数・優勝率」「2位数・2位率」「3位数・3位率」「4位数・4位率」を表示します。同順位は保存された順位に1回加算し、同率1位も優勝として数えます。
- 将棋のシングルスは「完全優勝数」「撃破数」「撃破率」も表示します。完全優勝数は本人が他の3人全員を撃破して単独1位になった対局数で、通常の優勝数の内数です。保存済みの過去対局も対象にします。撃破率は累計撃破数を対局数で割った1局あたりの平均撃破人数で、最大3.000です。受理された着手で新たに詰んだ相手1人につき着手者へ1を加算し、同時に2人を詰ませれば2です。CPUによる撃破も対局記録へ含めます。投了・退室・時間切れ・通信切れ・合法手なしとダブルスは数えず、順位・勝敗の判定には使いません。
- ダブルスは「対局数」「勝数・勝率」「敗数・敗率」を表示します。引き分けの行は表示しませんが、引き分けも対局数と率の分母に含めます。
- 戦績は角丸の外枠・薄い横の区切り線を持つ2列の表で表示します。縦罫線は設けず、先頭行にはゲームテーマに沿った淡い背景を付け、数値はラベルより少し大きく表示します。各セルはラベル幅をそろえて数値の左端を列ごとに縦にそろえ、ラベルと数値を間隔を空けすぎず横に並べます。ラベルが折り返す場合も数値は先頭行にそろえます。先頭行は左に「対局数」、四人将棋シングルスだけ右に「完全優勝数」を置き、他のゲーム・モードの右セルは空欄にします。続く行は左に件数、右に対応する率を置きます。戦法別戦績のダイアログも同じ表を使い、使用対局数の右セルは空欄にします。
- 各率は該当件数をそのモードの集計対象の対局数で割り、小数第4位を四捨五入します。先頭の0と `%` を付けず、`.000`・`.333`・`.500`・`1.000` のように小数3桁で表示します。対局数ゼロは各件数0・各率 `.000` とします。
- ゲームの初回選択時にそのゲームの両モードを取得し、戦績タイトル右側の「更新」で選択中ゲームの両モードを再取得します。取得失敗はゼロ件とせず再試行を案内し、更新の失敗時は取得済みの戦績を保持します。

### 四人将棋シングルスの戦法別戦績

- 通常戦績の下に全16戦法のカードを掲載図の順で横一列に並べます。内部No01〜16と既存の戦法IDを固定対応させ、Noは画面に表示しません。カード幅は180px、間隔は12pxとし、一覧内だけで横スクロールします。
- 集計対象の対人シングルスで本人の確定着手により不成立から成立した戦法を使用経験として記録し、終局・保存後に名前と盤面図を表示します。未経験は「???」と共通の画像プレースホルダーで操作不可とし、読み上げにも実名を含めません。CPU戦・ダブルスでは解放しません。
- 経験済みカードはクリック・タップ・Enter・Spaceで黄色テーマのダイアログを開きます。使用対局数、優勝数・優勝率、2〜4位の数・率だけを表示し、各率の分母はその戦法の使用対局数です。同率1位も優勝へ加算します。完全優勝数と撃破項目は通常戦績に表示します。
- 同じ戦法は1局で1回だけ数え、複数の戦法が成立した局はそれぞれに結果を加算します。戦法別の対局数の合計は通常戦績の対局数と一致しない場合があります。名前は省略せず折り返し、画像は高さ120pxの領域に縦横比を保って全体を表示します。
- 戦法別戦績は導入後に開始した対局だけを対象とし、導入時進行中の局・過去棋譜を補完しません。集計開始時点・集計期間は画面に表示しません。
- 将棋シングルスの選択時に取得・保持し、「更新」で通常戦績と戦法別戦績を更新します。読み込み・失敗を0件や未経験とせず、再試行を案内します。更新失敗時は取得済み表示を保持し、ゲーム・モード切替ではダイアログを閉じます。

## バッジ

登録ユーザーとゲストアカウントに、ゲーム別のシングルス戦績から判定するバッジを表示します。保存済みの過去対局も含め、通常戦績と同じ対象条件・優勝・撃破・完全優勝の定義を使います。ダブルス、CPU戦、アカウントを持たない旧ゲストの未引き継ぎ参加、観戦、未終局・保存待ちは対象外です。

| バッジ   | 対象ゲーム             | 星1 | 星2  | 星3   |
| -------- | ---------------------- | --- | ---- | ----- |
| 対局数   | 四人リバーシ・四人将棋 | 5局 | 20局 | 100局 |
| 優勝数   | 四人リバーシ・四人将棋 | 3回 | 15回 | 50回  |
| 撃破数   | 四人将棋               | 3人 | 15人 | 50人  |
| 完全優勝 | 四人将棋               | 1回 | 2回  | 3回   |

- ゲームごとに独立した累計を使い、達成済みの最高ランクを各種類1枚表示します。星3は金色の画像内に現在の累計を重ね、獲得後も数字が増えます。数字は省略しません。
- マイページはプロフィールと戦績の間に、対局数・優勝数・撃破数・完全優勝の順でコンパクトに表示します。未獲得もグレーの星1画像と「未獲得」、条件・現在値を表示します。未獲得と星1・2は現在値と次の星の目標、星3は累計を表示し、全段階の閾値一覧と残り件数の重複表示は設けません。ゲーム切替・戦績更新に追従し、取得失敗を未獲得や0件としません。バッジ画像はドラッグできません。
- ユーザー情報カードは表示元のゲームで獲得済みのバッジ画像だけを56px・間隔4pxで横に並べ、幅が足りない場合は折り返します。バッジ欄の見出し・名前・画像外の星と累計・獲得条件・ツールチップは表示しません。星3の画像内の累計と、読み上げ用の名前・ランク・累計は保持します。アカウントを持たない旧ゲスト・CPUと獲得済みバッジがない利用者にはバッジ欄を表示しません。
- マイページ・ユーザー情報カードとも、シングルス選択中だけ表示します。連続優勝、装備選択は提供しません。バッジの現在値・ランクは既存戦績から判定し、獲得通知の管理に必要な取得イベント・表示済み状態を保存します。過去記録にない撃破情報などは補完しません。

### バッジ獲得通知

- 四人リバーシ・四人将棋の登録ユーザーとゲストアカウントの本人に、対人シングルスによる星1の初獲得と星2・星3への昇格を画像付きtoastで通知します。星3以降の累計増加は通知しません。対象条件・閾値・優勝・撃破・完全優勝の定義は既存と共通です。
- 対局結果・本人索引・取得イベントをD1へ一緒に保存し、戦績への反映が確定してから通知します。保存待ち・保存失敗では通知せず、既存の保存再試行で確定させます。機能導入時点で保存済みの戦績を基準にし、過去の獲得通知は生成しません。
- 既存HeroUI toastの画面上部中央・背景・角丸・影・幅を使い、タイトル・ゲーム名・56pxの既存バッジ画像・バッジ名・星を中央揃えで表示します。星3の画像内には取得時点の累計を表示します。初獲得は「バッジを獲得しました！」、単独昇格は「バッジが星2になりました！」などとします。
- 同じ対局の取得・昇格は1つにまとめ、複数の場合は「バッジをN個獲得・更新しました！」と表示します。対局数・優勝数・撃破数・完全優勝の順で最大4種類を省略せず、狭い画面では折り返します。別対局のバッジ通知は順番に表示します。
- バッジtoastは5秒で閉じます。閉じるボタンを設け、ホバー・toast内のフォーカス・ページ非表示中は残り時間を停止します。フォーカスを奪わず、音は追加しません。ゲーム名・バッジ名・星・累計を控えめに読み上げ、装飾画像との重複を避けます。
- アプリ共通の通知管理で、ルームからロビー・マイページへの遷移でも表示中・待機中の通知を引き継ぎます。チャット・招待コピーの既存toastも同じ領域を使い、表示時間は従来の3秒を維持します。バッジ通知は既存toastが終わってから取得します。
- 未表示の取得イベントに期限を設けず、再接続・表示復帰後に取得します。非表示タブでは新しいバッジtoastを開始しません。アカウント・ゲーム・種類・星を一意に扱い、保存再試行でイベントを重複生成しません。
- 表示開始後に表示済みを記録し、再描画・重複受信では再表示・時間延長しません。複数タブ・端末はアカウント単位で表示済みと短時間の取得権を共有します。表示と表示済み記録の間の通信断・端末終了による再通知は許容し、障害時まで含めた厳密な「必ず1回」は保証しません。
- ログアウト・アカウント切替では本人の画面内通知を直ちに解除し、古い取得応答を反映しません。サーバーの未表示通知は本人用として保持し、別アカウントに表示しません。

## ランキングの表示

- 各ロビーのランキングは対象ゲームの保存済み対局だけを集計します。四人将棋シングルスでは、既存の戦績用の累計撃破数もランキングにします。撃破の数え方・帰属・導入前の扱いは[ルール正本](docs/rules/four-shogi.md#戦績用の撃破数)に従います。他ゲームとダブルスには撃破数の項目を表示しません。
- ロビーにはシングルスの優勝数（二人ゲームは勝利数）の上位3人を固定表示し、「シングルス・優勝数（対人戦のみ）」など現在の指標を示します。自動スライドとロビー内の切替操作は置きません。
- 「もっと見る」で詳細ダイアログを開き、シングルス・優勝数（二人ゲームは勝利数）から表示します。モードと優勝数／勝利数・対局数・四人将棋シングルスの撃破数を手動で切り替え、各上位10人を表示します。モード切替では最初の指標へ戻します。更新操作・読み込み・空一覧・再試行を共用し、詳細内の選択でロビーの固定表示は変えません。
- 戦績と同じく、開始時の参加者全員がゲームの定員を満たした人間だった保存済み対局だけを全期間・両モードで集計します。過去のCPU戦も対象外です。ゲストを含む対人戦は集計しますが、掲載する本人は開始時にゲストまたは登録アカウントで参加したか結果から引き継いだ、現在の設定済みアカウントに限ります。観戦・未終局・保存待ちは対象外です。ロビーと詳細ダイアログに「対人戦のみ集計」と表示します。詳細では、CPUを含まない対局のアカウント参加者を集計し、対戦相手にゲストがいても対象であることを説明します。
- 優勝数は確定順位1位を数え、同率優勝も加算します。勝利数はダブルスでは所属チーム、二人用では本人の勝利を数えます。引き分けは対局数に含めます。優勝数／勝利数は1回以上、対局数は1局以上、撃破数は1人以上の人を掲載します。
- 値の降順で、同数は同順位として人数分だけ次の順位を飛ばします。同順位内は現在の公開IDの昇順にし、境界で同数でも表示人数は最大3人／10人です。
- 名前・アイコンは取得時の最新プロフィールを表示します。アイコン未設定や読み込み失敗は仮アバターを使います。内部アカウントIDや棋譜はランキングで公開しません。
- 未ログインでも閲覧できます。ロビー表示時と詳細内の「更新」で全ランキングを取得し、読み込み・空一覧・失敗と再試行を表示します。更新失敗時は取得済みデータを保持します。

## プレイヤー情報カード

全ゲームの公開ルームのホストと参加者全員、ランキングと詳細、総合ロビーの最近の対局・ゲーム別ロビーの最近の対局ダイアログ・本人履歴の棋譜カード、通常ルーム・公開／本人用棋譜のプレイヤーカードは、アイコンまたは名前からプレイヤー情報を確認できます。空席・ホストなし・退会者は対象外です。

- 登録者は現在のアイコン・名前・公開IDと、表示元のゲーム・モードの戦績をコンパクトな1行の文章で表示します。通常の将棋・五目並べ・リバーシと四人ゲームのダブルスは `20局 12勝7敗1分 (.600)` の形式、四人リバーシ・四人五目並べのシングルスは `43局 3優勝 (.070) 平均2.53位` の形式、四人将棋シングルスは `83局 22優勝 (.265) 平均2.13位 51撃破` の形式です。四人将棋ダブルスに撃破数は表示しません。幅に収まらない場合は文章を折り返し、項目別の縦並びにはしません。
- 平均順位は保存済み順位の加重平均を小数2桁に四捨五入して表示し、同順位も保存済み順位を使います。0局は「平均—位」とします。未ログインでも閲覧でき、戦績は既存と同じ全期間の対人戦のみの集計と小数3桁に四捨五入する率の表示を使います。旧Workerで不足する敗数・引き分け数・平均順位・撃破数は推測せず省略し、取得済みの対局数・優勝数／勝数・率を表示します。別モードへの切替や過去名の補足は表示しません。
- アカウントを持たない旧ゲストは名前・仮アイコンと「ゲスト／ID・戦績なし」、ゲストアカウントは登録者と同じ戦績・バッジに加えて「ゲスト」のラベル、CPUはアイコン・レベルと「戦績集計対象外」を表示します。参照先のないアカウントはゲストとせず、プロフィールを表示できない旨を案内します。退会者以外の保存棋譜は従来の保存名へのフォールバックを維持します。退会者は [退会仕様](#アカウント削除) の表示とし、保存名へ戻しません。
- ホバーは300ms後、キーボードフォーカスは即時に開きます。トリガーとカードの両方からポインター・フォーカスが離れて150ms後に閉じ、カードへ移動すれば閉鎖を取り消します。クリック・タップ・Enter・Spaceでは表示を固定し、外側の操作・閉じるボタン・Escapeで閉じます。同時に開くカードは1枚です。
- ホバー／フォーカスではフォーカスを奪いません。明示操作ではカードへ移し、閉じる操作・Escapeでは元へ戻します。Escape後は同じホバー・フォーカスのまま再表示せず、ランキング詳細内のEscapeは情報カードだけを閉じます。画面遷移・背景スクロール・表示元の消失でも閉じます。
- カードは幅280pxを基本として左右16px内へ収め、画面端では配置を反転します。名前・IDは折り返し、元のカードや盤面の寸法を変えません。
- 戦績はカードを開くときだけ取得し、成功結果をページ内で最大60秒再利用します。プロフィール保存成功時は本人、終局検知時は対象ゲームのキャッシュを無効化します。元の棋譜の名前・画像は次回取得時に反映し、自動同期しません。取得失敗を0件やゲスト扱いせず再試行を表示します。

## 共通UIとスタイル

共通ヘッダーは768px以上でロゴ、ホーム、遊び方、直近ゲーム、アカウント、設定を表示します。767px以下は上部にロゴと設定、下部にホーム・遊び方・直近ゲーム・アカウントの固定タブを表示します。下部safe areaと本文の余白を確保し、操作対象を44px以上にします。ロビー・アカウント・情報・大会ページへ適用し、対局・観戦・棋譜には追加しません。「お知らせ」は既存のフッター等から開けます。総合ロビーと各ゲームロビーのフッターには「© 2026 chaossi · TetraBoard」を表示します。

総合ロビーの最近の対局、ゲーム別の最近の対局ダイアログと本人の対局履歴は共通カードを使い、ゲーム別ロビーのプレビューは簡潔な行表示を使います。総合ロビーと本人の対局履歴ではゲーム名をルームカードと共通のバッジで表示し、ゲーム別の対局ダイアログではゲーム名のバッジを省略します。長い参加者名だけ小さくし、必要に応じて折り返して順位や他の名前との重なりを防ぎます。手数には保存済み最終局面の着手カウンターを使い、投了・時間切れなどのイベント数を手数として数えません。応答に手数がない場合は表示を省略します。

HeroUIを継続使用し、ヘッダー・ボタン／ボタン風リンク・入力欄・カード・ダイアログ・タブ・アイコンを `apps/web/src/shared/ui/` にまとめます。色・文字・枠線・角丸・影は既存ロビーを基準とした緑の共通テーマを使い、ゲーム部分だけに将棋の黄色テーマを適用します。レイアウト・余白・操作状態は部品内のTailwindクラスで指定します。ログイン・初回設定・マイページも同じ共通部品を使います。

画面全体の配置・背景・盤面サイズ・レスポンシブ境界を維持します。ロビーヘッダーは共通部品にし、ルームには追加しません。CSSはTailwind／HeroUIの読み込み、共通テーマと最小リセット、背景・石の陰影、ダイアログ表示中のぼかし、アニメーション定義に限定し、ページ別CSSは使用しません。

直近ゲームはゲームロビーを開いた時だけ更新し、有効なGameIdを `localStorage` の `tetraboard:last-lobby-game` へ保存します。未保存・破損時は四人リバーシ、保存領域を使えない場合はメモリ内で保持します。別タブの変更にも同期し、表示名・盤面図・移動先は共通カタログから導出します。対局・観戦・棋譜を開いても更新しません。共通ナビの「遊び方」は `/how-to-play` の空ページ、各ゲーム右上は既存のルール説明ダイアログです。新ページは直接URL・再読み込みにも対応し、検索対象外にします。リンクの現在地とキーボード操作を維持します。

プレイヤーカードは4席とも親レイアウトから決めた同じ幅・高さを使います。高さは768px以上で60px、スマートフォンで48pxに固定し、盤面の縮小では変えません。スマートフォンの上下paddingは1pxとし、中央揃えによる追加の外側余白を残しません。アバターは通常32px／スマートフォン26pxで、右下の接続バッジを表示します。最大10文字の名前と王冠は一まとまりで実測し、省略・折り返しせず表示します。画面幅変更・フォント読込・タブ再表示でも再計測します。

名前・アバター・下段情報の領域を固定し、準備完了の有無や時計／順位の切替で他要素の位置・寸法を変えません。石と石数・順位の縮小はカード幅だけで決め、脱落状態では変えません。320pxを含む指定幅で、10文字名＋王冠・2桁の石数・最長の脱落理由が同時に収まる設計とします。

## 計測用管理画面

総合ロビーでは、[公開チャット専用の運営機能](#公開チャットβの運営と退会)と[総合ロビーの閲覧・滞在計測](#検索向け配信と効果の確認)を提供します。以下は計測画面の仕様です。

`apps/admin` は計測とフィードバック・お知らせ運営のための独立したReactアプリです。`/admin` から全体概要、四人リバーシ／四人将棋／リバーシの分析、ゲストと登録者を区別したユーザー一覧を確認できます。Googleログイン済みの本人のアカウントをサーバーの `ADMIN_ACCOUNT_IDS`（内部 `user.id` のJSON配列）で限定し、HTML・アセット・管理APIで確認します。指定した本人のアカウントはすべて集計の初期除外対象です。従来の1件用 `ADMIN_ACCOUNT_ID` は、配列が未設定の場合に利用できます。権限未設定・認証障害は503、未認証APIは401、別のアカウントは403です。管理応答はキャッシュしません。プロフィール編集・削除・アカウント全体の停止、ルーム内チャットの通報オペレーション、課金は初回範囲に含めません。公開チャット専用の投稿停止・通報操作は管理画面の「公開チャット」で行います。

- 日本時間の日別／月別、期間指定、本人・テスト利用を含める切り替え、更新と再試行を提供します。初期は直近30日、月別へ切り替えたときは直近12か月です。1回の指定期間は最大3年です。
- 全体概要は訪問ブラウザ数、ページ閲覧数、表示中の滞在時間、新規登録数と登録総数を表示します。新規登録は計測開始以降だけ、登録総数と一覧は既存の登録者も含めます。ゲーム別でも登録に関する値はサービス全体です。
- 全ゲームの開始・完了・未決着の打ち切り・進行中、平均完了対局時間、延べ対局参加時間、CPU戦／対人戦、シングルス／ダブルスを表示します。対局の指標は選択期間に開始した対局の取得時点の状態です。CPU戦も含め、棋譜や通常の戦績・ランキングの集計条件は変更しません。
- 開始率は、同じゲーム・同じ日本時間の日にロビーかルームを訪問したブラウザのうち、対局を開始したブラウザの割合です。個別データを保持する90日以内の期間全体はブラウザIDを重複排除します。90日を超える期間は、正しく算出できる指標だけを表示し、日別人数の合算で期間ユニーク数を代用しません。完了率は完了数／開始数で、進行中と打ち切りも併記します。
- 利用数とIDあたりの対局数は、登録アカウントとゲストのブラウザIDを分けます。継続率はゲーム別の計測開始後の初回完了から7日以内に別の対局を開始した割合です。同日の再戦も含み、初回完了から7日間の観測が済んだ対象だけを分母にします。期間は初回完了日で絞り、全体概要ではゲーム別コホートを合計します。分母0の率は「—」です。
- 本人と既存のテスト区分のログイン利用は初期表示で除外します。一般利用者との混在対局は対局数に残して本人の席だけを利用数・参加時間から除き、除外対象だけの対局は数えません。ログインしていない本人のゲスト利用は自動判別できません。
- Webは画面種別・ゲームと、下記の訪問開始時の流入情報を計測し、管理画面を除外します。URL全文、招待情報、参照元のパス・クエリ・検索語、IPアドレス、UA全文、チャット、操作内容は保存しません。ランダムな計測Cookieを同一オリジンに1年間保存し、ゲストの継続をブラウザ単位で識別します。登録前後の人物統合や端末間のゲスト統合はしません。Cookie削除・保存拒否・端末変更・通信失敗で欠測や重複が生じます。常時計測の目的・保存期間は [計測の確定仕様](#保存期間利用計測) に従います。
- 滞在時間は前面で表示されている時間で、操作せず盤面を見る時間も含みます。同一ブラウザのタブはWeb Locksで重複を防ぎ、未対応ブラウザはフォーカス状態で計測します。30秒ごと・非表示化・離脱時に累積時間を送り、再送で加算しません。日本時間の0時で分割します。延べ対局参加時間は対局経過時間×集計対象の人間の席数で、実際の操作時間や広告表示回数ではありません。
- 計測導入後に開始した対局だけを記録し、過去の保存対局を取り込みません。導入時に進行中の対局も補完しません。計測開始日時を表示し、個別計測の保存上限は90日とし、導入前のデータにも適用します。期限到達後は取得・分析から除外し、毎時削除を再試行します。長期集計と算出できない指標は [計測の確定仕様](#保存期間利用計測) に従います。ブラウザの計測障害でプレイを妨げず、サーバーの対局計測は状態と同じDOトランザクションで保存待ちを確定し、D1失敗時に5秒後のAlarmで再試行します。再戦・閉鎖・番号再利用後も保存待ちを維持します。
- ユーザー一覧は「連携済みユーザー」「ゲストユーザー」のタブに分け、初期表示はGoogle・Discord連携済みのユーザーにします。各一覧は現在のアイコン・名前・公開ID（ゲストの `@guest_…` を含む）、登録日時（ゲストは作成日時）、設定状態を50件ずつ表示します。名前／ID検索に対応し、プロフィール未完了のユーザーも表示します。タブ切り替え時は検索語を維持し、前の一覧とページ位置をリセットします。統合済みの元ゲストと退会済みユーザーは表示しません。メールや認証トークンは返しません。

### 流入元・端末別の計測

2026-10-19に開発者がIssue #214の仕様を承認しました。ポリシー本文と文書バージョンは改定しない方針です。自前の同一オリジン計測として実装し、外部解析サービスへ送信しません。

- 既存の計測Cookieだけでブラウザを識別し、新しいCookie・localStorage・sessionStorageの識別子を追加しません。サーバーは閲覧と前面滞在の増分を活動とし、30分以上途絶えた後の新しい閲覧で別の訪問セッションを開始します。複数タブ・再読み込み・日付変更・ログインだけでは区切りません。再送した同じ閲覧・累積滞在では活動を延長しません。30分以上途絶えた滞在送信だけでは古い訪問を復活させず、次の閲覧を待ちます。
- 最初に受理した閲覧で、参照元ホスト名・参照元分類・UTM3項目・端末分類を固定します。後のサイト内移動・UTM付きURLでは上書きしません。参照元はホスト名のみで、同一ホストは `internal`、空は `direct`。サーバーの明示的な一覧で `search / social / internal / direct / other` に分類します。UTMから参照元分類を推測しません。不正・取得不能な値と旧画面からの欠測は不明とし、directやdesktopに置き換えません。
- UTMは `utm_source`・`utm_medium`・`utm_campaign` のみ。英数字と `-_.` 以外を除去した後で各64文字までにし、大小文字は保ち、空は未指定にします。端末はサーバーでUAから `mobile / tablet / desktop` の3分類だけを推定し、UA全文と画面寸法は保存しません。デスクトップ向けUAを使うタブレット等は正確に分類できません。
- 管理画面に参照元分類・UTM3項目の組・端末別の訪問セッション数と開始対局の表を追加します。既存の訪問ブラウザ数とは別の指標です。全体の訪問はランディング日、ゲーム別の訪問は同じセッションでそのゲームを最初に閲覧した日、開始対局は実際の開始日で集計します。日本時間の日別・月別・選択期間、ゲーム別、本人・テスト利用の除外／包含に対応します。
- 開始時点の人間参加者の訪問へ関連付け、最初の対局計測保存で固定して再送では変えません。各区分内で同じ対局IDを1回だけ数えます。異なる流入元・端末の参加者が同じ対局にいる場合は各区分へ数えるため、行の合計は全体の開始対局数と一致しません。訪問がない参加者も開始対局の不明区分に含め、CPUは流入の主体にしません。既存の対局指標・戦績条件・開始率は変更しません。
- 新しい計測開始日時を別に表示します。開始前・将来の期間は「未計測」、初日・当日・一部未計測を含む合計は「途中集計」、計測済みの0件と欠測の「不明」を区別します。過去のデータは補完しません。旧Workerの応答は未計測として表示します。
- 個別の訪問情報・対応表は取得から90日を上限とし、期限後は分析対象外にして毎時の集約・削除へ接続します。訪問の正本はランディングから90日以内とし、そこで同じ訪問のゲーム別内訳も集約します。長期は日別・ゲーム別・各区分の件数だけを保持し、ブラウザ・アカウント・訪問・対局のIDや参照元ホスト名を含めません。退会受付で本人に結び付く訪問を除外・削除し、本人の開始対局内訳も除外します。

命名例・実装と互換性は[開発文書](docs/development.md#流入元端末別の計測)、確認項目は[テスト方針](docs/testing.md#流入元端末別の計測)を参照します。

### 終局後の星評価

全6ゲームで、ゲスト・登録ユーザーの参加した局が全体として終局し、本人が結果ダイアログを閉じた後に、星1〜5の評価と任意コメントを送れるダイアログを表示します。観戦者と途中脱落だけでは表示しません。CPU戦・対人戦、投了・時間切れを含む終局が対象です。評価は必須、コメントは既存受付と同じ数え方で2,000文字以内です。スキップや閉じる操作で回答せずに戻れます。入力中も接続・対局・時計は進みます。

表示済みの記録は同一オリジンのブラウザのlocalStorageに保存し、全ゲーム・ゲスト・登録ユーザーで共有します。送信の成否や回答の有無にかかわらず、再戦・再読み込み・ログイン後も再表示しません。導入前の対局経験は判定せず、表示記録がない既存利用者も対象です。別端末・別ブラウザ・保存データの削除後は別扱いです。保存領域の読取・書込ができない場合は自動表示を省略します。文章はlocalStorageへ保存しません。

星評価は既存の非公開フィードバック受付へ「その他のご意見」として保存し、同じ認証・送信上限・180日の保存期限・削除を適用します。投稿者のゲスト／ユーザー区分は送信時のサーバー認証、CPU戦／対人戦は終了した局の参加構成を使います。CPUが1人でも参加した局はCPU戦です。送信失敗では星・コメントを保持し、同じ入力の再試行は重複登録しません。星評価と対戦区分がない既存投稿を、星ゼロや対人戦として補完しません。

管理画面の一覧・詳細に星評価・コメント・投稿者区分・対戦区分を表示し、投稿者・対戦区分・星評価で絞り込めます。星評価は管理者だけが閲覧できます。

### 任意の不具合・ご意見

- 種別は不具合・機能の要望・その他のご意見。種別と内容は必須で、対象は開いた画面のゲームを初期選択します。内容は1〜2,000文字、期待・目的は任意500文字、再現手順は不具合だけに任意1,000文字まで。前後の空白を除き、Unicodeコードポイントで数えます。
- JPEG・PNG・WebPを任意で1枚添付できます。元画像5MiBまで、長辺1,600px以内に縮小した静止WebPは1MiBまで。変換後のプレビューと取り消しを提供し、画像内の名前・チャットは利用者が隠してから添付します。自動撮影・画像編集は行いません。
- 不具合では技術情報の添付を初期ONにし、取り消しと内容確認が可能です。画面種別、対象ゲーム、ブラウザ、画面サイズ、ビルド識別子、ルームでは部屋ID・世代・将棋の局IDを送ります。リバーシは既存の公開状態に局IDがないためnullです。URL全文・招待クエリ・参加資格・チャット・盤面は送信しません。
- 通信・保存・認証失敗時は入力と画像を保持します。同じ画面では閉じて開き直しても保持し、送信成功か画面離脱で破棄します。ブラウザの永続ストレージには文章・画像を保存しません。送信完了はD1と任意画像の保存が完了した場合だけ表示し、同じ送信の再試行は重複登録しません。
- 投稿から180日で本文・画像・技術情報・投稿者識別・編集履歴を閲覧・集計から外し、毎時処理で削除します。削除失敗は次回再試行します。運営による削除は直ちに非表示にし、画像などの物理削除は同じ定期処理で行います。長期の開発課題は個人情報を除いて手動でIssueへ整理します。投稿者の退会時は180日期限前でも [退会仕様](#アカウント削除) に従って原文・画像等を削除します。
- 受付は登録者ならアカウント、ゲストなら専用Cookieのブラウザを識別します。計測Cookieとは共有しません。同じアカウント・ブラウザは10分の固定窓に5件、24時間の固定窓に20件、同一IPは10分の固定窓に30件まで。窓はUTCのUNIX時刻を基準に切り替えます。IP原文を保存せず、専用secretで識別値をハッシュ化します。Cookie・端末変更、登録前後は同一人物として統合しません。

管理画面の `/admin/feedback` では50件ずつ新着順に表示し、種別・対象・対応状況・優先度・テーマで絞り込めます。詳細・添付画像・更新・削除を含め、既存の管理者認証で保護します。初期状態は「未確認」・優先度「通常」です。確認中・対応予定・対応中・完了・見送り・迷惑投稿、優先度高・通常・低、テーマ1つ、運営メモ、関連GitHub Issueを記録できます。見送りは理由、完了は本番公開の確認を必須とします。同時編集は更新番号で検出し、編集者・日時・変更前後を記録します。運営は原則翌日までに新着を確認しますが、利用者への修正期限は約束しません。

テーマ別に過去180日の投稿数とアカウント・ブラウザ単位の報告者数を表示します。運営・テスト投稿と迷惑投稿は初期除外し、内部投稿は明示的に含められます。未確認件数、最古の未確認の経過時間、初回確認時間の中央値も表示します。投稿数だけで開発順を決めず、困りごとの深刻さ・利用と継続・実装負担を合わせて判断します。投稿数は売上見込みではありません。

公開後30日でテーマと確認速度を見直し、次の改善を選びます。課金や売上測定は今回追加しません。

## お知らせの管理とロビー掲載

お知らせは既存のロビーフッターやロビーの告知から開きます。共通ヘッダーはホーム・遊び方・直近ゲームを表示し、お知らせの独立ボタンは置きません。`/updates` は公開記事の日付・種別・タイトル・説明文の冒頭を20件ずつ表示し、「もっと見る」で次のページへ進みます。`/updates/:id` は説明文全体と一覧へ戻るリンクを表示します。ゲスト・プロフィール未設定の利用者も閲覧でき、一覧・詳細は検索対象に含めません。取得失敗時は再試行を案内し、非公開・存在しない記事は見つからない案内を表示します。

管理画面の `/admin/announcements` では公開・非公開を含む記事を50件ずつ表示し、新規作成と編集ができます。記事はタイトル（必須1〜80文字）、説明文（必須1〜2,000文字）、日付、種別（改善・新機能・大会告知・その他）、公開状態、ロビー掲載先を持ちます。文字数は前後の空白を除いてUnicodeコードポイントで数え、説明文の改行を保持します。HTML・Markdown・画像は扱わず、投稿原文・個人情報・画像を転載しません。新規記事は非公開・掲載先なし・種別その他で、日付は日本時間の当日です。

日付は表示と並び順に使用し、公開予約には使いません。公開記事は日付・登録日時・IDの降順に並べ、編集しても登録日時を変更しません。管理者が内容・公開状態・掲載先を「保存」でまとめて反映します。保存失敗と同時編集の競合では入力を保持し、最新データを明示的に読み直すと保存済み内容へ置き換えます。記事と掲載先は一括保存し、権限を失った場合は管理データを破棄します。削除機能は設けず、公開終了には非公開を使います。

ロビー掲載先は四人リバーシ・四人将棋・リバーシを複数選択でき、未選択なら公開一覧だけに掲載します。公開状態と掲載先は独立して管理します。全ゲームのロビーはタイトル・説明・遊び方の下、対局開始ボタンの上に、対象となる公開記事の最新1件を表示します。PCでも本文の全幅を使い、スマートフォンでは操作ボタンの直前です。小さめの文字と余白のコンパクトな告知枠とし、「お知らせへ」はPCでは右側、スマートフォンではタイトルの横に置きます。タイトル、前後の空白と改行を正規化した説明文の最初の行、「お知らせへ」リンクだけを表示し、リンクは該当記事の詳細へ移動します。画面幅による折り返しは許可します。対象なし・取得中・取得失敗では枠と余白を出さず、対局操作を妨げません。ゲーム切り替えで以前のゲームの記事を残しません。

記事はD1で管理し、デプロイなしで更新できます。変更は次の画面表示・再読み込みから反映し、自動更新は行いません。既存の改善のお知らせはID・日付・内容を維持して公開記事へ移し、初期のロビー掲載先は設定しません。お知らせ管理では固定表示・公開予約・自動掲載終了・既読管理・大会の参加受付は提供しません。大会の受付・管理は[大会専用の仕様](#四人将棋大会の確定仕様)として実装します。

## 開発と本番公開

`main` を本番、`develop` を開発環境・GitHubの既定ブランチとして扱います。最新developから `feat/xxx`、`fix/xxx`、`docs/xxx`、`chore/xxx` などを作り、GitHub CIと必須のローカル検証の成功後に開発者が確認してdevelop向けPRをマージします。開発環境で確認後、develop→mainのリリースPRをマージコミットで取り込みます。両ブランチへの直接push・force pushは禁止します。非公開リポジトリの現行GitHubプランではブランチ保護を強制できないため、このルールを運用で守ります。他者レビューは必須ではありません。

developは `https://tetraboard-dev.chaossi-lab.workers.dev` へCI成功後に自動公開します。Workerは `tetraboard-dev`、D1は `tetraboard-dev-db`、R2は `tetraboard-dev-objects` とし、対局状態・アカウント・画像・棋譜を本番と分離します。本番データをコピーせず空の状態から開始します。誰でも利用できますがHTTPとHTMLのnoindexで検索対象外にします。canonicalは開発URL、サイトマップは空とし、robots.txtからサイトマップを案内しません。本番ドメイン・データ・検索設定は維持します。

通常CIは整形・lint・型チェック・単体テスト、本番・開発それぞれのWeb・AdminビルドとWorker dry-runを実行します。コード・設定変更ではPR提出前に、ローカルで `bun run check`、`bun run build`、Workerの `deploy:dry-run`、`bun run build:development`、Workerの `deploy:dry-run:development` を成功させ、検証対象コミット・環境・結果・未確認事項をPRに記載します。PR提出後のコード・設定変更とmain・develop取り込みによる変更も再検証します。文書だけの変更は同一コード・設定の直前の成功結果を再利用できます。

WorkerテストはローカルのD1・R2・SQLite対応Durable Objectとテスト専用の設定を明示し、開発用 `.dev.vars`・`.env` や個人の管理者設定を読み込みません。Workerの型生成は追跡済み `.dev.vars.example` を入力に固定します。設定の退避・一時コピーなしで通常の作業ディレクトリから検証し、CIでも設定なし・競合設定ありの結果と生成型の一致を確認します。

型チェックはmiseとCIで固定したBunの内蔵チェッカーを使い、全workspaceの本体・テスト・型検査専用fixture・ビルド用コードを検査します。通常は `bun run typecheck`、従来のTypeScriptとの診断比較は `bun run typecheck:tsc` を使います。検査対象と互換性の注意点は[開発手順](docs/development.md#checks)を参照してください。

自動検証はBunの単体テスト、Bun＋happy-domの部品・hookテスト、Worker統合テストを使います。format確認・lint・型チェック・全テストを含む `bun run check` の目標は180秒以内です。ブラウザテストとレポート保存は廃止し、画面寸法・ブラウザ固有の入力・実画像デコードを自動検証対象から外します。ゲーム・画面の仕様は維持します。リバーシ・将棋の少数E2Eの再構築は次の作業で行い、今回は追加しません。既存のPlaywright依存は維持します。[テスト方針と移管対応表](docs/testing.md)を参照してください。

本番URLは `https://tetraboard.net`、Worker名は `tetraboard-2026`、D1名は `tetraboard-2026-prod-db` です。Worker 1つでWeb画面・管理画面・HTTP API・WebSocketを配信します。GitHub ActionsはmainのCI成功後にD1マイグレーションとデプロイを行います。CloudflareのGit連携による別の自動公開は設定しません。

初回は差分と検証結果を確認し、開発者の承認後にマージ・公開します。以後はPRのマージが本番更新の契機です。ローカルのデータは本番へ移行せず、開発環境を設け、PRごとのプレビューは設けません。`tetraboard-2026.chaossi-lab.workers.dev` はパスとクエリを保持して本番ドメインへ308転送します。ドメインをまたいだログイン状態・タブ内の参加資格は引き継がず、再ログイン・再入室します。旧版の `/profile` はマイページ、`/games/game-…` の棋譜と `/guest/name` はリバーシロビーへ案内します。旧ルームは移行せず、存在しない部屋には既存のエラー画面とロビーへの導線を表示します。設定・認証・確認・復旧の手順は [開発手順](docs/development.md#本番デプロイ) を参照してください。

## ゲーム共通仕様

ルーム、参加、通信、持ち時間、チャット、スタンプなど、ゲームの種類に依存しない仕様はこの節を正本とします。各ゲームのルール文書には、そのゲーム固有の判定や表示だけを記します。

### 対局部屋と参加

- 未ログインでは、前後の空白を除いて1〜10文字のニックネームを使ってゲストとして参加する。ログイン中は必ず本人の設定済みプロフィールで参加し、ニックネームを別に指定しない。認証取得失敗・設定未完了では参加させない。
- ゲストで作成・参加に成功し、参加資格を保存できた場合、最新の使用名をブラウザの `localStorage` に期限なしで保存する。全ゲームの作成・CPUと遊ぶ・公開一覧からの参加・招待リンク／ルーム内からの参加で、画面の再読み込み・再訪時の初期入力に使う。登録からの復元入力は空文字も含めて保存名より優先し、表示中の入力は別タブの変更で上書きしない。入力変更・キャンセル・失敗・観戦・既存参加資格での復帰では更新せず、アカウント参加・プロフィール変更・ログアウトでも保存名を変更しない。保存名が不正、または読取り不能の場合は空文字で開始し、名前の保存失敗は作成・参加を妨げない。保存は同じブラウザ・オリジン内に限り、ブラウザの保存データを削除すると失われる。
- 作成・CPUと遊ぶ・各参加導線で、入室時の名前・アイコンとアカウント・席の対応を固定する。プロフィール変更・ログアウト・別アカウントへの切替で既存席を変更せず、通常ログインではゲスト席も付け替えない。結果からの専用登録だけは同じ席をアカウントへ切り替える。アップロード画像はカードが残る間保持する。
- 同一アカウントの席は全ルームを通して1席に制限する。別タブ・別端末から参加トークンなしで参加した場合も拒否し、アカウント認証だけでは参加資格を再発行しない。退室・通信切れから30秒の復帰期限切れ・部屋閉鎖で制限を解除する。投了・時間切れ後も在室中は制限を保持し、脱落後の切断にも30秒の席保持期限を適用する。期限後の元参加資格は閲覧用として維持するが、再戦の席を復元しない。
- 同じ部屋で同じニックネームを使用できる。参加者は部屋内のプレイヤーIDで区別する。
- 部屋の作成者をホスト、公開一覧・招待リンク・ルーム画面から入室した人をプレイヤーとして識別する。有効な参加資格がない人がルームURLを開いた場合は、参加を確定するまで観戦者として扱う。招待リンクでも、有効な参加資格がある人は入力なしで本人として表示する。新規参加者の準備状態は未完了とする。
- 参加資格は部屋ごとに発行し、同じタブの再読み込みでは本人として表示する。同じタブから同じ部屋へ再度入室しても新しい席は作らない。参加資格が無効な場合は観戦者として表示する。
- 対局部屋を作成し、URLでほかの人を招待できる。部屋の公開IDには5桁の数字を使う。招待URLは `/rooms/:id?invite=<instanceId>` とし、部屋が閉鎖されるまで有効とする。閉鎖後に番号が再利用されても、招待先の識別子が一致しなければ参加・閲覧へ進めない。番号のみの通常URLは、その時点で同じ番号の部屋を参照する。
- プレイヤー枠が埋まった部屋への入室は受け付けない。枠数はゲームごとに定める。
- すべての対局部屋を公開対象とし、公開・非公開の設定は設けない。公開ロビーには待機中・対局中の部屋を表示し、待機中で空席のある部屋には参加できる。いずれの部屋も観戦できる。ロビーの表示が一時的に古い場合があるため、参加・観戦時は部屋の現在状態を確認する。
- 対応するゲームでは、待機中のホストがCPU席の追加・削除とレベル変更を行える。CPUには参加資格を発行せず、席数には人間と同じように数える。対局終了後の再戦も提供する。対応の有無、CPUの行動、再戦時の役割・色の割り当ては各ゲームで定める。
- 観戦者は対局の進行を閲覧できる。盤面の向きなど、ゲーム固有の表示は各ゲームのルール文書で定める。
- 待機中のホストとプレイヤーは準備完了・準備取消を切り替えられ、その状態をルーム内の全員に表示する。観戦者は変更できない。準備状態は本人が取り消すまで保持し、通信切れや再読み込みでは解除しない。ただし、復帰期限切れで席が解放された場合は準備状態も失われる。CPUは常に準備完了とし、人間の参加者全員が準備完了かつ接続中になった後、ホストの明示操作で対局を開始する。全員が準備完了になっても自動では開始しない。
- ログイン中のホストがCPUのいない待機ルームの設定でCPUを追加するときは、「適用」の際に同じダイアログ内で「CPUを追加しますか？」と上記の戦績・ランキングの注意文を表示します。「CPUを追加して適用」で確認した場合だけ全設定を反映します。「編集に戻る」は下書きを保持し、キャンセル・閉じる・Escapeは未適用の編集を破棄します。CPUが既にいる場合とゲストは「適用」で反映します。全CPU削除後の再追加でも毎回確認し、確認済み状態は保存しません。確認中に満席・対局開始・ホスト権限喪失となった場合は送信しません。ログイン取得中・失敗時は追加の適用を止めて取得待ち・再試行を案内します。
- 待機中にホストが対局設定を変更した場合、人間全員の準備状態を解除する。CPUの準備状態は維持する。対局開始後は設定を変更できない。
- 「CPUと遊ぶ」の作成ダイアログでは「CPUレベル」をLv1（よわい）／Lv2（ふつう）から選ぶ。初期値はLv1で、作成時の全CPUに同じレベルを適用する。閉じて開き直した場合・作成失敗時は選択を保持し、再読み込み・ゲーム切替ではLv1へ戻す。登録・ログインからの復帰では他の作成設定と一緒に復元する。通常のルーム作成・参加には表示しない。作成後はホストが待機中にCPUごとに変更でき、再戦には現在の設定を引き継ぐ。
- 「CPUと遊ぶ」では、作成者を準備完了にした部屋に定員を満たすCPUを配置する。四人リバーシ・四人将棋・四人五目並べは3体、通常リバーシ・通常将棋・五目並べは1体とする。作成者が対局開始を確定するまで待機する。
- 待機中に退室するか、作成・入室後または通信切れから30秒以内に接続しなかった場合は席を解放する。ホストの席が空いた場合は、残る中で最も早く入室した人へホストを引き継ぐ。人間の席がなくなった部屋は、CPUや観戦者が残っていても閉鎖する。終局後の登録待ち中だけは10分の席保持を優先し、最後の人間の席も維持する。
- 対局の状態と手番を参加者・観戦者へリアルタイムに同期する。
- 終局時にサーバーが同じ部屋を再戦の待機状態へ戻す。前局の結果は次の対局開始まで「結果」ボタンから確認でき、終局データは部屋と独立した対局履歴として保存する。退室済みの人は再戦の席に残さず、人間の準備状態を解除する。未接続者の席は元の切断時刻から30秒まで保持する。登録待ち中は専用の保持期限を使い、取消・期限切れ後は元の切断時刻から判定する。ホストが退室していれば残る最古の参加者へ引き継ぐ。終局後に人間の参加者がいなければ部屋を閉鎖する。保存済みの棋譜と終局済み対局の保存待ちは、部屋の閉鎖でも保持する。
- 待機中・対局中・再戦待機中の部屋は、入退室、設定・準備・着手、チャット投稿などの最終活動から24時間後に閉鎖する。閲覧と再接続は活動に含めない。

### 投了、通信切れと持ち時間

- 対局中の任意の投了は、自分の手番に限り実行でき、その時点で脱落する。
- ページ離脱時はルームのWebSocket接続と再試行・取得処理を停止する。参加資格は保持し、明示退室とは区別する。履歴からの復帰と非表示からの表示復帰では、最新のルーム情報・本人確認を再取得し、接続・認証を確認してから操作を再開する。タブが非表示になっただけでは接続を終了しない。
- 準備・設定・開始・対局操作・チャットの応答待ちは各10秒を上限とする。接続開始・認証・復旧時のルーム取得・本人確認にも各10秒の期限を設ける。期限超過では送信待ちと未確定表示を解除し、再接続中の表示で操作を止め、状態を再取得して復旧する。操作は自動再送しない。チャット入力はサーバーの投稿反映を確認した場合だけ消す。
- 通信が途切れてから30秒以内に復帰した対局者は、同じ対局に戻れる。30秒経過時点で復帰していなければ正式な通信切れとして脱落する。
- 同じ参加資格を持つタブが接続中なら通信切れとは扱わない。復帰期限を過ぎた後の元対局者は、同じ資格で部屋を閲覧できるが、再び対局には参加できない。投了後も同様に閲覧できる。明示的に退室した場合は参加資格を失効する。
- 復帰待ちの間も対局と手番を止めない。手番中の対局者の持ち時間も通常どおり進める。切断中の対局者が30秒より先に時間切れになった場合は、その時点で脱落する。
- 対局中の退室と時間切れでも脱落する。脱落後の順位や盤面の扱いは、各ゲームのルール文書で定める。
- 全6ゲーム・全CPUレベルで、サーバー上の各CPUの手番開始から最低2,000ms待ってから着手を確定する。初手・再戦・CPUの連続手番・自動パス後に同じCPUへ戻る場合も一手ごとに待つ。計算・サーバー処理によって2秒を超えることはある。CPUの宣言・同意による終局も同じ最低待ち時間に従う。自動パス・ルール上の終局・時間切れは即時処理し、着手可能時刻と期限が同じなら時間切れを優先する。再接続・画面更新・DO休止復帰・手番を変えない通知で待ち時間を数え直さず、遅延処理でも複数のCPU着手をまとめて進めない。
- CPUも人間と同じ持ち時間で行動し、思考待ちと計算にかかった時間を計時する。対局中に最後の人間参加者が明示退室または30秒の復帰期限切れになった場合、脱落による終局判定を先に行い、未決着ならCPUの進行を停止して部屋を閉鎖する。投了・脱落後も在室する参加者と復帰期限内の参加者は残存扱いにする。通常の観戦者だけでは部屋を維持しない。ゲストも脱落後の切断から30秒まで在室扱いとし、期限切れで脱落を二重に処理しない。
- 持ち時間・秒読みは全ゲーム共通のルーム設定とし、持ち時間は「なし・1分・3分・5分・10分」、秒読みは「なし・10秒・30秒」から選ぶ。初期設定は1人5分＋1手30秒とする。作成・「CPUと遊ぶ」のダイアログで選び、待機中・再戦待機中はホストが変更できる。対局中は変更できない。実際に値が変わったときは人間全員の準備完了を解除し、再戦は現在の設定を引き継ぐ。
- 持ち時間を使い切った時点から、その手番に設定した秒読みを与える。以後の各手番も同じ秒読みとし、未使用分は持ち越さない。持ち時間なしでは最初の手番から秒読みになり、秒読みなしでは持ち時間を使い切った時点で時間切れとする。両方なしは禁止し、片方がなしならもう片方のなしは選択できない。サーバーもこの組み合わせとプリセット外の値を拒否する。
- 対局開始時は最初の手番者だけを計時する。着手・投了・脱落で手番が変わった時点から次の手番者を計時し、自動パスされた対局者は計時しない。期限ちょうど以降に届いた着手や投了は受け付けず、時間切れを先に確定する。復帰期限と同時刻なら時間切れを先に処理する。終局時には時計を止める。

### 表示・サウンド設定

[#121](https://github.com/yksw-clm/tetraboard-2026/issues/121)の機能です。2026年10月10日、開発者の指示により初期版の仕様を確定しました。設定UI・ブラウザ保存を提供します。全6ゲームで、ゲスト・ログインユーザー、ホスト・参加者・観戦者が共通の個人設定を使います。

| 項目                   | 初期値 | 対象                                            |
| ---------------------- | ------ | ----------------------------------------------- |
| 効果音                 | ON     | 参加・CPU追加・着手・開始・終了・時計音のすべて |
| カード上のスタンプ表示 | ON     | 送信者本人を含む全員のアバター上のスタンプ演出  |

- 共通ヘッダーのある利用者向け画面には、歯車アイコンの「表示・サウンド設定」ボタンを置きます。ルームにヘッダーは追加せず、1280px以上では右上のルーム情報・設定エリア、1279px以下では既存の「ルーム」タブ内のルーム情報エリアに同じ入口を置きます。タブレットも既存のタブ構成に従います。ホスト専用の「ルーム設定」の展開や権限に依存せず、対局中・観戦中も利用できます。管理画面は対象外です。
- ルームの入口は、ルーム情報の既存の見出し行の右側に歯車アイコンだけのボタンとして収め、「表示・サウンド設定」の読み上げ名を付けます。新しい行を追加せず、見出し行・ルーム情報カードの高さ、本文と既存操作の位置を維持します。設定ボタンの追加、設定の開閉・切替で、盤面・プレイヤーカード・持ち駒・状況カードの位置と寸法、棋譜操作欄とタブの位置を変えません。スマートフォンの状況カードや操作行、タブは追加・拡張しません。PCは既存の左右列の独立した高さと右列のスクロールを維持します。ゲーム名・ルーム番号・既存操作を隠したり、文字やカードを縮小して収めたりしません。
- ボタンから共通の「表示・サウンド設定」ダイアログを開き、2項目をスイッチで表示します。切替時に即時反映・保存し、保存ボタンは設けません。閉じても変更を維持します。キーボードで操作でき、Esc・閉じる操作後は入口へフォーカスを戻します。ゲーム画面ではそのゲームのテーマを使い、ダイアログの表示・保存で通信・手番・時計を停止しません。
- スタンプ選択パネル内にも「カード上のスタンプ表示」のスイッチを置き、同じ設定を変更できます。設定操作ではスタンプを送信せず、選択パネルは開いたままにします。送信待ち・3秒の送信制限中も設定を変更できます。6種類・3列2行の選択と既存の閉鎖条件は維持します。共通ダイアログを開くとスタンプ選択パネルは閉じ、結果自動表示などの競合は既存のダイアログ表示中の扱いに従います。
- 効果音OFFでは再生中・予約中の全対象音を即時停止し、新しいイベントでも鳴らしません。ONへ戻した後は新しいイベントだけを対象にし、OFF中の通知や再生途中の音を再演しません。時計音は[時間切れ5秒前の通知](#時間切れ5秒前の通知)に従い、5秒以下でONへ戻したカウントは通知済み相当とします。5秒より多い状態で戻した場合は、その後の5秒到達を対象にします。時計の強調は効果音の設定と独立して維持します。
- スタンプ表示OFFでは、自分を含む全送信者の表示中の暗いレイヤー・絵文字・終了タイマーを即時解除します。OFF中の通知は表示待ちにせず、重複抑止の対象として消費し、ONへ戻しても再演しません。ON後の新しい通知だけを表示します。OFFでも送信可能で、他の閲覧者の表示はその人自身の設定に従います。全体がONでも、チャットの送信者非表示に該当する人のスタンプは表示しません。チャット履歴・送信停止・送信間隔の仕様は変更しません。
- 2項目は同一ブラウザ・同一オリジンのlocalStorageに保存し、全ゲーム・全ルームで共有します。ゲストとログインユーザーで共通とし、ログイン・ログアウト・アカウント切替でも維持します。再読み込み・再入室・通常のブラウザ再起動後に復元します。アカウント別・ルーム別の保存や端末間同期は行いません。ブラウザの保存データを削除した場合は初期値へ戻ります。
- 保存済みの値は最初の音・スタンプ演出より前に復元します。未保存・不正な値は項目ごとに初期値ONとします。保存に成功した変更は、同一オリジンの開いている別タブにも反映します。音声の初回有効化は各タブのユーザー操作に従い、複数タブ間での再生担当の選出や通知済み記録の同期は行いません。
- 保存領域の読取・書込が失敗しても、現在のタブではメモリ内で変更を反映し、画面移動・再入室後もページ再読み込みまで保持します。保存できない変更は再読み込み後の保持・別タブへの反映を保証しません。設定ダイアログとパネル内の設定部分に「この画面では反映されていますが、次回の読み込み後は保持されない場合があります。」を表示し、保存成功後に解除します。失敗で設定を元へ戻したり、ゲーム操作を止めたりしません。
- 効果音ONはアプリ側の再生許可です。最初のタップ・キー操作などによる音声有効化、ambientと端末の消音設定への対応は既存仕様を維持します。ONへのユーザー操作で音声有効化を試みますが、別タブからのONや復元だけではユーザー操作を代替しません。設定に「音が出ない場合は、画面を操作し、端末の音量・消音設定を確認してください。」と表示します。確認音は鳴らさず、再生制限・音源未準備・再生失敗で見送った通知は後から鳴らしません。失敗時も通信・ゲーム操作を継続します。
- 初期版に音量、音ごとの個別設定、時計音専用設定、演出軽減の追加設定、石の模様・スキン、プレミアム設定、アカウントへの設定保存を含めません。既存のOSの「動きを減らす」設定への対応は維持します。

### 効果音

全ゲームで、対局者・観戦者に参加・着手・開始・終了などのライブイベントの効果音を再生する。時計音は本人の手番だけに鳴らす。[表示・サウンド設定](#表示サウンド設定)の共通ON／OFF設定に従い、初期値はONとする。音量設定は設けない。

| 音源    | 再生するタイミング                                                             |
| ------- | ------------------------------------------------------------------------------ |
| `join`  | 自分の新規参加・ルーム作成成功、他の人間の新規参加。観戦から参加への切替も含む |
| `bot`   | ルーム内でCPU追加が確定したとき。「CPUと遊ぶ」の初期CPUには鳴らさない           |
| `put`   | 自分の合法手の送信成功直後、他人・CPUの着手確定時                              |
| `start` | 対局開始の確定時。再戦も含む                                                   |
| `end`   | 終局の確定時。投了・脱落等による終局と引き分けも含む                           |
| `clock` | 本人の手番の実際の時間切れ5秒前。通知対象・停止・復帰は次節に従う              |

- 観戦者自身の入室、再読み込み・再接続、CPUのレベル変更・削除、準備変更では鳴らさない。駒選択・成り選択・不正操作・送信失敗・パス・単独の脱落・棋譜操作では着手音を鳴らさない。
- 自分の着手は確定通知で二重に鳴らさない。送信後に拒否された場合、送信時に鳴った音は取り消せない。最終着手と終局を同時に受けた場合は着手音の後に終了音を再生する。
- Web Audioを使い、対応環境では他アプリの音声と混ぜるambientを指定する。iOSの消音モードに従う。ブラウザ・OS・再生元アプリによる同時再生の挙動は実機確認が必要であり、すべての環境での継続を保証しない。
- 最初のタップ等で音声を有効化する。操作前・ページ非表示中・音源準備前のイベント、初回取得・接続復帰で取得した過去のイベントは後から再生しない。複数手をまとめて受信した場合は最新の着手音を1回だけ再生する。
- 音源読み込み・デコード・再生が失敗してもゲーム操作と通信を継続する。

### 時間切れ5秒前の通知

[#131](https://github.com/yksw-clm/tetraboard-2026/issues/131)の時計音と、時計の強調を残り5秒へそろえる共通仕様です。

- 対象は全6ゲーム・全対局モードのライブ対局です。時計音はゲスト・ログインユーザーとも、接続・同期・認証が完了した在室中の人間の本人手番だけに再生します。他人・CPUの手番、観戦者、脱落者、待機・再戦待機・ルーム内棋譜・保存済み棋譜では鳴らしません。時計の強調は対局者・観戦者に表示し、効果音の設定とは独立させます。
- 判定はサーバーの最終期限 `turnExpiresAt` と同期した現在時刻の差をミリ秒で計算し、表示文字列の丸め値を使いません。持ち時間と秒読みがある場合は秒読みの残り5秒、秒読みがない場合は持ち時間の残り5秒、持ち時間がない場合は毎手番の秒読みの残り5秒を対象にします。持ち時間から秒読みへの移行だけでは鳴らさず、強調もしません。
- 同じ手番のカウントを有効な状態で継続して観測している場合、残り5秒より多い状態から `0 < 残り時間 <= 5,000ms` へ入った最初の判定で時計音を1回再生します。ライブの新しい本人手番が残り5秒以下で始まった場合も、期限前なら即時に1回再生します。残り5,001msでは鳴らさず強調せず、5,000msで鳴らして強調し、期限ちょうど以降は新たに鳴らしません。通常のタイマー更新で5秒ちょうどを飛び越えても期限前なら通知します。ブラウザのタイマー・音声出力・通信の遅延による発音時刻のずれはあり得ます。
- 音源は開発者が添付した `clock.mp3`（メタデータ上で約5.64秒）とし、同一originから配信して先読み・デコードを再利用します。先頭から通常速度で1回再生し、ループ・時間伸縮は行いません。再生時間は開始時の残り時間と5秒の短い方を上限とし、期限で停止します。ファイルの末尾まで再生するために期限を越えて鳴らしません。音声中断からの復帰でも残りの音を再演しません。
- 本人の合法手・投了の送信成功時、サーバーでの手番交代・本人脱落・終局・次局開始、切断・復旧同期開始・退室開始・閉鎖・ページ非表示・離脱で時計音を停止します。送信失敗では時計音を停止せず、送信後に拒否されても同じカウントの時計音を再開しません。停止対象を時計音として識別し、既存の着手音・終了音の再生と順序を維持します。時計の強調と手番表示は着手送信時の楽観表示で解除せず、サーバーの確定状態と期限に従います。
- 非表示・切断・復旧同期中は時計音を鳴らさず、通知を蓄積しません。初回入室・再読み込み・再接続・表示復帰の基準状態で既に残り5秒以下なら、そのカウントは通知済み相当として扱い、後追いで鳴らしません。同期・認証が完了した基準状態で残り5秒より多ければ、その後の5秒到達を対象にします。視覚的な強調は最新の残り時間に即時追従します。
- 同じカウントの通知は最大1回です。部屋世代・局・担当色／陣営・手番開始・手数などからカウントを識別し、再描画・同じ時計の通知・手番を変えない操作・時計の同期補正・同じ画面での再接続では通知済み記録を解除しません。同期補正で5秒より上へ戻っても再通知しません。自動パスで同じ人へ手番が戻った場合も、時計がリセットされた新しい手番なら別カウントです。新しい局・部屋では記録を区切ります。複数タブ間での再生担当の選出・通知記録の同期は行わず、各表示中タブで判定します。
- 最初のユーザー操作による音声有効化、ambient、端末の消音設定、音声失敗時の操作継続は既存効果音と共通です。5秒到達時に音声未有効化・音源未準備・AudioContext中断・再生失敗なら、そのカウントの通知は見送り、後から鳴らしません。
- 時計音は[#121](https://github.com/yksw-clm/tetraboard-2026/issues/121)の共通「効果音ON/OFF」に含め、専用設定・音量設定を追加しません。初期値はONとし、OFFでは時計音も停止します。ONへ戻しても見送った通知を再演せず、残り5秒以下でONへ戻したカウントは通知済み相当とします。共通設定の入口・保存方式は[表示・サウンド設定](#表示サウンド設定)に従います。
- [#123](https://github.com/yksw-clm/tetraboard-2026/issues/123)のフィッシャー方式は未導入であり、この変更では実装しません。将来の通知条件の候補は「加算を反映した最終期限の5秒前・各本人手番1回」です。加算後の次の本人手番は別カウントとし、同じ手番の同期補正では再通知しない方針を#123へ引き継ぎます。加算ルール・対象ゲーム・提供形態は#123で確定します。

### チャット

ルームチャットの発言には、名前・時刻と送信者のアイコンを表示します。アイコンは発言の左側に置き、上端を名前の上端にそろえます。1行の吹き出し（本文20px＋上下余白14px）と同じ34pxの正方形に固定します。複数行の発言でもアイコンの大きさを保ちます。現在のルーム参加者の画像を送信者IDで参照し、画像のない人や退室済みの送信者には共通の仮アイコンを表示します。入退室などのシステム発言は中央のテキスト表示を維持します。

この節と次節はルーム内チャットの仕様です。総合ロビーの公開チャットは[専用仕様](#公開チャットβの投稿と更新)に従います。

- 対局者は対局部屋の共通チャットに送信・閲覧できる。観戦者は閲覧のみできる。
- 人間の入退室、CPUの追加・削除、対局形式の変更をシステムログに記録する。一時的な切断・再接続は入退室として記録せず、明示退室と復帰期限切れによる退室は一度だけ記録する。システムログは通報・送信者非表示の対象にしない。
- チャットの利用は手番や持ち時間に影響しない。チーム内だけで使うチャットなど、ゲーム固有の扱いは各ゲームのルール文書で定める。

### チャットの保存期間とモデレーション

- チャット投稿とシステムログを合わせて対局部屋の直近100件だけを保持し、復帰した参加者にも表示する。待機中、対局中、再戦待機中に送信でき、再戦にも引き継ぐ。古いログは100件を超えたときに、残る投稿は部屋の閉鎖時に削除する。
- 新規投稿は1件100文字以内（絵文字なども見た目の文字単位で数える）、スタンプと合わせて同じ送信者からは3秒に1件までとし、URLの投稿を受け付けない。暴言、嫌がらせ、個人情報の投稿、広告を禁止する。
- 保存済みの旧形式・200文字以内の過去投稿は引き続き閲覧・通報でき、新規投稿だけに100文字制限を適用する。
- 対局者と観戦者はメッセージを通報でき、自分の画面では任意の送信者の発言を非表示にできる。運営者は通報を確認し、メッセージの削除と、その対局部屋での送信停止を行える。
- 通報されたメッセージの本文、投稿時刻、部屋ID、送信者の対局内識別子は、確認のため7日間だけ保持する。7日経過時点から閲覧対象から外し、定期処理で削除する。物理削除には最大約1時間の遅れがあり得る。通常のチャットは部屋の閉鎖後に履歴として残さない。退会者の名前・画像・内部参照の除去は [退会仕様](#アカウント削除) に従う。

### ルームのスタンプ

- 全6ゲームの待機中・対局中・再戦待機中にスタンプを送信できる。着席中の人間だけが送信でき、ゲスト・ログインユーザー、自分・他人の手番を区別しない。脱落後も在室中なら送信できる。観戦者は閲覧のみ、CPUは送信しない。送信先は本人を含むルーム内の全閲覧者とし、チーム限定送信は設けない。保存済み棋譜では利用しない。
- 初期版は絵文字6種類に固定する。👋「よろしく！」、👍「いいね！」、🙏「ありがとう！」、😮「びっくり！」、👏「おつかれさま！」、😭「泣く」。名称は読み上げ用に使い、選択パネルとカード上には絵文字だけを表示する。端末標準の絵文字を使い、画像のアップロードや自由入力は設けない。
- 送信ボタンは状況カードの既存の操作行の右端に38×38pxで配置する。操作行やタブを増やさず、盤面・プレイヤーカードの位置と寸法、状況カードの高さ、タブの位置を維持する。既存の準備・開始・投了等のボタンは同じ行に残し、横幅だけを調整してスタンプボタンを収める。PC・タブレット・スマートフォンとも同じ入口を使う。
- ボタンを押すと、6種類を3列・2行で並べたコンパクトなパネルを画面内に重ねて表示し、画面の寸法を変えない。説明文は表示しない。選択で1件だけ送信して閉じ、外側の操作・Escでも閉じる。自分の手番への切替、次局開始、別のダイアログの表示、切断、退室開始、閉鎖でも閉じる。キーボードで選択・取消でき、閉じた後は操作元へフォーカスを戻す。
- サーバーが受理した通知を受けた後、送信者本人と受信者で同じ演出を表示する。送信者の既存アバターを残し、その上に黒50%のレイヤーと絵文字を重ねる。アバター領域だけを150msで暗くし、絵文字は中央に収める。表示開始から3,000msで消え、最後の150msで暗いレイヤーと絵文字をフェードアウトして元のアバターへ戻す。動きを減らす端末設定ではフェードを省き、表示時間は同じとする。
- アバター枠の大きさを変えず、絵文字と暗いレイヤーを枠内に収める。名前・ホストの王冠・接続バッジ・時計・石数・持ち駒・準備状態・順位を隠さない。表示はクリックを透過し、プレイヤー情報を開く操作、着手、駒の選択・ドラッグを維持する。盤面回転後も送信者のプレイヤーIDに対応するカードへ表示する。
- 同じ送信者の演出は最新1件だけとし、新しい通知では置き換えて3秒を数え直す。複数人の演出はそれぞれのアバター内に表示する。通知IDによる重複受信では再表示・延長しない。現在のカードに存在しない送信者には表示しない。席の削除・次局開始・切断・退室開始・閉鎖・ページ非表示・画面離脱で演出とタイマーを破棄する。
- スタンプはライブ通知だけとし、既存チャット履歴・システムログ・棋譜・対局記録へ追加せず、チャットの直近100件を消費しない。再読み込み・再接続・途中入室・非表示からの復帰では再表示せず、非表示中に受けた通知も表示待ちにしない。スタンプ専用のtoast・効果音・通報操作は追加しない。
- チャットとスタンプを合算し、同じ送信者から3秒に1件まで受け付ける。サーバーは送信者本人・在室・ルーム世代・固定6種類・送信間隔を検証し、複数タブからの送信にも同じ制限を適用する。不正・制限超過・失敗では演出を表示しない。切断・認証未完了・退室中・応答待ち・送信間隔内は送信を無効にする。
- スタンプの応答待ちは10秒を上限とし、失敗・期限超過では待ちを解除して既存の操作エラー表示で案内する。自動再送しない。スタンプの送信待ちで準備・開始・投了・着手をロックせず、手番・持ち時間・CPUの待ち時間を変更しない。受理した送信は部屋の活動に含めるが、履歴やゲーム状態を追加しない。
- 既存のチャットの送信者非表示に該当する人のスタンプは表示せず、既存の部屋内送信停止中の人はスタンプも送信できない。このための設定画面や保存方式の変更は行わない。
- 「カード上のスタンプ表示」のON/OFFは、[表示・サウンド設定](#表示サウンド設定)を正本とする。初期値ON、即時切替、共通入口とパネル内入口、ブラウザ保存、保存失敗・復元・別タブへの反映に対応する。OFFでもスタンプの送信は可能とする。
- 受け入れ条件は全6ゲーム・各画面幅・待機／各手番／再戦待機での寸法と位置の維持、主要操作との非干渉、3秒の表示と解除、チャット履歴の不変、権限・連打制限・重複抑止・再接続時の再演防止とする。純粋関数・部品とhook・Worker統合テストで通信と時刻境界を確認し、画面寸法・ネイティブ入力・絵文字の実表示は手動確認する。ブラウザ自動テストは追加しない。

## MVP機能

初期MVPは四人リバーシを対象としました。四人将棋もオンライン対局へ接続し、全ゲームで共通のルーム機能を利用します。全ゲームの終局保存・本人の戦績と棋譜・ゲーム別ランキングを利用できます。

### 対局

- 四人リバーシの合法手、手番、パス、終局、順位の判定
- 持ち時間の表示と時間切れによる脱落
- 「CPUと遊ぶ」から、1人とCPU 3体で始められる対局
- 人間とCPUを組み合わせた1〜4人での対局
- CPUによる合法手の選択と、最低限の局面評価
- 対局終了後の再戦
- 同じ部屋で、直前1局を次局開始まで振り返る棋譜モード
- 終局データ・棋譜の保存と、マイページでの本人の対局履歴・戦績

### オンライン機能

- ニックネームを使ったゲスト参加と、ログイン中のアカウント参加
- 対局部屋の作成
- URLを使った招待
- 公開ロビーでの対局部屋の一覧表示・参加・観戦
- ゲーム別の最近の対局一覧と、保存済み棋譜の公開閲覧
- モード別の優勝数／勝利数・対局数ランキング
- 席へのCPUの追加と削除
- 盤面と手番のリアルタイム同期
- 対局中の通信切れからの復帰
- 対局の観戦
- 対局部屋の共通チャット

### 初めて利用する人のための機能

- 四人リバーシのルール説明
- 石を置ける場所や現在の手番の分かりやすい表示
- PCとスマートフォンの両方に対応した画面
- エラー発生時の分かりやすい案内
- 簡単なフィードバックの送信
- 対局の開始、完了、エラーを把握するための計測

### MVPに含めないもの

- 駒落ち・追加の対局モード
- レーティング
- 他プレイヤーの戦績閲覧
- 課金
- 高度なCPUや機械学習による思考

### 四人将棋のゲームエンジン

四人将棋のルール正本と調査資料は [四人将棋ルール](docs/rules/four-shogi.md) に記す。独立した `@tetraboard/four-shogi` パッケージに、シングルス・通常のダブルスと三人攻撃禁止のON／OFF切り替えを実装している。初期化、合法手、王手、着手、脱落、順位・勝敗、千日手を純粋な関数で扱い、状態はJSONで保存・復元できる。CPUは合法手からランダムに選ぶLv1と、駒の価値・王の安全・次の手番の応手を評価するLv2を利用できる。Lv2は探索する候補と応手を制限するため、読み落としがある。使い方と確認方法は [開発ドキュメント](docs/development.md#四人将棋エンジン) を参照する。エンジンとCPUはオンラインルームへ接続し、時刻・接続期限はルーム側で管理する。 オンライン対局の千日手履歴は必要な局面キーだけをSQLiteから取得し、変更分を保存する。対局の長さに比例した全件読み取りを各手で行わない。

## KPI・KGI

### KGI

1か月のMVP開発におけるKGIは、次の状態を実現することです。

> ユーザーが自力で四人リバーシの対局を最後まで完了し、その一部が7日以内にもう一度対局する。

最低成功ラインは次のとおりです。

- 初回対局完了者が10人以上いる
- 7日以内の再対局者が3人以上いる
- 完了対局が合計30局以上ある

開発者との個人的なつながりの有無を問わず集計します。

### KPI

| 観点     | 指標                              | 1か月目の最低目標 |
| -------- | --------------------------------- | ----------------: |
| 流入     | 訪問者                            |              30人 |
| 対局開始 | 訪問から対局を開始した割合        |           40%以上 |
| 対局完了 | 開始した対局の完了率              |           70%以上 |
| 継続     | 初回対局完了者の7日以内の再対局率 |           20%以上 |
| 利用量   | 完了対局数                        |          30局以上 |
| 満足度   | 「また遊びたい」と回答した割合    |           70%以上 |
| 品質     | 対局を続行不能にする重大障害      |   最終検証時に0件 |

利用者が少ない初期段階では割合が大きく変動するため、KPIは割合だけでなく実数も併せて評価します。最初の1か月は売上を成功条件にせず、継続して遊ばれる価値があることを確認した後に収益化を検討します。
